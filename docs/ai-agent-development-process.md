# AI 智能体开发流程说明

## 1. 文档目的与适用范围

**目的**：统一「智能体类产品/功能」从立项到持续运营的开发方式，减少返工与安全合规风险。

**适用范围**：基于大模型的对话/工具调用型智能体、多步任务编排、RAG/检索增强、与工作流或业务系统集成的 Agent。

**不适用**：仅做一次性 Prompt 实验、与生产无关的原型（可裁剪部分环节）。

---

## 2. 核心原则

1. **任务边界清晰**：智能体解决什么问题、不解决什么，写进需求与评测集。
2. **可观测、可回放**：日志、轨迹（trace）、版本化的 Prompt/策略便于排障与回归。
3. **人机协同默认**：关键动作需确认、高风险操作需权限与审计。
4. **安全与合规前置**：数据分级、出网、工具权限在设计阶段定稿，而非上线后补洞。
5. **评测驱动迭代**：用例集 + 定量指标决定发版，而不是仅凭主观体验。

---

## 3. 端到端流程总览

```mermaid
flowchart LR
  A[需求与场景] --> B[方案与架构]
  B --> C[数据与知识]
  C --> D[能力设计]
  D --> E[工程实现]
  E --> F[评测与红队]
  F --> G[发布与灰度]
  G --> H[监控与运营]
  H --> A
```

## 4. 分阶段说明

### 阶段 0：立项与需求

| 活动 | 产出 |
|------|------|
| 明确用户、场景、成功标准 | 需求说明、非目标列表 |
| 梳理输入输出、延迟与成本约束 | 非功能需求 |
| 识别合规（个人信息、行业监管） | 合规检查清单 |

**退出条件**：范围、优先级、约束书面确认。

---

### 阶段 1：方案与架构

| 活动 | 产出 |
|------|------|
| 选型：单轮 vs 多步、是否需规划/工具 | 架构说明 |
| 定义「大脑」职责与外围系统边界 | 组件图、接口契约 |
| 设计会话状态、上下文窗口策略 | 状态与记忆策略 |

**关注点**：避免把所有业务逻辑堆进 Prompt；复杂规则尽量代码化或可配置。

---

### 阶段 2：数据与知识（RAG / 工具数据源）

| 活动 | 产出 |
|------|------|
| 数据源清单与更新频率 | 数据目录 |
| 清洗、分块、索引策略 | 流水线与版本 |
| 权限：谁能访问哪些知识 | 访问控制说明 |

**退出条件**：离线/在线检索质量抽样通过既定标准。

---

### 阶段 3：能力设计（行为层）

| 活动 | 产出 |
|------|------|
| 系统提示词、策略（含拒绝与澄清） | Prompt/策略版本库 |
| 工具列表：名称、参数、错误语义 | OpenAPI/Schema 或等价描述 |
| 多步流程：规划、反思、终止条件 | 流程说明或状态机 |

**关注点**：工具要少而稳；参数校验在代码侧强制执行。

---

### 阶段 4：工程实现

| 活动 | 产出 |
|------|------|
| 编排层：调用模型、工具、记忆 | 服务代码与配置 |
| 鉴权、限流、配额 | 中间件与策略 |
| 日志：请求 ID、模型版本、工具调用轨迹 | 可查询日志规范 |
| 密钥与配置管理 | 环境分层（开发/预发/生产） |

**关注点**：超时、重试、降级路径；敏感信息不落日志。

---

### 阶段 5：评测与质效

| 活动 | 产出 |
|------|------|
| 构建评测集：典型、边界、对抗样例 | 用例集与标注规范 |
| 指标：任务成功率、幻觉率、工具误用率、延迟、成本 | 评测报告模板 |
| 回归：Prompt/模型/知识库变更必跑 | CI 或定期任务 |

**退出条件**：达到版本门禁指标（由团队事先定义）。

---

### 阶段 6：安全与红队

| 活动 | 产出 |
|------|------|
| Prompt 注入、越权工具调用、数据泄露场景 | 测试用例与修复记录 |
| 输出内容策略（违法、隐私、品牌） | 过滤与拦截策略 |
| 第三方模型与 API 的数据处理协议 | 法务/采购结论 |

---

### 阶段 7：发布与灰度

| 活动 | 产出 |
|------|------|
| 特性开关、按用户/流量灰度 | 发布计划 |
| 回滚预案：模型/配置/路由 | Runbook |
| 用户侧说明与反馈入口 | 公告或帮助文档 |

---

### 阶段 8：监控与持续运营

| 活动 | 产出 |
|------|------|
| 业务看板：成功率、满意度、投诉类型 | Dashboard |
| 异常告警：错误率飙升、延迟、成本 | 告警规则 |
| 定期复盘：坏例入库、Prompt/知识迭代 | 迭代 backlog |

---

## 5. 角色与协作（参考）

| 角色 | 主要职责 |
|------|----------|
| 产品/业务 | 场景、指标、验收 |
| 算法/Prompt | 策略、评测集、模型选型建议 |
| 工程 | 编排、工具、稳定性、安全落地 |
| 数据 | 知识库与数据管线 |
| 安全/合规 | 审查与红队 |
| 运维/SRE | 容量、发布、监控 |

小团队可一人多职，但**评测、安全、工程**三类职责不要完全空缺。

---

## 6. 版本与变更管理（建议）

- **Prompt/策略**：语义化版本或变更单号；变更关联评测结果。
- **知识库/索引**：与代码类似，可回滚到指定版本。
- **模型**：固定默认版本；升级走灰度与对比评测。

---

## 7. 常见反模式（避免）

- 无评测集反复改 Prompt，线上问题难以归因。
- 工具权限过大且无审计。
- 把个人敏感数据喂给不可控的外部模型且无脱敏。
- 缺少 trace，用户投诉无法复现。
- 仅优化「会说话」，不优化「任务完成率与成本」。

---

## 8. 附录：最小检查清单（发版前）

- [ ] 需求与非目标已文档化
- [ ] 工具参数校验与权限已落实
- [ ] 评测集通过门禁
- [ ] 安全抽检/红队项已处理或有已知风险登记
- [ ] 监控、告警、回滚路径可用
- [ ] 隐私与数据流已评审
