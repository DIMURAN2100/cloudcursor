# 全球网络安全简报（AI 专题）— 2026-10-21（GMT+8）

本期主要覆盖东八区过去约 24 小时（约 10 月 20 日）可核验的公开披露；其中 Langchain-Chatchat / piflow / OpenSRE / LangAlpha / Aix-DB 一组智能体聊天与工具链 Critical/High 条目、官方 MCP TypeScript SDK 实验任务越权、IBM ContextForge MCP 网关 OAuth SSRF，以及 LangBot 飞书 Webhook 签名修复的正式发行，集中在 10 月 20 日经 NVD、GitHub Advisory、IBM 安全公告与 VulnCheck / Lasso 公开。时效均已对照 NVD 发布时间、发行说明与源码提交核对；不重复前几日已写且无新补丁进展的 Agent Mesh、crewAI、Apache Answer、SGLang、BentoML、Omnigent、OneUptime、DeepSeek Harness、LMCache、商务部第 48 号、EN 18286 等条目。

### 一、今日要点

**[1] piflow聊天面无认证可RCE**
📌 类型：AI自身安全

NVD / VulnCheck 于 10 月 20 日公开 CVE-2026-109442（CVSS 3.1 约 9.8 / CVSS 4.0 约 9.3 Critical）：中国科学院大数据实验室 piflow 2.0.0—2.0.1 的 DeepAgents 聊天接口 `POST /chat` 与 `POST /chat/stream` 缺少认证，攻击者可指示智能体调用 `exec_shell` 工具，经 `subprocess.run` 在无人工批准、无命令白名单的情况下执行任意命令，暴露 LLM API 密钥与数据库凭据等环境秘密。截至核验，最新公开发行仍为 v2.0.1，未见标明修复版本。属已确认缺认证叠加危险工具暴露；未见在野利用通报。

🔗 来源：[VulnCheck 公告](https://www.vulncheck.com/advisories/piflow-2.0.0-through-2.0.1-unauthenticated-rce-via-chat-agent-exec-shell) · [NVD CVE-2026-109442](https://nvd.nist.gov/vuln/detail/CVE-2026-109442) · [Lasso 条目](https://www.lasso.security/vulnerability-database/cve-2026-109442)

**[2] Chatchat工具调用口可直打Shell**
📌 类型：AI自身安全

同日披露 CVE-2026-75128（CVSS 3.1 约 9.8 / CVSS 4.0 约 9.3 Critical）：Langchain-Chatchat 至 0.3.1.3 暴露未认证的 `POST /tools/call`，可按名称调用任意已注册工具；默认始终注册的 shell 工具使远程攻击者单次请求即可执行操作系统命令，官方 Docker 镜像中常以 root 运行。公开材料未见正式修复版本。属已确认缺认证 RCE 设计缺陷；未见在野利用通报。

🔗 来源：[VulnCheck 公告](https://www.vulncheck.com/advisories/langchain-chatchat-through-0.3.1.3-unauthenticated-rce-via-tools-call-endpoint) · [NVD CVE-2026-75128](https://nvd.nist.gov/vuln/detail/CVE-2026-75128) · [Lasso 条目](https://www.lasso.security/vulnerability-database/cve-2026-75128)

**[3] LangBot飞书Webhook正式补丁**
📌 类型：AI自身安全

昨日披露的 LangBot 飞书/Lark Webhook 缺签名校验问题（CVE-2026-112265）迎来正式发行进展：项目于 10 月 20 日发布 v4.11.1，版本区间包含提交 `7b7f1d20`（在分发前校验 `X-Lark-Signature` 事件订阅签名）。此前公开材料仅确认主分支已有修复、最新标签仍停在 v4.11.0。属已确认缺陷的补丁进展；建议将公网暴露的飞书 Webhook 模式升至 4.11.1+。GitHub Advisory 条目尚未同步标注 first patched version，以发行说明与提交为准。

🔗 来源：[LangBot v4.11.1 发布说明](https://github.com/langbot-app/LangBot/releases/tag/v4.11.1) · [签名校验提交](https://github.com/langbot-app/LangBot/commit/7b7f1d20f4921ae827f9cd6ee65e130bedf7ec49) · [NVD CVE-2026-112265](https://nvd.nist.gov/vuln/detail/CVE-2026-112265)

**[4] MCP官方TS SDK任务可跨会话读写**
📌 类型：AI基础设施CVE

GitHub Advisory / NVD 于 10 月 20 日公开 CVE-2026-111767（CVSS 3.1 约 8.6 High）：官方 `@modelcontextprotocol/sdk`（MCP TypeScript SDK）1.24.0 至 1.31.0 的实验性 `taskStore` 未绑定创建任务的会话，共享同一 `InMemoryTaskStore` 的客户端可列举、读取与取消彼此任务。官方已在 1.32.0 将任务与会话绑定；2.x 不受影响。公告建议停用已弃用的实验任务机制（2026-07-28 规范已由新扩展取代）。属已确认授权缺陷，仅影响向 `McpServer`/`Server` 传入 `taskStore` 的 HTTP 部署。

🔗 来源：[GitHub Advisory GHSA-22jm-h49p-29qw](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-22jm-h49p-29qw) · [NVD CVE-2026-111767](https://nvd.nist.gov/vuln/detail/CVE-2026-111767) · [修复提交](https://github.com/modelcontextprotocol/typescript-sdk/commit/727075b5bbeb77fbea22041b36b72a73042160fa)

**[5] OpenSRE审批门可被提示注入绕过**
📌 类型：AI自身安全

NVD / VulnCheck 于 10 月 20 日公开 CVE-2026-109444（CVSS 3.1 约 8.8 / CVSS 4.0 约 8.7 High）：OpenSRE 至 0.1.2026.10.19 中，无头 presenter 的 `execution_allowed()` 恒返回 True，使 `shell_run` 审批门失效；攻击者可向智能体分流的告警或 Slack 消息注入指令，在主机执行命令并外泄 LLM、Slack 与云凭据。同日发布的 v0.1.2026.10.20 变更说明未宣称修复该审批门，源码中同一函数仍恒返回 True。属已确认授权绕过叠加提示注入利用路径；未见在野利用通报。

🔗 来源：[VulnCheck 公告](https://www.vulncheck.com/advisories/opensre-through-0.1.2026.10.19-approval-gate-bypass-via-shell-run-prompt-injection) · [NVD CVE-2026-109444](https://nvd.nist.gov/vuln/detail/CVE-2026-109444) · [Lasso 条目](https://www.lasso.security/vulnerability-database/cve-2026-109444)

**[8] ContextForge网关OAuth可SSRF**
📌 类型：AI基础设施CVE

NVD 于 10 月 20 日收录 CVE-2026-8355（NVD CVSS 3.1 约 5.4 Medium；IBM 公告自评 6.4）：IBM ContextForge MCP Gateway ≤1.0.5 在 OAuth `client_credentials` 网关注册时，未对 `oauth_config.token_url`（及同类 URL 字段）施加与 `gateway.url` 同等的 SSRF 校验，持有 `gateways.create` 的低权限认证用户可诱使网关向内网、回环或云元数据发起 HTTP POST，并在 502 错误中回显最多约 256 字节响应体。IBM 要求升级至 v1.0.6+；临时缓解包括收回不可信角色的网关创建权限并封锁元数据/RFC1918 出口。属已确认厂商公告缺陷。

🔗 来源：[IBM 安全公告](https://www.ibm.com/support/pages/node/7285723) · [NVD CVE-2026-8355](https://nvd.nist.gov/vuln/detail/CVE-2026-8355) · [v1.0.6 发布说明](https://github.com/IBM/mcp-context-forge/releases/tag/v1.0.6)

### 二、深度速览

#### 【AI 赋能防御】

LangBot v4.11.1 将飞书事件签名校验带入正式发行，说明 IM Webhook 这类“把聊天事件当可信指令源”的入口，最终仍需平台密码学校验，而不能依赖模型自觉或仅靠网络边界。对自建 Bot/Agent 平台，可对照：事件签名是否在反序列化与工具调度之前强制失败关闭，以及含修复提交是否已进入可部署标签而非仅停留在主分支。

🔗 来源：[v4.11.1 发布说明](https://github.com/langbot-app/LangBot/releases/tag/v4.11.1) · [签名校验提交](https://github.com/langbot-app/LangBot/commit/7b7f1d20f4921ae827f9cd6ee65e130bedf7ec49)

IBM ContextForge 1.0.6 将 SSRF/TLS 校验扩展到 OAuth 配置 URL，暴露出“主 URL 字段已加固、附属配置字段漏检”的常见网关失败模式。对 MCP/A2A 网关与工具注册面，应对所有会触发服务端出站请求的 URL 参数统一施加拒绝私网/元数据策略，并以权限最小化限制谁可以注册新后端。

🔗 来源：[IBM 安全公告](https://www.ibm.com/support/pages/node/7285723) · [v1.0.6 发布说明](https://github.com/IBM/mcp-context-forge/releases/tag/v1.0.6)

#### 【AI 系统风险】

本期主轴是“聊天/工具 API 缺认证 + 永久挂载 shell/execute”与“审批门形同虚设 + 间接提示注入”。piflow 与 Langchain-Chatchat 证明，一旦 DeepAgents/工具注册表对外裸奔，模型工具链即退化为远程命令通道；OpenSRE 与 LangAlpha 则表明，即使存在审批或沙箱叙事，只要 headless 路径恒放行或 Bash/代码执行无白名单，提示注入即可把告警、Slack 与网页内容变成主机 RCE；Aix-DB 进一步把文档上传变成同等攻击面。MCP TypeScript SDK 的跨会话 task 读写，则提醒共享内存型会话状态同样是多租户 MCP 服务的横向风险。共性缓解包括：聊天与工具调用强制认证与授权、默认禁用或强隔离 shell/execute、审批门在无头路径也必须生效、检索内容与消息通道按不可信输入处理，以及对实验性会话存储做每会话隔离或直接停用。

🔗 来源：[CVE-2026-109442](https://nvd.nist.gov/vuln/detail/CVE-2026-109442) · [CVE-2026-75128](https://nvd.nist.gov/vuln/detail/CVE-2026-75128) · [GHSA-22jm-h49p-29qw](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-22jm-h49p-29qw)

### 三、今日趋势洞察

智能体产品的高危面正从“单个 MCP 服务器缺认证”进一步落到“聊天 API / 工具调用口缺认证且默认挂载 shell”的组合失败；与此同时，审批门与沙箱若仅在交互式路径生效、在 headless/网关路径恒放行，提示注入即可把告警与即时消息直接升级为主机命令执行，使控制面缺陷与模型输入污染成为同一条利用链。

### 四、企业行动清单

- 立即盘点是否公网暴露 piflow DeepAgents 聊天口或 Langchain-Chatchat `/tools/call`：下线或加反向认证，禁用默认 shell/exec 工具，并轮换可能泄露的 LLM 与数据库密钥。
- 将 LangBot 升至 4.11.1+，确认飞书/Lark Webhook 已启用事件签名校验后再恢复公网回调。
- 审查依赖 `@modelcontextprotocol/sdk` 1.24.0—1.31.0 且启用 `taskStore` 的 MCP HTTP 服务：升级至 1.32.0+，或移除共享 `InMemoryTaskStore` / 改为每会话实例。
- 对 OpenSRE、LangAlpha、Aix-DB 等带 shell/execute 的 Agent：在官方修复前切断 Slack/告警自动执行与文档驱动代码执行，或仅允许隔离只读角色访问。
- 将 IBM ContextForge MCP Gateway 升至 1.0.6+，收回不可信角色的 `gateways.create`，并封锁网关主机至云元数据与 RFC1918 的出站 HTTP。
