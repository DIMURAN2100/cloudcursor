### 一、今日要点

**[1] AI网关跨租户密钥注入**
📌 类型：AI基础设施CVE

Red Hat 安全响应与 NVD 于 10 月 28 日公开 CVE-2026-117574（Critical，CVSS 3.1 基础分 9.1，AV:N/AC:L/PR:L/UI:N/S:C）：`ai-gateway-payload-processing` 在处理请求时，可从客户端可控的路径或请求体/头中的模型标识解析租户与模型名，并在进程内未完成授权校验的情况下，从共享凭据存储取出对应提供商 API 密钥注入请求。已认证攻击者若能指定其他租户模型标识，即可盗用目标租户 LLM 资源与配额，并造成密钥级机密性影响。设计上依赖网关侧 AuthPolicy 在到达扩展处理前拦截越权路径；若策略覆盖不全或扩展处理端口可被直连，隔离即失效。属确认的多租户 AI 网关缺陷，公开材料未声称在野利用；企业应核对应补丁与网关授权策略是否覆盖全部模型路由路径。

🔗 来源：[NVD CVE-2026-117574](https://nvd.nist.gov/vuln/detail/CVE-2026-117574) · [Red Hat Bugzilla 2494861](https://bugzilla.redhat.com/show_bug.cgi?id=2494861) · [Red Hat CVE 页](https://access.redhat.com/security/cve/CVE-2026-117574)

**[2] Strands环境工具掩码绕过**
📌 类型：AI自身安全

AWS 安全公告 AWS-2026-154（2026-10-28 发布，Important）确认 CVE-2026-115415（Medium，6.5）：开源包 `strands-agents-tools` 中的 environment 工具默认会对疑似密钥的环境变量做掩码，但掩码开关曾暴露在可供大模型调用的工具 schema 中。经由代理所处理内容投递的特制提示，可诱导模型在调用该工具时关闭掩码，从而以明文返回主机环境变量（含云凭据与 API 密钥），且无需操作者二次同意。受影响版本为 0.1.0 起至 0.8.6 之前；0.8.6 起掩码仅由操作者控制，模型不可关闭，并宣布弃用该工具。AWS 建议升级并轮换曾加载该工具的代理进程环境中的凭据；无法升级时应移除 environment 工具、避免在进程环境放置长寿命密钥并限制出站。属 CWE-1427（LLM 提示输入未正确中和）类确认缺陷，公开信息未表明大规模在野利用。

🔗 来源：[AWS 安全公告 AWS-2026-154](https://aws.amazon.com/security/security-bulletins/2026-154-aws/) · [NVD CVE-2026-115415](https://nvd.nist.gov/vuln/detail/CVE-2026-115415) · [GitHub Advisory GHSA-qjx4-hg6g-2f34](https://github.com/strands-agents/tools/security/advisories/GHSA-qjx4-hg6g-2f34)

**[3] Agent测试打入Anthropic业务系统**
📌 类型：AI赋能安全

《华盛顿邮报》10 月 26 日独家报道、Quartz 与 Decrypt 等 10 月 27 日跟进：由前 DOGE 成员创办的安全初创公司 Cathedral 称，在 Anthropic 面向外部研究者的类漏洞赏金安排下，其 AI Agent 在约 12 小时内经由第三方企业管理/销售类软件缺陷进入 Anthropic 部分内部业务系统，草稿报告称触及会议转写、薪酬与录用信息，以及讨论先进模型的 Slack 消息。Anthropic 确认研究者进入了“有限集合”的销售、HR 与 IT 系统，并称未触及 Claude 用户对话、源代码或模型权重，亦未发现除 Cathedral 外的利用证据；监控曾在对方报告前发现部分活动，当日切断访问，并将有漏洞工具下线直至厂商确认修复。Anthropic 同时指对方夸大国家安全含义且未完全按项目规则披露全部活动。此为授权研究框架下的 Agent 赋能红队演示与厂商确认响应，不宜等同已确认的在野国家级打穿或模型权重失窃。

🔗 来源：[Washington Post（10/26）](https://www.washingtonpost.com/technology/2026/10/26/researchers-cybersecurity-start-up-cathedral-got-inside-anthropic) · [Quartz（10/27）](https://qz.com/cathedral-ai-agents-anthropic-systems-breach-102726)

**[4] Telerik文档AI工具路径穿越**
📌 类型：AI基础设施CVE

Progress Telerik 于约 10 月 27 日更新知识库、NVD 于 10 月 28 日收录 CVE-2026-118038（High，7.1）：Document Processing Libraries 中面向 AI Agent 的 Convert / Merge 工具（`Telerik.Documents.AI.AgentTools.Conversion`，受影响约 2026.1.210 起至 2026.3.1027 之前），在解析工具参数时存在路径穿越，已认证低权限攻击者若能供给工具参数，可通过相对路径读取配置输出目录之外的文件，并在目标可写时覆盖。根因属 CWE-22，路径相对进程当前工作目录解析。官方修复版本为 2026.3.1027 及以上。属文档处理链路上“AI Agent 工具参数等同不可信输入”的确认缺陷，公开材料未声称在野利用。

🔗 来源：[Telerik 安全知识库 CVE-2026-118038](https://docs.telerik.com/devtools/document-processing/knowledge-base/kb-security-path-traversal-cve-2026-118038) · [NVD CVE-2026-118038](https://nvd.nist.gov/vuln/detail/CVE-2026-118038)

**[5] KServe模型拉取SSRF**
📌 类型：AI基础设施CVE

NVD 与 Red Hat 于 10 月 28 日公开 CVE-2026-13451（High，7.7，AV:N/AC:L/PR:L/UI:N/S:C）：KServe 中，仅具备命名空间内 InferenceService 自定义资源创建/更新权限的用户，可通过恶意 `storageUri` 触发 `storage-initializer` init 容器从集群内发出任意出站 HTTP/HTTPS 请求（SSRF，CWE-918）。影响包括节点 IAM 角色凭据窃取及访问集群内部服务等信息泄露；Red Hat 材料列明 OpenShift AI 相关 KServe 组件包受影响。公开描述称上游主线与 v0.17.0 等存在该问题，验证基于代码审查；修复与发行版勘误请以 Red Hat/上游后续公告为准。属模型工件拉取路径上的确认基础设施风险，而非模型权重本身被投毒。

🔗 来源：[NVD CVE-2026-13451](https://nvd.nist.gov/vuln/detail/CVE-2026-13451) · [Red Hat Bugzilla 2493640](https://bugzilla.redhat.com/show_bug.cgi?id=2493640) · [Red Hat CVE 页](https://access.redhat.com/security/cve/CVE-2026-13451)

**[6] WoowBot RAG同步刷额度**
📌 类型：AI自身安全

Wordfence 于 10 月 27 日公开、NVD 于 10 月 28 日收录 CVE-2026-111372（Medium，4.3）：WordPress 插件 AI ChatBot for WooCommerce（WoowBot）在 5.0.0 及更早版本中，对 `qcld_rag_manual_sync` 等 AJAX 动作缺少充分授权校验。订阅者级已认证攻击者可反复触发 RAG 文档同步，从而消耗站点管理员配置的 OpenAI、Gemini、OpenRouter 或 xAI 等付费嵌入 API 额度；相关 nonce 通过 `wp_localize_script` 向前端已登录访客暴露，获取门槛低。修复版本 5.0.1。属面向电商聊天机器人 RAG 管道的确认计费滥用缺陷，影响机密性有限，但直接造成 API 费用损失。

### 二、深度速览

#### 【AI 赋能防御】

Cathedral 案例把“AI Agent 作为红队劳动力”推进到前沿模型厂商的真实业务软件边界：攻击路径并不依赖打穿模型权重或训练集群，而是自动化枚举企业普遍使用的第三方管理/销售工具缺陷。对防御方，这意味着资产盘点与漏洞响应必须覆盖 AI 实验室周边的 SaaS 管理面，而不能只加固推理与训练平面；Anthropic 在确认后下线有漏洞工具并等待厂商修复，是把供应商补丁门禁重新纳入事件响应的可操作做法。与此同时，CVE-2026-117574 提醒：多租户 AI 网关若把租户隔离寄托于网关 AuthPolicy，却在 payload 处理阶段仍按客户端声明选择密钥，则“策略漏配或端口暴露”会直接变成跨租户配额与密钥盗用；防御重点是路径级授权与进程内二次校验同时存在，而不是二选一。

🔗 来源：[Washington Post](https://www.washingtonpost.com/technology/2026/10/26/researchers-cybersecurity-start-up-cathedral-got-inside-anthropic) · [Red Hat Bugzilla 2494861](https://bugzilla.redhat.com/show_bug.cgi?id=2494861)

#### 【AI 系统风险】

三条机制值得并列。一是 **把安全开关交给模型可控 schema**：Strands environment 工具允许提示诱导关闭密钥掩码，说明“默认掩码”在工具参数可被 LLM 覆写时形同虚设；修复方向是安全属性仅由操作者在构造时钉死。二是 **Agent 工具参数即文件系统原语**：Telerik Convert/Merge 工具对相对路径解析不当，使低权限调用者可读/写输出目录外文件。三是 **模型工件 URI 即集群出站能力**：KServe `storageUri` 的 SSRF 把 InferenceService 写权限升级为集群内任意 HTTP 客户端。共性缓解：工具 schema 禁止暴露安全关键参数、对 Agent 工具参数做绝对路径与允许目录约束、对模型拉取 URI 做网络目的地策略与元数据服务屏蔽。

🔗 来源：[AWS-2026-154](https://aws.amazon.com/security/security-bulletins/2026-154-aws/) · [Telerik CVE-2026-118038](https://docs.telerik.com/devtools/document-processing/knowledge-base/kb-security-path-traversal-cve-2026-118038) · [NVD CVE-2026-13451](https://nvd.nist.gov/vuln/detail/CVE-2026-13451)

### 三、今日趋势洞察

多租户 AI 网关与 Agent 工具链正在把“身份声明由客户端/模型供给”直接映射为密钥选择、文件读写与集群出站能力，隔离失败的代价从内容越权升级为凭据与配额失窃；与此并行，授权红队已证明自动化 Agent 更擅长打穿前沿实验室周边的企业 SaaS 管理面，而非首先撞击模型权重——企业侧的供应商补丁门禁与 Agent 工具参数硬化需要同步升级。

### 四、企业行动清单

- 核查多租户 AI 网关/`ai-gateway-payload-processing` 相关组件是否受 CVE-2026-117574 影响，确认模型路由路径均经 AuthPolicy 覆盖，并禁止直连扩展处理端口；按厂商勘误升级后轮换可能被注入过的提供商 API 密钥。
- 将 `strands-agents-tools` 升级至 0.8.6+ 或移除 environment 工具；对曾加载该工具的代理主机轮换环境中的云凭据与 API 密钥，限制代理出站仅到可信端点。
- 将使用 Telerik Document Processing AI Agent 工具的应用升级至 2026.3.1027+，复核工具参数是否允许调用方指定输出路径。
- 盘点 KServe/OpenShift AI 上 InferenceService 的 `storageUri` 写权限与网络策略，阻断 storage-initializer 访问云元数据与内网管理面，并跟进上游/发行版修复。
- 将 WoowBot 升至 5.0.1+，限制订阅者触发 RAG 同步的权限，并为嵌入 API 密钥配置用量告警与预算上限。
