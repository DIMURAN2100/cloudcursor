# 全球网络安全简报（AI 专题）— 2026-09-26（GMT+8）

本期覆盖东八区过去约 48 小时可核验动态；ServiceNow、DBHub、Cline、Amazon Q 等公告可上溯至 9 月 24 日（约 72 小时内），MemTensor 恶意版本发布时间约为 9 月 23 日，一并列示。

### 一、今日要点

**[1] ServiceNow AI平台SQL注入**
📌 类型：AI基础设施CVE

ServiceNow 披露并已修复 AI Platform 中的 SQL 注入漏洞 CVE-2026-13016（CVSS 9.3，严重）。在特定条件下，未认证用户可能对实例底层数据库执行任意 SQL，从而越权读取或修改实例数据。厂商称已向托管实例推送安全更新，并向合作伙伴与自托管客户提供补丁；官方表示目前未见在野利用证据。该缺陷直接触及企业 AI 平台数据面，应按紧急变更处理。

🔗 来源：[NVD CVE-2026-13016](https://nvd.nist.gov/vuln/detail/CVE-2026-13016) · [ServiceNow KB3159623](https://support.servicenow.com/kb?id=kb_article_view&sysparm_article=KB3159623)

**[2] DBHub MCP DNS重绑定泄库**
📌 类型：AI基础设施CVE

Bytebase 数据库 MCP 服务 DBHub 披露 CVE-2026-61742（CVSS 9.3）：在文档化的 HTTP 传输模式下，未认证 `/mcp` 端点仅用 Origin/Host 主机名相等性校验浏览器来源，可被 DNS 重绑定绕过，使恶意网页在无需提示注入或模型参与的情况下直接调用 MCP 工具读写数据库。同日披露的 CVE-2026-61788 表明 `readonly=true` 未真正启用只读连接，语句首词分类可被绕过。官方修复版本分别为 0.22.5 与 0.22.6；属已确认的工具链漏洞，未见公开在野利用报告。

🔗 来源：[GHSA-fm8p-53ww-hf6w](https://github.com/advisories/GHSA-fm8p-53ww-hf6w) · [GHSA-mwwr-p57h-56pf](https://github.com/advisories/GHSA-mwwr-p57h-56pf) · [NVD CVE-2026-61742](https://nvd.nist.gov/vuln/detail/CVE-2026-61742)

**[3] Zammad AI Agent配置RCE**
📌 类型：AI自身安全

客服平台 Zammad 披露 CVE-2026-84462：7.1.2 之前版本中，保护 AI Agent 配置的安全过滤可被特制字段文本绕过；具备创建或编辑 AI Agent 权限的管理员可借此在托管服务器执行任意命令，进而读写或破坏服务器数据，无需其他用户交互。厂商已在 7.1.2 修复；同批还修复 AI 分析运行标识越权读取错误信息（CVE-2026-63204）及选项标签 XSS（CVE-2026-63216）。属已确认产品漏洞，非在野攻击报道。

🔗 来源：[NVD CVE-2026-84462](https://nvd.nist.gov/vuln/detail/CVE-2026-84462) · [Zammad GHSA-gp3x-9xm8-rcj6](https://github.com/zammad/zammad/security/advisories/GHSA-gp3x-9xm8-rcj6)

**[4] Cline Hub跨源WebSocket劫持**
📌 类型：AI自身安全

开源编码智能体 Cline 披露 CVE-2026-59723（高危）：`cline dashboard` 启动的 Hub 在 `/browser` WebSocket 上未校验 Origin；本地默认未设置 `ROOM_SECRET` 时授权恒为通过，攻击者控制的网页可连接至本机仪表盘。攻击者可读写工作区/会话状态、篡改 MCP 与模型提供方配置，并在默认 `autoApprove` 下触发命令执行；研究已确认可注入恶意 stdio MCP 条目。修复版本为 cline 3.0.30。

🔗 来源：[GHSA-3cj3-hqcr-g934](https://github.com/advisories/GHSA-3cj3-hqcr-g934) · [NVD CVE-2026-59723](https://nvd.nist.gov/vuln/detail/CVE-2026-59723)

**[5] BragJack劫持浏览器内置AI**
📌 类型：AI自身安全

Forever Security 披露 BragJack 研究：恶意扩展可通过劫持浏览器内置 AI 助手所信任的页面通道，在零点击条件下向 Chrome（Gemini）、Edge、Opera Neon、Perplexity Comet 及 Claude in Chrome 下发指令，影响面包括本地文件、音视频设备、截屏与浏览器代理操控等（因产品而异）。研究称已获多家厂商赏金，并给出 CVE-2026-0628、CVE-2026-55945 等标识。此为已协调披露的研究演示，SecurityWeek 于 9 月 25 日转述；不等同于大规模在野活动确认。

🔗 来源：[Forever Security](https://forever.security/blog/bragjack-hijacking-5-browsers-via-built-in-ai-assistants/) · [SecurityWeek 周报](https://www.securityweek.com/in-other-news-clop-leak-site-takeover-docker-botnet-hunts-ai-keys-water-utility-exposure/)

**[6] MemTensor记忆组件供应链投毒**
📌 类型：AI基础设施CVE

Semgrep、Aikido、StepSecurity 等报告：MemTensor MemOS 相关合法包在 npm/PyPI 被植入名为 sckit 的 Go 植入体（恶意版本约出现于 9 月 23 日），载荷不在 install 钩子触发，而在 Python import 或 OpenClaw 插件注册时执行，用于窃取 npm、PyPI、GitHub、AWS、Hugging Face 等凭据，并含向多生态扩散的模板。SecurityWeek 9 月 25 日汇总称暂无已传播证据。属已确认的 AI Agent 记忆/插件供应链投毒（多源交叉印证）。

🔗 来源：[Semgrep 分析](https://semgrep.dev/blog/2026/the-ai-ecosystem-has-worms-now-inside-the-memtensor-compromise/) · [SecurityWeek 周报](https://www.securityweek.com/in-other-news-clop-leak-site-takeover-docker-botnet-hunts-ai-keys-water-utility-exposure/)

**[7] Carbonato滥用Hermes智能体**
📌 类型：AI赋能安全

Malwarebytes ThreatDown 披露 Carbonato 活动：攻击暴露且未认证的 Docker API（2375），植入开源 Hermes Agent，并以 GH0ST 等人设经 Telegram 接收自然语言指令、自主生成并执行终端命令，优先搜集 AI API 密钥等凭据。BleepingComputer 与 SecurityWeek 于 9 月 24–25 日跟进。该活动展示将合法智能体框架用作事后控制层的在野手法；企业需把未授权 Agent 框架与 AI 密钥失窃纳入容器与密钥响应流程。

🔗 来源：[BleepingComputer](https://www.bleepingcomputer.com/news/security/new-carbonato-malware-uses-ai-agents-to-hijack-exposed-docker-hosts/) · [SecurityWeek 周报](https://www.securityweek.com/in-other-news-clop-leak-site-takeover-docker-botnet-hunts-ai-keys-water-utility-exposure/)

**[8] Amazon Q语言服务器越界写**
📌 类型：AI基础设施CVE

AWS 语言服务器（支撑 Amazon Q Developer 等 IDE 智能体能力）于 9 月 24 日公开两则高危公告：CVE-2026-12957 涉及打开并信任恶意工作区时可能自动执行项目配置中的命令；CVE-2026-12958 涉及符号链接校验缺失导致工作区信任边界外任意文件写入。npm 包 `@aws/lsp-codewhisperer` 修复版本分别指向 0.0.113 与 0.0.117。属本地工作区信任模型问题，需用户打开恶意项目触发，并非远程未认证 RCE。

🔗 来源：[GHSA-xhcr-j4j9-3gh7](https://github.com/advisories/GHSA-xhcr-j4j9-3gh7) · [GHSA-6v3r-4p5c-mrp5](https://github.com/advisories/GHSA-6v3r-4p5c-mrp5)

### 二、深度速览

#### 【AI 赋能防御】

Carbonato 把开源 Hermes Agent 变成 Docker 失陷主机上的自然语言控制通道，并将 AI API 密钥设为优先搜集目标。对 SOC 而言，检测面需延伸到“未备案智能体框架进程 + 即时通讯外联 + 异常模型 API 调用”，而不能只匹配传统后门家族签名。建议在容器基线中禁止公网可达的未认证 Docker API，对开发与 CI 中的 AI 密钥实施短时限与可审计发放；一旦发现未授权 Agent，应按密钥泄露事件同步轮换下游模型与云凭证。

MemTensor/sckit 事件说明 AI 供应链扫描不能只盯 `postinstall`：投毒方已转向 import/插件注册期执行。软件物料清单应显式纳入 Agent 记忆插件、MCP 服务与模型 SDK，并按 Semgrep 公布的恶意版本与 IoC 回溯 `@memtensor/*`、`MemoryOS` 等包，监控异常的多生态凭据读取。

#### 【AI 系统风险】

ServiceNow AI Platform 的未认证 SQL 注入把企业 AI 功能面直接连到核心业务库，AI 模块补丁优先级不应低于 CRM/ITSM 主干。DBHub 展示了 MCP HTTP 传输的典型失败组合：以 Origin/Host 字符串相等冒充认证，再叠加“只读开关未落到连接参数”，即可在无提示注入条件下操作数据面。Cline Hub 与 Zammad AI Agent 配置面则表明：智能体控制台、自动批准工具与高权限管理配置同属高价值攻击面，本机回环绑定并不能阻止恶意网页发起的跨源 WebSocket 或管理端滥用。

BragJack 把风险前移到浏览器内置助手：扩展一旦污染助手信任通道，即可在零点击下调用已授权的文件、媒体与代理能力。缓解应组合扩展准入、助手敏感能力默认拒绝，以及将浏览器 AI 代理纳入终端安全策略，而不是仅依赖模型输出护栏。

#### 【全球治理与标准】

本日该类别无可核实的重要更新，不强行补充。

### 三、今日趋势洞察

企业 AI 风险正同时出现在平台数据面（ServiceNow）与工具协议/控制面（DBHub MCP、Cline/Zammad），补丁与暴露面治理必须覆盖 AI 产品模块与 MCP/Agent 运行时。攻击侧则把合法智能体框架与 AI 记忆插件生态用作供应链与事后控制基础设施（MemTensor、Carbonato），防御重心正从提示词过滤转向依赖完整性、密钥治理与未授权 Agent 检出。

### 四、企业行动清单

- 立即核验 ServiceNow 实例（含自托管）是否已应用 KB3159623/CVE-2026-13016 相关更新，并由平台负责人确认 AI Platform 组件版本。
- 清点内网与开发机上的 DBHub、Cline Hub、Zammad：升级至厂商修复版本，关闭或鉴权 MCP HTTP/本地仪表盘暴露面，禁用默认 auto-approve。
- 对 npm/PyPI 依赖执行 MemTensor/MemOS 恶意版本排查，轮换可能接触过可疑包的 GitHub、云与 Hugging Face 令牌。
- 扫描并关闭未认证 Docker API（尤其 2375），检出 Hermes Agent 等未批准智能体框架及异常 Telegram 外联。
- 收紧浏览器扩展与内置 AI 助手策略，升级至厂商已修复构建，并将 Amazon Q/`@aws/lsp-codewhisperer` 升至含 0.0.117 修复链的版本。
