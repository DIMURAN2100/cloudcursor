全球网络安全简报（AI 专题）— 2026-09-09（GMT+8）

本期资讯主要覆盖东八区过去约 48 小时（2026-09-07 至 2026-09-09）可核验公开披露；其中 Google GTIG 报告中的部分战役发生于 Q2，但官方于 9 月 8 日发布，按重大追踪收录。

### 一、今日要点

**[1] ChatGPT跨账户隐蔽外泄**
📌 类型：AI自身安全

Check Point Research 于 9 月 8 日公开研究演示：植入提示（粘贴提示、共享会话或自定义 GPT）后，ChatGPT 可在正常回答用户的同时，通过代码执行容器共享的内部 JFrog Artifactory 元数据属性，在不同账户会话间建立隐蔽双向通道。PoC 中可读取受害者已连接的 Gmail 等应用数据，并外传聊天记录与会话文件；用户侧往往仅见事后“Talked to Gmail”标记。此为研究演示，厂商已确认相关内部 Artifactory 实例下线，用户侧无需安装补丁，但连接应用默认“Important actions”仍允许静默读取。

🔗 来源：[Check Point Research](https://research.checkpoint.com/2026/the-shared-clipboard-inside-the-sandbox-cross-account-data-leakage-in-chatgpt/) · [The Hacker News](https://thehackernews.com/2026/09/chatgpt-flaw-let-planted-prompt-send.html)

**[2] 多智能体六小时窃凭据**
📌 类型：AI赋能安全

Google Threat Intelligence Group 于 9 月 8 日发布 Q3 2026 AI Threat Tracker，基于 Mandiant 应急响应与平台防御观测：攻击方正从基础提示转向多智能体工作流。Q2 一起疑似牟利活动中，入侵者在受害云环境内部署自主多智能体框架，借助编码聊天机器人、提示与代理指令，在不足六小时内完成大规模第三方凭据收割；另发现暴露的 “Recon” C2 曾管理逾 2.38 万枚密钥（含云与 AI 服务 API）。Google 同时注明尚未普遍看到对目标的全自主攻击流水线，但代理化趋势缩短防御响应窗口。

🔗 来源：[Google Cloud / GTIG](https://cloud.google.com/blog/topics/threat-intelligence/from-prompting-to-autonomy-the-evolution-of-adversarial-ai) · [Help Net Security](https://www.helpnetsecurity.com/2026/09/08/ai-agents-cyberattacks-automation-google-research/)

**[3] vLLM跨用户结果串扰**
📌 类型：AI基础设施CVE

GitHub Advisory（2026-09-08）披露 CVE-2026-73558：vLLM 激活核 `act_and_mul_kernel` 中整数溢出，可在同一推理批次内将一名用户的输出片段并入另一用户响应，造成跨用户信息泄露；官方复现配置涉及特定模型维度与批大小。受影响版本为 vLLM < 0.27.0，已在 0.27.0 修复。属中危已确认漏洞，公开信息未显示在野利用。

🔗 来源：[GitHub Advisory GHSA-7m6h-x95x-82q5](https://github.com/advisories/GHSA-7m6h-x95x-82q5)

**[4] vLLM多模态SSRF读文件**
📌 类型：AI基础设施CVE

同日披露 CVE-2026-73560：`MiMoV2OmniMultiModalProcessor` 对用户提供的图像/音频 URL 与本地路径直接拉取，未复用既有 MediaConnector 的 SSRF 与本地媒体路径防护，可导致 SSRF 与任意本地文件读取。该路径被视为此前同类加固的遗漏代码面。受影响版本为 vLLM < 0.26.0，修复版本 0.26.0。多租户或接受不可信多模态输入的推理服务应优先核对是否启用该处理器。

🔗 来源：[GitHub Advisory GHSA-4hhp-h66f-j5j7](https://github.com/advisories/GHSA-4hhp-h66f-j5j7)

**[5] n8n代理工具绕过策略**
📌 类型：AI基础设施CVE

GitHub Advisory（2026-09-08）披露 CVE-2026-86996（中危）：工作流“This workflow can be called by”调用方策略由 Execute Workflow 节点强制执行，但同一工作流作为 Agent 工具挂载时未被校验，具备 Agent 构建权限的用户可调用本应受限的子工作流并回读返回结果。已修复于 n8n 2.37.7 与 2.38.2；临时缓解包括限制实例访问、审计 Agent 工具绑定并移除敏感工作流挂载。

🔗 来源：[GitHub Advisory GHSA-7hgx-277f-7vmg](https://github.com/advisories/GHSA-7hgx-277f-7vmg)

**[6] 供应链瞄准编码助手**
📌 类型：AI赋能安全

同一份 GTIG 报告指出，UNC6780（TeamPCP）等势力持续针对 PyPI/npm/Docker Hub，并通过 DUSTMAKER 等组件污染 AI 编码助手工作区、利用提示注入规避检测，以及伪造可过信任检查的发布证明。攻击面已从“用 AI 写恶意代码”扩展到“把 MCP、助手工作区与 CI 信任链一并武器化”。属威胁情报观察，需结合企业软件供应链遥测验证具体 IOC。

🔗 来源：[Google Cloud / GTIG](https://cloud.google.com/blog/topics/threat-intelligence/from-prompting-to-autonomy-the-evolution-of-adversarial-ai) · [The Hacker News](https://thehackernews.com/2026/09/autonomous-ai-agents-compromise.html)

### 二、深度速览

#### 【AI 赋能防御】

本期公开材料更多落在“对手如何用 AI 加速攻击”而非新的防御产品发布。GTIG 报告建议以平台侧滥用监测、账号与算力劫持遏制、以及将威胁情报反哺模型安全分类器等方式压缩代理化攻击窗口；同时强调企业 AI 资产（模型权重、API 密钥、云配额）已成高价值目标，需纳入与核心业务同等的监测与遏制范围。上述为厂商威胁情报与防御主张，企业应对照自身 SIEM/SOAR 与云审计能力评估可落地的检测点，而非把报告结论直接等同于已部署控制。

🔗 来源：[Google Cloud / GTIG](https://cloud.google.com/blog/topics/threat-intelligence/from-prompting-to-autonomy-the-evolution-of-adversarial-ai)

#### 【AI 系统风险】

Check Point 研究把问题从“模型是否听从恶意指令”推进到“沙箱隔离是否被共享内部服务击穿”：容器对公网与彼此直连的隔离可能完好，但若共享制品仓库允许跨租户可写元数据，就会变成隐蔽信箱。叠加连接应用默认静默读取，隐蔽任务流可在用户无感的情况下调用邮箱等能力。OpenAI 已下线相关 Artifactory 实例；治理上仍应收紧连接应用审批、慎用共享会话与未审计自定义 GPT，并把内部管理面从模型运行时可达范围中剥离。

🔗 来源：[Check Point Research](https://research.checkpoint.com/2026/the-shared-clipboard-inside-the-sandbox-cross-account-data-leakage-in-chatgpt/)

vLLM 同日两条 Advisory 提醒推理服务的两类隔离失败：GPU 核级整数溢出导致批次内跨用户串扰，以及多模态加载路径绕过既有 SSRF/本地路径闸门。对共享集群与对外暴露的多模态入口，补丁版本与输入校验缺一不可。

🔗 来源：[GHSA-7m6h-x95x-82q5](https://github.com/advisories/GHSA-7m6h-x95x-82q5) · [GHSA-4hhp-h66f-j5j7](https://github.com/advisories/GHSA-4hhp-h66f-j5j7)

### 三、今日趋势洞察

代理化能力正同时抬高攻防两侧的“行动速度”：对手用多智能体压缩凭据收割与排错周期，而助手运行时一旦共享内部状态或默认连接应用权限过宽，隐蔽任务即可在用户可见对话之外完成。另一条并行线是推理与编排基础设施的租户隔离——从 vLLM 批次串扰到 n8n Agent 工具绕过调用策略——显示 AI 运行时的权限边界正在成为与模型对齐同等重要的安全面。

### 四、企业行动清单

- 盘点 ChatGPT/同类助手工作区中已连接的邮箱与文件类应用，将默认静默读取改为需确认，并禁用未审计的共享会话与自定义 GPT。
- 对照 GTIG 披露，检查云审计日志中短时大规模外联扫描、异常 IP 轮换与 AI API/云密钥异常调用，并轮换可能暴露的第三方凭据。
- 将生产与多租户 vLLM 升级至包含 0.27.0（跨用户泄露）及 0.26.0（多模态 SSRF）修复的版本线，并限制不可信多模态 URL/本地路径输入。
- 升级 n8n 至 2.37.7/2.38.2 或更高，审计所有挂到 Agent 的子工作流及其“可被谁调用”策略。
- 将 MCP 服务器、AI 编码助手工作区目录与 CI OIDC 发布路径纳入供应链扫描与变更监控，重点关注助手配置目录被植入的持久化钩子。
