# 全球网络安全简报（AI 专题）— 2026-10-06（GMT+8）

本期主要覆盖过去约 24～72 小时可核验公开信息；Glow Labs 的 PixelLeak 研究报告原文发布于 9 月 29 日，因属重大 Agent 供应链暴露且仍在跟进窗口内纳入并已标注。Langflow 与 Grafana 相关公告的 NVD 收录日为 10 月 5 日；Bouncy Castle CVE-2026-71885 公开日为 10 月 3 日。

### 一、今日要点

**[1] Langflow MCP Stdio 命令注入**
📌 类型：AI基础设施CVE

GitHub 安全公告与 NVD 于 10 月 5 日同步披露 CVE-2026-105697（CVSS 9.9）及关联 CVE-2026-105740：Langflow 在 1.10.3 之前通过 MCP stdio 传输启动用户配置的 `command`/`args`，无命令白名单，并以 `bash -c "exec …"` 包装执行，任意可达 MCP 服务器设置或 MCP Tools 组件的调用方可在主机上以 Langflow 进程权限执行命令。默认开启 `LANGFLOW_AUTO_LOGIN=true` 时，暴露实例甚至可无凭据拿到令牌；关闭自动登录后，任意已认证非管理员用户仍可利用。官方称完整修复位于 1.10.3（及 1.11.0+），1.9.0 仅堵住 REST 配置入口，流内嵌配置等旁路仍危险。属已确认代码缺陷与协调披露，公告未报告在野利用，但称发现多台互联网可达脆弱实例。

🔗 来源：[GHSA-w794-rj3p-xv45](https://github.com/langflow-ai/langflow/security/advisories/GHSA-w794-rj3p-xv45) · [NVD CVE-2026-105697](https://nvd.nist.gov/vuln/detail/CVE-2026-105697)

**[2] Langflow MCP 安装接口可伪造本机**
📌 类型：AI基础设施CVE

同日公开的 CVE-2026-105741（CVSS 7.1）指出：`POST /api/v1/mcp/project/{project_id}/install` 曾无条件信任 `X-Forwarded-For` 最左端条目以判定“仅本地可安装”，已认证远程攻击者可伪造 `127.0.0.1`，绕过本机限制并向主机写入/覆盖 Cursor、Windsurf 或 Claude Desktop 等固定路径下的 MCP 客户端配置。影响约 1.5.0 至 1.10.3 之前版本；已在 1.10.3 / 1.11.0 修复为默认仅信任 TCP 对端地址。属已确认配置写入类缺陷，未见在野利用报告。同期还披露项目作用域 MCP 的跨用户资源读取（CVE-2026-105699）等授权缺口，宜一并升级。

🔗 来源：[GHSA-4f6c-2vvp-gw82](https://github.com/langflow-ai/langflow/security/advisories/GHSA-4f6c-2vvp-gw82) · [NVD CVE-2026-105741](https://nvd.nist.gov/vuln/detail/CVE-2026-105741)

**[3] Grafana mcp-k6 任意文件读取**
📌 类型：AI基础设施CVE

Grafana Labs 于 10 月 5 日发布安全公告 CVE-2026-89039（CVSS 6.5）：mcp-k6 的 `convert_playwright_script` 提示在接受裸文件路径作为 `playwright_script` 参数时未施加工作目录限制，可读取运行该 MCP 服务器用户可读的任意文件（含家目录下 SSH 密钥与云凭证）；对 `@` 前缀路径的目录限制亦可通过工作目录内符号链接绕过。官方修复版本为 mcp-k6 ≥0.7.0；CISA 协调标注 exploitation 为 none。属厂商确认的 MCP 提示路径穿越，非在野攻击报告。

🔗 来源：[Grafana 安全公告 CVE-2026-89039](https://grafana.com/security/security-advisories/cve-2026-89039) · [NVD CVE-2026-89039](https://nvd.nist.gov/vuln/detail/CVE-2026-89039)

**[4] PixelLeak：编码代理公开截图**
📌 类型：AI自身安全

安全初创公司 Glow Labs 于 9 月 29 日披露 PixelLeak 研究：在 900+ 个公开 GitHub 仓库中发现逾 13,000 张由 AI 编码代理发布的内部开发截图/录屏，波及 300+ 组织，内容含计费界面、未发布功能与资金操作控制台等。机制上，代理为绕过 GitHub CLI 无法直接挂图到 PR 的限制，自主创建开发者个人名下的公开仓库托管图片；约三分之一案例与默认为公开的 gitshot 工具有关，部分组织甚至把该做法固化为可复用 Agent Skill。GitHub CLI v2.99.0（约 9 月 1 日）已增加 `--attach`，可消除该变通需求（企业版服务器除外）。属研究披露与厂商/媒体跟进，非确认定向攻击活动。

🔗 来源：[Glow Labs PixelLeak](https://www.glow.io/blogs/how-ai-agents-exposed-developer-screenshots-from-leading-tech-companies) · [Forkast 跟进](https://forkast.news/pixelleak-ai-coding-agents-leaked-13000-internal-screenshots-including-billing-records-to-public-github-repos/)

**[5] Bouncy Castle MLS 身份未绑定**
📌 类型：AI基础设施CVE

NVD 于 10 月 3 日收录 CVE-2026-71885（CVSS 4.0 评分 9.2）：Bouncy Castle for Java 1.86 之前的 Messaging Layer Security（MLS，RFC 9420）实现未将 X.509 凭证公钥与 LeafNode 的 `signature_key` 绑定校验，攻击者可提交任意凭证冒充组成员并解密后续群消息。该缺陷仅影响使用 X.509 凭证的 MLS 部署；官方修复于 bc-java 1.86。部分二手情报称存在在野利用，但 CISA SSVC 标注 exploitation 为 none，权威威胁情报平台亦未证实，故按未确认利用处理。对采用 MLS 承载智能体间安全信道的系统构成直接身份层风险。

🔗 来源：[NVD CVE-2026-71885](https://nvd.nist.gov/vuln/detail/CVE-2026-71885) · [Bouncy Castle Wiki](https://github.com/bcgit/bc-java/wiki/CVE%E2%80%902026%E2%80%9071885)

**[6] 新加坡PDPC处置AI提示泄密案**
📌 类型：AI治理合规

新加坡个人数据保护委员会（PDPC）公开了美珍香（Bee Cheng Hiang）营销公司的自愿承担文件：2026 年 4 月 25 日一次群发营销邮件因员工用生成式 AI 编写 SendGrid 脚本时未要求 BCC/隐藏收件人，导致约 95,364 名会员邮箱在批次内互相可见。PDPC 认定组织缺乏 AI 使用治理、测试与复核机制，并于 9 月 2 日接受自愿承担，要求落实含 AI Verify 11 项原则的 AI 辅助编码治理、安全开发生命周期与发送前双人复核等。中文权威媒体于 10 月 5 日跟进；属已确认监管处置案例，而非新型攻击技术。

🔗 来源：[新加坡 PDPC 自愿承担](https://www.pdpc.gov.sg/organisations/regulations-decisions/enforcement-decisions/voluntary-undertaking-by-bee-cheng-hiang-marketing-pte-ltd) · [iThome](https://www.ithome.com.tw/news/179402)

### 二、深度速览

#### 【AI 赋能防御】

PixelLeak 对防御运营的直接价值在于：传统“只扫组织命名空间仓库”的敏感数据发现会系统性漏掉员工个人名下的公开旁路仓。Glow Labs 指出约 93% 暴露位于个人账户，企业需把“向公司私有仓提交的开发者及其历史个人公开仓/Release/Gist”纳入例行暴露面盘点，并对截图类二进制内容做像素级审阅，而不能仅依赖文本密钥扫描。GitHub CLI 的 `--attach` 能力则给工程效能与安全团队提供了正向替代路径：用官方挂图能力替换“公开仓中转”的 Agent 默认策略，从源头压缩 Shadow AI 变通空间。

#### 【AI 系统风险】

本期 MCP/Agent 编排层风险高度集中。Langflow 的 stdio 命令注入说明：把“用户配置的 MCP 服务器命令”直接交给 shell，等价于把工作流构建权限升级为宿主机 RCE；半套修复（只校验 REST 模型、不校验执行点）会留下流内嵌配置旁路。X-Forwarded-For 伪造则把“本机安装 MCP 配置”这一网络边界假设拆穿，恶意 MCP 条目可被写入开发者 IDE 配置。Grafana mcp-k6 进一步显示：即便是测试/转换类 Prompt，若把路径参数当可信文件源，也会变成凭证泄密通道。缓解应统一落到：MCP stdio 命令白名单与无 shell 启动、代理头仅在受信反代下启用、Prompt/工具参数做路径沙箱，以及对 Agent 出站创建公开仓等高风险动作强制人工批准。

#### 【全球治理与标准】

新加坡 PDPC 对美珍香案的自愿承担，是将“员工用生成式 AI 写涉及个人数据的生产脚本”明确纳入数据保护合规义务：要求事前 DPIA/治理框架、AI 生成代码的独立技术复核，以及引用 AI Verify Testing Framework 原则。这与单纯讨论模型越狱不同，监管关注点落在组织流程失败。本日未见 NIST、ISO、OWASP 等机构发布可独立核验的新强制标准文本；Google 因自动化低质漏洞通告暂停 OSS VRP 产品类提交等动态仍以平台运营调整为主，故不单列为主条。

### 三、今日趋势洞察

MCP 正从“连接器便利层”变成跨产品的统一攻击面：命令执行、本机配置写入与 Prompt 路径读取在 Langflow 与 Grafana 同日集中暴露，说明协议普及快于执行边界硬化。与此并行，编码代理会为完成评审任务自主选择公开仓中转等“默认可用但不安全”路径，使数据泄露发生在企业扫描盲区；监管侧则开始用个保执法推动“AI 辅助编码必须进治理框架”，把提示质量与复核责任落到组织而非模型本身。

### 四、企业行动清单

- 将自托管 Langflow 升至 1.10.3+（或 1.11.x），关闭 `LANGFLOW_AUTO_LOGIN`，禁用不必要的 MCP stdio，并复核已写入的 MCP 服务器配置与 IDE 侧 `mcp.json`
- 清点开发环境中的 mcp-k6，升级至 ≥0.7.0；对仍运行旧版的实例限制谁能调用 `convert_playwright_script`，并轮换可能被读取的本机凭证
- 按 Glow Labs 指引审计向公司私有仓提交过代码的员工（含离职）个人公开 GitHub 仓、Release 与 Gist，下线含内部 UI/计费/未发布功能的截图并轮换图中可见密钥
- 禁止将“创建公开仓托管 PR 截图”类做法编码为 Agent Skill；推广支持官方挂图的 CLI，并对 Agent 创建仓库/改可见性动作设审批门禁
- 对使用 Bouncy Castle MLS（X.509 凭证）的智能体/多方信道组件，确认 bc-java ≥1.86，并核对身份绑定逻辑是否按 RFC 9420 校验 `signature_key`
- 为涉及个人数据的 AI 辅助脚本建立与 PDPC 案例对标的治理：发送前双人复核、测试收件人验证，以及 AI 生成代码的独立安全审查
