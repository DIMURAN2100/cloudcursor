# 全球网络安全简报（AI 专题）— 2026-10-19（GMT+8）

本期主要覆盖东八区过去约 24～72 小时（约 10 月 16 日—18 日）可核验的公开披露；其中 OneUptime Kubernetes AI 动作越权于 10 月 18 日发布修复，其余 MCP / 编码智能体相关 CVE 与美国能源部 Agent Skills 资源发布集中在 10 月 16—17 日，因直接影响 AI 运维与开发供应链，放宽至约 72 小时一并纳入。时效均已对照 NVD、GitHub Advisory / 发布说明、Wordfence、DOE 官网与研究者披露核对；不重复前几日已写且无新补丁进展的商务部第 48 号、ZCode、Claude Code 插件哈希钉扎、Tandoor、WSP、Nezha、LMCache、LangChat、NullHub、Portkey、Roo Code、EN 18286 等条目。Archon 控制面缺认证（CVE-2026-111322）虽已有 v0.12.x 发布，但官方说明未宣告该 CVE 关闭，本期仅收录其独立的 `.env` 泄露回归修复。

### 一、今日要点

**[1] OneUptime集群AI动作越权**
📌 类型：AI自身安全

NVD 于 10 月 18 日收录 CVE-2026-112047（CVSS 3.1 约 5.4 / CVSS 4.0 约 5.3 Medium）：OneUptime 14.0.2 至 14.0.68，Kubernetes「AI 连通性测试」「重置 AI Agent」与批准含 kubectl 的 AI 计划等接口，仅按项目级权限判断，未对目标集群的标签、属主与阻止规则做细粒度校验；事件/告警侧 AI 对话还可对调用方不可见的关联集群发起只读 kubectl/基础设施命令，从而泄露 Agent/Runner 的 RBAC 能力、断开 Agent 或批准越权变更。官方已在 14.0.69 修复，改为按目标集群/资源的编辑或查看权限判定。属已确认授权缺陷，未见在野利用通报。

🔗 来源：[GitHub Advisory GHSA-8fph-9j9f-xxgc](https://github.com/OneUptime/oneuptime/security/advisories/GHSA-8fph-9j9f-xxgc) · [14.0.69 发布说明](https://github.com/OneUptime/oneuptime/releases/tag/14.0.69) · [NVD CVE-2026-112047](https://nvd.nist.gov/vuln/detail/CVE-2026-112047)

**[2] DeepSeek Harness压缩可持久注入**
📌 类型：AI自身安全

NVD 于 10 月 16 日收录 CVE-2026-95183：DeepSeek Harness（dsh）在已验证的 master 提交 c291e796 上，上下文压缩组件 `@deepseek-ai/dsh-compaction-basic` 会把对话历史替换为模型生成的 `<compacted-summary>`，且指令要求 verbatim 复述“主请求/意图”与“待办”。外部内容中的间接提示注入因缺少信任标记，可被原样写入摘要并在恢复会话后作为既定任务继承；研究者验证注入的 shell 心跳指令可稳定出现在摘要多处，模型层偶发拒绝执行但载荷本身确定落盘。属研究演示路径，公开材料未见正式补丁版本与在野利用通报。

🔗 来源：[NVD CVE-2026-95183](https://nvd.nist.gov/vuln/detail/CVE-2026-95183) · [研究者披露 gist](https://gist.github.com/lkloliver/c54c0cc91e1ec4f16b538e0d8a1411b6)

**[3] 编码Agent防护钩可被超时绕过**
📌 类型：AI赋能安全

GitHub Advisory / NVD 于 10 月 16 日披露 CVE-2026-77474（CVSS 约 7.1 High）：`destructive_command_guard`（dcg）在 0.6.6 之前作为 PreToolUse 钩拦截破坏性 shell 命令；嵌套或未闭合的 `$(` / `$((` 会使命令替换预处理进入指数级耗时，钩超时后多数编码 Agent 会失败开放并继续执行原命令，从而绕过防护。约 30 个嵌套 `$(` 即可使评估挂起。官方 v0.6.6 将扫描改为线性并保持对破坏性命令的拦截。属已确认防护旁路，触发依赖攻击者能影响待评估命令内容（含注入指令）；未见在野利用通报。

🔗 来源：[GitHub Advisory GHSA-4cfr-w3v5-w5j5](https://github.com/Dicklesworthstone/destructive_command_guard/security/advisories/GHSA-4cfr-w3v5-w5j5) · [NVD CVE-2026-77474](https://nvd.nist.gov/vuln/detail/CVE-2026-77474) · [v0.6.6 发布](https://github.com/Dicklesworthstone/destructive_command_guard/releases/tag/v0.6.6)

**[4] Wheels CLI经MCP可注入Shell**
📌 类型：AI基础设施CVE

GitHub Advisory / NVD 于 10 月 16 日披露 CVE-2026-111451（CVSS 约 7.8 High）：Wheels CLI 4.0.0—4.1.1 对部署版本、包名与生成器名称等调用方输入校验不足；`wheels deploy` 可将形如 `feat$(cmd)` 的值插进远程 shell，在部署主机与 CI runner 上执行命令。相关包删除、解包与代码生成路径还存在路径穿越与 CFML 注入，且多条命令以 MCP 工具暴露给 Agent。官方修复版本为 4.1.2。属已确认 CLI/MCP 供应链缺陷，利用需 Agent 或 CI 传入不可信输入；未见在野利用通报。

🔗 来源：[GitHub Advisory GHSA-cghp-86c6-6fjc](https://github.com/wheels-dev/wheels/security/advisories/GHSA-cghp-86c6-6fjc) · [NVD CVE-2026-111451](https://nvd.nist.gov/vuln/detail/CVE-2026-111451)

**[5] Archon发布版误加载仓库密钥**
📌 类型：AI自身安全

Archon 于 10 月 17 日发布 v0.12.1 安全说明：v0.12.0 的发行版二进制在目标仓库启动 Claude / Codex / Pi 等 provider 插件时，会重新加载工作目录中的 `.env` / `bunfig.toml`，抵消原先剥离，导致仓库内 `ANTHROPIC_API_KEY` 等可到达模型侧并覆盖订阅凭据；源码安装不受影响。修复要求升级至 0.12.1 并重新执行 `archon provider add`。此为发行通道回归，独立于此前控制面缺认证 CVE-2026-111322（该条目仍无明确关闭声明）。属厂商确认的密钥边界缺陷。

🔗 来源：[Archon v0.12.1 发布说明](https://github.com/coleam00/Archon/releases/tag/v0.12.1)

**[6] WordPress MCP插件可上传任意文件**
📌 类型：AI基础设施CVE

Wordfence / NVD 于 10 月 15—16 日披露 CVE-2026-111311（CVSS 8.8 High）：带 MCP 能力的 WordPress 插件 DoubleScale（至 1.5.1）在 Helpdesk 模块启用时，`store_upload` 对未识别扩展名 fail-open，且仅做 magic-byte MIME 检测、缺少超越登录态的能力校验，订阅者及以上即可上传可执行文件，形成远程代码执行面。官方已修复至 1.6.0。属已确认上传校验失败，未见在野利用通报。

🔗 来源：[Wordfence 漏洞情报](https://www.wordfence.com/threat-intel/vulnerabilities/id/0feed03e-fedf-4443-94e0-fbb2c8baba71?source=cve) · [NVD CVE-2026-111311](https://nvd.nist.gov/vuln/detail/CVE-2026-111311)

**[7] 美国能源部发布Genesis Agent Skills**

美国能源部（DOE）于约 10 月 16 日宣布发布 “Genesis Agent Skills”，作为 Genesis Mission 下 ModCon / 美国科学云的首批公开技术资源，经 GitLab 免费提供。内容覆盖超级智能（SI）安全、智能体评测与监测、数据治理、科学工作流与多智能体系统等可复用指引与工作流，支持研究者用自然语言触发代码库安全评估等技能。属政府来源的治理与安全能力交付，非强制法规；可作科研与工程侧 Agent 安全基线素材。

### 二、深度速览

#### 【AI 赋能防御】

`destructive_command_guard` 本意是在编码 Agent 执行破坏性 shell 前做 PreToolUse 拦截，但 0.6.6 之前的指数级预处理与 Agent 钩超时失败开放叠加，使防护在对抗输入下失效。对依赖钩/策略引擎兜底的团队，本期可落地的是：为安全钩设定明确超时与失败关闭策略，并对钩自身做最坏情况复杂度测试，避免“挂起即放行”。

🔗 来源：[GHSA-4cfr-w3v5-w5j5](https://github.com/Dicklesworthstone/destructive_command_guard/security/advisories/GHSA-4cfr-w3v5-w5j5)

DOE Genesis Agent Skills 将实验室侧的 SI 安全、评测监测与数据治理沉淀为可被编码助手按自然语言触发的技能包，属于“把安全与治理写成可调用能力”的防御向交付，而非单一漏洞补丁。适合作为内部 Agent Skill 目录建设的参考形态，但仍需按组织策略审阅后再引入。

🔗 来源：[DOE 官网公告](https://www.energy.gov/science/articles/genesis-agent-skills-release-support-innovation-across-genesis-mission)

#### 【AI 系统风险】

本期风险主轴是“AI 运维动作的授权粒度”与“Agent 工具链对不可信输入/上下文的信任”。OneUptime 用项目级权限放行集群 AI 测试、重置与 kubectl 计划批准；DeepSeek Harness 压缩摘要把外部注入写进持久上下文；Wheels 把未转义的部署参数与包操作暴露为 MCP 工具；Archon 发行版把仓库 `.env` 交回 provider；DoubleScale 则在 MCP 相关 WordPress 插件上留下可执行上传面。共性缓解是：AI 运维动作按目标资源做细粒度授权与审计、压缩/记忆层区分用户意图与工具输出并拒绝 verbatim 继承外部指令、MCP 工具对 shell/路径参数做严格校验与确认、发行通道禁止从工作区隐式加载密钥、插件上传路径默认拒绝未知扩展名。

🔗 来源：[OneUptime GHSA-8fph-9j9f-xxgc](https://github.com/OneUptime/oneuptime/security/advisories/GHSA-8fph-9j9f-xxgc) · [DeepSeek Harness 披露](https://gist.github.com/lkloliver/c54c0cc91e1ec4f16b538e0d8a1411b6) · [Wheels GHSA-cghp-86c6-6fjc](https://github.com/wheels-dev/wheels/security/advisories/GHSA-cghp-86c6-6fjc)

#### 【全球治理与标准】

美国能源部发布 Genesis Agent Skills，将 SI 安全、智能体评测监测与数据治理纳入 Genesis Mission 的公开共享研究基础设施，属政府实验室体系的治理能力输出，不构成新的强制法规或认证义务。其余 NIST / ISO / OWASP 本日无单独强制更新需单列。

🔗 来源：[DOE 官网公告](https://www.energy.gov/science/articles/genesis-agent-skills-release-support-innovation-across-genesis-mission)

### 三、今日趋势洞察

编码与运维侧 Agent 的失败模式正在从“模型说错话”转向“钩超时放行、项目级权限放行、压缩摘要放行”等控制系统静默失败；同时 MCP/CLI 工具把部署、包管理与集群变更直接暴露给不可信输入，使提示注入与传统命令/路径注入在同一调用链上汇合。

### 四、企业行动清单

- 将 OneUptime 升至 14.0.69+，并复核项目成员对 Kubernetes 集群 AI 测试、Agent 重置与 kubectl 计划批准的标签/属主权限。
- 盘点编码 Agent 的 PreToolUse / 命令防护钩版本，确认超时策略为失败关闭，并升级 `destructive_command_guard` 至 0.6.6+（若在使用）。
- 审计暴露给 Agent 的 CLI/MCP 工具（含部署、包删除、代码生成），禁止将分支名等不可信字符串直接拼进 shell，Wheels 用户升至 4.1.2+。
- 若使用 Archon 发行版二进制且曾运行 v0.12.0，立即升至 0.12.1 并重新配置 provider，排查工作区 `.env` 是否曾被加载。
- 清点 WordPress 站点上声明 MCP 能力的插件，DoubleScale 升至 1.6.0+ 或禁用 Helpdesk 上传端点，并对订阅者上传做能力与扩展名双校验。
