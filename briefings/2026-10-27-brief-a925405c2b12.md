### 一、今日要点

**[1] 编码代理 Downloads 指令投毒**
📌 类型：AI自身安全

Forever Security 披露并经 Aviatrix 于 10 月 25–26 日公开复盘：攻击者可利用浏览器静默将恶意 `AGENTS.md`（及同类指令文件）写入开发者 `~/Downloads`，当 Codex、Claude Code 等编码代理从该目录启动时会自动吞并指令。已观察到投毒链路引导安装 MALFEX 相关恶意 npm 包（如 `function-color`），并可链式下载 Windows 载荷或改写 API 基址以窃取 OAuth/会话令牌。该路径依赖代理“信任工作区指令文件”的设计行为，厂商侧暂无通用补丁；企业需从工作目录白名单、包安装审批与出站 API 允许列表等控制面缓解。此为已确认的研究披露与活动复盘，不宜直接等同大规模在野打穿统计。

🔗 来源：[Aviatrix（MALFEX/AGENTS.md，10/26）](https://aviatrix.ai/threat-research-center/malicious-agentsmd-downloads-folder-ai-coding-agent-malfex-npm-2026) · [Aviatrix（AGENTS.md 劫持机制，10/25）](https://aviatrix.ai/threat-research-center/ai-coding-agents-hijacked-agentsmd-downloads-folder-2026)

**[2] OpenHands 沙箱默认未认证 RCE**
📌 类型：AI基础设施CVE

GitHub Advisory Database 与 NVD 于 10 月 26 日公开 CVE-2026-112346（CVSS 3.1 达 9.8）：OpenHands Software Agent SDK 在 1.52.0 之前，`DockerWorkspace`/`Apptainer` 启动器将沙箱 agent 服务绑定到 `0.0.0.0`，且默认空 `session_api_keys` 关闭认证。攻击者只要能访问已发布容器端口，即可通过未认证 HTTP/WebSocket 以沙箱 root 执行任意命令、读写挂载工作区并读取明文密钥。修复已合入并将端口发布收敛到回环等更安全默认；使用方应升级至 v1.52.0 及以上，并核查历史工作区端口是否仍对非本机网段暴露。补丁合入早于本日 CVE 公告，但公开漏洞编号与咨询于本日窗口落地。

🔗 来源：[NVD CVE-2026-112346](https://nvd.nist.gov/vuln/detail/CVE-2026-112346) · [GitHub Advisory GHSA-rp7h-crm7-h5qj](https://github.com/advisories/GHSA-rp7h-crm7-h5qj) · [VulnCheck 公告](https://www.vulncheck.com/advisories/openhands-software-agent-sdk-unauthenticated-sandbox-agent-server-rce)

**[3] Frappe Builder 越权刷 LLM 额度**
📌 类型：AI基础设施CVE

Frappe Builder 于 10 月 26 日公开 GHSA-58mj-c563-p78w / CVE-2026-115718：`improve_prompt` 接口缺少权限校验，任意已登录非 Guest 用户（含无 Builder 权限的 Website User）可调用该接口，借助站点配置的 AI 提供商密钥（经 `resolve_api_key`，常见为 OpenRouter）发起补全，消耗站点所有者付费额度并把结果返回给调用方，实质把站点变成“免费 LLM 代理”。官方在 1.36.0 删除该端点（该线要求 Frappe ≥ v16.36.1）；无法立即升级时可先移除 Builder AI 设置中的提供商密钥。同日还披露 convert_to_webp 写文件/内网请求（CVE-2026-115717）与远程资源 SSRF 绕过（CVE-2026-115720），低代码 AI 构建面应一并盘点。

🔗 来源：[GitHub Advisory（improve_prompt）](https://github.com/frappe/builder/security/advisories/GHSA-58mj-c563-p78w) · [NVD CVE-2026-115718](https://nvd.nist.gov/vuln/detail/CVE-2026-115718) · [VulnCheck 公告](https://www.vulncheck.com/advisories/frappe-builder-before-missing-authorization-via-improve-prompt)

**[4] Builder 同日 SSRF 与写文件簇**
📌 类型：AI基础设施CVE

与 LLM 额度问题同日公开的 GHSA-5qcg-q3jf-fjcg（CVE-2026-115717）允许已认证用户经 `convert_to_webp` 诱使服务器拉取内网 URL 并写文件；GHSA-hvrf-fhv3-3v7p（CVE-2026-115720）显示远程资源获取的 SSRF 防护可被重定向与 DNS rebinding 绕过。二者并非模型权重漏洞，但发生在集成 AI 能力的低代码构建器攻击面上，可与提示改进接口越权形成组合利用链。修复版本同为升级至 Builder 1.36.0 所在安全波次；对外暴露的 Builder 实例应优先验证认证边界与出站 URL 策略。

🔗 来源：[GitHub Advisory CVE-2026-115717](https://github.com/frappe/builder/security/advisories/GHSA-5qcg-q3jf-fjcg) · [GitHub Advisory CVE-2026-115720](https://github.com/frappe/builder/security/advisories/GHSA-hvrf-fhv3-3v7p)

### 二、深度速览

#### 【AI 赋能防御】

本日窗口内缺少独立、可核验的 SOC 产品效果数据稿；与本期直接相关的防御线索来自对编码代理指令投毒的响应建议。Aviatrix 复盘（厂商来源）强调：将代理可读取的指令源限制在受信项目目录之外（例如阻止从 `Downloads` 等浏览器落盘目录自动加载）、对 npm/包安装实施加密完整性或允许列表，以及对模型 API 出站做 FQDN 允许列表，以切断 `ANTHROPIC_BASE_URL` 一类重定向盗令牌路径。Forever Security 侧还给出受控测试中的高成功率观察（研究演示数据），说明“代理按设计服从本地 markdown 指令”本身即可被武器化，检测应转向异常工作目录启动、异常包注册表与异常 API 基址变更，而不是等待 CVE 编号。

🔗 来源：[Aviatrix MALFEX 分析](https://aviatrix.ai/threat-research-center/malicious-agentsmd-downloads-folder-ai-coding-agent-malfex-npm-2026)

OpenHands 一类本地/沙箱 agent 服务的暴露面治理同样属于运营动作：默认绑定全网卡且空鉴权，会使“开发者本机实验端口”迅速变成可远程打的执行面。补丁将发布地址与客户端地址对齐到本机回环，并传播会话 API 密钥，是把 agent 运行时重新纳入传统网络隔离与身份校验的范例；资产盘点应覆盖 Docker 发布端口与空 `session_api_keys` 配置残留。

🔗 来源：[OpenHands PR #5209](https://github.com/OpenHands/software-agent-sdk/pull/5209) · [NVD CVE-2026-112346](https://nvd.nist.gov/vuln/detail/CVE-2026-112346)

#### 【AI 系统风险】

AGENTS.md/CLAUDE.md 投毒的核心机制是：浏览器可无交互落盘 + 编码代理自动信任工作区指令文件 + 代理具备包安装与网络工具权限。恶意指令可安装供应链包、改写提供商基址或诱导外泄环境变量；在企业环境中，若代理还挂载 CI 凭据或内部源码，影响会超出单台开发机。缓解不能依赖“模型更安全”，而要切断不可信目录指令源、限制工具写权限与高危出站。

🔗 来源：[Aviatrix AGENTS.md 劫持](https://aviatrix.ai/threat-research-center/ai-coding-agents-hijacked-agentsmd-downloads-folder-2026)

低代码/构建器把站点级 LLM 密钥放在服务端供“提示改进”等功能复用时，缺失对象级鉴权会直接变成额度盗用与内容代理。Frappe 案例说明：AI 功能接口必须按 Builder 权限而非“任意登录会话”授权，密钥轮换与额度异常监测应进入日常运营。同日 SSRF/写文件问题提醒：AI 功能所在应用的传统 Web 漏洞仍可放大智能体与密钥的暴露半径。

🔗 来源：[Frappe GHSA-58mj-c563-p78w](https://github.com/frappe/builder/security/advisories/GHSA-58mj-c563-p78w)

### 三、今日趋势洞察

编码代理与低代码 AI 构建器正把“默认可信的本地文件/已登录会话”变成新的权限边界：指令文件与改进提示接口一旦缺乏来源与对象鉴权，即可在无模型漏洞编号的情况下完成供应链投毒或密钥额度盗用。与此同时，agent 沙箱若默认监听全网卡且空鉴权，会把本应本机调试的执行面暴露给网络攻击者——运行时网络绑定与会话密钥正在成为与提示注入同等优先的基线控制。

### 四、企业行动清单

- 盘点开发机与 CI 中 Codex/Claude Code/同类代理的启动目录，禁止从 `Downloads` 等浏览器落盘路径自动加载 `AGENTS.md`/`CLAUDE.md` 等指令文件。
- 对编码代理的包安装与模型 API 出站实施允许列表，告警异常 npm 注册表与提供商基址重定向。
- 将 OpenHands Software Agent SDK 升级至 1.52.0+，并扫描历史容器是否仍把 agent 端口发布到非回环地址或空 `session_api_keys`。
- 将 Frappe Builder 升级至 1.36.0（并满足对应 Frappe 版本要求），或临时移除 Builder AI 提供商密钥；核查 LLM 额度异常消耗。
- 复查集成 AI 能力的低代码/构建器应用中“已登录即可调用”的提示、转换与远程拉取接口，补齐对象级授权与 SSRF 出站策略。
