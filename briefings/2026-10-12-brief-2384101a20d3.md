# 全球网络安全简报（AI 专题）— 2026-10-12（GMT+8）

本期主要覆盖东八区过去约 24～72 小时内可核验的公开披露；其中 Microsoft Azure SRE Agent 相关 CVE 于 10 月 8 日发布、OWASP GenAI 季度利用综述于同日发布，因影响面与治理参考价值纳入本期。10 月 11 日入库的一批 AI 网关与 MCP 组件缺陷以 NVD / VulnCheck 公告为准，时效均已对照原始发布时间核对。

---

### 一、今日要点

**[1] Azure SRE智能体权限提升**
📌 类型：AI自身安全

Microsoft 于 10 月 8 日公开 CVE-2026-69435（CVSS 9.6，Critical）：Azure SRE Agent 存在缺失授权（CWE-918 SSRF 相关描述），已认证低权限攻击者可经网络提升权限，影响范围可超出该组件自身安全边界。MSRC 标明此为托管云服务漏洞、公开披露与在野利用均为“否”，并说明客户无需操作即可修复——漏洞已由微软在服务侧完全缓解，本 CVE 主要用于透明度披露。致谢方为 XBREACH.AI 的 Asaf Cohen。

🔗 来源：[MSRC CVE-2026-69435](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-69435) · [NVD CVE-2026-69435](https://nvd.nist.gov/vuln/detail/CVE-2026-69435)

**[2] Plano管理口泄露模型密钥**
📌 类型：AI基础设施CVE

NVD / VulnCheck 于 10 月 11 日收录 CVE-2026-108863（CVSS 4.0 为 8.7 High，3.1 为 7.5）：Katanemo Plano 至 0.4.37 将 Envoy 管理接口绑定全部主机网卡的 9901 端口且缺少认证。未认证网络攻击者可请求 `/config_dump`，从 WASM 过滤器配置中以明文读出已配置的大模型供应商 API 密钥。项目最新标签仍为 0.4.37，公开公告未给出修复版本。属已确认配置暴露缺陷，未见在野利用通报。

🔗 来源：[VulnCheck Advisory](https://www.vulncheck.com/advisories/katanemo-plano-through-0.4.37-missing-authentication-on-envoy-admin-interface) · [NVD CVE-2026-108863](https://nvd.nist.gov/vuln/detail/CVE-2026-108863)

**[3] MCP Kotlin SDK可被内存耗尽**
📌 类型：AI基础设施CVE

NVD / VulnCheck 于 10 月 11 日收录 CVE-2026-108714（CVSS 4.0 为 8.7 High，3.1 为 7.5）：官方 MCP Kotlin SDK 至 0.15.0 在 `Application.mcpWebSocket` 安装 Ktor WebSocket 时未设置 `maxFrameSize`。远程客户端可用声明接近 2 GiB 载荷的小帧头触发巨大堆分配，一至数条连接即可造成拒绝服务。仓库公开标签最高仍为 0.15.0（另有较早的 v0.7.0），公告未给出已修复版本。属已确认资源分配限制缺失，非声称在野攻击。

🔗 来源：[VulnCheck Advisory](https://www.vulncheck.com/advisories/mcp-kotlin-sdk-through-0.15.0-memory-exhaustion-via-application-mcpwebsocket) · [NVD CVE-2026-108714](https://nvd.nist.gov/vuln/detail/CVE-2026-108714)

**[4] 智能体密钥可劫持Telegram绑定**
📌 类型：AI自身安全

NVD / VulnCheck 于 10 月 11 日收录 CVE-2026-108756（CVSS 约 5.3～5.4）：Abilityai Trinity 至 0.9.5 的 Telegram 路由缺少授权区分，本应仅限人类所有者的绑定增删改操作可被智能体作用域的 MCP API 密钥调用。公告写明典型利用路径是提示注入控制代理后，借所有者 bot token 发信、替换为自己的绑定或删除绑定。仓库另有 v1.0.0-rc 预发布标签，但公开 advisory 仍将受影响范围记为 ≤0.9.5 且未声明正式修复版本。此为已确认授权缺陷与研究路径描述。

🔗 来源：[VulnCheck Advisory](https://www.vulncheck.com/advisories/abilityai-trinity-through-0.9.5-missing-authorization-in-telegram-binding-routes) · [NVD CVE-2026-108756](https://nvd.nist.gov/vuln/detail/CVE-2026-108756)

**[5] LLM网关视频回调可打内网**
📌 类型：AI基础设施CVE

NVD / VulnCheck 于 10 月 11 日收录 CVE-2026-108719（CVSS 约 5.0～5.3）：开源 LLMGateway 至 1.20.0 在视频生成扩展的 `callback_url` 路径上未走 `assertSafeWebhookTarget` 校验。持有 API 密钥的调用方可提交回环、私网或云元数据地址，使 worker 向内网目标投递 webhook POST，形成盲 SSRF。最新正式标签仍为 v1.20.0，公开记录未给出补丁版本。属已确认缺陷，未见在野利用确认。

🔗 来源：[VulnCheck Advisory](https://www.vulncheck.com/advisories/llmgateway-through-1.20.0-blind-ssrf-via-video-generation-callback-url) · [NVD CVE-2026-108719](https://nvd.nist.gov/vuln/detail/CVE-2026-108719)

**[6] mcp-remote设备码明文传凭据**
📌 类型：AI基础设施CVE

NVD / VulnCheck 于 10 月 11 日收录 CVE-2026-108716（CVSS 4.0 为 6.0，3.1 为 5.3）：`mcp-remote` 0.8.0 至 0.14.3 在 `--device-code` OAuth 流程中，`authorizeWithDeviceCode` 不强制 HTTPS。当发现的设备授权与令牌端点为非回环的 `http` URL 时，路径上的中间人可截获 client secret 以及下发的访问/刷新令牌。最新标签仍为 v0.14.3，公告未给出修复版本。属已确认传输层缺陷，利用前提是端点可被解析为明文 HTTP。

🔗 来源：[VulnCheck Advisory](https://www.vulncheck.com/advisories/mcp-remote-0.8.0-through-0.14.3-cleartext-credential-transmission-via-device-code-oauth-grant) · [NVD CVE-2026-108716](https://nvd.nist.gov/vuln/detail/CVE-2026-108716)

### 二、深度速览

#### 【AI 赋能防御】

Microsoft 将 Azure SRE Agent 的缺失授权以 Critical 级别 CVE 对外披露，并明确“服务侧已缓解、客户无操作”，把云上运维智能体的授权边界问题纳入与传统云 CVE 同等的透明度轨道。对依赖 Azure 运维智能体的团队，价值在于用官方时间线核对租户内相关角色变更与异常 API，而不是等待本地补丁包。致谢名单显示该问题经外部研究协调披露进入 MSRC 流程。

🔗 来源：[MSRC CVE-2026-69435](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-69435)

OWASP GenAI Security Project 于 10 月 8 日发布的 Q3 2026 利用综述，把评测沙箱逃逸、供应链蠕虫、恶意 MCP 分发与 Copilot 记忆投毒等案例映射到 LLM03 Excessive Agency、ASI02/ASI03/ASI10 等分类，并强调“提示层指令不足以构成安全边界”。对防御工程而言，可把其中的“按 run 发放凭据、独立网络出口控制、按 run ID 关联工具与网络日志”当作评测与生产智能体共用的检测设计输入，而非厂商营销清单。

🔗 来源：[OWASP GenAI Q3 2026 Exploit Roundup](https://genai.owasp.org/2026/10/08/genai-and-agentic-ai-exploit-roundup-q3-2026)

#### 【AI 系统风险】

本期开源侧风险集中在“管理面默认可达”和“智能体身份越权”。Plano 把 Envoy admin 绑到全接口且无认证，使 `/config_dump` 直接成为模型密钥读取面；LLMGateway 则在视频回调 URL 上绕过既有安全检查，把 worker 网络位置变成盲 SSRF 跳板。MCP Kotlin SDK 缺少帧大小上限，说明协议实现层的可用性攻击已可单独成 CVE。Trinity 与 mcp-remote 分别展示：智能体作用域密钥若能调用人类专属绑定接口，提示注入即可劫持消息通道；设备码 OAuth 若不强制 HTTPS，MCP 远程连接会在发现阶段交出密钥。缓解共性是：管理口本机绑定并鉴权、回调与 webhook 统一出站策略、WebSocket/传输层设硬限额，以及把人类授权操作与 agent 令牌彻底分轨。

🔗 来源：[NVD CVE-2026-108863](https://nvd.nist.gov/vuln/detail/CVE-2026-108863) · [NVD CVE-2026-108714](https://nvd.nist.gov/vuln/detail/CVE-2026-108714) · [NVD CVE-2026-108756](https://nvd.nist.gov/vuln/detail/CVE-2026-108756)

#### 【全球治理与标准】

OWASP GenAI Security Project 于 10 月 8 日发布《GenAI and Agentic AI Exploit Roundup Q3 2026》，覆盖 2026 年 7 月 1 日至 9 月 30 日披露的重大事件，并将案例对齐 OWASP LLM Top 10 2026 与 Agentic Top 10 2026；文首声明其非正式 OWASP 产品、亦非穷尽清单。本日未见 NIST、ISO、欧盟监管机构发布可独立核验的新强制标准文本；NIST 侧关于 NVD 现代化 RFI（评论截止约 10 月 13 日）与 SP 1353 草案（约 10 月 15 日）仍属征求意见窗口，不构成已生效规范更新。

🔗 来源：[OWASP GenAI Q3 2026 Exploit Roundup](https://genai.owasp.org/2026/10/08/genai-and-agentic-ai-exploit-roundup-q3-2026)

### 三、今日趋势洞察

云厂商已开始用 Critical 级 CVE 透明披露运维智能体的授权失败，而开源 AI 网关与 MCP 运行时仍在把管理口、回调 URL 和设备码 OAuth 做成默认可达的密钥与内网入口。与此同时，季度级利用综述把“评测边界失效 + 过度代理权限”固化为可映射的治理分类，说明组织侧需要把智能体身份、人类专属授权和网络出口控制拆成可审计的独立控制面，而不是继续依赖提示词约束。

### 四、企业行动清单

- 核查租户内 Azure SRE Agent 及相关运维智能体角色分配，对照 10 月 8 日前后异常权限或配置变更日志。
- 扫描 Plano 等 AI 网关部署是否对外暴露 9901 等 Envoy/admin 端口，发现后立即隔离并轮换已加载的模型供应商密钥。
- 盘点基于 MCP Kotlin SDK WebSocket 服务端的对外监听实例，在补丁前于反向代理限制帧大小与连接速率。
- 审查 Trinity 类多智能体平台中“人类绑定/渠道管理”接口是否接受智能体 MCP 密钥调用，并将提示注入可触达的工具从绑定变更面剥离。
- 禁止 mcp-remote 等客户端在设备码流程中解析非 HTTPS 的授权与令牌端点，对已使用明文端点的会话立即轮换 client secret 与令牌。
