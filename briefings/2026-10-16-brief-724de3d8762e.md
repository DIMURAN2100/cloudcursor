# 全球网络安全简报（AI 专题）— 2026-10-16（GMT+8）

本期主要覆盖东八区过去约 24～48 小时内可核验的公开披露；其中官方 MCP Python / Java SDK 的请求体与会话资源耗尽类修复、Flyto2 Core MCP 未认证执行与 n8n MCP 原型污染公告于 10 月 14 日前后进入 NVD / GitHub Advisory，因影响 MCP 生态基础组件与自动化平台面，放宽至约 72 小时一并纳入。时效均已对照 NVD / VulnCheck、GitHub Security Advisory、JetBrains 已修复问题页与 EC-Council / GlobeNewswire 原文核对，不重复前几日已写且无新补丁进展的 Portkey、Roo Code、Ludwig、Open WebUI 等条目。

### 一、今日要点

**[1] Archon控制面默认可被接管**
📌 类型：AI自身安全

NVD / VulnCheck 于 10 月 15 日收录 CVE-2026-111322（CVSS 约 9.3–9.8 Critical）：开源 AI 编码编排平台 Archon 0.2.13 至 0.11.1 的 `/api/*` 控制面在默认安装下不启用认证（需同时配置 Postgres `DATABASE_URL` 与 `BETTER_AUTH_SECRET` 才打开门禁），且默认绑定 `0.0.0.0`。网络可达的未认证调用者可启动工作流、向智能体会话注入消息、批准或拒绝暂停中的操作，并改动提供商密钥配置。VulnCheck 描述称智能体以 `bypassPermissions` 运行时，可进一步在宿主机以 Archon 用户执行命令；研究者 HackMD 报告明确为源码审阅结论、未做运行时复现，并强调直接主机 RCE 路径未在实验中确立。截至披露时尚无正式修复版本；临时缓解需改为本机绑定并启用 Web 认证。属已确认默认配置缺陷，未见在野利用通报。

🔗 来源：[NVD CVE-2026-111322](https://nvd.nist.gov/vuln/detail/CVE-2026-111322) · [VulnCheck Advisory](https://www.vulncheck.com/advisories/archon-0.2.13-through-0.11.1-missing-authentication-via-api-control-api) · [研究者披露](https://hackmd.io/@hieuPenguinnn/archon-os-api-missing-authentication-default)

**[2] 官方MCP SDK可被撑爆内存**
📌 类型：AI基础设施CVE

NVD 于 10 月 14 日集中收录官方 MCP 运行时资源耗尽缺陷。Python SDK（`mcp`）CVE-2026-109527（CVSS 7.5）：1.29.1 之前及 2.0.0a1–2.0.1 的 Streamable HTTP / SSE / OAuth 相关路由在无上游限流时完整缓冲请求体，可达端点的未认证客户端可反复耗尽进程内存；另有 CVE-2026-59951（CVSS 6.9）指出有状态 Streamable HTTP 会话默认不回收且无会话上限，普通短请求即可造成无界内存增长，修复于 1.30.0 / 2.2.0。Java SDK CVE-2026-108395（CVSS 7.5）：Servlet 系 SSE / Streamable HTTP / Stateless 传输在指定版本区间不限制 POST 体大小，可致堆耗尽；维护线修复版本为 mcp-core 0.18.4、1.1.4、2.0.1。属已确认拒绝服务类缺陷，stdio / 已做上游限流的部署影响有限。

🔗 来源：[NVD CVE-2026-109527](https://nvd.nist.gov/vuln/detail/CVE-2026-109527) · [GitHub Advisory GHSA-84m7-p3x7-pcfv](https://github.com/advisories/GHSA-84m7-p3x7-pcfv) · [NVD CVE-2026-108395](https://nvd.nist.gov/vuln/detail/CVE-2026-108395)

**[3] Flyto2的MCP口可未授权执行**
📌 类型：AI基础设施CVE

GitHub Advisory GHSA-h9f9-h6gm-wc85 / CVE-2026-55786（CVSS 8.4 High）披露：自动化与 AI Agent 执行内核 Flyto2 Core 自 2.26.2 至 2.26.4 之前，HTTP MCP 的 `POST /mcp` 接受未认证 JSON-RPC `tools/call`，可将 `execute_module` 参数转发至模块注册表，进而调用 `sandbox.execute_shell` 并以服务进程权限执行任意命令。默认绑定回环时为高危本地面；若以非回环地址监听则变为网络可达。官方确认在容器内无 Authorization 头即可复现，修复版本为 2.26.4。同批另有 CVE-2026-55787（CVSS 7.1）针对 SSRF 防护未解包 IPv4 映射等过渡地址，修于 2.26.3。属已确认研究验证路径，未见在野利用确认。

🔗 来源：[GitHub Advisory GHSA-h9f9-h6gm-wc85](https://github.com/flytohub/flyto-core/security/advisories/GHSA-h9f9-h6gm-wc85) · [NVD CVE-2026-55786](https://nvd.nist.gov/vuln/detail/CVE-2026-55786)

**[4] n8n的MCP校验可提权到所有者**
📌 类型：AI自身安全

NVD / 官方 Advisory 于 10 月 14 日披露 CVE-2026-110842（CVSS 7.7 High）：工作流自动化平台 n8n 在 2.41.4 与 2.42.1 之前，MCP 工作流校验工具的解释器在主进程中评估调用方代码，可读继承属性并向共享原型赋值。仅持有 `workflow:read` 的认证成员即可污染内置方法，使服务端权限检查接受其本不具备的范围，报告者演示可接管未启用 MFA 的所有者账户。修复版本为 2.41.4 / 2.42.1；临时缓解包括关闭实例级 MCP、收紧访问与为所有者启用 MFA。属已确认平台提权缺陷，利用需已获低权限 MCP 授权。

🔗 来源：[GitHub Advisory GHSA-5jr4-xmvf-frmj](https://github.com/n8n-io/n8n/security/advisories/GHSA-5jr4-xmvf-frmj) · [NVD CVE-2026-110842](https://nvd.nist.gov/vuln/detail/CVE-2026-110842)

**[5] Junie CLI可因MCP配置执行代码**
📌 类型：AI自身安全

JetBrains 已修复问题页与 NVD 于 10 月 15 日公布 CVE-2026-111091（High，CVSS 7.8）：Junie CLI 在 26.8.3 之前，可通过不受信任项目中的 MCP 服务器配置实现代码执行（CWE-829）。影响面为打开或加载含恶意 MCP 配置的本地项目场景，属于开发者终端智能体供应链路径，而非远程未认证入口。官方修复版本为 Junie CLI 26.8.3。属厂商已确认并完成缓解的缺陷，未见在野利用通报。

🔗 来源：[JetBrains Fixed Security Issues](https://www.jetbrains.com/privacy-security/issues-fixed/) · [NVD CVE-2026-111091](https://nvd.nist.gov/vuln/detail/CVE-2026-111091)

**[6] 消费级机器人AI接口可被未认证改写**
📌 类型：AI基础设施CVE

NVD 于 10 月 15 日收录 EnergizeLab Eilik / EilikO 相关高危簇：CVE-2026-105032（CVSS 9.1）指出 FastAPI AI 推理与画像服务上的 AI skill 上传端点无认证且不约束上传路径，未认证远端可借路径穿越篡改机器人所用 skill 文件；CVE-2026-105038（CVSS 9.8）指出同组服务暴露无认证的模型管理接口，可在运行时更换模型配置。同日 The Verge 报道跟进该系列研究披露，确认问题落在消费级 AI 机器人后端与更新通道。属已确认设备侧 AI 控制面缺陷；公开材料未给出统一客户补丁版本号，企业与用户侧应隔离推理服务网络暴露并关注厂商固件更新。

🔗 来源：[NVD CVE-2026-105032](https://nvd.nist.gov/vuln/detail/CVE-2026-105032) · [NVD CVE-2026-105038](https://nvd.nist.gov/vuln/detail/CVE-2026-105038) · [The Verge 报道](https://www.theverge.com/tech/1010727/eiliko-robot-hack-energize-lab)

**[7] EC-Council发布ADG 2.0治理框架**
📌 类型：AI治理合规

EC-Council 于 10 月 14 日通过 GlobeNewswire 发布 Adopt, Defend, Govern（ADG）框架 2.0，并将框架及其与 90 余项法规 / 标准的对照表免费开放给各国政府、监管机构与标准组织；Yahoo Finance 等转载标注发布时间约为 10 月 15 日 00:03 UTC。ADG 2.0 将原 12 项最低控制扩展为 12 个控制族、180 余项控制，映射 NIST AI RMF、ISO/IEC 42001、EU AI Act 等，并提出 ADMIT / DECIDE / EMIT / COMMIT 运行时治理点与分级自主级别。此为行业协会框架发布与开放许可，非新的强制性法规文本；企业可用于对照多法域要求的统一控制集，但仍需按其适用法域单独评估合规效力。

### 二、深度速览

#### 【AI 赋能防御】

ADG 2.0 把“运行时治理”拆成准入、决策、输出与提交四个卡点，并要求在既定决策阈值保留人审证据，使安全运营可以把智能体工具调用、外部动作与审批门禁映射到同一套可审计控制，而不是停留在模型输出内容审查。对已建设 SOC / 自动化编排的组织，本期可用处在于：把 MCP 网关、工作流平台与编码智能体的变更事件接入 ADMIT–COMMIT 证据链，并按 Assistive / Conditional / Autonomous 分级收紧默认可执行动作。需注意该框架为 EC-Council 开放治理产品，映射表可加速对照，但本身不构成监管豁免。

🔗 来源：[ADG Framework 官网](https://www.eccouncil.org/adgframework/) · [GlobeNewswire 通稿](https://markets.businessinsider.com/news/stocks/ec-council-releases-adg-2-0-and-offers-its-ai-governance-crosswalks-free-to-every-government-regulator-and-standards-body-as-nations-split-on-ai-rules-1036627729)

官方 MCP SDK 的限体长与会话回收补丁，属于平台侧基础硬化：在把第三方 MCP 服务暴露给不完全可信客户端前，先升级 Python / Java SDK，并在反向代理强制请求体上限，可显著降低“用合法协议流量打垮 Agent 网关”的可用性攻击面，为后续检测规则与容量规划腾出稳定基线。

🔗 来源：[GitHub Advisory GHSA-84m7-p3x7-pcfv](https://github.com/advisories/GHSA-84m7-p3x7-pcfv) · [NVD CVE-2026-108395](https://nvd.nist.gov/vuln/detail/CVE-2026-108395)

#### 【AI 系统风险】

本期高影响面再次集中在“默认开放的智能体控制面”。Archon 把工作流启动、消息注入与人审放行全部挂在默认关闭的 API 门禁之后，且监听全网接口；Flyto2 的 MCP 路由缺少 REST 侧已有的 `require_auth`，使 `tools/call` 直接落到 shell 模块；n8n 则把 MCP 校验解释器放进主进程并允许原型污染，把只读授权抬升为所有者接管。共性机制是：MCP / Agent 控制协议被当成“内部调试面”，却以网络服务形态交付。缓解应默认本机绑定、对变更类路由强制身份、禁止在主进程解释不可信代码，并对所有者账户启用 MFA。Junie CLI 与消费级机器人 skill / 模型管理接口则提示第二条路径——不可信项目配置与边缘设备推理服务同样可成为智能体供应链入口。

🔗 来源：[研究者披露（Archon）](https://hackmd.io/@hieuPenguinnn/archon-os-api-missing-authentication-default) · [Flyto2 Advisory](https://github.com/flytohub/flyto-core/security/advisories/GHSA-h9f9-h6gm-wc85) · [n8n Advisory](https://github.com/n8n-io/n8n/security/advisories/GHSA-5jr4-xmvf-frmj)

#### 【全球治理与标准】

EC-Council ADG 2.0 于 10 月 14 日发布，并向政府与标准组织免费提供与 90 余项规则的对照及实施协助入口。内容侧重多法域映射、运行时治理卡点与分级自主，属行业框架更新而非新的强制令；其余监管或认证文本本日无单独强制更新需单列。

### 三、今日趋势洞察

智能体平台的高危缺陷正从“单个工具参数校验失败”上移到“控制面默认无身份、解释器跑在主进程、SDK 传输层无资源上限”的组合，使网络可达性本身成为利用前提。与此同时，治理侧开始用运行时卡点与跨法域对照表回应 Agent 越界事件，但企业仍需把框架映射落到 MCP 网关、工作流平台与开发者 CLI 的具体版本与绑定策略上，否则对照表无法缩短暴露窗口。

### 四、企业行动清单

- 盘点内网是否部署 Archon、Flyto2 Core、n8n 实例级 MCP 或自建 MCP HTTP 服务，确认监听地址是否为 `0.0.0.0` 以及变更类 API 是否强制认证。
- 将官方 MCP Python SDK 升级至含请求体限制与会话回收的修复线（如 1.29.1+ / 1.30.0、2.1.0 / 2.2.0 对应修复），Java mcp-core 升至 0.18.4、1.1.4 或 2.0.1，并在反向代理设置请求体上限。
- 自托管 n8n 升级至 2.41.4 或 2.42.1 及以上，复核 `workflow:read` MCP OAuth 授权范围，并为所有者 / 管理员账户启用 MFA。
- 将 JetBrains Junie CLI 升级至 26.8.3 及以上，并禁止未经审查的仓库 MCP 配置自动加载。
- 隔离消费级 / 边缘 AI 设备的推理与 skill 管理端口，禁止其管理 API 对不可信网络可达，并跟踪厂商固件与凭证轮换通知。
