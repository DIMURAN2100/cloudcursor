### 一、今日要点

**[1] Cisco开源Agent跨步检测**
📌 类型：AI赋能安全

Cisco 于 10 月 28 日官方博客宣布开源 Project Quarry（GitHub：`cisco-ai-defense/project-quarry`），SecurityWeek 于 10 月 29 日跟进。Quarry 被定位为面向 Agent 行为的神经符号规则语言与求值引擎：把机器学习判定与精确规则检查结合，覆盖单轮/多轮 LLM 对话、工具调用、MCP 交互与多模态输入，用于识别“单步看似合法、仅在动作序列上才显现恶意意图”的攻击或越权模式。官方强调其可作运行时护栏、事后分析与事件响应的共享策略层，并计划与 DefenseClaw 等治理组件及 Splunk 联动；属厂商开源的检测能力发布，而非在野攻击通报。

🔗 来源：[Cisco 博客 Project Quarry](https://blogs.cisco.com/ai/project-quarry-agent-security-detections) · [SecurityWeek（10/29）](https://www.securityweek.com/cisco-open-sources-quarry-to-catch-ai-agent-attacks-hidden-in-harmless-steps/)

**[2] WordPress AI Engine MCP越权**
📌 类型：AI基础设施CVE

Wordfence 报送、NVD 于 10 月 30 日公开 CVE-2026-110732（High，CVSS 3.1 基础分 7.5）：WordPress 插件 AI Engine（MCP Server & AI Chatbot）在至 3.8.6（含）版本中，MCP 模块的 OAuth 2.1 Dynamic Client Registration 端点 `/wp-json/mcp/v1/oauth/register` 的 `permission_callback` 为 `__return_true`，未认证攻击者可注册带攻击者控制 redirect URI 的活跃 OAuth 客户端。若管理员随后在同意页批准该客户端，攻击者可获得绑定管理员身份的 MCP 访问令牌，进而通过 MCP 工具实施用户创建、选项更新等管理员级操作；同意页还存在点击劫持相关风险描述。公开材料指向 3.8.7 相关变更集为修复方向。属确认的 MCP 身份绑定缺陷，公开信息未声称大规模在野利用。

🔗 来源：[NVD CVE-2026-110732](https://nvd.nist.gov/vuln/detail/CVE-2026-110732) · [Wordfence 漏洞情报](https://www.wordfence.com/threat-intel/vulnerabilities/id/eb115a8a-35f8-426f-bb67-4a523f67cb34?source=cve)

**[3] Kubeflow流水线跨租户读工件**
📌 类型：AI基础设施CVE

Kubeflow Pipelines 于 10 月 29 日发布 GitHub 安全公告 GHSA-vjhf-6c8f-qhwj，NVD 同日收录 CVE-2026-118760（Medium，6.5）：多用户部署中，前端制品（artifact）路由未校验调用者是否有权访问所请求命名空间。已认证且能到达前端、并知晓制品位置的用户，可选择其他租户命名空间或省略命名空间以触达未受保护的直接处理路径，读取数据集、模型或流水线输出等内容。公告明确不构成任意 Kubernetes Secret 泄露、存储内容篡改或服务端代码执行。受影响组件为 `ghcr.io/kubeflow/kfp-frontend` 版本 ≥0.5.1 且 <2.17.0；修复版本 2.17.0（亦含于 2.18.0），修复通过 SubjectAccessReview 在取回制品前校验命名空间 `viewers` 的 `get` 权限。

🔗 来源：[GitHub Advisory GHSA-vjhf-6c8f-qhwj](https://github.com/kubeflow/pipelines/security/advisories/GHSA-vjhf-6c8f-qhwj) · [NVD CVE-2026-118760](https://nvd.nist.gov/vuln/detail/CVE-2026-118760)

**[4] Agno Pandas工具反射RCE**
📌 类型：AI自身安全

VulnCheck 作为 CNA、NVD 于 10 月 29 日公开 CVE-2026-119050（High，CVSS 4.0 向量由 VulnCheck 给出）：Agent 框架 Agno 至 3.1.11，`PandasTools` 使用模型可控字符串经 `getattr(pd, …)` 选择 pandas 可调用对象并传入模型可控参数。提示注入可诱导代理调用 `pandas.read_pickle` 等对攻击者可控路径执行反序列化，从而在运行代理的主机上实现代码执行，或其他读文件原语。GitHub 议题 #8699（2026-07 起公开）与代码引用可相互印证机制；公开 CVE 材料未给出已合并的正式修复版本号，NVD 标注该记录暂不优先充实。属确认的“模型可控工具名即反射入口”设计缺陷与新 CVE 编目，不宜表述为已出现大规模在野利用。

🔗 来源：[NVD CVE-2026-119050](https://nvd.nist.gov/vuln/detail/CVE-2026-119050) · [GitHub 议题 #8699](https://github.com/agno-agi/agno/issues/8699) · [VulnCheck 公告](https://www.vulncheck.com/advisories/agno-through-3.1.11-code-execution-via-pandastools-unsafe-reflection)

**[5] fickling模块信任绕过分析**
📌 类型：AI基础设施CVE

Bombadil Systems 与 NVD 于 10 月 30 日公开 CVE-2026-16760（High，CNA CVSS 3.1 基础分 8.8）：Trail of Bits 的 pickle 安全分析工具 fickling 至 0.1.12，在 `_process_import()` 中仅因导入来自“未列入危险名单的标准库模块”即把名称加入 `likely_safe_imports`，随后分析阶段对同名调用一律跳过，导致经 `dataclasses._create_fn`、`mailcap.findmatch`、`readline` 写历史等路径可达的代码执行或任意写文件载荷被判定为 `LIKELY_SAFE`；`fickling.load()` 会据此放行反序列化。公告强调根因是“按模块来源推断可调用对象安全性”，与同日相关的另一条 dotted `__qualname__` 问题（CVE-2026-118938）可分别修复；截至公告日正式发行版仍受影响，补丁方向在主线待发。因大量 ML/模型工件仍依赖 pickle，该缺陷直接影响把 fickling 当作门禁的模型供应链扫描流程。

🔗 来源：[NVD CVE-2026-16760](https://nvd.nist.gov/vuln/detail/CVE-2026-16760) · [Bombadil Systems 公告页](https://bombadil.systems/advisories.html)

**[6] ATT&CK将新增AI平台**
📌 类型：AI治理合规

MITRE 于 10 月 27 日在 ATT&CKcon 7.0 宣布：ATT&CK Enterprise 将新增面向 AI 使能系统的平台，内容部分来自 MITRE ATLAS，并由专职 ATT&CK AI Platform 团队维护，计划于明年初发布。新平台将收录针对 AI 系统的特有对手技术，例如结果投毒（results poisoning）与提示注入等，使 Enterprise 在 Windows、Cloud、Network Devices 等之外覆盖 AI 运行时威胁建模。同期还预告将推出可机器读取的 Protection Strategies（对既有 Mitigations 的升级）。此为标准知识库范围扩展的官方宣布，尚非当日即生效的完整技术矩阵发布。

🔗 来源：[MITRE 新闻稿](https://www.mitre.org/news-insights/news-release/mitre-attck-enterprise-add-ai-platform)

### 二、深度速览

#### 【AI 赋能防御】

Quarry 把“单点动作放行”与“跨步意图识别”拆开：传统允许/拒绝控制仍负责每一步的授权，而规则语言负责在完整 trace（模型所见、所言与工具结果）上匹配可疑序列，并附带证据链。这对 SOC 与 Agent 运行时团队意味着检测资产要从单条提示或单次工具调用，扩展到 MCP 会话与多轮工具轨迹的可查询策略。Google DeepMind 于 10 月 28 日发布 Gemini 4 Carbon 时（厂商来源）亦强调网络安全与间接提示注入评测表现，并称在 Gray Swan IPI Benchmark 上攻击成功率为 0.0%；该数字属厂商评测声明，需与第三方复现及生产护栏部署区分看待。两者共同指向同一运营缺口：仅加固模型对齐不足以覆盖 Agent 合法权限下的跨步滥用。

🔗 来源：[Cisco Project Quarry](https://blogs.cisco.com/ai/project-quarry-agent-security-detections) · [Google Gemini 4 Carbon 公告（厂商来源）](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-carbon)

#### 【AI 系统风险】

三条机制并列。一是 **MCP OAuth 动态注册等同开放注册入口**：AI Engine 将注册回调设为恒真，使“管理员点一次同意”成为把 MCP 工具面交给攻击者的关键步骤。二是 **ML 流水线前端认证≠租户授权**：Kubeflow 制品路由证明入口身份建立后，若缺少命名空间级 SubjectAccessReview，模型与数据集即可被横向读取。三是 **把函数选择权交给模型字符串**：Agno 的 `getattr(pd, model_string)` 与 pickle 读路径叠加后，提示注入可直接落到主机代码执行；而依赖 fickling 一类门禁的团队还须意识到分析器自身的“模块来源信任”可被构造载荷绕过。共性缓解方向：MCP 客户端注册需强认证与管理员绑定审计、流水线制品 API 强制命名空间鉴权、Agent 工具白名单禁止任意反射/反序列化、模型工件扫描工具需独立于单一启发式门禁做纵深验证。

🔗 来源：[NVD CVE-2026-110732](https://nvd.nist.gov/vuln/detail/CVE-2026-110732) · [GHSA-vjhf-6c8f-qhwj](https://github.com/kubeflow/pipelines/security/advisories/GHSA-vjhf-6c8f-qhwj) · [NVD CVE-2026-119050](https://nvd.nist.gov/vuln/detail/CVE-2026-119050) · [NVD CVE-2026-16760](https://nvd.nist.gov/vuln/detail/CVE-2026-16760)

#### 【全球治理与标准】

MITRE 将 AI 平台并入 ATT&CK Enterprise，实质是把 ATLAS 中面向 AI 的对手行为知识，迁移到企业安全运营更常用的 ATT&CK 工作流（检测工程、对抗仿真、产品评测）。对依赖 ATT&CK 映射的 SOC 与 MSSP 而言，这意味着明年起可将提示注入、结果投毒等技术与既有 Windows/Cloud 技术在同一知识库中编排；在完整平台内容发布前，仍应继续以 ATLAS 与内部威胁模型作过渡参照。

🔗 来源：[MITRE 新闻稿](https://www.mitre.org/news-insights/news-release/mitre-attck-enterprise-add-ai-platform)

### 三、今日趋势洞察

Agent 安全正同时向“跨步检测语言”和“身份/租户边界硬化”两端推进：一边是 Quarry 类规则试图连接合法工具调用序列，另一边是 MCP OAuth 与 ML 流水线制品路由暴露出认证完成后的授权空洞；叠加模型可控反射与 pickle 门禁绕过，说明供应链与运行时若把安全属性交给模型参数或单一静态分析结论，隔离会在工具层而非模型权重层首先失效。

### 四、企业行动清单

- 清点已启用 MCP OAuth/动态客户端注册的 WordPress AI Engine 及其他站点侧 MCP 宿主，确认版本不低于厂商修复线，并审计近期 OAuth 客户端注册与管理员同意记录。
- 对 Kubeflow Pipelines 多用户集群，将 `kfp-frontend` 升级至 2.17.0+，并用 SubjectAccessReview/命名空间绑定抽样验证跨租户制品不可读。
- 盘点 Agno 等将模型输出直接映射为 `getattr`/反序列化工具名的 Agent 项目，禁用或白名单化 PandasTools 类反射入口，隔离运行代理的主机权限与密钥。
- 若模型入库门禁用 fickling `check_safety()`/`load()`，勿将其作为唯一放行条件；对 pickle/PyTorch 工件叠加独立扫描、签名与执行沙箱。
- 评估将 Quarry 类跨步规则接入现有 Agent 审计日志或 SIEM，优先覆盖 MCP 工具链与敏感文件/出站组合序列。
