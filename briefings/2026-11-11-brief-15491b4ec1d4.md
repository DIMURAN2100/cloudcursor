### 一、今日要点

**[1] 低代码 MCP 监听未限制**
📌 类型：AI基础设施CVE

西门子 ProductCERT 于 2026-11-10 发布 SSA-710379（当前版本 V1.0），说明 Mendix Studio Pro 自带的 MCP 服务器有两项缺陷。CVE-2026-112136 写明 HTTP 监听没有限制在回环地址，具备网络访问的攻击者可能远程与该服务器交互；西门子给出的 CVSS 3.1 为 8.8，向量含用户交互，CVSS 4.0 为 9.2，并把攻击要求标为存在、用户交互标为无。CVE-2026-112137 写明服务器未校验 Content-Type 和 Origin，恶意网页可以让浏览器向本地 MCP 服务器发送请求并执行非预期动作，CVSS 3.1 为 5.4、4.0 为 5.1。受影响范围是 Studio Pro 11 的 11.15.0（含）至 11.16.0（不含），以及 11.12 的 11.12.6（含）至 11.12.7（不含）；对应修复版本为 11.16.0、11.12.7 或更高。公告建议在完成升级前阻断 7782 端口的外部入站，并写明标准 Windows 安装的防火墙默认已经这样做。公告没有写在野利用。

🔗 来源：[西门子 SSA-710379](https://cert-portal.siemens.com/productcert/html/ssa-710379.html) · [NVD CVE-2026-112136](https://nvd.nist.gov/vuln/detail/CVE-2026-112136)

**[2] 云端模型提权已缓解**
📌 类型：AI基础设施CVE

微软安全更新指南于美西 11 月 10 日 08:00 发布 CVE-2026-119990，标题为 Azure OpenAI 权限提升，严重性为严重，CVSS 3.1 基础分 9.8，时间分 8.5。描述只写明关键功能缺少身份认证，未经认证的攻击者可以经网络提升权限，CWE 为 CWE-306。指南把事先公开和已知利用都标为否；向量中的利用成熟度为未证实，补救级别为官方修复。常见问题写明该漏洞已经由微软完全缓解，用户没有需要执行的更新步骤，发布 CVE 是为了提高透明度。更新指南记录的修复构建为 hyena-infra-build-official/20260923.14，客户动作要求为否。

🔗 来源：[微软安全更新指南](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-119990) · [NVD CVE-2026-119990](https://nvd.nist.gov/vuln/detail/CVE-2026-119990)

**[3] 检索条件合并漏过拒绝**
📌 类型：AI自身安全

Okta 于 2026-11-10 发布两项检索授权缺陷，CVSS 3.1 均为 6.5，类型为不正确的授权（CWE-863）。CVE-2026-107372 影响 @auth0/ai：在启用 Auth0 FGA 条件检查，且同一次检索中的多份文档具有相同对象、用户和关系、但授权上下文不同时，检索器不区分这些条件，被 FGA 拒绝的文档仍会进入模型上下文并用于生成回答。受影响产品栏写的是 6.0.2 之前的版本，客户建议升级到 6.0.3 或更高。CVE-2026-108167 影响 auth0-ai-langchain 1.0.2 之前和 auth0-ai-llamaindex 1.0.3 之前：同一次检索里映射到同一 FGA 对象、但用户、关系或授权上下文不同的文档，被拒绝的文档同样会进入上下文；客户建议分别升到 1.0.2、1.0.3 或更高。两份公告都没有写在野利用。

🔗 来源：[Okta：auth0-ai-js](https://trust.okta.com/security-advisories/improper-access-control-in-auth0-ai-js-document-retrieval-cve-2026-107372) · [Okta：auth0-ai-python](https://trust.okta.com/security-advisories/improper-access-control-in-auth0-ai-python-document-retrieval-cve-2026-108167)

**[4] 网关命名冲突获得编号**
📌 类型：AI基础设施CVE

微软安全更新指南于美西 11 月 10 日收录 CVE-2026-109492，产品为 Microsoft MCP Gateway，影响为权限提升，严重性为重要，CVSS 3.1 为 8.8。指南的常见问题写明，已认证攻击者可以经网络发送特制请求，读取其他用户的工作负载日志或干扰其工作负载，不需要用户交互；指南将事先公开和已知利用标为否。仓库公告 GHSA-frpg-5vp2-p974 已于 10 月 16 日公开同一问题：适配器与工具按资源名创建同命名空间中的 Kubernetes 对象，名称冲突被忽略后，已认证用户可以接管名为 toolgateway 的内置工具网关，或读取、删除其他用户的工作负载。修复版本为 1.0.0，对应标签 v1.0.0，提交日期为 10 月 14 日。11 月 10 日新增的公开事实是 CVE 编号，以及该问题进入当月安全更新指南。

🔗 来源：[微软安全更新指南](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-109492) · [mcp-gateway 仓库公告](https://github.com/microsoft/mcp-gateway/security/advisories/GHSA-frpg-5vp2-p974)

**[5] 代理框架披露请求伪造**
📌 类型：AI基础设施CVE

CVE-2026-109485 于美西 11 月 10 日进入安全更新指南，标题为 Microsoft 365 Agents SDK 信息泄露，严重性为重要，CVSS 3.1 为 6.3。描述写明，已授权攻击者可以利用服务端请求伪造，经网络泄露信息；向量中的攻击复杂度为高，范围改变。指南将事先公开和已知利用标为否，客户动作要求为是。安全更新指向的产品名称是 Microsoft Agent Framework SDK（dotnet），版本 1.8.77，发布说明位于 Agents-for-net 的 v1.8.77。该标签的发布时间是 8 月 24 日，说明正文写的是 .NET 10 支持、多通道适配和出站请求校验。请求伪造的依据是更新指南。该仓库的安全公告列表为空。仍低于 1.8.77 的安装应按指南升级。

🔗 来源：[微软安全更新指南](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-109485) · [Agents-for-net v1.8.77](https://github.com/microsoft/Agents-for-net/releases/tag/v1.8.77)

**[6] 编程插件本地命令注入**
📌 类型：AI自身安全

#### 【AI 系统风险】

Mendix 的两项缺陷都落在 Studio Pro 本机启动的 MCP 服务器上，而不是落在已部署的低代码应用里。监听地址不受限时，同一网络上的访问者可以直接对服务器说话；西门子把默认暴露端口写为 7782，并把“标准 Windows 防火墙已经阻断外部入站”写成现成状态。跨站请求伪造则依赖用户的浏览器：外部网页在缺少 Origin 和 Content-Type 校验时，可以把请求送到本机服务器。两条路径的修复版本不同，11 与 11.12 要分别升到 11.16.0 和 11.12.7。3.1 与 4.0 对“是否需要用户交互”的标法并不相同，影响判断应以公告里的两条向量和文字描述一起看。

Auth0 的两份公告描述的是检索过滤的键，而不是模型权重。FGA 已经对某份文档给出拒绝，检索器仍可能把它放进同一次生成所用的上下文。JavaScript 库的触发条件是条件授权：对象、用户和关系相同，授权上下文不同。Python 的 LangChain 与 LlamaIndex 检索器还把不同用户或不同关系合并进同一次检查。公告给出的升级目标分别是 @auth0/ai 6.0.3、auth0-ai-langchain 1.0.2 和 auth0-ai-llamaindex 1.0.3。未使用 FGA 条件或多文档同对象检索的集成，不在这两份公告写明的前提里。

Microsoft MCP Gateway 的仓库公告把问题写在 Kubernetes 对象的名字上。适配器和工具只在各自的记录里查重，内置工具网关使用的名字 toolgateway 以及另一类资源已经占用的名字仍能创建；Kubernetes 返回冲突后，冲突被忽略，调用者成为新记录的所有者，随后的更新、删除、日志和工具调用仍按名字找到原有对象。后果包括替换内置工具网关的容器镜像，以及读取或删除其他用户的工作负载。1.0.0 已于 10 月中旬修复。11 月 10 日的指南使用了更短的表述，只写到读取他人工作负载日志和干扰工作负载，并把事先公开标为否；仓库公告的公开日期是 10 月 16 日。

🔗 来源：[西门子 SSA-710379](https://cert-portal.siemens.com/productcert/html/ssa-710379.html) · [Okta：auth0-ai-js](https://trust.okta.com/security-advisories/improper-access-control-in-auth0-ai-js-document-retrieval-cve-2026-107372) · [Okta：auth0-ai-python](https://trust.okta.com/security-advisories/improper-access-control-in-auth0-ai-python-document-retrieval-cve-2026-108167) · [mcp-gateway 仓库公告](https://github.com/microsoft/mcp-gateway/security/advisories/GHSA-frpg-5vp2-p974)

### 三、今日趋势洞察

这一天新编号的问题集中在模型通往工具、检索文档和网关对象的权限边界：云端接口缺少认证，低代码环境的 MCP 监听不受回环限制，检索器把不同的授权条件并成一次检查，自建网关则按 Kubernetes 名字接管他人的工作负载。Azure OpenAI 写明用户无需操作。MCP 网关、代理 SDK 和 JetBrains 插件的修复构建分别在 10 月 14 日、8 月 24 日和 9 月 7 日就已经存在。核对时应把公告日期和本机已经安装的构建日期分开记录。

### 四、企业行动清单

- 核对 CVE-2026-119990 的微软常见问题，把 Azure OpenAI 登记为服务端已经缓解、用户无需执行更新；修复构建标识以更新指南中的 hyena-infra-build-official/20260923.14 为准。
- 将 Mendix Studio Pro 11 升到 11.16.0 或更高，将 11.12 升到 11.12.7 或更高；升级完成前核对 7782 端口的外部入站是否仍被阻断。
- 对使用 Auth0 FGA 条件检索的应用，把 @auth0/ai 升到 6.0.3 或更高，把 auth0-ai-langchain 升到 1.0.2 或更高，把 auth0-ai-llamaindex 升到 1.0.3 或更高。
- 清点 Microsoft MCP Gateway：低于 1.0.0 的部署，包括 10 月 14 日之前构建的 latest 镜像和含工具管理的 main，按仓库公告重新部署；已经运行 1.0.0 的实例，把 CVE-2026-109492 记为 10 月公告的编号。
- 核对 Microsoft Agent Framework SDK（dotnet）是否低于 1.8.77，以及 JetBrains 中的 GitHub Copilot 是否低于 1.17.0-251；低于上述版本的安装按更新指南升级。
