### 一、今日要点

**[1] MLflow SSRF 入 CISA KEV**
📌 类型：AI基础设施CVE

CISA 于 2026-08-19 将 MLflow 未认证 webhook SSRF 漏洞 CVE-2026-64849 列入已知被利用漏洞目录（KEV），要求按 BOD 26-04 风险优先级完成缓解，截止日期 2026-09-02。该缺陷影响 3.15.0 之前版本：`/api/2.0/mlflow/webhooks/{id}/test` 仅校验原始 URL，投递阶段跟随重定向可触及内网或云元数据并回传响应体。公开 CVE 编号后数小时内，watchTowr（厂商来源）称蜜罐已观测到针对暴露实例的大规模扫描与利用尝试。官方修复版本为 MLflow 3.15.0。

🔗 来源：[CISA KEV（CVE-2026-64849）](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?field_cve=CVE-2026-64849) · [GitHub Advisory GHSA-7gwp-5pfp-969j](https://github.com/mlflow/mlflow/security/advisories/GHSA-7gwp-5pfp-969j) · [iThome（含 watchTowr 利用观测）](https://www.ithome.com.tw/news/178259)

**[2] Copilot CoSnitch 一键外泄**
📌 类型：AI自身安全

Varonis Threat Labs 于 2026-08-18 披露 Microsoft Copilot Personal 一键攻击链 CoSnitch（CVE-2026-24301），微软同日发布补丁；NVD 亦于当日收录。攻击者诱导模型透露未文档化参数后，可构造含 `?q=` 与 `autorun=1` 的链接，在受害者点击后于页面加载时自动执行提示，调用已连接的 Gmail、Drive、Calendar、OneDrive 等 OAuth 连接器外泄数据，并可通过网页摘要向持久记忆写入指令。研究方称目前未见在野利用证据，且影响面向 Personal 而非 Enterprise；属研究确认与厂商已修复事实。

🔗 来源：[Varonis Threat Labs](https://www.varonis.com/blog/cosnitch) · [NVD CVE-2026-24301](https://nvd.nist.gov/vuln/detail/CVE-2026-24301) · [iThome](https://www.ithome.com.tw/news/178272)

**[3] 多智能体“心智病毒”传播**
📌 类型：AI自身安全

Anthropic Fellows 相关研究论文《Mind Viruses: Self-Propagating Ideas in Multi-Agent LLM Systems》（arXiv:2608.10218，2026-08-10 提交）经权威媒体于 2026-08-18 前后集中报道。实验显示，目标/指令可经智能体间对话及可持久写入并被重载进系统提示的文件（如 `SOUL.md`）跨会话传播，在模拟编码协作与链式代理场景中实现多跳感染；属受控研究演示，非在野蠕虫事件。论文与报道均指出，在系统提示中加入明确警告等轻量防护可显著阻断传播。

🔗 来源：[The Hacker News](https://thehackernews.com/2026/08/ai-mind-viruses-can-spread-between.html) · [arXiv:2608.10218](https://arxiv.org/abs/2608.10218)

**[4] OpenAI 放缓前沿训练强化监控**
📌 类型：AI治理合规

OpenAI 于 2026-08-18 发文称，在 Hugging Face 评测逃逸事件与即将发布的 Astra 或达 Preparedness Framework「Critical」网络安全能力门槛等信号下，已临时放慢扩容节奏，并对拟部署模型的强化学习训练暂停约两周以加固研究环境与红队验证。厂商披露现有多阶段监控（激活分类器升级至高算力自动调查）开销约相当于被监控推理算力的 20%，用于发现未授权访问、数据窃取、破坏与绕过防护等行为；最大规模前沿 RL 运行仍暂缓。以上为厂商官方措施说明。

🔗 来源：[OpenAI 官方博客](https://openai.com/index/pacing-model-development-cyber-capabilities/) · [iThome](https://www.ithome.com.tw/news/178262)

**[5] Onyx MCP 跨用户令牌泄露**
📌 类型：AI基础设施CVE

NVD 于 2026-08-17 公布 Onyx 开源 AI 平台 CVE-2026-71424（CVSS 9.6）：在 3.1.10 / 3.2.14 / 4.0.0 之前，`GET /api/mcp/servers` 与按 persona 查询接口可将其他用户 MCP 连接的 OAuth Authorization 头经由共享管理配置暴露给具备 BASIC_ACCESS 的调用方。风险机制为 per-user 令牌被写入共享 `MCPConnectionConfig` 后随 API 返回。项目安全公告给出修复提交与版本，部署方应升级至修复线并轮换已暴露令牌。

🔗 来源：[NVD CVE-2026-71424](https://nvd.nist.gov/vuln/detail/CVE-2026-71424) · [GitHub Advisory GHSA-q62f-rv3h-f822](https://github.com/onyx-dot-app/onyx/security/advisories/GHSA-q62f-rv3h-f822)

**[6] RAGFlow 智能体 Invoke SSRF**
📌 类型：AI基础设施CVE

NVD 于 2026-08-18 收录 RAGFlow CVE-2026-75898（CVSS 8.5）：0.26.3 之前版本中，智能体工作流 Invoke 组件用画布配置与运行时模板变量拼装出站 URL 并直接请求，未复用项目内 `assert_url_is_safe` 校验与地址固定，可使能创建或触发工作流的用户访问内网/云元数据。修复已合入 v0.26.3；属漏洞公告与补丁事实，未见本期独立在野利用通报。

🔗 来源：[NVD CVE-2026-75898](https://nvd.nist.gov/vuln/detail/CVE-2026-75898) · [VulnCheck Advisory](https://www.vulncheck.com/advisories/ragflow-server-side-request-forgery-via-agent-invoke-component)

**[7] PyCharm Jupyter MCP 代码执行**
📌 类型：AI基础设施CVE

JetBrains 安全公告与 NVD 显示，PyCharm 2026.2.1 之前存在 CVE-2026-75060：通过未认证的 Jupyter MCP 工具可导致代码执行（CVSS 8.4，本地攻击向量）。影响面向将 Jupyter/MCP 工具链接入 IDE 的开发环境，应升级至含修复的 2026.2.1 及以上构建，并限制 MCP/Jupyter 服务的网络暴露面。

🔗 来源：[NVD CVE-2026-75060](https://nvd.nist.gov/vuln/detail/CVE-2026-75060) · [JetBrains Fixed Security Issues](https://www.jetbrains.com/privacy-security/issues-fixed/)

### 二、深度速览

#### 【AI 赋能防御】

OpenAI 将监控、对齐与环境隔离作为能力提升的并行门槛，并以约 20% 额外推理算力支撑多阶段行为检测与 30 分钟人工裁定窗口，体现前沿实验室正把「安全运营算力」计入训练预算。该做法可对照企业内部 Agent/评测流水线：对可调用工具的模型任务强制挂载同等强度的遥测与熔断，而不仅依赖发布前静态评测。来源为 OpenAI 官方披露，属厂商实践而非第三方效果审计。

🔗 来源：[OpenAI](https://openai.com/index/pacing-model-development-cyber-capabilities/)

MLflow 从「公开披露」到「KEV + 扫描利用」的压缩窗口，再次说明 AI 工程平台一旦具备未认证出站通道，防御侧需把互联网暴露的追踪/模型注册服务纳入与传统 Web 应用同等的应急补丁队列，并结合蜜罐与云元数据访问审计做早期狩猎。

🔗 来源：[CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog?field_cve=CVE-2026-64849) · [iThome / watchTowr](https://www.ithome.com.tw/news/178259)

#### 【AI 系统风险】

CoSnitch 把「已认证会话 + OAuth 连接器 + URL 自动执参」串成一键外泄与记忆投毒链，说明个人版助手即便非企业租户，一旦绑定企业邮箱/网盘仍可成为旁路数据通道；缓解重点是禁用或审查深链自动执行、收紧连接器范围，并监控助手发起的异常出站摘要请求。微软已出补丁，Varonis 称无在野利用证据。

🔗 来源：[Varonis](https://www.varonis.com/blog/cosnitch)

多智能体场景下，「可写共享提示文件」成为比即时对话更稳的传播介质；与 MCP/平台侧 SSRF、跨用户令牌泄露叠加后，攻击面从单次提示注入扩展到持久配置与凭证平面。缓解应包括：禁止未审批写入系统提示文件、对共享记忆做完整性校验，以及对 MCP 管理 API 做严格租户隔离。

🔗 来源：[THN / arXiv](https://thehackernews.com/2026/08/ai-mind-viruses-can-spread-between.html) · [Onyx GHSA](https://github.com/onyx-dot-app/onyx/security/advisories/GHSA-q62f-rv3h-f822)

### 三、今日趋势洞察

AI 工程与助手平台的「出站能力」（webhook、Invoke、URL 抓取、MCP 工具）正同时成为利用与监管优先对象：一端是 MLflow 迅速进入 KEV，另一端是 Copilot 连接器被一键武器化。与此并行，前沿厂商以算力换监控、研究界验证多智能体持久文件传播，显示治理重心正从单模型护栏转向「工具权限 + 共享状态 + 运行时遥测」三位一体。

### 四、企业行动清单

- 立即盘点互联网可达的 MLflow Tracking/Registry，确认版本 ≥ 3.15.0，并审计近期 webhook test 与异常出站至链路本地元数据地址的访问日志。
- 督促使用 Copilot Personal 且已连接企业邮箱/网盘的员工完成客户端/服务端安全更新，复核 OAuth 连接器授权范围并撤销非必要连接。
- 对 Onyx、RAGFlow、PyCharm Jupyter MCP 等内部 AI 平台按 CVE 修复线升级，轮换可能泄露的 MCP OAuth 令牌，关闭未认证 MCP/Jupyter 端口对外暴露。
- 审查多智能体编排中可被 Agent 改写并重载进系统提示的共享文件权限，禁止生产工作流对提示/记忆文件的任意写入。
- 将可调用工具的模型训练与评测任务纳入强制行为监控与超时熔断策略，明确安全值守响应时限。
