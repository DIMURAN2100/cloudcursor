### 一、今日要点

**[1] 只读桶引出恶意扩展**
📌 类型：AI自身安全

Cursor 于页面日期 Nov 13, 2026 发布《An update on our recent security incident》，结构化数据中的 `datePublished` 为 2026-11-13T12:00:00.000Z。文中写明，攻击者取得 Cursor 发给 Fireworks 的访问密钥，该密钥由 Fireworks 暴露；攻击者用它复制了 Cursor 与 Fireworks 共享的只读存储桶。桶内是主要用于 2025 年、未开启 Privacy Mode、并被允许用于模型训练的有限编码智能体痕迹，其中少量痕迹的凭据没有脱敏，不到 0.01% 的客户因此暴露了 API 凭据。攻击者从这些凭据进入 Cursor 使用的部分 SaaS 工具，接触到部分已归档的非生产源代码库、有限的客户支持数据和邮件、产品用量与联系信息、部分编码会话摘要，以及用户发给支持团队的一些凭据。10 月 29 日，攻击者用从这些内部数据中取得的凭据，把 Anthropic Claude Code 扩展的未授权副本放到 Cursor VS Code 扩展市场的缓存上；Anthropic 没有发布这个副本，Open VSX 也没有这批恶意文件。最多 5,000 名在当天请求特定缓存版本的用户可能收到该构建，窗口约 11 小时，涉及 `Anthropic.claude-code` 2.1.312 与 2.1.313。Cursor 写明最后一次看到的攻击者活动在 11 月 1 日且已被阻止，并已把全部推理流量移出 Fireworks。属厂商对已确认事件的后续说明。

🔗 来源：[Cursor 事件更新](https://cursor.com/blog/security-incident-update) · [The Hacker News](https://thehackernews.com/2026/11/stolen-fireworks-ai-key-led-to-cursor.html)

**[2] 联邦局汇总渗透框架**
📌 类型：AI赋能安全

美国联邦调查局于 2026 年 11 月 13 日发布 FLASH-20261113-001，标记为 TLP:CLEAR，题为《Threat Overview of ARTEX Autonomous Penetration Testing Framework》。摘要写明，至少自 2026 年 8 月起，多个恶意行为体使用开源的大模型驱动智能体平台 ARTEX，对全球多个行业的机构开展活动，行业范围包括金融服务、政府、科技、国防、半导体、能源、医疗、制造、电信和法律。摘要同时写明，部分入侵从开始瞄准到取得高权限不到三小时。文中点名的活动包括针对韩国金融机构、导致约 67,000 人个人信息外传的攻击，以及影响 ConnectWise Cloud Backup 客户、使攻击者能够访问 2,250 个以上下游租户的供应链入侵。脚注把这些叙述指向 10 月 7 日至 11 月 5 日已经发表的厂商报告，因此这份 FLASH 是官方汇总，不是 11 月 13 日新发现的一次入侵。原文仓库已于 2026 年 10 月撤下；摘要写明框架仍通过社区分叉、本地化变体、归档副本和商业版 ARTEX PRO 流传。截至 2026 年 11 月上旬，研究者识别出超过 1,600 个公开暴露的控制台。BleepingComputer 于 11 月 15 日转述了这份通报。

🔗 来源：[FBI FLASH-20261113-001](https://www.ic3.gov/CSA/2026/261113.pdf) · [BleepingComputer](https://www.bleepingcomputer.com/news/security/fbi-warns-artex-ai-hacking-tool-is-powering-global-cyberattacks/)

**[3] 只读提示仍能改站**
📌 类型：AI基础设施CVE

NVD 于 2026-11-15T15:16:46Z 收录 CVE-2026-125771，CNA 为 Patchstack。插件《MCP Server for WordPress》2.0.4 的更新说明日期是 11 Nov 2026，WordPress.org 记录的最后更新时间是 2026-11-11 03:20 GMT，早于本期 72 小时窗口。说明写明，已连接为 “Read only” 的 AI 应用仍可通过提示改动站点；2.0.4 起，只读连接无论 AI 应用以何种方式提出要求都只能读取。同一版本还写明，暂停 AI 访问时，提示词和资源此前不会一起暂停，现在会暂停。Patchstack 页面把公开条目的发布日期写成 13 Nov 2026，受影响版本为 2.0.3 及更早，修复版本为 2.0.4，CVSS 3.1 为 7.2，向量为 `AV:N/AC:L/PR:H/UI:N/S:U/C:H/I:H/A:H`。该页侧栏另有 “Required privilege Unauthenticated” 字样，与这条向量和插件更新说明不一致，本简报不采用侧栏那一句。页面没有写已经发现在野利用；“预期将被大规模利用”属于该站高优先级条目的通用表述，不是对本编号的利用确认。

🔗 来源：[插件更新说明](https://wordpress.org/plugins/ai-workflow-automation-ai-agent-hub/) · [Patchstack](https://patchstack.com/database/wordpress/plugin/ai-workflow-automation-ai-agent-hub/vulnerability/wordpress-mcp-server-for-wordpress-plugin-2-0-3-privilege-escalation-vulnerability) · [NVD CVE-2026-125771](https://nvd.nist.gov/vuln/detail/CVE-2026-125771)

**[4] 钉住版本依赖仍变**
📌 类型：AI自身安全

Help Net Security 于 2026-11-13T05:30:22Z 报道 Corelight 技术合作总监 James Lagermann 在本公司实验室中的观察，属厂商来源。一台把某个社区 MCP 服务器固定到一个发行标签、PyPI 版本或 Git 提交的工作站，配置没有改动，五周内却跑过 15 套不同的依赖；69 个包中有 23 个换过版本，其中包括密码学库、JSON Web Token 库和 MCP SDK。启动器用的是 `uvx`：它按包声明的依赖安装，跳过项目里用哈希钉住的锁文件，环境重建时大约 60 个下层包会从 Python Package Index 重新解析。该服务器一周内启动 162 次，缓存里仍有同一发行与提交的 19 个构建。Corelight 还查看了两个厂商目录和实验室中的 35 个 MCP 服务器，其中 23 个的推荐安装方式会在每次启动、安装或构建镜像时从公共注册表拉取依赖。报道没有把它写成某一个 CVE，也没有给出在野入侵案例。

🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/11/13/corelight-mcp-server-supply-chain/)

### 二、深度速览

#### 【AI 赋能防御】

Corelight 在同一篇报道里给出了冻结后的对照，数字来自该厂商实验室。五个服务器被钉到提交、从带哈希的锁文件安装一次、直接启动，并关闭更新检查。随后两周内这五个服务器启动 457 次，每次装上的包清单都与安装当天记录的清单一致。冻结同时带来旧依赖：其中一个社区服务器在冻结时，有 40 个包旧于启动器当天会拉到的版本，其中一部分与安全相关。受访者对重新上锁的建议是按 MCP 维护者自己的更新节奏；他维护的服务器每晚做漏洞复查，发现漏洞再更新。这是实验室测量，不是部署面统计。

🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/11/13/corelight-mcp-server-supply-chain/)

#### 【AI 系统风险】

Cursor 这次更新把 10 月 29 日的市场缓存投毒接到训练数据通道上。只读桶里的对象不是当前推理请求，而是未开启 Privacy Mode 的历史编码痕迹；未脱敏的 API 凭据不到客户数的 0.01%，未开启 Privacy Mode 的用户中，痕迹暴露面不到 0.05%。页面把隐私模式用户的提示词和代码、眼下正在发送的数据、运行 Cursor 的生产系统和基础设施、Cursor 应用及其官方更新与发布签名密钥、客户代码仓库、市场上的其他扩展和从 Cursor Marketplace 下载的插件，以及 Cloud Agents、Grok Bot 等其他产品，列为未受影响。活跃推理请求也写明没有暴露；推理流量已从这家训练与推理供应商移走。10 月 30 日的安全通知仍是 2.1.312 与 2.1.313 的处置入口，更新写明只卸载扩展可能不够。

CVE-2026-125771 的入口在插件自己的提示词通道，而不是匿名访问 WordPress。2.0.3 及更早版本把连接标成只读之后，AI 应用仍能通过提示改站；2.0.4 同时把提示词改成只用于读取，会改站的动作仍以工具形式提供，并且只提供站点实际开放的工具。CVSS 的高权限要求与“任意互联网用户可直接利用”不是同一句话。暂停开关的缺口写在同一条更新说明里：只暂停工具时，提示词和资源仍可继续。插件目录里的 2.0.4 早在 11 月 11 日已经更新，11 月 15 日新增的是编号和评分。

`uvx` 的漂移不需要攻击者改管理员写下的那一行配置。顶层发行被钉住之后，锁文件没有参与解析，公共索引上的下层包仍会在缓存重建时换版本。一周 162 次启动里多数复用缓存，缓存中仍积累了 19 个构建；报道据此提醒，被劫持的发行即使只在线上停留数分钟到数小时，也可能赶上某一次重建。35 个服务器里的 23 个在推荐安装方式上就有这个缺口。Lagermann 对 Help Net Security 说，他交谈过的管理员迄今全部至少使用一个有此问题的 MCP 服务器；这是个人观察，不是抽样调查。

### 三、今日趋势洞察

智能体的限制写在通道名称上，数据离开这条通道之后限制不再跟着走。Cursor 把未开启隐私模式的编码痕迹交给训练厂商，未脱敏密钥从只读桶进入内部工具，再进入扩展市场缓存；WordPress 插件把连接标成只读，改站动作仍从提示词发生。Corelight 观察到顶层版本钉住之后，启动器仍按公开索引重解下层依赖。FBI 的 FLASH 则把能自行把目标拆成步骤的框架写成已经在多个行业被使用，并把部分入侵从瞄准到高权限写成三小时以内；脚注显示这些战役叙述来自 10 月和 11 月上旬的厂商报告。

### 四、企业行动清单

- 核对 Cursor 账户是否收到 11 月 13 日更新所说的单独通知。未收到通知的，按该更新的说法，数据不在被复制的痕迹中。收到痕迹或凭据通知的，轮换通知里点名的 API 凭据，并按邮件中的第三方服务撤销结果复核。开启 Privacy Mode 的提示词和代码，更新写明不在受影响范围内。
- 检查 2026 年 10 月 29 日是否从 Cursor VS Code 扩展市场安装或更新到 `Anthropic.claude-code` 2.1.312 或 2.1.313。若是，按 Cursor 10 月 30 日安全通知处置；该更新写明只卸载扩展可能不够。通知地址为 [claude-code-extension-security-notice](https://cursor.com/blog/claude-code-extension-security-notice)。
- 盘点编码智能体痕迹是否会交给训练或推理供应商。Cursor 写明受影响痕迹来自未开启 Privacy Mode、并被允许用于训练的会话。不允许痕迹离开本组织的部署，应打开对应的隐私开关，并在分享前去掉痕迹中的凭据。
- 盘点《MCP Server for WordPress》的版本。2.0.3 及更早版本按更新说明和 CVE-2026-125771 的受影响范围处理，升级到 2.0.4 或更高。升级后确认只读连接不能再通过提示改站，暂停 AI 访问时提示词和资源一并暂停。CVSS 向量要求高权限，不要按 Patchstack 侧栏的 “Unauthenticated” 字样扩大成匿名可利用。
- 检查用 `uvx` 或其他启动器拉起的 MCP 服务器。顶层发行标签、版本号或提交被钉住时，确认安装是否使用带哈希的锁文件，并直接启动这一份已安装环境。Corelight 的冻结对照在两周、457 次启动中包清单没有变化；冻结时同时核对下层包是否旧于维护者当前建议的版本。
- 按 FBI FLASH-20261113-001 的建议，清点暴露在公网的外围应用，范围包括伙伴门户、员工应用、遗留服务和第三方集成。曾在 Microsoft 365 中安装或授权过受影响 ConnectWise 应用的租户，按应用 ID 而不是显示名称检索；在 ConnectWise 给出正式恢复说明之前保持这些连接停用，第一步不要删除企业应用。通报脚注中的战役细节来自 10 月 7 日至 11 月 5 日的厂商报告。
