### 一、今日要点

**[1] Langflow多漏洞含MCP执行**
📌 类型：AI自身安全

IBM 于 10 月 28 日首发、10 月 29 日更新的 Security Bulletin 披露 Langflow OSS 1.0.0–1.12.8 受多项问题影响，并给出修复版本 1.13.0。公告摘要将风险归纳为：自动登录类认证控制不完整、经第三方库的智能体代码执行、在未达预期授权条件下可触达的运维注入 API 密钥暴露，以及可通过模型上下文协议（MCP）工具枚举路径利用的未认证远程代码执行；NVD 同日收录的 CVE-2026-93680（认证绕过，CVSS 9.8）、CVE-2026-110186（代码生成控制不当导致任意代码执行，9.8）与 CVE-2026-110193（低权限账户诱导 Agentic Assistant 生成/提交未拦截模式组件代码并在服务器执行命令，8.8）与之对应。属厂商正式安全通报与 CVE 编目，公开材料未声称大规模在野利用。

🔗 来源：[IBM Security Bulletin（node/7294467）](https://www.ibm.com/support/pages/node/7294467) · [NVD CVE-2026-110193](https://nvd.nist.gov/vuln/detail/CVE-2026-110193)

**[2] n8n废弃节点逃出任务隔离**
📌 类型：AI基础设施CVE

n8n 于 10 月 28 日发布 GHSA-9p7v-45m2-wxgj（High）：已弃用的 Function、Function Item 节点在 vm2 中运行用户代码，LangChain Code 节点则直接在 n8n 主进程执行；拥有工作流创建/修改权限的认证用户可借这些隐藏节点类型，在任务运行器隔离之外于主进程执行任意 JavaScript。修复版本为 2.42.6、2.43.3、2.44.0 与 3.0.1：上述节点默认弃用并拦截新增/修改保存，既有工作流仍可继续运行，需人工改用 Code 节点；`N8N_DEPRECATED_NODES_BLOCK=false` 会恢复脆弱行为。NVD 于 10 月 30 日编目为 CVE-2026-119408（CVSS 8.8）。同日公告簇还包含 MCP OAuth 动态客户端注册开放重定向（GHSA-rc3w-8jc8-7x3w，修 1.123.89 / 2.45.5 / 2.46.1 / 3.0.1），与昨日 WordPress AI Engine MCP OAuth 问题形成同类身份面对照。

🔗 来源：[GitHub Advisory GHSA-9p7v-45m2-wxgj](https://github.com/n8n-io/n8n/security/advisories/GHSA-9p7v-45m2-wxgj) · [NVD CVE-2026-119408](https://nvd.nist.gov/vuln/detail/CVE-2026-119408) · [GHSA-rc3w-8jc8-7x3w（MCP OAuth）](https://github.com/n8n-io/n8n/security/advisories/GHSA-rc3w-8jc8-7x3w)

**[3] Kubeflow未授权制品SSRF簇**
📌 类型：AI基础设施CVE

继昨日收录的前端制品跨租户读取（CVE-2026-118760）之后，Kubeflow Pipelines 在 10 月 28–29 日继续公开同批次公告：默认独立部署下前端 `GET /artifacts/get?source=http` 可将全数字 `bucket` 经 WHATWG URL 解析为 IPv4（含链路本地/回环），在鉴权关闭时构成未认证 SSRF（GHSA-v3vh-xv5f-p4p4 / CVE-2026-88980，CVSS 8.6）；S3/MinIO 提供方元数据同样可把共享 UI Pod 定向到任意端点（GHSA-3pcj-8j5w-jmxq / CVE-2026-88981）。更严重的是，多用户模式下空命名空间流水线上传跳过 SubjectAccessReview，低权限租户可写入集群共享流水线并替换其他租户将执行的镜像与命令（GHSA-rjr3-43j3-4q8g / CVE-2026-77596，Critical 9.6）。统一修复线为 2.18.0（受影响至 2.17.3）。此为对既有 Kubeflow 条目的影响面扩展，而非重复单点复述。

🔗 来源：[GHSA-v3vh-xv5f-p4p4](https://github.com/kubeflow/pipelines/security/advisories/GHSA-v3vh-xv5f-p4p4) · [GHSA-rjr3-43j3-4q8g](https://github.com/kubeflow/pipelines/security/advisories/GHSA-rjr3-43j3-4q8g) · [GHSA-3pcj-8j5w-jmxq](https://github.com/kubeflow/pipelines/security/advisories/GHSA-3pcj-8j5w-jmxq)

**[4] LMDeploy权重接口Pickle执行**
📌 类型：AI基础设施CVE

VulnCheck 与 NVD 于 10 月 30 日公开 CVE-2026-119706（Critical，NVD CVSS 3.x 基础分 9.8）：InternLM LMDeploy 0.9.0 至 0.18.0 的 `/update_weights` 端点对请求中的 `serialized_named_tensors` 做 base64 解码后，经 `ForkingPickler.loads` 反序列化且缺少有效校验，未认证攻击者可向 api_server 进程投递恶意 pickle 并执行操作系统命令。GitHub 议题 #4698 自 2026-06 起公开，相关修复 PR 仍处开放状态，截至公告覆盖范围正式发行版 0.18.0 仍被标为受影响。属对已知设计缺陷的新 CVE 编目与严重性标定，不宜表述为当日新发现的在野攻击。

🔗 来源：[NVD CVE-2026-119706](https://nvd.nist.gov/vuln/detail/CVE-2026-119706) · [VulnCheck 公告](https://www.vulncheck.com/advisories/lmdeploy-0.9.0-through-0.18.0-unauthenticated-rce-via-update-weights-pickle-deserialization) · [GitHub 议题 #4698](https://github.com/InternLM/lmdeploy/issues/4698)

**[5] Flowise自定义函数沙箱逃逸**
📌 类型：AI基础设施CVE

VulnCheck 作为 CNA、NVD 于 10 月 30 日公开 CVE-2026-119978（High，CVSS 4.0 向量由 VulnCheck 给出）：Flowise 至 3.1.4，在 `ALLOW_BUILTIN_DEP=true` 时，认证用户可向 `/api/v1/node-custom-function` 提交 JavaScript，滥用白名单中的 langchain 与 mammoth 模块，经 `LocalFileStore` 向 mammoth 包路径写文件再 `require`，从而逃逸 vm2，以 Flowise 进程用户执行操作系统命令。公开 CVE 材料未给出已合并的正式修复版本号，且引用链中存在指向既有其他沙箱逃逸 GHSA 的交叉链接，需以 NVD/VulnCheck 正文机制为准。属确认的“白名单依赖 + 可写包路径”组合缺陷与新编目，未声称大规模在野利用。

🔗 来源：[NVD CVE-2026-119978](https://nvd.nist.gov/vuln/detail/CVE-2026-119978) · [VulnCheck 公告](https://www.vulncheck.com/advisories/flowise-through-3.1.4-custom-function-sandbox-escape-rce-via-localfilestore)

**[6] Replit发布Agent栖息地架构**
📌 类型：AI赋能安全

Replit 于 10 月 28 日在 Frontier 站点发布《Agent Habitat Architecture》白皮书（厂商来源），将“Agent Habitat”定义为企业为智能体划定的受控运行环境，覆盖身份、执行、权限、数据流、出站连接、审批与恢复。文档提出可信/半可信/不可信分区与凭证 Broker 作为对外唯一通路，列出可测试的 12 条核心原则（默认拒绝、权限单向收缩、凭证对模型不可见等），并以 11 个赛道、0–3 级成熟度量表要求凭证据自评；明确安全逻辑须在模型域外强制执行。该材料为参考架构与评估框架发布，不是漏洞通报或在野事件。

🔗 来源：[Replit Agent Habitat Architecture](https://frontier.replit.com/agent-habitat-architecture)

### 二、深度速览

#### 【AI 赋能防御】

Replit Habitat 把“模型是否配合”从信任前提中拿掉：权限只减不增、密钥仅由 Broker 注入、出站必经策略与可带外切断的遏制链路，并用成熟度量表把口号换成可审计证据。这与运营侧把 Agent 当作集群排障助手时的需求形成对照——Aikido 于 10 月 30 日整理的播客访谈（厂商媒体来源）强调，只读 RBAC 并不能阻止被投毒日志诱导的 Agent 读取 Secret；需要同时约束其可读面与把非指令数据当作不可信输入。两者共同指向：检测与治理资产要从提示词过滤，扩展到工作负载身份、出站代理与密钥不可见性。

🔗 来源：[Replit Agent Habitat Architecture](https://frontier.replit.com/agent-habitat-architecture) · [Aikido：Kubernetes 中的 AI Agent 安全（2026-10-30）](https://www.aikido.dev/blog/ai-agent-security-in-kubernetes-prompt-injection)

#### 【AI 系统风险】

本期高危面集中在三类机制。一是 **自动化/编排平台把“代码节点”留在主进程**：n8n 弃用节点与 Langflow Agentic Assistant/MCP 工具链说明，工作流保存权或低权限会话一旦可触达代码生成面，隔离边界会在编排层而非模型权重层被击穿。二是 **ML 流水线前端默认独立部署等于未认证内网探针**：Kubeflow 制品 HTTP/S3 路径把 bucket/endpoint 交给调用方，叠加空命名空间上传跳过授权，使共享流水线成为跨租户供应链写入点。三是 **推理与低代码运行时仍把反序列化/白名单模块当作捷径**：LMDeploy 对请求 pickle 直接 `loads`，Flowise 在开启内置依赖时允许向包目录写后再加载，提示注入或认证后 RCE 可落到宿主机命令执行。缓解方向应优先：升级至已给出补丁线的版本、关闭或网络隔离管理/权重更新与自定义函数端点、禁止空命名空间共享写、将 MCP OAuth 注册面移出默认暴露。

🔗 来源：[IBM Bulletin](https://www.ibm.com/support/pages/node/7294467) · [n8n GHSA-9p7v-45m2-wxgj](https://github.com/n8n-io/n8n/security/advisories/GHSA-9p7v-45m2-wxgj) · [Kubeflow GHSA-v3vh-xv5f-p4p4](https://github.com/kubeflow/pipelines/security/advisories/GHSA-v3vh-xv5f-p4p4) · [NVD CVE-2026-119706](https://nvd.nist.gov/vuln/detail/CVE-2026-119706)

### 三、今日趋势洞察

Agent 与 ML 平台的高危披露正从“单点提示注入演示”转向“默认开启的管理/制品/代码执行面”：Langflow 与 n8n 显示编排层代码节点和 MCP 注册一旦默认暴露，认证强度决定主机沦陷成本；Kubeflow 同批次 SSRF 与空命名空间上传则说明流水线控制面在独立部署假设下仍按内网可信设计。叠加推理服务对 pickle 热更新的依赖，供应链与运行时风险继续在工具与反序列化边界而非模型参数边界率先失效。

### 四、企业行动清单

- 将自建 Langflow OSS 升级至 1.13.0，核查是否启用自动登录、Agentic Assistant 与对外 MCP 工具枚举，并轮换可能暴露的 API 密钥。
- 清点 n8n 实例版本与工作流中的 Function / Function Item / LangChain Code 节点，升级至修复线并确认未设置 `N8N_DEPRECATED_NODES_BLOCK=false`；限制 `/mcp-oauth/register` 未认证可达性。
- 对 Kubeflow Pipelines 多用户或独立 UI 部署，将 `kfp-frontend` 与 `kfp-api-server` 升至 2.18.0，关闭默认空命名空间共享上传，抽测制品 HTTP/S3 端点不可指向 IMDS/内网。
- 盘点对公网或半信任网络暴露的 LMDeploy `api_server`，在官方合并修复并发版前禁用或鉴权隔离 `/update_weights`，禁止接受请求侧 pickle。
- 审查 Flowise 是否开启 `ALLOW_BUILTIN_DEP` 与自定义函数端点，限制可调用白名单模块的写路径，并将运行用户降权、文件系统只读化。
