### 一、今日要点（5～8 条）

**[1] Mozilla 用 AI 挖洞**
📌 类型：AI 赋能安全

Mozilla 在数月内运行以 Claude Mythos Preview 为核心的智能体化测试流水线，对 Firefox 源码做规模化安全挖掘，并在 Firefox 150 等版本中修复 **271** 个安全问题，涉及 HTML、XSLT、IPC 与 DNS 相关解析等多类缺陷，部分为需与其他利用链配合的沙箱逃逸类问题。工程团队强调以可验证触发条件（如 AddressSanitizer）收敛误报，并在隔离虚拟机中完成改码与验证，计划进一步把能力前移到 CI 做补丁级扫描。该实践把大模型能力沉淀为可复用安全工程基础设施，而非一次性人工审计。

🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/05/07/mozilla-firefox-claude-ai-security-bug-hunting/)

![Mozilla 与 Claude 相关配图](https://img.helpnetsecurity.com/wp-content/uploads/2026/05/07073721/claude-firefox-1500.webp)

**[2] AIMap 测绘 AI 暴露面**
📌 类型：AI 赋能安全

Bishop Fox 研究员发布的开源平台 AIMap 面向互联网侧 **Ollama、MCP、vLLM、LiteLLM、Open WebUI** 等常见 AI 推理与编排面，做发现、指纹、0～10 风险评分，并在授权前提下运行协议相关的提示注入、工具滥用与模型提取等测试套件。文章引用产品演示数据称存在大量缺少鉴权或配置不当的暴露实例，并强调主动测试模块需操作者自担合规责任。该工具把「AI 攻击面管理」从概念推进到可脚本化、可度量的红队与评估工作流。

🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/05/06/aimap-ai-attack-surface-discovery/)

**[3] 微软披露代理框架 RCE**
📌 类型：AI 基础设施 CVE

微软 Defender 安全研究团队发文披露 **Semantic Kernel** 中两条已修复的高危路径：**CVE-2026-26030** 与默认内存向量检索过滤逻辑中 **eval()** 相关的不安全拼接有关，在满足「存在提示注入面 + 使用默认 In‑Memory Vector Store 搜索插件」时可从提示词一路到主机级远程代码执行；**CVE-2026-25592** 则与 **SessionsPythonPlugin** 文件下载路径在 .NET SDK 中被误标为可由模型调用的工具函数有关，可演化为沙箱逃逸与任意写等后果。官方给出升级 **Python semantic-kernel ≥ 1.39.4**、**.NET SDK ≥ 1.71.0** 等版本门槛，并配套高级狩猎查询与 CTF 练习仓库，便于蓝队复盘与开发者自测。

🔗 来源：[Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2026/05/07/prompts-become-shells-rce-vulnerabilities-ai-agent-frameworks/)

![Microsoft Security Blog 配图：Agentic AI](https://www.microsoft.com/en-us/security/blog/wp-content/uploads/2026/03/MS_Actional-Insights_AI-agents.jpg)

**[4] LiteLLM 网关 SQL 注入遭利用**
📌 类型：AI 基础设施 CVE

The Hacker News 援引 LiteLLM 维护者与社区分析指出 **CVE-2026-42208** 影响代理在 API Key 校验相关数据库查询路径上的参数化缺失，未认证攻击者可通过特制 `Authorization` 头触发 **SQL 注入**，进而读取或改写代理数据库中的敏感数据；报道还引用第三方观点，强调单行 `litellm_credentials` 往往聚合多家云厂商与模型供应商凭据，成功利用后的爆炸半径接近云账户级失陷。维护者建议尽快升级至修复版本，并在无法立即补丁时按公告临时关闭相关错误日志路径以降低可达性。

🔗 来源：[The Hacker News](https://thehackernews.com/2026/04/litellm-cve-2026-42208-sql-injection.html)

**[5] LeRobot 反序列化致未认证 RCE**
📌 类型：AI 基础设施 CVE

GitHub Advisory Database 条目描述 **CVE-2026-25874**：Hugging Face **LeRobot** 在异步推理链路中对经 gRPC 传入的数据使用 **pickle.loads()** 反序列化，且通道缺少强认证与 TLS，导致网络可达攻击者可在 **SendPolicyInstructions / SendObservations / GetActions** 等调用上投递恶意序列化负载，从而在服务端或客户端执行任意代码。该缺陷对贴近 GPU、内网与物理控制回路的机器人学习部署尤为敏感，修复应结合版本升级、网络隔离与最小权限运行。

🔗 来源：[GitHub Advisory Database](https://github.com/advisories/GHSA-f7vj-73pm-m822)

**[6] 补丁周期折射 AI 安全重心**
📌 类型：AI 赋能安全

Help Net Security 在 **2026 年 5 月**补丁周期前瞻中写到，安全产业正在明显感受到 **AI 对漏洞管理、优先级排序与响应流程** 的牵引，并点名 **Anthropic Mythos** 等面向代码与漏洞研究的新型能力可能改变补丁与攻防节奏；文章同时穿插对传统平台漏洞与 OOB 修复的盘点。该观察有助于 CISO 在预算与组织设计上把「模型辅助安全工程」与经典漏洞运营并表治理。

🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/05/08/may-2026-patch-tuesday-forecast/)

### 二、深度速览

#### 【AI 升级安全】AI 赋能防御与检测

Mozilla 将大模型驱动的安全挖掘工程化：以清晰可判定成功条件（例如是否触发 ASan）驱动智能体反复迭代，先在沙箱逃逸等子问题上验证可行性，再并行分发到短命虚拟机对具体源文件做目标化分析，产出经去重与分级后进入常规漏洞生命周期。文章披露已修复漏洞数量与若干代表性缺陷年代，说明即便在 Firefox 这类长期高强度审计的代码库中，AI 仍可能系统性地压缩「从未被注意的攻击面」与人工审计之间的落差。文末引用 Mozilla Hacks 进一步解释架构层防御（如冻结原型链）如何在多次对抗尝试中阻断利用路径。

🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/05/07/mozilla-firefox-claude-ai-security-bug-hunting/) · 延伸：[Mozilla Hacks](https://hacks.mozilla.org/2026/05/behind-the-scenes-hardening-firefox/)

AIMap 把「发现—指纹—评分—在授权下测试—可视化」串成一体：发现阶段利用面向 AI 栈特征的 Shodan 查询模板；指纹阶段结合 Nuclei 与实时 HTTP 探测识别协议、鉴权状态、工具暴露与系统提示泄露；测试阶段按 MCP、Ollama、OpenAI 兼容接口等协议加载不同攻击套件并输出严重度与修复建议。研究者向媒体解释如何用 `/v1/models` 等响应区分「可达但已鉴权」与「真正敞开」的部署，并承认部分「半鉴权」误配置仍待后续版本增强检测。对红队与紫队而言，这类工具把 AI 暴露面从模糊担忧变成可排序、可复测的技术债清单。

🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/05/06/aimap-ai-attack-surface-discovery/) · 项目仓库：[BishopFox/aimap（GitHub）](https://github.com/BishopFox/aimap)

#### 【AI 安全风险与治理】AI 自身威胁与监管动态

微软长文把「提示注入」从内容安全议题推进到「主机执行原语」层面：一旦模型输出可影响工具参数，框架层任何把不可信文本拼接进 **eval**、文件系统或跨隔离边界传输的实现，都可能把单次成功的社会工程式提示放大为 **RCE / 任意写 / 凭据外带**。文章用 Semantic Kernel 两个 CVE 完整展示从工具调用 schema 到 AST 绕过与错误暴露函数标注的攻击链，并明确结论——**LLM 不是安全边界，工具暴露面才是**；同时预告后续将覆盖更多第三方智能体框架中的结构相似问题。对治理团队，这意味着要把 AI 应用纳入与传统应用等同甚至更高的变更与威胁建模节奏。

🔗 来源：[Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2026/05/07/prompts-become-shells-rce-vulnerabilities-ai-agent-frameworks/)

OpenAI 于 **2026-02-13**（厂商来源）宣布为 ChatGPT 推出可选的 **Lockdown Mode** 与 **Elevated Risk** 标签，通过确定性关闭或限制实时联网浏览、部分代理式能力、自动下载等高风险通路，降低提示注入驱动的敏感数据外带概率；官方亦坦言该模式无法从数学上消除所有提示注入进入上下文的途径，例如经由缓存内容间接进入的风险仍需组合治理。该发布对高价值账号（企业、教育、医疗等计划）具有直接配置意义，也为「如何把生成式 AI 产品放进零信任架构」提供了可对照的厂商基线。

🔗 来源：[OpenAI（厂商来源）](https://openai.com/index/introducing-lockdown-mode-and-elevated-risk-labels-in-chatgpt/)

在国际监管语境下，**欧盟《人工智能法》**将「对抗测试 / 红队」作为高风险与系统性通用模型治理工具箱的一部分，要求提供者在全生命周期开展可记录的模型评估与风险缓释；IAPP 的分析文章梳理了美欧在生成式 AI 监管中如何把红队实践从行业自律推向合规要件的总体趋势。需要强调的是，这类材料偏制度与合规背景解读，并不等价于单日漏洞情报，但可帮助安全与法务统一语言。

🔗 来源：[IAPP](https://iapp.org/news/a/emerging-trends-in-regulating-generative-ai-how-red-teaming-is-shaping-the-landscape)

### 三、今日趋势洞察（1～3 句）

当 **LiteLLM、LeRobot、Semantic Kernel** 等「模型之上的编排与具身智能栈」相继出现可被利用的高危缺陷时，企业攻击面正快速从「聊天窗口」迁移到 **网关数据库里的聚合密钥、机器人策略服务与智能体工具参数通道**；与此同时，**Mozilla + AIMap** 一类实践表明，大模型也能反向压缩复杂软件与互联网暴露推理面的发现成本，攻防两侧都在同一轮架构浪潮中被重新定价。

💡 关键洞察（3～5 行）

- **智能体工具链**正成为比「模型本体」更危险的失陷面：任何把模型输出映射到 eval、文件与跨隔离传输的设计，都需要按不可信输入处理（微软长文、GitHub 公告）。
- **AI 网关与凭据聚合层**一旦存在注入或反序列化缺陷，其危害等级接近云平台账户级事件（THN 对 LiteLLM 的报道与 GitHub 安全公告）。
- **红队 / 评估工具**（AIMap）与 **模型辅助挖掘**（Mozilla）并行成熟，说明企业需要同时投资「发现自家 AI 暴露面」与「用 AI 压缩传统软件漏洞积压」。

---

⚠️ 核心风险（3 条）

1) **工具参数即攻击面** — 为智能体函数实施严格 schema 校验、路径规范化与最小权限执行身份；默认禁用高危 sink（eval、任意路径读写）。  
2) **网关数据库即密钥库** — 对 LiteLLM 等代理做版本核查、网络分段与数据库加密/访问审计；避免在单行记录中堆叠多厂商高权限凭据。  
3) **机器人推理服务默认暴露** — 为 gRPC/反序列化链路强制 TLS 与双向认证，禁用对不可信字节流的 pickle；结合网络层默认拒绝。

---

📌 建议行动（3～5 条）

- 立即核对 **semantic-kernel** Python / .NET SDK 是否低于公告阈值版本并安排升级与重启窗口。  
- 对 **LiteLLM** 部署执行版本比对（参考 GitHub GHSA‑r75f‑5x8p‑qvmc）与数据库凭据轮换。  
- 清点互联网暴露的 **Ollama / MCP / vLLM** 等端点，优先处理「无鉴权 + 工具/代码执行」组合（AIMap 方法论）。  
- 在高风险人群启用 **ChatGPT Lockdown Mode** 等确定性限制能力，并记录仍为残余风险的间接注入路径（OpenAI 厂商说明）。  
- 将 **LeRobot PolicyServer** 等组件纳入漏洞管理与网络微隔离范围，禁止未打补丁实例对公网监听。
