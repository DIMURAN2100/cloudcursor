资讯覆盖优先过去 24～48 小时（约 8 月 17 日—19 日东八区）；CodeWhale、MLflow、MemOS 等直接影响 AI 编码智能体/记忆与实验平台的高价值漏洞以 NVD/项目公告日为准，部分条目补充至约 72 小时内。

### 一、今日要点

**[1] CodeWhale审批绕过致RCE**
📌 类型：AI自身安全

开源编码智能体框架 CodeWhale（`codewhale` / `codewhale-tui`）在 0.8.41 至 0.8.64 之前被连续披露多条高危缺陷：`rlm_eval` 工具将审批需求设为 Auto，使模型下发的任意 Python 在本地解释器执行且不咨询用户 `--approval-policy`（CVE-2026-75858）；`exec_shell_interact` 可向已批准的交互式 shell（如 `python3 -i`、`ssh`）写入 LLM 控制的 stdin（CVE-2026-75857）；`git_show` 对模型提供的 `rev` 缺少参数分隔，可通过 `--output=` 类注入实现写文件，工具却被标为只读并自动批准（CVE-2026-75913，CVSS 3.1 约 9.3）。属已确认的产品安全公告与补丁范围，非在野利用通报。请升级至 ≥0.8.64，并复核所有 Auto 批准的代码执行类工具。

🔗 来源：[NVD CVE-2026-75858](https://nvd.nist.gov/vuln/detail/CVE-2026-75858) · [VulnCheck 公告](https://www.vulncheck.com/advisories/codewhale-rlm-eval-before-remote-code-execution) · [修复提交](https://github.com/Hmbown/CodeWhale/commit/57f3c89471e27ac4032d9791f6885e5d4408c381)

**[2] MemOS内部密钥未设即旁路**
📌 类型：AI自身安全

面向 LLM/智能体的记忆操作系统 MemOS（≤2.0.30）在启用认证（`AUTH_ENABLED=true`）但未配置无默认值的 `INTERNAL_SERVICE_SECRET` 时，`is_internal_request()` 对“请求头缺失”与“环境变量为 None”比较为真，fail-open 将外部请求当作受信任内部主体并授予 `scopes: ["all"]`（CVE-2026-75110，CVSS 3.1 9.8 / CVSS 4.0 9.3，NVD 约 8 月 17 日收录）。未认证攻击者可触达管理端点铸造/枚举/吊销任意用户 API 密钥乃至主密钥，并访问数据接口。属已确认漏洞机制；公开跟踪见项目 Issue，部署方应立即设置强随机内部密钥、限制管理面暴露，并关注厂商后续正式修复版本。

🔗 来源：[NVD CVE-2026-75110](https://nvd.nist.gov/vuln/detail/CVE-2026-75110) · [VulnCheck 公告](https://www.vulncheck.com/advisories/memos-authentication-bypass-via-unset-internal-service-secret) · [GitHub Issue #2259](https://github.com/MemTensor/MemOS/issues/2259)

**[3] MLflow Webhook未授权SSRF**
📌 类型：AI基础设施CVE

MLflow（面向智能体、大模型与机器学习工程的平台）在 3.15.0 之前，默认 Tracking Server 在未启用认证时暴露模型注册 Webhook 接口；`POST /api/2.0/mlflow/webhooks/{id}/test` 仅对原始 URL 做 `_validate_webhook_url()`，投递阶段却跟随重定向并重新解析主机，导致校验被绕过，可探测内网或云元数据等目标并回传上游响应（CVE-2026-64849，CVSS 3.1 9.3，GitHub/NVD 约 8 月 17 日）。同日还披露经授权用户的数据集血缘注入（CVE-2026-69146）与跨用户工件读取（CVE-2026-69148）。已在 v3.15.0 修复；生产环境应升级并强制认证、禁用对不可信调用方开放的 webhook 测试端点。

🔗 来源：[GitHub Advisory GHSA-7gwp-5pfp-969j](https://github.com/mlflow/mlflow/security/advisories/GHSA-7gwp-5pfp-969j) · [NVD CVE-2026-64849](https://nvd.nist.gov/vuln/detail/CVE-2026-64849) · [v3.15.0 发布说明](https://github.com/mlflow/mlflow/releases/tag/v3.15.0)

**[6] Trigger.dev元数据原型污染**
📌 类型：AI基础设施CVE

托管 AI 智能体与工作流平台 Trigger.dev 在 3.3.8 至 4.5.5，`PUT /api/v1/runs/:runId/metadata` 将攻击者可控的 `operation.key` 直接传入 `JSONHeroPath` 而无原型污染防护，持有普通环境 API 密钥的调用者即可污染共享 webapp 进程的 `Object.prototype`，造成跨租户查询失败、其他租户 worker 鉴权异常与进程级拒绝服务（CVE-2026-73654，CVSS 3.1 8.5，约 8 月 13 日公告）。官方已在 4.5.6 修复；自建与 SaaS 使用方应确认版本并轮换可能暴露的环境密钥。

🔗 来源：[GitHub Advisory GHSA-p28v-f755-9qrg](https://github.com/triggerdotdev/trigger.dev/security/advisories/GHSA-p28v-f755-9qrg) · [NVD CVE-2026-73654](https://nvd.nist.gov/vuln/detail/CVE-2026-73654) · [v4.5.6 发布说明](https://github.com/triggerdotdev/trigger.dev/releases/tag/v4.5.6)

**[7] Apify MCP路径权威注入**
📌 类型：AI基础设施CVE

Apify MCP Server（供智能体调用 Apify Store 爬虫与自动化 Actor）在 0.10.11 之前，`getActorMCPServerURL` 将受信任的 Actor standby URL 与 Actor 定义中攻击者可控的 `webServerMcpPath` 直接拼接且未校验最终 origin，恶意发布者可利用 userinfo 等形式权威混淆，使后续请求偏离预期主机并可能导致 Apify 令牌泄露（CVE-2026-50143，CVSS 3.1 8.1；NVD 约 8 月 18 日收录，GitHub 公告更早）。已修复版本为 0.10.11；使用第三方 Actor 作为 MCP 后端时应升级客户端并限制可安装 Actor 来源。

🔗 来源：[GitHub Advisory GHSA-6gr2-qh89-hxwm](https://github.com/apify/apify-mcp-server/security/advisories/GHSA-6gr2-qh89-hxwm) · [NVD CVE-2026-50143](https://nvd.nist.gov/vuln/detail/CVE-2026-50143) · [v0.10.11 发布说明](https://github.com/apify/apify-mcp-server/releases/tag/v0.10.11)

### 二、深度速览

#### 【AI 赋能防御】

Fortinet 将 Virtue AI 的智能体红队（含提示注入与 MCP 攻击仿真）、MCP/源码扫描、运行时工具调用阻断与持续验证证据链并入既有 Security Fabric，标志着传统网络安全平台加速把“保护 AI 系统本身”做成与网络/端点并列的产品层。并购本身不改变现网风险，但反映出企业对 agentic 运行时可见性与对抗验证的采购需求上升；集成效果与防护覆盖仍需以后续产品发布与独立测试为准（厂商来源）。

🔗 来源：[Fortinet 新闻稿](https://investor.fortinet.com/news-releases/news-release-details/fortinet-advances-continuous-ai-protection-acquisition-virtue-ai) · [MSSP Alert](https://www.msspalert.com/brief/fortinet-acquires-virtue-ai-to-expand-security-for-ai-agents)

iThome 8 月 18 日对 Google Security Operations 的产品综述称，Gemini 驱动的告警分诊与调查代理已在超过 1,200 家客户侧处理逾 900 万条告警，典型人工约 30 分钟的调查可压缩至约 1 分钟，并与远程 MCP、威胁猎捕代理及 AI Threat Defense 等能力组合。上述客户数与时长对比来自厂商对外口径，属效果宣传数据，可作 SOC 自动化成熟度参考而非跨厂商基准。

🔗 来源：[iThome 产品综述](https://www.ithome.com.tw/review/178171)

#### 【AI 系统风险】

CodeWhale 系列缺陷的共性是“工具元数据声称只读/低风险 + Auto 审批”，使提示注入或不可信仓库内容一旦进入模型上下文，即可在开发者主机上执行代码、向持久 shell 注入命令或借 `git show` 写任意路径。缓解不能只靠升级：应默认拒绝 Auto 执行类工具、对仓库来源做信任分级，并把审批策略配置纳入变更审计。

🔗 来源：[NVD CVE-2026-75858](https://nvd.nist.gov/vuln/detail/CVE-2026-75858) · [NVD CVE-2026-75913](https://nvd.nist.gov/vuln/detail/CVE-2026-75913)

MemOS 的 None==None fail-open 与 MLflow webhook “校验一次、跟随重定向”表明 AI 平台中间件仍大量复制传统 Web 漏洞模式，但影响面变为记忆库、实验血缘与跨租户工作流。Trigger.dev 原型污染进一步说明：低权限环境密钥一旦可写共享进程状态，即可把单租户写操作升级为平台级可用性与鉴权事件。防御重点是默认安全配置、认证强制开启，以及对元数据/路径类 API 做原型与重定向钉扎校验。

🔗 来源：[CVE-2026-75110](https://nvd.nist.gov/vuln/detail/CVE-2026-75110) · [GHSA-7gwp-5pfp-969j](https://github.com/mlflow/mlflow/security/advisories/GHSA-7gwp-5pfp-969j) · [GHSA-p28v-f755-9qrg](https://github.com/triggerdotdev/trigger.dev/security/advisories/GHSA-p28v-f755-9qrg)

#### 【全球治理与标准】

OWASP Agentic Skills Top 10 v1.0 将 Skill 明确为独立攻击面（恶意 Skill、供应链、过度授权、不可信外部指令、弱隔离、更新漂移、缺乏治理等），并提供与既有 AI/应用安全框架的交叉映射与示例控制，填补“代理可自装工具包”缺少共用语言的空白。企业可将 AST 清单嵌入 Skill/插件准入、签名与沙箱策略；本日未见新的国家级 AI 法规正式文本，故治理类以该标准发布为主。

🔗 来源：[OWASP Agentic Skills Top 10](https://owasp.org/www-project-agentic-skills-top-10/) · [白皮书 PDF](https://owasp.org/www-project-agentic-skills-top-10/assets/publications/ast10-top10-whitepaper-2.pdf)

### 三、今日趋势洞察

编码/运维智能体的“自动批准工具”与 AI 平台中间件的认证、URL 校验缺陷在同一窗口集中暴露，说明风险正从模型输出质量转向**工具元数据与服务端默认配置**。与此同时，厂商并购与 OWASP Skills Top 10 并行出现，显示防御侧正把 MCP/Skill 运行时治理从最佳实践提升为可采购能力与可审计标准语言。

### 四、企业行动清单

1. 清点开发机与 CI 中的 CodeWhale 及同类编码智能体版本，升级至已修复版本，关闭 Auto 批准的代码执行/交互 shell/看似只读的 git 工具。
2. 检查 MemOS 等记忆服务是否启用认证却未设置 `INTERNAL_SERVICE_SECRET`，立即配置强随机内部密钥并限制管理 API 网络可达性。
3. 将 MLflow Tracking Server 升级至 ≥3.15.0，启用认证，审计 webhook 测试接口与模型注册暴露面，禁止未鉴权实例对公网开放。
4. 确认 Trigger.dev 与 Apify MCP Server 分别不低于 4.5.6 与 0.10.11，轮换环境 API 密钥，并对第三方 Actor/Skill 来源实施允许列表。
5. 以 OWASP Agentic Skills Top 10 为检查表，建立组织内 Skill/MCP 清单、签名校验与安装审批流程，禁止智能体从不可信市场自动加载新 Skill。
