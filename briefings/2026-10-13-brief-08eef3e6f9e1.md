### 一、今日要点

**[1] Obsidian库跨租户越权**
📌 类型：AI自身安全

NVD 于 10 月 12 日收录 CVE-2026-77366（CVSS 9.9，Critical）：面向 Obsidian 库的 MCP 服务 `obsidian-tc` 在 1.3.1 之前，工具分发未将调用方受控的 `input.vault` 与调用者绑定库比对，JWT 亦无 vault 声明，文件夹 ACL 为全局共享。持有任意有效令牌的调用者可通过指定其他已配置库名，读写删其内容，破坏多租户隔离。同日还收录同版本修复的 CVE-2026-77363（CVSS 8.8）：Streamable HTTP 在 `auth.mode: none` 环回默认下缺少 Host/Origin 与 DNS 重绑定防护，恶意网页可驱动本机 MCP 端点获得完整库权限。官方已在 v1.3.1 修复；属已确认授权与传输面缺陷，未见在野利用通报。

🔗 来源：[GitHub Advisory GHSA-84c9-qqpq-2pq5](https://github.com/The-40-Thieves/obsidian-tc/security/advisories/GHSA-84c9-qqpq-2pq5) · [NVD CVE-2026-77366](https://nvd.nist.gov/vuln/detail/CVE-2026-77366) · [GitHub Advisory GHSA-pqh8-4pj7-32xx](https://github.com/The-40-Thieves/obsidian-tc/security/advisories/GHSA-pqh8-4pj7-32xx)

**[2] Nginx UI的MCP可绕过配置校验**
📌 类型：AI基础设施CVE

NVD 于 10 月 12 日收录 CVE-2026-84317 / CVE-2026-84318（CVSS 8.8，High）：Nginx UI 自 2.0.0-rc.6 至 2.4.1 之前，REST 写配置路径会调用 `ValidateConfigFile` 拦截危险指令，但 MCP 工具 `nginx_config_add` 直接落盘并触发 nginx reload。已认证 MCP 调用方（或经提示注入诱导的智能体）可写入被阻断列表中的 `perl`、`js_import`、`load_module`、`user root` 等指令；在官方镜像等加载了 njs/Perl 模块的环境可形成认证后远程代码执行。已在 v2.4.1 修复。属已确认“MCP 路径漏检”缺陷与研究演示级利用链，公开材料未确认大规模在野利用。

🔗 来源：[GitHub Advisory GHSA-9jww-cxg5-rj9m](https://github.com/0xJacky/nginx-ui/security/advisories/GHSA-9jww-cxg5-rj9m) · [NVD CVE-2026-84318](https://nvd.nist.gov/vuln/detail/CVE-2026-84318) · [NVD CVE-2026-84317](https://nvd.nist.gov/vuln/detail/CVE-2026-84317)

**[3] Unla网关OAuth可自签令牌**
📌 类型：AI基础设施CVE

NVD / VulnCheck 于 10 月 11 日收录 CVE-2026-108865（CVSS 4.0 为 8.8 High，3.1 为 8.2）：自托管 MCP 网关 AmoyLab Unla 至 0.10.0 的 OAuth2 实现从不认证资源所有者。未认证攻击者可注册客户端、请求 `/authorize` 获取 code 并在 `/token` 兑换有效访问令牌，进而访问受 OAuth2 保护的 MCP 前缀、被代理的上游 API 以及注入凭据。公开发行标签截至核查时仍为 v0.10.0，advisory 未给出修复版本；研究者说明属源码审阅确认的授权缺失，披露时主分支仍受影响。未见在野利用确认。

🔗 来源：[VulnCheck Advisory](https://www.vulncheck.com/advisories/amoylab-unla-through-0.10.0-oauth2-authentication-bypass-via-authorize) · [NVD CVE-2026-108865](https://nvd.nist.gov/vuln/detail/CVE-2026-108865)

**[4] EdgeEver经MCP植入存储XSS**
📌 类型：AI自身安全

NVD / VulnCheck 于 10 月 12 日收录 CVE-2026-109557 与 CVE-2026-109558（CVSS 约 8.7 High）：笔记/模板产品 EdgeEver 至 1.112.0 在拖拽预览与模板预览路径存在存储型 XSS。攻击者可通过 MCP 工具（如 `create_notebook` / `create_memo`）或 MCP 令牌写入恶意笔记本名、备忘标题或模板 Markdown；受害者交互预览时脚本可在渲染器执行，触及桌面桥 `window.edgeeverDesktop` 的会话令牌。项目于 10 月 12 日合入加固提交，但公开发布标签截至核查时仍指向受影响的 v1.112.0。属已确认跨站脚本缺陷，利用需用户交互，未见在野通报。

🔗 来源：[VulnCheck Advisory（拖拽预览）](https://www.vulncheck.com/advisories/edgeever-through-1.112.0-stored-xss-via-setmemodragpreview-drag-preview) · [NVD CVE-2026-109557](https://nvd.nist.gov/vuln/detail/CVE-2026-109557) · [NVD CVE-2026-109558](https://nvd.nist.gov/vuln/detail/CVE-2026-109558)

**[5] mac-shell白名单可被元字符绕过**
📌 类型：AI基础设施CVE

NVD / VulnCheck 于 10 月 12 日收录 CVE-2026-108953（CVSS 3.1 为 7.8 High，4.0 为 8.5）：`mac-shell-mcp` 在 2.0.0 之前，`execute_command` 参数处理允许 MCP 客户端（或恶意提示诱导的调用）向看似安全的命令注入 shell 元字符，从而绕过命令白名单，以服务用户身份执行未批准命令。仓库已有面向 2.0.0 的加固提交（主分支版本显示为 2.0.1），但 npm 登记的 `latest` 截至核查时仍为 1.0.4。属已确认命令注入，公开材料将其描述为可被恶意提示触发的研究路径，未见在野利用确认。

🔗 来源：[VulnCheck Advisory](https://www.vulncheck.com/advisories/mac-shell-mcp-before-2.0.0-os-command-injection-via-execute-command-arguments) · [NVD CVE-2026-108953](https://nvd.nist.gov/vuln/detail/CVE-2026-108953) · [修复提交](https://github.com/cfdude/mac-shell-mcp/commit/932ce733cde07bb30b1f186303e6692dbb5d087a)

**[6] 编码代理拒绝规则可被旁路**
📌 类型：AI自身安全

NVD 于 10 月 12 日收录 CVE-2026-109331（CVSS 3.1 为 7.4 High）：npm 包 Network-AI 在 5.14.0 至 5.15.2 之前，`ClaudeHookBridge` PreToolUse 钩子仅用候选字段列表中“第一个出现的字段”匹配 `denyPatterns`。提示注入控制的智能体可把危险载荷放在 `Write.content` 或 MCP 的 `script` 等非首位字段，同时保留无害的 `file_path`/`command`，从而绕过运营者配置的硬拒绝规则并写入 webshell 或执行脚本。NVD 记修复起点为 5.15.2；npm 当前 latest 为 5.15.4。属已确认安全控制旁路与研究验证路径，非声称在野攻击。

🔗 来源：[GitHub Advisory GHSA-9p2w-prp8-5722](https://github.com/Jovancoding/Network-AI/security/advisories/GHSA-9p2w-prp8-5722) · [NVD CVE-2026-109331](https://nvd.nist.gov/vuln/detail/CVE-2026-109331)

### 二、深度速览

#### 【AI 赋能防御】

本期窗口内未见带独立效果数据、可核验方法学的 AI 赋能 SOC / 威胁狩猎产品或研究发布，故不强行收录厂商扩容或营销稿。与防御工程直接相关的信号来自“控制面一致性”失效：Nginx UI 已在 REST 写路径落实指令黑名单，却在 MCP 添加工具上漏检，说明把同一安全控制接到智能体工具面，本身就是可审计的防御交付项。运营侧可将“MCP 工具路径是否复用与人机 API 相同的校验、鉴权与审计”纳入变更门禁，而不是仅依赖模型侧拒答。

🔗 来源：[GitHub Advisory GHSA-9jww-cxg5-rj9m](https://github.com/0xJacky/nginx-ui/security/advisories/GHSA-9jww-cxg5-rj9m)

#### 【AI 系统风险】

本期高危簇集中在 MCP 身份、租户绑定与“看起来像策略、实际只扫半截输入”的钩子。`obsidian-tc` 跨库越权表明多 vault / 多租户 MCP 若令牌无绑定资源范围，任意合法会话即可横向进入其他知识库；环回 HTTP 缺 Origin 校验则把浏览器驱动变成零点击库接管。Unla 把 OAuth2 做成无资源所有者认证的自签发码器，等于 MCP 网关前置鉴权整段失效。Network-AI 的 denyPatterns 只匹配首个候选字段，则把“运营者硬门禁”降级为可被提示注入构造的字段选择游戏。缓解共性：令牌声明绑定租户/库；HTTP MCP 强制 Host/Origin 与 DNS 重绑定防护；OAuth 必须完成资源所有者认证与同意；策略引擎对完整工具入参做匹配；MCP 写操作与人机 API 共用同一校验函数。

🔗 来源：[NVD CVE-2026-77366](https://nvd.nist.gov/vuln/detail/CVE-2026-77366) · [NVD CVE-2026-108865](https://nvd.nist.gov/vuln/detail/CVE-2026-108865) · [NVD CVE-2026-109331](https://nvd.nist.gov/vuln/detail/CVE-2026-109331)

### 三、今日趋势洞察

MCP 正在把“第二套写入口”变成系统默认攻击面：人机 API 已做的校验、租户绑定和拒绝策略，一旦未同步到工具调用路径，就会在智能体或提示注入场景下被整段绕过。与此同时，自托管 MCP 网关若 OAuth 只“发码不认人”，会把代理链上游凭据暴露给任意网络调用方，说明 Agent 供应链的认证强度必须按网关而非按聊天 UI 来验收。

### 四、企业行动清单

- 盘点 `obsidian-tc` 及同类多库 MCP 服务版本，低于 1.3.1 的立即升级，并禁止在生产使用 `auth.mode: none` 的 HTTP 环回暴露。
- 核查 Nginx UI 是否启用 MCP；低于 2.4.1 的实例优先升级或暂时关闭 `nginx_config_add`，并审计近期经 MCP 写入的 nginx 配置与 reload 记录。
- 对 AmoyLab Unla 等自托管 MCP 网关做暴露面扫描，确认 OAuth `/authorize` 是否可在无登录条件下换取令牌；未修复前隔离公网入口并轮换已代理上游凭据。
- 清点 IDE / 编码代理中的 deny/allow 钩子实现，验证是否对完整工具入参（含 `content`、`script` 等字段）匹配，受影响 Network-AI 升级至 ≥5.15.2。
- 检查桌面笔记/Agent 产品是否允许 MCP 写入渲染为 HTML 的标题或模板；对 EdgeEver ≤1.112.0 暂停不可信 MCP 令牌，待正式修复版本发布后再恢复。
