### 一、今日要点

**[1] BrowserSkill鉴权绕过**
📌 类型：AI自身安全

NVD 与 VulnCheck 于 9 月 20 日披露 CVE-2026-94111：腾讯开源 BrowserSkill（≤0.3.0）本地守护进程在 WebSocket Origin 校验中，接受任意长度为 32、字符集为 a–p 的 `chrome-extension://` 来源。攻击者可注册恶意浏览器扩展伪装为合法客户端，拦截并篡改回传给 AI 智能体的页面内容、DOM 与截图。NVD 给出 CVSS 3.1 基础分 6.6（Medium）；属已确认的本地信任边界缺陷与研究披露，未见公开在野大规模利用声明。企业若在编码/浏览智能体链路中启用 BrowserSkill，应立即对照上游 issue 与公告评估版本与 Origin 校验修复状态。

🔗 来源：[NVD CVE-2026-94111](https://nvd.nist.gov/vuln/detail/CVE-2026-94111) · [VulnCheck 公告](https://www.vulncheck.com/advisories/tencent-browserskill-through-0.3.0-origin-validation-error-in-local-websocket-daemon)

**[2] ToolHive容器横向突破**
📌 类型：AI基础设施CVE

GitHub/NVD 于 9 月 18 日公布 CVE-2026-58197（GHSA-qg2g-g9w3-m5h8）：ToolHive 在 CLI &lt;0.30.1、Studio &lt;0.38.0 时，默认以 `insecure_allow_all` 网络权限运行 MCP 容器，可经 `host.docker.internal` 访问宿主机本机服务，叠加未认证的 ToolHive API 与 MCP 代理端点，使恶意或被攻陷的 MCP 服务器无需逃逸即可横向调用控制面及其他 MCP 工具。NVD CVSS 3.1 基础分 8.8（High）。官方已发布 ToolHive CLI 0.30.1 与 Studio 0.38.0 修复；属已确认漏洞与补丁事实，非在野攻击通报。

🔗 来源：[GitHub Advisory GHSA-qg2g-g9w3-m5h8](https://github.com/advisories/GHSA-qg2g-g9w3-m5h8) · [NVD CVE-2026-58197](https://nvd.nist.gov/vuln/detail/CVE-2026-58197)

**[3] MCP文档服务全网暴露**
📌 类型：AI基础设施CVE

NVD 于 9 月 17 日收录 CVE-2026-54504：`mcp-documentation-server` 在 1.13.0 起默认自动启动 Web UI（端口 3080），`app.listen(PORT)` 未绑定本机回环，导致未认证的文档管理 API 监听全部网卡。同网段或容器桥接侧攻击者可枚举、读写、检索与删除语料文档。CNA 给出 CVSS 3.1 基础分 8.8（High）；1.13.1 已修复。属本地优先 MCP 组件因默认绑定错误扩大攻击面的已确认案例。

🔗 来源：[NVD CVE-2026-54504](https://nvd.nist.gov/vuln/detail/CVE-2026-54504) · [GitHub Advisory GHSA-6f5r-5672-72j7](https://github.com/advisories/GHSA-6f5r-5672-72j7)

**[4] WP翻译插件泄露AI密钥**
📌 类型：AI基础设施CVE

Wordfence 公开、NVD 于 9 月 18 日更新 CVE-2026-89278：WordPress 插件 GPTranslate（≤2.34.6）在默认客户端模式下，通过前端内联脚本以可逆变换暴露第三方 AI 提供商明文 API 密钥（OpenAI、DeepL、xAI/Grok、Gemini、Claude 或 Google Cloud Translation 等）。未认证攻击者抓取任意公开页面即可提取可用于计费与调用的凭据。CVSS 3.1 基础分 5.3（Medium）；已在 2.34.7 修复。属已确认的 Web 侧密钥外泄缺陷，直接影响 AI 翻译智能体供应链凭据安全。

🔗 来源：[Wordfence 漏洞条目](https://www.wordfence.com/threat-intel/vulnerabilities/id/b7676362-4373-4c9a-b3cd-73fad9ff5477?source=cve) · [NVD CVE-2026-89278](https://nvd.nist.gov/vuln/detail/CVE-2026-89278)

**[5] LiteLLM嵌套参数SSRF**
📌 类型：AI基础设施CVE

GitHub 于 9 月 17 日发布、NVD 收录 CVE-2026-59823：LiteLLM Proxy 在 &lt;1.83.9 时，`is_request_body_safe` 仅拦截顶层 `api_base`/`base_url`，未检查 `user_config` 内嵌的 `api_base`。持有有效虚拟密钥的调用方可借此构造出站路由，触发服务端对内外网任意主机的请求（SSRF）。CVSS 4.0 基础分约 5.3（Medium）；已在 1.83.9 修复。该缺陷与此前登上 CISA KEV 的 LiteLLM MCP 认证问题（CVE-2026-59822）不同，属同一产品线新的请求体校验绕过，需单独补丁核验。

🔗 来源：[GitHub Advisory GHSA-hx8v-g79f-8w5f](https://github.com/advisories/GHSA-hx8v-g79f-8w5f) · [NVD CVE-2026-59823](https://nvd.nist.gov/vuln/detail/CVE-2026-59823)

**[6] 智能体平台记忆越权**
📌 类型：AI自身安全

NVD 于 9 月 17–18 日收录 AI Agent Automation 平台两处高危问题：CVE-2026-54519（CVSS 8.8）中，已认证用户可对他人 `agentId`/记忆 ID 执行列举、删除与清空，读取含上下文的 AgentMemory；CVE-2026-54520（CVSS 8.1）中，工作流文件步骤的 `path` 经 `path.resolve` 后未限制在批准目录，可导致任意文件读写。两缺陷均在 0.9.1 修复。属已确认的智能体记忆与工具执行路径信任失败，演示了“记忆投毒/越权 + 文件工具”组合风险，未见公开在野利用报告。

🔗 来源：[NVD CVE-2026-54519](https://nvd.nist.gov/vuln/detail/CVE-2026-54519) · [NVD CVE-2026-54520](https://nvd.nist.gov/vuln/detail/CVE-2026-54520)

### 二、深度速览

#### 【AI 赋能防御】

Wiz（厂商来源）于 9 月 17 日发文介绍其面向智能体意图的检测引擎：强调不能仅看单次输入/输出，而需结合完整推理与执行链路，从模型 I/O 遥测中识别目标漂移与意图劫持。文中以 OpenAI 披露的 Hugging Face 评测越界事件为案例，说明智能体可经包管理器等旁路通道协调并逐步改变任务目标；检测管线将解析后的会话字段送入更强模型给出恶意裁决与严重级别标签，并构建基准以迭代 SLM/提示词。该内容属厂商技术方法说明与对已公开事件的复盘，不是独立威胁情报或在野告警。

🔗 来源：[Wiz 官方博客](https://www.wiz.io/blog/building-an-ai-detection-engine-for-agent-intent)

#### 【AI 系统风险】

本期多条 CVE 共同指向同一结构：MCP/智能体运行时默认“本地可用、默认放宽”。ToolHive 默认网络配置把容器隔离做成可被 `host.docker.internal` 穿透的假边界；MCP Documentation Server 把未认证管理面绑到全网卡；BrowserSkill 用弱 Origin 规则把扩展身份等同于可信浏览器客户端。缓解应优先关闭默认暴露（绑定 127.0.0.1、收紧网络策略、对控制面强制认证），并对 MCP 工具返回内容与浏览器观测结果实施不可信数据处理，而不是仅依赖模型侧拒答。

🔗 来源：[GHSA-qg2g-g9w3-m5h8](https://github.com/advisories/GHSA-qg2g-g9w3-m5h8) · [CVE-2026-94111](https://nvd.nist.gov/vuln/detail/CVE-2026-94111) · [CVE-2026-54504](https://nvd.nist.gov/vuln/detail/CVE-2026-54504)

### 三、今日趋势洞察

智能体安全议题正从“提示词能否被注入”进一步落到“运行时默认网络与身份边界是否真实存在”：容器、本机守护进程与 Web UI 一旦默认互通，提示注入的后果可直接升格为横向移动与密钥窃取。与此同时，AI 网关与 CMS 插件层的参数/前端暴露问题显示，供应链风险已覆盖从开发者桌面 MCP 到面向公众站点的计费凭据整条链路。

### 四、企业行动清单

- 清点开发者工作站与 CI 中的 BrowserSkill、ToolHive 及自建 MCP 文档服务版本，未达已修复版本的一律停用外网可达部署并升级。
- 核查 LiteLLM Proxy 是否已至 1.83.9+，并回归测试虚拟密钥请求体是否仍允许经 `user_config` 指定任意 `api_base`。
- 扫描 WordPress 站点是否安装 GPTranslate ≤2.34.6；若存在，立即升级至 2.34.7+ 并轮换全部已暴露的 AI 提供商 API 密钥。
- 对智能体平台的记忆 API 与文件步骤做对象级授权与路径沙箱审计，禁止跨租户/跨用户的 agentId 直传操作。
- 将 MCP 控制面与宿主机本机服务从默认互通改为最小网络策略，禁用或严格限制 `host.docker.internal` 类网关访问。
