# 全球网络安全简报（AI 专题）— 2026-10-20（GMT+8）

本期主要覆盖东八区过去约 24～72 小时（约 10 月 17 日—19 日）可核验的公开披露；其中 Google Agent Mesh（原 SAM）两项 Critical 授权缺陷、CrewAI 工具 SSRF、Apache Answer MCP 越权、LangBot Webhook 伪造、SGLang 分离部署面、BentoML 镜像投毒路径与 Omnigent 子智能体路径穿越等，集中在 10 月 18—19 日经 NVD / GitHub Advisory / Apache 邮件列表公开，因直接影响 MCP 网格、智能体工具链与推理基础设施，放宽至约 72 小时一并纳入。时效均已对照 NVD、GitHub Advisory / 发行说明、Apache 公告与 VulnCheck 核对；不重复前几日已写且无新补丁进展的 OneUptime、DeepSeek Harness、dcg、Wheels、Archon、DoubleScale、DOE Genesis、商务部第 48 号、ZCode、Claude Code、LMCache、LangChat、NullHub、Portkey、Roo Code、EN 18286 等条目。

### 一、今日要点

**[1] Agent Mesh可自助入网控工具**
📌 类型：AI自身安全

NVD / GitHub Advisory 于 10 月 19 日公开 CVE-2026-103091（CVSS 4.0 约 9.3 Critical）：Google OSS Agent Mesh（原 Sovereign Agent Mesh / SAM，仓库现为 `google/agentmesh`）0.1.0-alpha.1 至 0.1.0-alpha.8 中，MCP 代理透传与 OIDC 注册流存在缺省过宽策略——`GET /info` 公开 OIDC 配置，`POST /register` 对任意有效 OIDC 令牌持有者自动入网且缺少 claim / 封禁校验，默认策略还将 `sam:system:authenticated` 绑定到通配服务与目标，使攻击者可获得对后端 MCP/工具的读写与执行能力。官方要求升级至 0.1.0-alpha.9+，改为失败关闭默认策略、显式策略绑定与封禁检查。属已确认授权缺陷；未见在野利用通报。

🔗 来源：[GitHub Advisory GHSA-cgmg-9xf6-rrgw](https://github.com/google/sam/security/advisories/GHSA-cgmg-9xf6-rrgw) · [v0.1.0-alpha.9 发布说明](https://github.com/google/sam/releases/tag/v0.1.0-alpha.9) · [NVD CVE-2026-103091](https://nvd.nist.gov/vuln/detail/CVE-2026-103091)

**[2] Agent Mesh旁路入口可直调后端**
📌 类型：AI自身安全

同日披露 CVE-2026-102503（CVSS 4.0 约 9.3 Critical）：Agent Mesh 0.1.0-alpha.1—0.1.0-alpha.2 的 `/libp2p-http` 入口在 MCP 流处理已启用 Biscuit 能力校验的同时，平行 HTTP 入口未验证令牌或网格入网状态，未认证的远程 libp2p 对等方可直达已注册后端，包括命令/stdio 型 MCP、A2A 与推理端点。官方修复起点为 0.1.0-alpha.3；若仍停留在早期 alpha，应至少升至含该修复的版本，并优先升到含默认策略收紧的 alpha.9+。属已确认认证/授权旁路；未见在野利用通报。

🔗 来源：[GitHub Advisory GHSA-r6hp-67wp-c7jx](https://github.com/google/sam/security/advisories/GHSA-r6hp-67wp-c7jx) · [v0.1.0-alpha.3 发布](https://github.com/google/sam/releases/tag/v0.1.0-alpha.3) · [NVD CVE-2026-102503](https://nvd.nist.gov/vuln/detail/CVE-2026-102503)

**[3] CrewAI抓取工具可被注入打内网**
📌 类型：AI自身安全

NVD / VulnCheck 于 10 月 19 日收录 CVE-2026-112308（CVSS 3.1 约 7.4 / CVSS 4.0 约 8.3 High）：`crewai-tools` 至 1.15.28 的 `SeleniumScrapingTool` 未调用已有的 `validate_url` 私网地址校验，攻击者可通过提示注入影响智能体工具输入，驱动无头 Chrome 访问回环、RFC1918 或云元数据地址，窃取内网数据与云凭据。社区 PR #6870 提出与同包其他抓取工具对齐的修复，但因贡献流程要求关闭且尚未并入正式发行；公开材料仍将受影响范围记为 through 1.15.28。属已确认 SSRF 缺陷叠加提示注入利用路径，未见在野利用通报。

🔗 来源：[VulnCheck 公告](https://www.vulncheck.com/advisories/crewai-tools-through-1.15.28-ssrf-via-seleniumscrapingtool) · [NVD CVE-2026-112308](https://nvd.nist.gov/vuln/detail/CVE-2026-112308) · [修复 PR #6870](https://github.com/crewAIInc/crewAI/pull/6870)

**[4] Apache Answer MCP可读非公开答复**
📌 类型：AI基础设施CVE

Apache 软件基金会于 10 月 16 日经开发列表通报、NVD 于 10 月 19 日收录 CVE-2026-71563：Apache Answer 至 2.0.2 的 MCP 答复检索工具仅凭全局 API 密钥即可取回隐藏、已删除或待审问题关联的答复内容，属缺失授权。同批还披露 API 密钥完整写入日志（CVE-2026-64943）等多项问题。官方建议升级至 2.0.3。属已确认平台缺陷；对将 Answer 知识库经 MCP 挂给智能体的部署，会扩大非公开内容暴露面。未见在野利用通报。

🔗 来源：[Apache 开发列表 CVE-2026-71563](https://lists.apache.org/thread/msodd7g2r6xdn9wpkpdp04m9g1jb2xtl) · [NVD CVE-2026-71563](https://nvd.nist.gov/vuln/detail/CVE-2026-71563) · [Answer v2.0.3 发布](https://github.com/apache/answer/releases/tag/v2.0.3)

### 二、深度速览

#### 【AI 赋能防御】

Agent Mesh alpha.9 将默认策略改为失败关闭、要求显式策略绑定并强化封禁校验，是对“多智能体网格一旦入网即可通配调用工具”这一失败模式的工程纠偏。对自建 MCP/A2A 网格的团队，可直接对照：入网是否默认可调用全部后端、OIDC 注册是否做 claim 过滤、以及旁路传输通道是否与主协议共用同一套能力令牌校验。

🔗 来源：[v0.1.0-alpha.9 发布说明](https://github.com/google/sam/releases/tag/v0.1.0-alpha.9) · [GHSA-cgmg-9xf6-rrgw](https://github.com/google/sam/security/advisories/GHSA-cgmg-9xf6-rrgw)

CrewAI 同包中 Firecrawl / Scrapfly 等抓取工具已使用 `validate_url`，而 Selenium 路径漏接同一辅助函数，说明“工具白名单已有、个别工具忘挂校验”仍是智能体工具链的高发缺陷类型。在等待官方发行修复前，可对暴露给模型的 URL 类工具统一强制私网/元数据拒绝列表，并禁止将未校验抓取工具挂到生产 Agent。

🔗 来源：[VulnCheck 公告](https://www.vulncheck.com/advisories/crewai-tools-through-1.15.28-ssrf-via-seleniumscrapingtool) · [PR #6870](https://github.com/crewAIInc/crewAI/pull/6870)

#### 【AI 系统风险】

本期主轴是“网格入网与旁路入口”“提示注入驱动工具 SSRF”“IM Webhook 伪造驱动 Agent”“推理分离面未认证控制通道”。Agent Mesh 证明 MCP 代理的默认信任边界一旦过宽，即可从身份注册走到全后端工具执行；CrewAI 与 SGLang 则把不可信主机/端口参数直接变成内网探测或调度阻塞；LangBot 把聊天事件入口当成可信指令源；BentoML / Omnigent 把构建配置与子智能体工作目录变成供应链与主机逃逸面。共性缓解包括：网格默认失败关闭与旁路通道统一鉴权、工具层强制 URL/路径校验且与提示注入防护联动、Webhook/事件入口强制平台签名、分离部署控制面与数据面隔离并禁止客户端指定引导地址、对 bento/bundle 与子 Agent 配置做来源与路径约束。

🔗 来源：[GHSA-cgmg-9xf6-rrgw](https://github.com/google/sam/security/advisories/GHSA-cgmg-9xf6-rrgw) · [CVE-2026-112308](https://nvd.nist.gov/vuln/detail/CVE-2026-112308) · [CVE-2026-112265](https://nvd.nist.gov/vuln/detail/CVE-2026-112265)

### 三、今日趋势洞察

多智能体基础设施的高危点正从“单个 MCP 服务器缺认证”扩展到“网格入网默认过宽 + 平行入口未鉴权”的组合失败；与此同时，提示注入、IM 事件伪造与客户端可控引导地址，正在把传统 SSRF/路径穿越直接接到 Agent 工具与推理调度链路上，使控制面缺陷与模型输入污染成为同一条利用路径。

### 四、企业行动清单

- 盘点是否部署 Google Agent Mesh / SAM：升至 0.1.0-alpha.9+，关闭公开自助注册，并确认 `/libp2p-http` 等旁路入口与 MCP 流共用能力令牌校验。
- 审查 CrewAI 等 Agent 抓取工具清单：在官方发行修复前移除或禁用 `SeleniumScrapingTool`，对 URL 类工具统一施加私网与云元数据拒绝策略。
- 将 Apache Answer 升至 2.0.3+，轮换可能曾写入日志的 API 密钥，并复核挂给智能体的 MCP 检索范围是否包含隐藏/待审内容。
- 对 LangBot 飞书/Lark Webhook 模式：在含签名校验的正式版本发布前暂停公网暴露或仅允许平台源 IP，跟进含修复提交的发行版。
- 若使用 SGLang prefill/decode 或 Mooncake 分离部署，将引导地址改为服务端配置、隔离 Prefill/Decode 网络，并跟踪上游对 #45008/#45012/#45014 的修复版本。
