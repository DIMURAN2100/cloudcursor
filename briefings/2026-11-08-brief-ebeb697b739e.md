### 一、今日要点

**[1] 编码代理把密钥写入仓库**
📌 类型：AI自身安全

安全厂商 Apiiro 于 11 月 5 日发布测量，The Hacker News 于 11 月 7 日报道：Claude Code 在用户选择“Yes, and don't ask again”后，会把获准执行的命令原文写入项目内 `.claude/settings.local.json`，命令中的口令、令牌和连接串因此以明文留下。厂商统计称，GitHub 上有 104,185 份该文件公开副本，其中 1,122 份至少含一个密钥，合计 1,379 个不同密钥；计入 git 历史、团队故意提交的 `.claude/settings.json` 和代理聊天记录后，为 1,994 个仓库中的 2,539 个密钥，涉及 63 个组织。研究称未逐一验证这些密钥是否仍有效，但有一家被通知的公司确认其密钥当时仍然有效；并称用 Opus 5.5 与 Fable 5.1 复现了这一保存行为。属厂商测量与研究复现，不是在野攻击活动统计。删除当前文件不能消除历史和 fork 中的副本，应先轮换再清理。

🔗 来源：[Apiiro（11/05，厂商研究）](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again) · [The Hacker News（11/07）](https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html)

### 二、深度速览

#### 【AI 赋能防御】

Uber 这篇博客的可核验内容是一套运行时架构，不是漏洞通告。身份系统仍然回答“谁可以做”，该文补充的问题是：拟执行的动作是否与用户请求、智能体的人格和意图、用户角色以及此前会话一致。提示来源追溯和证据链被用来把特权工具调用连回原始请求，用来对付间接提示注入和目标劫持。第三方 MCP 与工具则在接入前做静态和动态分析、成分分析和工具描述检查。厂商同时写明，已知模式可以被护栏缓解，新的操纵手法仍然不稳定，收紧意图和约束比叠加护栏更有效，但会牺牲一部分自主性。这些判断没有独立测试数据。

🔗 来源：[Uber 工程博客（厂商来源）](https://www.uber.com/us/en/blog/securing-ai-agents/)

#### 【AI 系统风险】

Apiiro 描述的机制发生在产品默认的权限记忆，而不是模型权重。开发者批准一条带密钥的命令后，命令字符串进入项目目录里的本地设置文件；Claude Code 会把该文件加入用户电脑上的全局 git 排除，但不会写入仓库自己的 `.gitignore`，因此换机器、补建仓库或已经提交过的副本都不受这条排除保护。厂商称，在追溯到的 1,105 个含密钥仓库中，有 539 个出现过由 Claude 共同署名的、改动该文件的提交。gitleaks 与 TruffleHog 在不做在线验证的扫描中分别标出 564 与 643 份文件，另有 215 份两者都未标出，漏报多来自写在命令里的口令。Junie CLI 的两项公告指向相邻问题：批准逻辑和会话日志也会留下或放大命令与环境变量。公开材料都没有给出在野利用规模。

🔗 来源：[Apiiro（11/05，厂商研究）](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again) · [JetBrains 已修复问题](https://www.jetbrains.com/privacy-security/issues-fixed/)

#### 【全球治理与标准】

11 月 6 日，工业和信息化部办公厅在官网发布《关于加强智能体终端设备进网管理的通知》，发文字号工信厅信管〔2026〕42号，发布机构栏为信息通信管理局。文件规范的对象是预置智能体的电信终端，以及参与适配、进网、现网升级和应用分发的相关单位。正文分工作任务与工作要求：任务涉及智能体与终端适配、进网检测、在线升级和应用分发；要求涉及市场监管、责任落实，以及由该部组织中国信息通信研究院等机构开展的技术研究、适配库、标准研制和可信身份体系。成文日期与发布日期在页面上分开列出，正文落款为 2026 年 10 月 24 日，页面没有另写施行日期。同日政策解读用问答复述文件范围，不增加另一份规章文本。

### 三、今日趋势洞察

编码代理正在把一次性批准变成会进仓库或日志的持久记录：Claude Code 的本地允许列表可以带上命令中的密钥，Junie CLI 则被确认在旧版本的会话事件日志中暴露敏感环境变量。与此同时，监管文本开始直接定义“能执行的智能体终端”，而部署方公开的经验是，特权动作必须能回溯到用户请求和明确意图，提示词护栏本身留有缺口。控制点因此同时落在开发者仓库、编码代理日志和终端分发，而不只在模型回答上。

### 四、企业行动清单

- 在本组织的代码托管平台和开发机上检索 `.claude/settings.local.json`、`.claude/settings.json` 以及已提交的代理会话记录，包括 git 历史和 fork；发现口令、令牌或连接串时先轮换，再删除历史中的副本。
- 把上述路径加入预提交与持续集成的密钥扫描，并确认规则能识别写在命令参数中的口令；将 `.claude/settings.local.json` 写入组织级忽略模板。
- 将仍在使用的 Junie CLI 核对到 26.8.24 或更高版本，并检查更旧版本的会话事件日志是否留下敏感环境变量。
- 由智能体终端、终端生产和应用分发的相关团队核对工信厅信管〔2026〕42号及同日政策解读中的适用主体、成文日期与发布日期。
- 对已经上线、可以调用特权工具的智能体，抽查每次调用能否回溯到用户原始请求和事先限定的意图；不要把提示词护栏当成唯一边界。
