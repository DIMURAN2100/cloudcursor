### 一、今日要点

**[1] UFO 移动MCP命令注入**
📌 类型：AI基础设施CVE

NVD 于 10 月 6 日收录微软开源智能体自动化框架 UFO 的两则 Mobile MCP 缺陷：CVE-2026-105793（CVSS 9.1）指向 `press_key` 将调用方控制的 `key_code` 传入 `adb shell input keyevent`；CVE-2026-105788（CVSS 8.8）显示此前仅校验 `press_key` 后，同文件中的 `type_text`、`launch_app` 仍把 `text`/`package_name` 放入 `adb shell` 参数位。因 Android `adb` 会把 `shell` 后参数拼接交设备侧 shell 再解析，持有效 Mobile MCP API 密钥的调用方可在已授权连接的 Android 设备上以 `shell` 用户执行额外命令。官方修复分别对应 v3.0.9（press_key）与 v3.0.10（type_text/launch_app）；属已确认代码缺陷，公告未报告在野利用。

🔗 来源：[GHSA-5cjx-4375-4877](https://github.com/microsoft/UFO/security/advisories/GHSA-5cjx-4375-4877) · [NVD CVE-2026-105793](https://nvd.nist.gov/vuln/detail/CVE-2026-105793) · [GHSA-6ppj-5886-4f26](https://github.com/microsoft/UFO/security/advisories/GHSA-6ppj-5886-4f26)

**[2] SimpleChat绕过MCP stdio门禁**
📌 类型：AI基础设施CVE

NVD 于 10 月 6 日收录 CVE-2026-105797（CVSS 8.8）：微软 SimpleChat 在 `POST /api/user/plugins` 中先调用 `_reject_non_admin_mcp_stdio`，再补全缺失的顶层 `type`。低权限认证用户可刻意省略 `type=mcp`，使门禁提前跳过，随后由元数据恢复类型，使个人动作进入 `McpPluginFactory` 并以 stdio 传输启动任意进程，进程身份为 Web 应用服务器。受影响版本包括 0.261.003 与 0.261.027；修复于 ≥ v0.261.031。属已确认授权顺序缺陷导致的任意进程生成，未见在野利用报告。

🔗 来源：[GHSA-h4mw-qw8m-5x4j](https://github.com/microsoft/simplechat/security/advisories/GHSA-h4mw-qw8m-5x4j) · [NVD CVE-2026-105797](https://nvd.nist.gov/vuln/detail/CVE-2026-105797)

**[3] MCP TypeScript SDK OAuth劫持**
📌 类型：AI基础设施CVE

NVD 于 10 月 6 日收录官方 MCP TypeScript SDK 的 CVE-2026-104850（CVSS 7.5）：受影响 OAuth 客户端允许所连接的 MCP 服务器决定向哪台授权服务器提交客户端凭据，且已存储/预置凭据未绑定所属 issuer。恶意或被攻陷的 MCP 服务器可在无交互路径下诱使客户端交出 `refresh_token`、`client_secret` 或签名断言。影响 `@modelcontextprotocol/sdk` 1.12.0～1.30.x 与 `@modelcontextprotocol/client` 2.0.0～2.1.x（特定用法）；修复为 sdk ≥1.31.0、client/core ≥2.2.0，捆绑 Provider 还需配置 `expectedIssuer`。stdio 客户端与仅作 MCP 服务器的用法不在影响范围。属协议客户端信任边界缺陷，与此前 Python SDK 同类问题同源。

🔗 来源：[GHSA-6qxp-vccf-f47h](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-6qxp-vccf-f47h) · [NVD CVE-2026-104850](https://nvd.nist.gov/vuln/detail/CVE-2026-104850)

**[4] Payload MCP密钥可跨账户接管**
📌 类型：AI基础设施CVE

NVD 于 10 月 6 日收录 CVE-2026-105806（CVSS 4.0 评分 8.6）：`@payloadcms/plugin-mcp` 在 3.61.0 至 3.88.0 之前，已认证用户可管理超出预期账户范围的 MCP API 密钥，进而通过账户接管实现提权。未启用该插件的 Payload 部署不受影响。官方修复版本为 plugin-mcp ≥3.88.0；临时缓解为禁用 MCP 插件或将密钥管理限制给受信用户。属已确认访问控制缺陷，公告未声称在野利用。

🔗 来源：[GHSA-2q76-m6w6-qgc6](https://github.com/payloadcms/payload/security/advisories/GHSA-2q76-m6w6-qgc6) · [NVD CVE-2026-105806](https://nvd.nist.gov/vuln/detail/CVE-2026-105806)

**[5] Dify MCP配置存在IDOR**
📌 类型：AI基础设施CVE

NVD 于 10 月 5 日收录 CVE-2026-105761（CVSS 7.1）：Dify 在 1.16.0 之前，`PUT /console/api/apps/<app_id>/server` 按客户端提供的 MCP server ID 取对象时，未校验该服务器是否属于目标应用与租户。同工作区已认证成员可改写其他应用的 MCP 服务器状态与参数，存在重定向数据流或禁用服务的风险。官方修复于 Dify 1.16.0。属已确认授权旁路，未见在野利用报告。

🔗 来源：[GHSA-ccrj-frp2-c945](https://github.com/langgenius/dify/security/advisories/GHSA-ccrj-frp2-c945) · [NVD CVE-2026-105761](https://nvd.nist.gov/vuln/detail/CVE-2026-105761)

**[6] 安全分类器可被分片绕过**
📌 类型：AI自身安全

CrowdStrike 于 10 月 6 日发布研究（厂商来源）：对受 Level 3 安全分类器保护的前沿模型，攻击者可将敏感请求改写为“检测工程/游戏外挂”等善意意图，分多轮提取 Windows 进程注入等原语，再交由未受同等分类器保护的较小模型拼装为可编译利用链；将“为某 CVE 编写 Sigma 规则”等防御话术作为掩护时，同样可导出漏洞利用细节。属研究演示与厂商评测，文中未宣称已观察到大规模在野武器化；结论强调单靠输出分类器不足以覆盖跨模型编排。

🔗 来源：[CrowdStrike 研究博客](https://www.crowdstrike.com/en-us/blog/how-attackers-can-bypass-llm-safety-classifiers/)

**[7] OpenAI推textGrain契合AI法**
📌 类型：AI治理合规

OpenAI 于 10 月 5 日公布面向欧盟《人工智能法》第 50 条文本可溯源要求的应对：未来数周为欧盟地区 ChatGPT/Codex 合格文本输出加入不可见浮水印技术 textGrain；全球 API 客户可对部分模型自行选择开启（默认关闭）。官方技术报告说明其在选词阶段嵌入统计信号，并坦言短文本、数学类内容及同义改写会显著降低检出率（例如 400 token 文本替换 10% 词后检出率约自 92% 降至 66%），故检测器初期仅向获批研究者与专业机构开放。属厂商合规措施披露，并非安全事件。

🔗 来源：[OpenAI 官方说明](https://openai.com/index/eu-text-provenance/) · [iThome](https://www.ithome.com.tw/news/179435)

### 二、深度速览

#### 【AI 赋能防御】

CrowdStrike 的分类器绕过实验对 SOC/检测工程有反向启示：把“写检测规则”“做防御分析”当作高信任话术，会在安全运营自身的 LLM 工作流中放大知识外泄面。防御侧应把多模型管线（前沿模型抽取细节 → 小模型合成 PoC）视为可观测对象：对跨会话、跨模型的分片请求做关联审计，并对“检测规则生成”类提示增加敏感 CVE/注入原语的二次审核，而不是假设分类器已阻断。同期 MCP/Agent 编排层连续出现命令注入与凭据类 CVE，也意味着漏洞运营需把“AI 网关、MCP 插件、移动端自动化代理”纳入与传统边缘设备同等优先级的补丁队列。

#### 【AI 系统风险】

本期风险主轴是 MCP 执行与身份边界失效的产品化复现。UFO 展示了“宿主进程参数未进 shell ≠ 远端设备安全”：`adb shell` 的拼接语义把工具参数变成设备侧命令注入面。SimpleChat 则是门禁顺序错误——在类型归一化前做 stdio 限制，等价于可被省略字段绕过。TypeScript SDK 与此前 Python SDK 同类 OAuth 问题说明：客户端若让 MCP 服务器指定授权服务器且不绑定 issuer，HTTP 远程 MCP 即可偷走长期凭据。Payload 的跨账户 MCP 密钥与 Dify 的 MCP 配置 IDOR，则把“插件/应用范围内的密钥与路由”证明为租户隔离必测项。缓解应落到：工具参数白名单与设备侧无 shell 拼接、授权检查在默认值回填之后、OAuth 凭据绑定 issuer、以及 MCP 资源的严格所有权校验。

#### 【全球治理与标准】

除 OpenAI 的 textGrain 落地外，纽约市议会 10 月 5 日就 AI 安全举行听证会，OpenAI、Anthropic、Google、Meta 代表宣誓作证；在审草案包括对在纽约市营销/部署的模型要求独立第三方验证与人类可关闭机制，以及市府合约场景下 AI 安全事故限时通报等（草案仍处立法程序）。挪威政府同日前后提出在公园、校园、医疗等场所对 AI 眼镜类装置施行临时禁令的法案意向，官方担心未经同意的拍摄与录音，并计划成立专家组制定长期规则；禁令尚未生效。本日未见 NIST/ISO/OWASP 发布可独立核验的新强制标准文本。

🔗 来源：[纽约市议会会议详情](https://legistar.council.nyc.gov/MeetingDetail.aspx?GUID=325D66DF-B99B-4C9A-8061-6EC9907142F2&ID=1445976&Search) · [iThome 纽约听证](https://www.ithome.com.tw/news/179440) · [iThome 挪威禁令](https://www.ithome.com.tw/news/179436)

### 三、今日趋势洞察

MCP 正同时在“工具参数→系统命令”“授权门禁顺序”“OAuth 发现信任”和“租户内密钥/配置隔离”四条线上暴露缺陷，说明协议普及后产品实现仍把“已认证调用方”默认为可信执行主体。与治理侧并行的是：欧盟透明度义务推动文本浮水印进入生产默认路径，而城市级立法听证开始把“独立验证 + 人类关闭能力”写进本地监管选项，安全工程与合规工程的时间表正在重叠。

### 四、企业行动清单

- 清点并升级微软 UFO 至 ≥3.0.10，轮换 `UFO_MCP_API_KEY`，限制谁可调用 Mobile MCP，并复核已授权 Android 调试连接
- 将 SimpleChat 升至 ≥0.261.031，审计个人插件/MCP stdio 配置，排查是否曾绕过类型门禁注册动作
- 升级 MCP TypeScript 客户端至 sdk ≥1.31.0 或 client/core ≥2.2.0，为捆绑 OAuth Provider 配置 `expectedIssuer`，并让用户对无 issuer 绑定的旧令牌重新登录
- 对使用 `@payloadcms/plugin-mcp` 的实例升至 ≥3.88.0，轮换 MCP API 密钥；将 Dify 升至 1.16.0 并复核各应用 MCP 服务器归属与回调目标
- 对安全团队使用的多模型/Agent 管线启用跨会话审计，禁止把“写检测规则”类提示直接通向可执行代码生成通道而不经人工复核
