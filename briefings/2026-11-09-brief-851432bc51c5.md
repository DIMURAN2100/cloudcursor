### 一、今日要点

**[1] 编码代理把邮箱写入请求**
📌 类型：AI自身安全

一名使用者于 11 月 6 日 06:13（东八区）在 Claude Code 议题 #107757 报告：代理访问第三方网站时，把登录账户邮箱写进 User-Agent；报告提及的版本为 2.1.318。议题中的项目侧回复称，这不是单独上线的发送功能，而是模型使用上下文里的账户邮箱，去满足部分网站对自动化客户端联系方式的要求，并称 2.1.317 起加入内置隐私模块。该模块说明写明，它只拒绝在 Bash、PowerShell 或 Monitor 调用中同时出现该邮箱和 User-Agent 字样的情况，不检查 WebFetch、WebSearch 与 MCP，也不覆盖脚本、变量和运行时拼接，并写明这是礼节性拦截而不是边界。截至 11 月 8 日议题仍开放，2.1.319 的更新说明没有写把邮箱移出上下文；另有使用者报告 2.1.318 看不到该模块且调用未被拒绝，这属于使用者报告，报告者把垃圾邮件归因于这次外发，线程没有证明这些邮件的来源。

🔗 来源：[GitHub 议题 #107757](https://github.com/anthropics/claude-code/issues/107757) · [隐私模块说明](https://github.com/anthropics/claude-code/blob/main/mods/privacy/README.md)

**[2] 版本修复命令权限绕过**
📌 类型：AI自身安全

Claude Code 于 11 月 7 日 01:04（东八区）发布 2.1.319。更新说明写明修复了三类权限问题：精心构造的环境变量前缀可以让命令的一部分避开权限检查；创建 worktree 时存在沙箱逃逸；在 accept-edits 和 auto mode 下，sed 命令可能跳过权限检查。同版还写明，带引号的命令曾漏过拒绝和询问规则；在遥测或功能开关关闭、包括位于大模型网关之后时，服务端无法检查的调用改为询问或拒绝，不再退回内置分类器。说明没有给出 CVE，也没有称这些缺陷已被在野利用。仍在使用更旧版本的安装应升到 2.1.319 或更高。

🔗 来源：[Claude Code v2.1.319](https://github.com/anthropics/claude-code/releases/tag/v2.1.319)

**[3] 外部红队测自身连接**
📌 类型：AI赋能安全

OpenAI 于 11 月 6 日宣布与 Hacktron 合作，在 OpenAI 自己的系统中寻找漏洞，重点是这些系统与第三方服务如何交互，并把 Hacktron 对前沿模型的访问扩展到 Daybreak Red。公告称 Hacktron 构建用于代码审查、渗透测试和红队的智能体，双方将选择高优先级区域一起测试。这是厂商宣布的合作，不是已披露的漏洞或入侵事件。公开文本没有给出发现的缺陷、影响客户或修复版本。

### 二、深度速览

#### 【AI 赋能防御】

OpenAI 这次合作写明的对象是自己的系统，测试重点是系统与第三方服务的交互，而不是模型回答本身。公告同时写明，将通过 Daybreak Red 扩大 Hacktron 对前沿模型的访问；Hacktron 的工作形态被描述为代码审查、渗透测试和红队智能体。文本把此次合作放在同一周已宣布的内部安全冲刺和提高漏洞赏金之后，但没有提供新的缺陷编号、利用状态或客户影响。因此它只说明厂商开始把外部智能体测试用到自身集成，不能当作已发现入侵的证据。

🔗 来源：[OpenAI（厂商来源）](https://openai.com/index/partnering-with-hacktron/)

#### 【AI 系统风险】

邮箱外发发生在模型编写对外请求的环节。项目侧回复把触发条件描述为：部分网站要求自动化客户端在 User-Agent 中留下联系方式，而账户邮箱已经在交给模型的上下文里。2.1.317 的更新说明写的是，网页或 shell 工具调用把邮箱发往网络之前先询问；已公开的隐私模块说明写的则是直接拒绝、不弹确认，并且只覆盖点名 User-Agent 的 Bash、PowerShell 和 Monitor。WebFetch、WebSearch、MCP、脚本、变量和运行时拼接按该说明可以穿过。截至 11 月 8 日，议题仍开放，2.1.319 没有写移除上下文中的邮箱。

同一版本另把本地执行边界收紧。更新说明承认，环境变量前缀、worktree 创建和特定模式下的 sed 曾绕开权限或沙箱检查，带引号的命令也曾漏过拒绝和询问规则。网关后的自动模式被改为：服务端检查不到的调用询问或拒绝，不再退回内置分类器。这些都是厂商在发布说明里确认并随 2.1.319 修复的缺陷，公开材料没有给出在野利用规模。

### 三、今日趋势洞察

编码代理的身份数据和本地执行权限出现在同一产品的相邻版本里：账户邮箱会随模型编写的请求离开本机，而 2.1.319 仍在修补命令权限检查和 worktree 沙箱。厂商把邮箱拦截写成不覆盖网页工具、MCP 和运行时拼接的礼节性模块，同时模型厂商开始用外部智能体红队测试自己与第三方服务的连接。可检查的边界因此落在上下文里有什么、工具调用检查到哪里，以及系统之间的调用是否被单独测试。

### 四、企业行动清单

- 将仍在使用的 Claude Code 升到 2.1.319 或更高，并在本机更新说明中核对环境变量前缀、worktree 沙箱、sed 权限检查和带引号命令的修复是否已包含。
- 对放在大模型网关之后的自动模式，确认服务端检查不可用时调用会被询问或拒绝；只有在需要保留旧行为时，才设置厂商写明的开关。
- 按隐私模块自己的说明核对缺口：WebFetch、WebSearch、MCP、脚本、变量和运行时拼接不在其拒绝范围内，不要把它当成邮箱不会离开本机的保证。
- 在开发机的 Claude Code 会话记录中检索账户邮箱是否已经出现在对外工具调用里；若已出现，按该邮箱已经暴露来处理后续钓鱼邮件。
- 把本组织模型服务与第三方系统的连接列入自身安全测试，而不是只测试模型回答。
