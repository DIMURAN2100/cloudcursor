# 全球网络安全简报（AI 专题）— 2026-11-15（GMT+8）

本期写入官方页面日期为 2026-11-12 与 2026-11-13 的公告。11 月 12 日的两份 IBM 公告和 ENISA 报告超出 48 小时，按 72 小时窗口纳入；这些页面没有给出时刻。ContextForge 的修复标签早于公告日。

### 一、今日要点

**[1] 请求头可替换上游凭据**
📌 类型：AI基础设施CVE

IBM 安全公告将 CVE-2026-110279 的首次发布记为 12 Nov 2026，页面 `dcterms.date` 为 2026-11-12。ContextForge MCP Gateway 把客户端请求转到上游时，会将 `X-Upstream-Authorization` 一律改名为 `Authorization`，已认证用户因此可以用另一个凭据换掉网关保管的上游凭据，绕过按用户区分的权限和审计归属；CVSS 3.1 为 8.1，所需权限为低，范围包括 OAuth（授权码与客户端凭据）、bearer 和 basic。受影响版本栏写的是 v1.0.0 至 v1.1.0，修复表的版本单元格写的是 2.0，修复说明写的是下载并部署 v1.1.1，该标签发布于 2026-11-10T13:46:57Z。完成升级前，公告要求在前方反向代理去掉全部 MCP 端点上的这一请求头，并把端点限制在受信任网络；公告没有写在野利用。

🔗 来源：[IBM CVE-2026-110279](https://www.ibm.com/support/pages/node/7296490) · [ContextForge v1.1.1](https://github.com/IBM/mcp-context-forge/releases/tag/v1.1.1)

**[2] 身份传播开关被忽略**
📌 类型：AI基础设施CVE

同一页面日期首次发布的 CVE-2026-110278，CVSS 3.1 为 7.4，向量为网络、高复杂度、无需权限。网关可以按上游服务器分别开关身份传播，但公告写明调用工具和读取资源时该设置被忽略，配置为不接收身份的上游仍会收到用户标识、邮箱、组和团队，细节同时写明声明签名的载荷是静态的。受影响范围为 v1.0.0 至 v1.1.0，修复说明要求立即升级到 v1.1.1。不能升级时把 `IDENTITY_PROPAGATION_ENABLED` 设为 false，并只允许受信任用户访问网关；公告没有写在野利用。

🔗 来源：[IBM CVE-2026-110278](https://www.ibm.com/support/pages/node/7296489) · [ContextForge v1.1.1](https://github.com/IBM/mcp-context-forge/releases/tag/v1.1.1)

**[3] 同账户令牌被缓存复用**
📌 类型：AI基础设施CVE

IBM 于 13 Nov 2026 首次发布 CVE-2026-110195，CVSS 3.1 为 5.4。网关用调用者的入站 JWT，按 RFC 8693 向授权服务器交换访问上游 MCP 服务器的令牌，缓存键此前没有绑定到具体的入站 JWT；同一账户下权限更低的凭据，例如 API 令牌，可以复用交互式会话已经换到并缓存的上游 bearer。受影响版本为 v1.0.0 至 v1.0.11，修复版本为 v1.1.0，该标签发布于 2026-10-20T17:31:29Z。不能升级时，公告要求上游对同一账户的交互式 JWT 和 API 令牌赋予相同范围和权限，或在混合凭据上避免配置 `subject_token_source=inbound_user_jwt`；公告没有写在野利用。

🔗 来源：[IBM CVE-2026-110195](https://www.ibm.com/support/pages/node/7296695) · [ContextForge v1.1.0](https://github.com/IBM/mcp-context-forge/releases/tag/v1.1.0)

**[4] 模式正则与管理页脚本**
📌 类型：AI基础设施CVE

13 Nov 2026 首次发布的另外两份公告，修复版本都是 v1.1.0，都没有变通办法，受影响版本都是 v1.0.0 至 v1.0.11。CVE-2026-94407 的 CVSS 3.1 为 6.5：工具参数、工具结果和提示词参数按 JSON Schema 校验，摘要写明这些模式可以由工具作者或联邦远端 MCP 服务器提供；细节写明具有工具注册权限的已认证用户可以把灾难性回溯的正则放进 `pattern` 字段，校验时耗尽网关工作进程的 CPU。CVE-2026-110199 的 CVSS 3.1 为 4.8，所需权限为高并需要用户交互：管理仪表板把 URL 中的状态和错误提示经客户端净化后写入页面，变异型跨站脚本可以绕过净化，管理员打开特制链接后，脚本在其已认证会话中执行。两份公告都没有写在野利用。

🔗 来源：[IBM CVE-2026-94407](https://www.ibm.com/support/pages/node/7296667) · [IBM CVE-2026-110199](https://www.ibm.com/support/pages/node/7296694)

**[5] 前沿模型辅助审代码**
📌 类型：AI赋能安全

ENISA 与 CERT-EU 的联合报告《Joint Advisory on the Use of Frontier AI Models for Code Review》在网站上的发布日期为 12 Nov 2026。报告记录的是实验：自 2026 年 6 月起，使用 OpenAI GPT-5.5 与 GPT-5.6 系列（含网络安全变体）、经 Daybreak 提供的 GPT-6 Astra，以及经 Project Glasswing 提供的 Anthropic Mythos 5，只审查欧盟机构维护的 27 个代码库的源代码，没有测试在线应用。模型标出 220 项，并于 2026 年 8 月发给代码所有者；截至发表，所有者完成 88 项评估，报告写明 95% 为真阳性，图 6 计为高 22、中 29、低 24、信息性 9、假或不适用 4，并由此在其中一个代码库分配了 4 个未列出编号的 CVE。全部扫描的费用估算约为 6648.90 欧元，报告写明模型访问由提供方计划免费给予，数字只作参考。

🔗 来源：[ENISA 出版物页](https://www.enisa.europa.eu/publications/joint-advisory-on-the-use-of-frontier-ai-models-for-code-review) · [报告 PDF](https://www.enisa.europa.eu/sites/default/files/2026-11/ENISA_CERTEU_JOINTREPORT_Final.pdf)

### 二、深度速览

#### 【AI 赋能防御】

这次实验放在欧盟网络安全与人工智能行动计划的第 4 项关键行动之下，法律声明写明出版物不构成监管义务。通用编码代理加安全 Skill 或插件使用 Codex、Codex Security 插件和 OpenCode；专用框架 Vigilo 于 2026 年 9 月开源，这次只用白盒并只看源代码，由对抗性复核合并重复项。代码所有者保持 Vigilo 所标严重性的比例为 74%，通用代理为 60%，两类变更都以下调为主。模型最初把 220 项标成严重 4%、高 44%、中 34%、低 18%；已评估的 88 项里模型分类为严重 3、高 39、中 30、低 16，人工复核后不再保留严重一级。令牌消耗合计 611,486,042；报告把专用框架写成更适合单次深入审计，把通用代理加 Skill 写成更适合拉取请求一类的例行检查，并写明自动生成的补丁要由代码所有者验证后再应用。

🔗 来源：[报告 PDF](https://www.enisa.europa.eu/sites/default/files/2026-11/ENISA_CERTEU_JOINTREPORT_Final.pdf)

#### 【AI 系统风险】

CVE-2026-110279 与 CVE-2026-110278 的受影响栏都写到 v1.1.0，修复说明都指向 v1.1.1。前者用请求头里的值替换网关本来要附上的授权码、客户端凭据、bearer 或 basic 凭据。后者在工具调用和资源读取时忽略按服务器关闭身份传播的设置，静态签名又使声明可以被重放。11 月 13 日的三项停在 v1.0.11，修复版本写成 v1.1.0：缓存键漏掉入站 JWT，正则校验没有时间和复杂度上限，管理页脚本则要求高权限用户打开链接。v1.1.0 的标签在 2026-10-20 发布，v1.1.1 在 2026-11-10 发布，只升到 v1.1.0 的实例仍落在前两项的受影响范围内；CVE-2026-110279 的修复表版本单元格写着 2.0，与受影响栏不一致，部署时同时看受影响栏和修复说明里的 v1.1.1。

🔗 来源：[IBM CVE-2026-110279](https://www.ibm.com/support/pages/node/7296490) · [IBM CVE-2026-110278](https://www.ibm.com/support/pages/node/7296489) · [IBM CVE-2026-110195](https://www.ibm.com/support/pages/node/7296695) · [IBM CVE-2026-94407](https://www.ibm.com/support/pages/node/7296667) · [IBM CVE-2026-110199](https://www.ibm.com/support/pages/node/7296694)

### 三、今日趋势洞察

同一产品的五份公告把修复版本拆成两级：11 月 13 日的令牌缓存、正则耗尽和管理页脚本把修复写在 v1.1.0，11 月 12 日的凭据替换和身份传播仍把 v1.1.0 列在受影响范围内，对应标签却分别在 10 月 20 日和 11 月 10 日就已经存在。ENISA 的实验给出同一结构的另一端：模型在发表前已经标出 220 项，发表时仍有 60% 等待代码所有者评估，已评估的 88 项里严重性以下调为主。版本核对要看到具体标签，发现项则要经过掌握部署上下文的人复核之后才能当作严重性结论。

### 四、企业行动清单

- 盘点 IBM ContextForge MCP Gateway 的运行版本。v1.1.0 及更低版本同时落在 CVE-2026-110279 与 CVE-2026-110278 的受影响栏内。按这两份公告的修复说明部署 v1.1.1。CVE-2026-110279 的修复表版本单元格写的是 2.0，受影响栏写的是 v1.0.0 至 v1.1.0。
- 完成上述升级前，在网关前方的反向代理去掉全部 MCP 端点上的 `X-Upstream-Authorization`，并把这些端点的网络访问限制在受信任网络。同时把 `IDENTITY_PROPAGATION_ENABLED` 设为 false，只允许受信任用户访问网关。
- 低于 v1.1.0 的实例还落在 CVE-2026-110195、CVE-2026-94407 与 CVE-2026-110199 的受影响栏内。这三项公告写的修复版本是 v1.1.0。CVE-2026-94407 与 CVE-2026-110199 没有变通办法。CVE-2026-110195 在不能升级时，要求上游对同一账户的交互式 JWT 和 API 令牌赋予相同范围和权限，或在混合凭据上避免配置 `subject_token_source=inbound_user_jwt`。同时覆盖 11 月 12 日两项的版本仍是 v1.1.1。
- 升级后复查上游 MCP 服务器的审计记录，核对是否出现与网关保管凭据不一致的 `Authorization`，以及被配置为关闭身份传播的上游是否收到过用户标识。公告没有写在野利用，升级本身也不回答这些调用是否已经发生。
- 若用前沿模型对自有代码做安全审计，按 ENISA 报告把代理、Skill 和框架放在不能访问实验范围以外系统的隔离环境中运行。严重性以掌握部署上下文的代码所有者复核为准。发现项沿项目既有的协调披露渠道送出，自动生成的补丁在应用前由代码所有者验证。
