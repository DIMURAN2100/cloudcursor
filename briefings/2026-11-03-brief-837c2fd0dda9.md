### 一、今日要点

**[1] AWS Serverless MCP路径穿越**
📌 类型：AI基础设施CVE

AWS 于 11 月 2 日发布安全公告 2026-164-AWS，并同步公开 GHSA-r6mm-377j-qg8m / CVE-2026-116635：开源包 `awslabs.aws-serverless-mcp-server` 在 v0.2.1 之前，部署状态组件对项目名输入的路径限制不当；能够影响 MCP 智能体的攻击者可通过目录穿越或绝对路径，读取预定部署状态目录之外的 JSON 文件内容；在启用写权限（如 `--enable-write`）时可在该目录外创建或覆盖 JSON。AWS 给出 CVSS 3.1 基础分 6.1（Medium），并称无可用变通方案，正式修复版本为 v0.2.1。属厂商确认的 MCP 服务器路径校验缺陷与协调披露，公开材料未声称在野利用。

🔗 来源：[AWS 安全公告 2026-164-AWS](https://aws.amazon.com/security/security-bulletins/2026-164-aws/) · [GitHub Advisory GHSA-r6mm-377j-qg8m](https://github.com/awslabs/mcp/security/advisories/GHSA-r6mm-377j-qg8m) · [NVD CVE-2026-116635](https://nvd.nist.gov/vuln/detail/CVE-2026-116635)

**[2] VOLTA窃密木马用LLM估价**
📌 类型：AI赋能安全

Cisco Talos 于 10 月 31 日发布分析、The Hacker News 于 11 月 2 日跟进：自删除型 Windows 窃密木马 VOLTA-AUTODOXER（简称 VOLTA）在完成浏览器凭据、会话、加密货币钱包等常规采集与会话 enrichment 后，将结构化“证据包”经 OpenRouter 提交给大模型，要求以“法医情报分析师”角色输出含“WHAT THEY'RE WORTH”“THEIR OPSEC”等栏目的目标评估，从而按变现价值对受害人资产排序。默认模型链路为 Claude Opus，遇拒答则回落到 Kimi、Gemini；另可扫描受害者环境变量中的 `OPENAI_API_KEY` 以滥用其额度（LLMjacking）。Talos 指出未见攻击者自建基础设施、疑似面向买家的 builder 模式，并给出 Chrome ABE/`--headless` 启动控制等缓解建议。属研究机构确认的 AI 集成恶意软件能力分析，不是漏洞 CVE 通报。

🔗 来源：[Cisco Talos 分析（10/31）](https://blog.talosintelligence.com/appraisal-by-ai-model-driven-victim-prioritization-in-the-volta-infostealer/) · [The Hacker News（11/02）](https://thehackernews.com/2026/11/new-volta-infostealer-uses-claude.html)

**[3] ChatGPT分享链接跨沙箱执行**
📌 类型：AI自身安全

Parameter 于 10 月 28 日公开、The Hacker News 于 10 月 31 日报道：恶意 ChatGPT 公开分享链接可在打开者已登录会话中执行攻击者 JavaScript，枚举对话列表、读取从未分享的私聊并向外传数据。机制上，Preview 沙箱内的任意代码经 MathLive 虚拟键盘 `postMessage` 监听器（未校验消息来源且允许携带原始 HTML）写入主站页面，再构造同源帧调用受害方认证 API；可靠路径曾需点击 Preview，后续版本可自动打开 Preview。研究者经 Bugcrowd 于 10 月 18 日报告，OpenAI 于 10 月 26 日前在两套 Web 前端修复并将评级升至 P1，用户侧无需安装补丁。属已修复的研究演示与厂商确认，公开材料未报告在野利用。

🔗 来源：[Parameter 研究原文](https://www.parameter.ai/labs/we-found-a-gap-at-openai) · [The Hacker News（10/31）](https://thehackernews.com/2026/10/a-shared-chatgpt-link-could-run.html)

**[4] LaraDashboard MCP发信越权**
📌 类型：AI基础设施CVE

LaraDashboard 于 11 月 1 日发布 GHSA-gjfv-h634-pxpv，NVD/VulnCheck 于 11 月 2 日编目 CVE-2026-120450：1.4.0 至 1.4.8 中，MCP 工具 `SendEmailTool` 仅以只读权限 `email_template.view` 门控，持有该权限的认证用户可铸造 MCP 令牌并调用 `send-email`，向任意收件人发送任意主题与原始 HTML，借站点邮件通道投递钓鱼或垃圾邮件；公告还指出令牌能力快照在权限变更后可能静默扩大。项目 CVSS 自评约 8.5（High）。修复版本为 1.4.9（提交 5955d72）。属确认的 MCP 工具授权过宽缺陷，未见公开声称在野利用。

🔗 来源：[GitHub Advisory GHSA-gjfv-h634-pxpv](https://github.com/laradashboard/laradashboard/security/advisories/GHSA-gjfv-h634-pxpv) · [NVD CVE-2026-120450](https://nvd.nist.gov/vuln/detail/CVE-2026-120450) · [v1.4.9 发布](https://github.com/laradashboard/laradashboard/releases/tag/v1.4.9)

**[5] Chainalysis遭进攻型智能体入侵**
📌 类型：AI赋能安全

Chainalysis 于 10 月 30 日发布安全事件说明：本月检测到外部行为体使用“进攻型智能体技术（offensive agentic techniques）”未经授权访问其系统与内部工具；截至通报，未发现调查内容（图表、笔记、案件）、交易/查询结果、明文密码、MFA 机密或会话令牌遭未授权访问，但平台用户的用户 ID、姓名、邮箱与组织角色标签等非敏感客户数据曾被访问。公司称已聘请第三方专家，并使用大模型协助扩大平台安全复核与加固；同时声明该事件与近期 Binance 相关加密资产盗窃无关。属厂商来源的事件通报，公开材料未给出具体工具链、CVE 或利用细节，不宜外推为可复现的通用攻击手册。

**[6] MCPHub请求头凭据外传**
📌 类型：AI基础设施CVE

NVD 于 11 月 2 日公开 CVE-2026-120323（VulDB CNA）：samanhappy MCPHub 至 1.0.45/1.1.7，OpenAPI 型 MCP 服务器的 `passthroughHeaders` 可将调用方请求中的 `Authorization`、`Cookie`、`X-Api-Key` 等头原样复制到指向攻击者控制 `openapi.url` 的出站请求，使低权限用户通过注册恶意 OpenAPI 服务器、诱使高权限用户调用工具来窃取会话凭据。公开 writeup 在 v1.0.45 上动态验证；NVD 建议升级至 1.1.8（相关提交约 10 月 20–21 日已合入发布）。属确认的 MCP 管理面请求头透传设计缺陷与新 CVE 编目，公开材料未声称大规模在野利用。

### 二、深度速览

#### 【AI 赋能防御】

进攻侧已把大模型嵌进窃密后处理：VOLTA 不依赖自建 C2 完成“受害人价值排序”，而是走 OpenRouter 多模型拒答回落，并把受害者自有 API 密钥当作算力掩护。对防御方，这意味着检测不能只盯静态 IOC，还需覆盖异常的 `openrouter.ai`/`chat/completions` 出站、Chrome 被非开发者进程以 `--headless` 拉起以绕过 ABE，以及对终端上突发的“身份报告 + AI 分析”成对产物。并行地，Chainalysis 在事件响应中明确使用大模型协助扩大安全复核，说明同一类能力既可被用于进攻分诊，也可被纳入防御侧代码与配置审计；前提是模型调用本身处于可审计、密钥隔离的受控通道。

🔗 来源：[Cisco Talos VOLTA 分析](https://blog.talosintelligence.com/appraisal-by-ai-model-driven-victim-prioritization-in-the-volta-infostealer/) · [Chainalysis 事件说明](https://www.chainalysis.com/blog/security-incident-october-30/)

#### 【AI 系统风险】

本期系统风险沿三条边界展开。一是 **MCP 服务器把调用方输入当作可信路径或权限**：AWS Serverless MCP 的项目名路径穿越、LaraDashboard 以只读权限门控发信工具、MCPHub 透传认证头，均显示工具描述与鉴权元数据一旦错配，智能体或低权限用户即可触达文件读写、邮件通道或会话凭据。二是 **消费级 AI Web 产品的“无害功能组合”**：ChatGPT 的 Preview 沙箱与主站 MathLive 监听器各自合理，却在 `postMessage` 来源校验缺失时拼出账户接管链；修复必须在服务端前端完成，终端用户几乎无本地补丁面。三是 **AI 被用于事后分诊而非初始侵入**：VOLTA 的新颖处在于把 LLM 当成变现分析师，对 SOC 则要求把模型 API 调用与窃密行为关联狩猎。共性缓解：升级 MCP 组件至修复线、对 MCP 工具实施最小权限与敏感头拒绝列表、将 AI Web 预览/分享面视为高信任交互并依赖厂商补丁节奏。

🔗 来源：[AWS 2026-164-AWS](https://aws.amazon.com/security/security-bulletins/2026-164-aws/) · [Parameter ChatGPT 研究](https://www.parameter.ai/labs/we-found-a-gap-at-openai) · [LaraDashboard GHSA-gjfv-h634-pxpv](https://github.com/laradashboard/laradashboard/security/advisories/GHSA-gjfv-h634-pxpv)

### 三、今日趋势洞察

AI 安全冲突正同时落在“智能体工具链的输入校验”与“大模型作为攻防劳动力”两端：MCP 路径、发信与请求头透传说明权限边界仍按传统 Web API 惯性设计；而 VOLTA 与 Chainalysis 事件则表明，模型调用本身已成为犯罪分诊与企业应急加固的共用基础设施，检测与治理必须把模型 API、密钥来源与工具权限纳入同一资产账本。

### 四、企业行动清单

- 清点开发机与 CI 中的 `awslabs.aws-serverless-mcp-server`，升级至 v0.2.1+，关闭不必要的写权限开关，并核查近期项目名参数是否含 `../` 或绝对路径。
- 在终端与代理层增加对 OpenRouter/异常 LLM API 出站、Chrome `--headless` 非白名单启动，以及成对出现的身份报告/AI 分析产物的狩猎规则，覆盖 VOLTA 公开行为特征。
- 将 LaraDashboard 升至 1.4.9+，复核 MCP 令牌权限是否仍仅绑定 `email_template.view` 即可发信，并在权限变更后强制轮换 MCP 令牌。
- 将 MCPHub 升至 1.1.8+，禁止非特权用户注册可指向外部 URL 的 OpenAPI 服务器，并对 `passthroughHeaders` 实施认证头拒绝列表。
- 对使用 ChatGPT 企业版/团队工作区的单位，确认 Web 前端已随 OpenAI 10 月 26 日修复线更新；安全意识培训中将“未知分享链接一键 Preview”列为高风险交互，并审计近期异常对话枚举或外联行为。
