全球网络安全简报（AI 专题）— 2026-08-18（GMT+8）

资讯覆盖优先过去 24～48 小时（约 8 月 16 日—18 日）；CISA 将 Ray 漏洞列入 KEV 等重大进展以官方公告日为准。部分直接影响 AI/MCP 运行时的高价值 CVE 补充至约一周内新披露条目，并在条目中标明发布时间。

---

### 一、今日要点

**[1] Ray漏洞入CISA KEV**
📌 类型：AI基础设施CVE

美国 CISA 于 8 月 17 日宣布，将 AI 分布式计算框架 Ray 的代码注入漏洞 CVE-2025-62593 纳入已知被利用漏洞目录（KEV），并要求联邦民事行政部门在 8 月 20 日前按 BOD 26-04 完成缓解与取证分诊。该缺陷源于 Dashboard 以可被篡改的 User-Agent（“Mozilla”前缀）拦截浏览器请求，结合 DNS 重绑定即可在开发者使用 Firefox/Safari 访问恶意页时触发远程代码执行；官方已在 2.52.0 修复。NVD 同步将利用状态标为 active，并引用 CISA 与项目安全公告。

🔗 来源：[CISA 公告](https://www.cisa.gov/news-events/alerts/2026/08/17/cisa-adds-one-known-exploited-vulnerability-catalog) · [Ray GHSA-q279-jhrf-cc6v](https://github.com/ray-project/ray/security/advisories/GHSA-q279-jhrf-cc6v) · [iThome 报道](https://www.ithome.com.tw/news/178204)

**[2] MCP服务器泄露企业密钥**
📌 类型：AI自身安全

The Hacker News 于 8 月 17 日刊发（Keeper Security 供稿）分析称，MCP 服务器常以明文配置、环境变量持有 API 令牌与服务账号密钥，并因过度授权与提示注入，使智能体在读取文档/工单时被诱导滥用工具或交出密钥。文中强调影子 MCP、凭证散落与缺少人工确认等高风险操作检查点；缓解建议包括最小权限、敏感动作人审与零知识密钥托管。以上为厂商来源的机制梳理与最佳实践，非针对单一在野 CVE 的利用通报。

🔗 来源：[The Hacker News（厂商来源）](https://thehackernews.com/2026/08/how-mcp-servers-can-expose-enterprise.html)

**[3] UFO移动MCP未认证暴露**
📌 类型：AI基础设施CVE

Microsoft UFO（跨设备智能自动化开源框架）在 3.0.8 之前，`mobile_mcp_server.py` 于 TCP 8020/8021 暴露无认证 Streamable HTTP MCP 服务（CVE-2026-73296，GitHub 安全公告约 8 月 10 日、NVD 收录约 8 月 12 日）。未认证攻击者可调用截屏、UI 树获取、点击/滑动/输入与启停应用等能力，对已 ADB 连接的 Android 设备实施窥屏与操控。同日相关公告还覆盖 DNS 重绑定与 SSRF 等问题；请升级至 3.0.8+ 并禁止将 MCP 端口暴露至不可信网络。

🔗 来源：[GitHub Advisory GHSA-24fq-m9rr-g3mm](https://github.com/microsoft/UFO/security/advisories/GHSA-24fq-m9rr-g3mm) · [NVD CVE-2026-73296](https://nvd.nist.gov/vuln/detail/CVE-2026-73296)

**[4] CKAN MCP错误路径信息泄露**
📌 类型：AI基础设施CVE

CKAN MCP Server（对接开放数据门户的 MCP 工具）在 0.4.112 之前存在多条安全缺陷；其中 CVE-2026-73844（约 8 月 14 日收录）指出错误路径会把上游响应原文与内部异常（主机名、内网 IP、数据库错误、堆栈片段）直接回传给调用方，在被指向非 CKAN 主机或遭遇 SSRF 重定向时扩大侦察面。同批还有参数规范化与质量接口相关问题。已在 0.4.112 修复，部署方应升级并审查 MCP 错误回显策略。

🔗 来源：[NVD CVE-2026-73844](https://nvd.nist.gov/vuln/detail/CVE-2026-73844)

**[5] AI开发工具攻击面升温**
📌 类型：AI赋能安全

The Hacker News Expert Insights（8 月 17 日，GitProtect 供稿）汇总称：据其实验室统计，2026 上半年已追踪到 84 起与 AI 相关的 DevOps 安全事件，较 2025 同期接近三倍；调查中约三分之一受访者称已遭遇直接关联 AI 的安全事件。文章梳理间接提示注入经工单/PR/MCP 工具描述外泄代码与密钥、自治运维智能体误删基础设施，以及利用“自愈”命令拉取 DNS TXT 载荷等研究演示与厂商观察场景，并建议限制智能体权限、隔离执行环境与强化 DevOps 备份。数据与案例属性为厂商调研，非独立监管通报。

🔗 来源：[The Hacker News Expert Insights（厂商来源）](https://thehackernews.com/expert-insights/2026/08/why-your-ai-developer-tools-might-be.html)

**[6] Skill与MCP配置成供应链面**
📌 类型：AI自身安全

Xygeni 于 8 月 17 日更新的技术博文指出，Skill、Rules 与 MCP 服务器配置常被当作“文档”提交而缺少安全评审，却可改写助手指令与可达系统；并结合近年隐藏 Unicode 规则后门、高下载量 MCP 桥接命令注入、npm 蠕虫与“幻装包名”（slopsquatting）等公开案例，论证传统 SAST/SCA 对模型/智能体/MCP 资产不可见。文中同时推销其 AI-BOM 与运行时阻断产品，属厂商分析，机制描述可作供应链盘点参考。

🔗 来源：[Xygeni 博客（厂商来源）](https://xygeni.io/blog/ai-security-explained)

### 二、深度速览

#### 【AI 赋能防御】

GitProtect 供稿文章强调：在编码助手与自治运维智能体加速交付的同时，安全团队需要把“提示注入—工具调用—外联”链路纳入检测与变更审批，并以不可变备份作为智能体误操作后的最后恢复手段。其给出的企业动作包括收紧智能体管理权限、阻断不可信出站、对进入模型上下文的外部仓库/文档做预审，以及按 3-2-1 原则备份 DevOps 关键状态。上述效果数据来自厂商实验室与问卷，宜作为优先级参考而非行业基准。

🔗 来源：[GitProtect / THN Expert Insights](https://thehackernews.com/expert-insights/2026/08/why-your-ai-developer-tools-might-be.html)

Keeper 文中提出的 MCP 密钥治理路径（集中保管、即时取用、敏感动作人审）与 SOC/身份团队现有密钥管理能力可直接对接，有助于把“智能体持有的长期静态令牌”从影子配置拉回可轮换、可审计的库存。

🔗 来源：[THN MCP 密钥分析](https://thehackernews.com/2026/08/how-mcp-servers-can-expose-enterprise.html)

#### 【AI 系统风险】

Ray CVE-2025-62593 的利用前提是开发者本机/内网 Ray 节点缺乏强认证，仅依赖脆弱的浏览器流量启发式；一旦 User-Agent 可被浏览器侧请求改写并叠加 DNS 重绑定，恶意站点即可触达 `/api/jobs` 等关键接口完成代码执行。CISA 将其升格为 KEV 并设定 8 月 20 日截止，说明威胁情报侧已掌握活跃利用证据。缓解重点：升级 ≥2.52.0、对 Dashboard/Jobs API 强制网络隔离与认证，并按 BOD 26-04 对暴露面做补丁前取证分诊。

🔗 来源：[CISA](https://www.cisa.gov/news-events/alerts/2026/08/17/cisa-adds-one-known-exploited-vulnerability-catalog) · [Ray Advisory](https://github.com/ray-project/ray/security/advisories/GHSA-q279-jhrf-cc6v)

Microsoft UFO 的未认证移动 MCP 则把“无鉴权工具面”从桌面开发节点延伸到物理设备控制面：任意可路由至 8020/8021 的攻击者即可截取屏幕并注入输入。这与 CKAN MCP 错误回显、以及行业对 MCP 明文密钥的讨论共同指向同一结构问题——协议连接便利性领先于默认安全基线。

🔗 来源：[UFO GHSA-24fq-m9rr-g3mm](https://github.com/microsoft/UFO/security/advisories/GHSA-24fq-m9rr-g3mm) · [CVE-2026-73844](https://nvd.nist.gov/vuln/detail/CVE-2026-73844)

#### 【全球治理与标准】

本日该类别无可核实的重要法规或标准文本更新，不强行补充。CISA 将 Ray 漏洞纳入 KEV 并援引 BOD 26-04，属于美国联邦漏洞运营指令层面的执行动作，已在要点第 1 条覆盖。

### 三、今日趋势洞察

AI 运行时与智能体工具面（Ray 作业接口、UFO/CKAN 等 MCP 服务）正从“开发便利默认开放”转入“监管与利用双重加压”的阶段：一边是 CISA 对活跃利用的硬性时限，一边是密钥明文、无认证 MCP 与配置即指令等供应链弱点被集中曝光。企业若仍把 MCP/Skill 当普通文档、把本地 AI 计算面板当可信内网服务，将同时承受远程利用与提示注入滥用的叠加风险。

---

### 四、企业行动清单

1. 立即清点 Ray 集群与开发机节点版本，将低于 2.52.0 的实例升级，并按 CISA KEV/BOD 26-04 对曾暴露的 Jobs/Dashboard 接口做补丁前取证分诊。
2. 扫描内网与云安全组，关闭或鉴权 Microsoft UFO 及其他 MCP 监听端口（含 8020/8021），禁止未认证 Streamable HTTP MCP 对不可信网络可达。
3. 盘点仓库与终端中的 MCP 配置、Skill/Rules 文件，将长期静态 API 令牌迁入集中密钥库并开启轮换，对删改生产、外发数据类工具调用强制人工确认。
4. 将 CKAN MCP 等数据门户连接器升级至厂商已修复版本，统一错误回显为脱敏消息，防止异常路径泄露内网拓扑与数据库细节。
5. 在 DevOps/SOC 流水线增加“进入模型上下文的外部内容”预检，限制编码/运维智能体的云资源销毁与密钥读取权限，并验证离线备份可在智能体误操作后快速回滚。
