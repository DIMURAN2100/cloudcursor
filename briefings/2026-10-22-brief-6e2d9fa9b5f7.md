### 一、今日要点

**[1] DB-GPT聊天Agent可无认证RCE**
📌 类型：AI自身安全

NVD / VulnCheck 于 10 月 20 日公开 CVE-2026-77932（CVSS 3.1 约 9.8 / CVSS 4.0 约 9.3 Critical）：DB-GPT 至 0.8.2 的 `/api/v1/chat/react-agent` 依赖会把每位调用者授予 admin 角色的 mock `get_user_from_headers`，未认证攻击者可向 ReAct 智能体投递提示，驱动未沙箱化的 `code_interpreter` / `shell_interpreter` 以 web 容器 root 执行任意 Python 或 bash，并可能触达捆绑数据库默认凭据。截至核验最新标签仍为 v0.8.2，未见标明修复版本。属已确认缺认证叠加危险工具暴露；未见在野利用通报。

🔗 来源：[VulnCheck 公告](https://www.vulncheck.com/advisories/db-gpt-through-0.8.2-unauthenticated-rce-via-api-v1-chat-react-agent) · [NVD CVE-2026-77932](https://nvd.nist.gov/vuln/detail/CVE-2026-77932) · [Lasso 条目](https://www.lasso.security/vulnerability-database/cve-2026-77932)

**[2] Google ADK工件服务可路径穿越**
📌 类型：AI基础设施CVE

GitHub Advisory / NVD 于 10 月 20 日公开 CVE-2026-105772（Advisory 标 Critical）：Google ADK TypeScript（`@google/adk`）0.4.0 至 0.6.0 之前，在非默认启用 `FileArtifactService` 且 API 服务对外暴露时，攻击者可在 `userId` / `sessionId` 中构造相对路径或百分号编码穿越（如 `../`、`..%2F`），读取符合工件目录布局的文件，或在智能体工具调用 `saveArtifact` 时写出目录外文件。默认 `InMemoryArtifactService` 不受影响。官方要求升级至 `@google/adk` 0.6.0+。属已确认路径穿越；条件为暴露 API 且启用文件工件存储。

🔗 来源：[GitHub Advisory GHSA-r3pf-g3mr-cmr7](https://github.com/advisories/GHSA-r3pf-g3mr-cmr7) · [NVD CVE-2026-105772](https://nvd.nist.gov/vuln/detail/CVE-2026-105772)

**[3] Vibe-Trading提示注入可主机RCE**
📌 类型：AI自身安全

NVD 于 10 月 21 日公开 CVE-2026-114107（CVSS 3.1 约 8.8 High）：HKUDS Vibe-Trading 0.1.0 至 0.1.7 之前，攻击者可在智能体处理的文档或网页中植入间接提示注入；`BashTool` / `BackgroundRunTool` 将模型输出命令以 `shell=True` 交给 `subprocess.run` 且无白名单与审批，`read_url` 还可拉取任意 URL，形成命令执行与 SSRF。同日另披露 CVE-2026-114106：`read_document` 等文件读取工具缺沙箱/路径门控，可泄露 `/etc/shadow`、进程环境中的 API 密钥等。公开材料指向 0.1.7 起修复；属研究披露的已确认缺陷组合。

🔗 来源：[NVD CVE-2026-114107](https://nvd.nist.gov/vuln/detail/CVE-2026-114107) · [NVD CVE-2026-114106](https://nvd.nist.gov/vuln/detail/CVE-2026-114106) · [GHSA-66r3-5f65-g64j](https://github.com/advisories/GHSA-66r3-5f65-g64j)

**[4] Langflow OSS会话消息可被劫持**
📌 类型：AI自身安全

IBM 安全公告披露 Langflow OSS 1.0.0—1.12.4 多组缺陷，并建议升级至 1.12.5。其中 CVE-2026-107366（IBM 自评 CVSS 3.1 约 8.3 High）：三条消息接口未校验资源所有权，认证用户可批量删除他人消息、覆写消息内容以注入恶意提示，或通过改写 session ID 劫持整段会话。同公告还覆盖路径穿越、密钥导出与多条认证后代码/命令执行类条目；IBM 注明 107366 等部分问题曾在更早小版本单独修复，但综合修复基线为 1.12.5，并建议按部署启用 MCP interpreter hardening 等配置控制。属厂商安全公告已确认事实。

🔗 来源：[IBM 安全公告](https://www.ibm.com/support/pages/node/7293016) · [NVD CVE-2026-107366](https://nvd.nist.gov/vuln/detail/CVE-2026-107366) · [GHSA-qf42-fp6f-25w9](https://github.com/advisories/GHSA-qf42-fp6f-25w9)

**[5] Trigger.dev本地MCP可被LAN接管**
📌 类型：AI基础设施CVE

NVD / GitHub Advisory 于 10 月 21 日公开 CVE-2026-114090（CVSS 3.1 约 7.1 / CVSS 4.0 约 7.6 High）：`trigger.dev` CLI（cli-v3）3.0.0 至 4.5.4 之前，`trigger dev --mcp` 将 `/sse` 与 `/messages` 绑定到全部网卡且缺认证，局域网攻击者或恶意网页可发起 MCP `tools/call`，借助开发者已存储的访问令牌调用 `trigger-task`、`cancel-run`、`list-runs`、`get-run-logs`。官方修复起点为 4.5.4；当前 npm `trigger.dev` 最新已远高于该版本。属已确认本地开发面暴露；需 LAN/同网可达前提。

🔗 来源：[GitHub Advisory GHSA-8v2q-27xw-2fjh](https://github.com/advisories/GHSA-8v2q-27xw-2fjh) · [NVD CVE-2026-114090](https://nvd.nist.gov/vuln/detail/CVE-2026-114090) · [VulnCheck 公告](https://www.vulncheck.com/advisories/trigger-dev-cli-3.0.0-before-4.5.4-missing-authentication-in-mcp-server)

**[6] A2A Java SDK默认任务授权过宽**

**[7] Letta可用user_id头冒充租户**
📌 类型：AI自身安全

NVD / VulnCheck 于 10 月 20 日公开 CVE-2026-77937（CVSS 3.1 约 8.1 / CVSS 4.0 约 8.6 High）：Letta 至 0.16.8 允许 API 调用方通过自声明的 `user_id` HTTP 头冒充其他用户；即便开启 `LETTA_SERVER_SECURE`，攻击者仍可将 `user_id` 设为其他租户 ID，读写其智能体、记忆与配置。截至核验最新标签仍为 0.16.8。属已确认跨租户冒充；未见正式修复版本与在野利用通报。

**[8] D365 F&O MCP一键部署可匿名读**

NVD 于 10 月 21 日公开 CVE-2026-114123（CVSS 3.1 约 7.5 High）：dynamics365ninja/d365fo-mcp-server 在 1.11.0 之前，官方 Azure 一键部署模板默认将 `apiKey` 置空并写入 App Service `API_KEY`；空密钥时鉴权中间件直接放行，监听默认绑定 `0.0.0.0`。若部署者未另加网络限制或上游认证，公网 App Service 可被未认证 JSON-RPC `tools/call` 访问只读检索类工具，泄露已索引的专有 X++ 源码片段、扩展/事件处理与安全角色结构。已在 1.11.0 修复；已配置有效 API 密钥或网络隔离的部署不在该未认证暴露场景内。

### 二、深度速览

#### 【AI 赋能防御】

微软于 10 月 19 日发布 Agent 安全博文（厂商来源），将智能体定位为需按“内部人风险”治理的主体：强调把智能供给与权限权威分离，不让模型充当自身安全边界；并介绍 Project Perception 向“守护智能体 / Guardian Agents”延伸、Entra Agent ID、任务级 Dynamic Permissions，以及随证据变化收缩写权限或要求可验证人工批准的 Dynamic Agent Risk / Conditional Access。对企业侧可对照的落地要点是：为每个 Agent 建立独立于赞助人的身份与注册表、默认零权限再按任务授时限权限、以及在提示注入或行为漂移时优先降权而非仅依赖事后告警。（厂商产品叙事，非独立事件取证。）

🔗 来源：[Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2026/10/19/agents-are-your-newest-insiders-security-must-move-at-their-speed/)

IBM Langflow OSS 1.12.5 修复包把消息所有权校验与多条代码执行面一并收口，并给出 `LANGFLOW_MCP_SERVER_INTERPRETER_HARDENING=true`、限制自定义组件管理员权限等缓解开关。对自建 Agent/Flow 平台，可把“会话/消息资源所有权校验”和“MCP/自定义组件执行面默认硬化”列入发布门禁，而不是只盯单条 CVE 编号。

🔗 来源：[IBM 安全公告](https://www.ibm.com/support/pages/node/7293016)

#### 【AI 系统风险】

本期高危主轴仍是“聊天/工具 API 的身份假定错误 + 永久挂载 shell/代码解释器”。DB-GPT 用 mock 鉴权把所有调用者变成 admin，使未认证请求直接驱动宿主机解释器；Vibe-Trading 则在有模型工具链的前提下，用间接提示注入打穿无审批的 `shell=True` 执行路径，并用缺沙箱的读文件工具外泄密钥。另一条线是 MCP/工件/部署默认值：Trigger.dev 本地 MCP 全网卡无认证、D365 一键部署空 API Key、Google ADK 文件工件服务路径穿越，以及 A2A Java SDK 默认任务授权 fail-open，说明“开发便利默认值”正在成为 Agent 协议栈的横向风险源。共性缓解：强制真实鉴权与租户绑定、默认禁用或强隔离 shell/代码执行、对 MCP 与工件路径施加最小权限与路径规范化，以及拒绝空密钥/全接口绑定的生产模板。

🔗 来源：[CVE-2026-77932](https://nvd.nist.gov/vuln/detail/CVE-2026-77932) · [CVE-2026-114107](https://nvd.nist.gov/vuln/detail/CVE-2026-114107) · [GHSA-r3pf-g3mr-cmr7](https://github.com/advisories/GHSA-r3pf-g3mr-cmr7)

### 三、今日趋势洞察

Agent 平台高危面正从“单个工具缺认证”扩展到“身份函数形同虚设 / 自声明租户头 / 部署模板空密钥”等控制面失败，使同一条利用链可同时打穿聊天 API、MCP 本地服务与多租户记忆；与此同时，间接提示注入仍稳定地把文档与网页内容升级为宿主机命令通道，说明审批门与沙箱若未覆盖异步工具与文件读取路径，模型侧输入污染会直接变成基础设施事件。

### 四、企业行动清单

- 立即盘点公网或内网暴露的 DB-GPT `/api/v1/chat/react-agent`：下线或前置强认证，禁用未沙箱的 code/shell interpreter，并轮换可能暴露的数据库与模型密钥。
- 将 Langflow OSS 升至 1.12.5+，核对消息/会话所有权校验是否生效，并按公告启用 MCP interpreter hardening 与自定义组件管理员限制。
- 审查 `@google/adk` 是否启用对外暴露的 `FileArtifactService`：升级至 0.6.0+，或改回默认内存工件服务并规范化 userId/sessionId。
- 将 `trigger.dev` CLI 升至 4.5.4+（建议跟当前稳定线），避免在共享局域网以 `--mcp` 暴露无认证 SSE/消息口；轮换本地开发访问令牌。
- 对 Letta、Vibe-Trading、A2A Java SDK、D365 F&O MCP：分别核对跨租户头、shell 工具门控、默认任务授权与 Azure 部署 API Key 非空/网络隔离，未修补前限制仅受信网络访问。
