# 全球网络安全简报（AI 专题）— 2026-10-24（GMT+8）

本期主要覆盖东八区过去约 48～72 小时（约 10 月 21～23 日）经厂商正式事故通告、NVD、GitHub Advisory 与权威安全媒体可核验的新披露；文首说明：LiteLLM 1.107.0 供应链投毒与 PHP2Shell（AI 辅助发现）发生于 10 月 21 日，相对昨日已刊载的 LiteLLM CVE-2026-114612、vLLM/Strands 等条目属于独立事件，故在 72 小时窗内首次收录。时效均已对照官方发布时间与 NVD `published` 核对；不重复前几日已写且无新补丁进展的 DB-GPT 77932、Letta 77937、LiteLLM 114612、Strands 115419、vLLM 114049–055、GraphRAG 114510、Royal MCP 111958 等条目。

### 一、今日要点

**[1] LiteLLM发行管道遭供应链投毒**
📌 类型：AI基础设施CVE

LiteLLM 官方于 10 月 21 日确认：其发布流水线被攻破后，恶意版本 `litellm==1.107.0` 进入 PyPI（约 11:39–13:23 UTC）及 Docker Hub/GHCR 标签 `v1.107.0`/`latest`/`main-latest`/`main-stable`（约 11:46–14:20 UTC），载荷为凭据窃取与可按小时拉取执行的远程代码加载器；官方称 GitHub 源码标签本身不含恶意文件，制品由仿冒仓库构建。调查（厂商来源）指向三名工程师被盗用的 GitHub CLI OAuth 令牌，并怀疑内部对公网暴露的 LiteLLM 部署日志中出现了 Claude Code 在特定情形下写入响应体的令牌。Wiz 等观测约 4.9 万次下载，并在窃密后约 4.5 小时见到以失窃 AWS 凭据查询 Bedrock 等活动（厂商威胁情报）。已拉取受影响制品；企业私有发行未受影响；建议回退并固定至 1.106.2，轮换云与模型提供商密钥。属已确认供应链投毒事件，无单独 CVE。

![Wiz 公开的 LiteLLM 恶意载荷执行流程示意](https://www.datocms-assets.com/75231/1792601134-payload-flow.svg)

🔗 来源：[LiteLLM 官方事故通告](https://docs.litellm.ai/blog/security-incident-oct-21-2026) · [Wiz 分析](https://www.wiz.io/blog/litellm-compromised-steals-credentials) · [SecurityWeek 报道](https://www.securityweek.com/litellm-compromised-in-fresh-supply-chain-attack)

**[2] PHP2Shell由AI辅助发现并加速披露**
📌 类型：AI赋能安全

PHP 项目于 10 月 21 日紧急发布修复，公开 CVE-2026-109618 / CVE-2026-109619（PHP 侧 CVSS 约 9.2）：核心引擎在 OOM/`longjmp` 与跨请求残留状态等路径上存在内存破坏，默认可导致未认证远程代码执行或类 Heartbleed 的内存泄露，影响面覆盖大量互联网 PHP 站点。Wiz Research、Calif（报道称使用 OpenAI 模型）与 OpenAI Codex Security 等独立路径参与发现与复现；补丁版本含 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35。公开报道称 Amazon MadPot 等在正式披露前已观测到利用尝试，披露当日亦有扫描流量；属“AI 加速漏洞发现与攻防时间窗压缩”的已确认事实与观测，漏洞本体为传统 PHP 运行时，而非 AI 产品缺陷。

🔗 来源：[Wiz：PHP2Shell](https://www.wiz.io/blog/php2shell-php-rce) · [NVD CVE-2026-109618](https://nvd.nist.gov/vuln/detail/CVE-2026-109618) · [PHP 安全公告 GHSA-w8hw-w9fx-j79w](https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w)

**[3] ReqLLM WebSocket未校验TLS可窃钥**
📌 类型：AI自身安全

NVD / GitHub Advisory 于约 10 月 22～23 日公开 CVE-2026-107685（CVSS 3.1 约 9.1 Critical）：Elixir 库 `req_llm` 在 1.9.0 至 1.28.0，其 WebSocket 客户端启动时未启用证书校验（WebSockex 默认 `insecure: true`），且选项白名单丢弃调用方 TLS 配置。路径攻击者可终止 `wss://` 会话、读取 Authorization Bearer（OpenAI API Key 或 OAuth）、并篡改流式响应与工具调用；Finch HTTP 与 Mint HTTP/2 路径不受影响。正式修复为 1.29.0。属已确认实现缺陷，利用依赖网络中间人位置。

🔗 来源：[GHSA-6vww-5m28-f26v](https://github.com/agentjido/req_llm/security/advisories/GHSA-6vww-5m28-f26v) · [NVD CVE-2026-107685](https://nvd.nist.gov/vuln/detail/CVE-2026-107685)

**[4] HF Datasets pandas构建可反序列化RCE**
📌 类型：AI基础设施CVE

NVD 于 10 月 23 日公开 CVE-2026-57845（CVSS 3.1 约 8.8 High）：Hugging Face `datasets` 至 5.1.0，废弃的 pandas 打包构建器经 `pandas.read_pickle()` 加载攻击者提供的 pickle，可在受害者调用 `load_dataset("pandas", data_files=...)` 时执行任意 Python。当前最新发行仍为 5.1.0，修复 PR #8879 尚未合并；在补丁落地前应禁止加载不可信 pickle 数据集并停用该构建路径。属已确认研究披露，攻击链依赖用户主动加载恶意数据工件。

🔗 来源：[NVD CVE-2026-57845](https://nvd.nist.gov/vuln/detail/CVE-2026-57845) · [修复 PR #8879](https://github.com/huggingface/datasets/pull/8879)

**[5] Uni-CLI遗留MCP口可被网页驱动**
📌 类型：AI自身安全

NVD / GitHub Advisory 于 10 月 23 日公开 CVE-2026-58497（CVSS 3.1 约 8.6 High）：Uni-CLI 在 0.225.2 之前，遗留的 JSON-RPC-over-HTTP MCP 传输在回环地址上未校验浏览器 `Origin`，恶意网页可用 CORS 简单请求向本地 `/mcp` 投递 `tools/call`；Streamable HTTP 路径已有边界校验，两套传输策略漂移导致缺口。0.225.2 将 Origin 策略前置到共用守卫。属已确认浏览器到本机 MCP 边界缺陷；官方明确不改变“本地代码执行”信任模型本身。

🔗 来源：[GHSA-v3f4-w7r7-v3hm](https://github.com/olo-dot-io/Uni-CLI/security/advisories/GHSA-v3f4-w7r7-v3hm) · [NVD CVE-2026-58497](https://nvd.nist.gov/vuln/detail/CVE-2026-58497) · [v0.225.2 发布说明](https://github.com/olo-dot-io/Uni-CLI/releases/tag/v0.225.2)

**[6] MLflow评分器端点可未认证SSRF**
📌 类型：AI基础设施CVE

NVD 于 10 月 23 日公开 CVE-2026-115886（CVSS 3.1 约 6.5 Medium）；对应 GHSA-2wqp-q3c6-ccj5。MLflow 自 3.12.0rc0 至 3.17.0 之前，未认证的 scorer invoke/register 与 GenAI evaluate 端点对第三方 scorer JSON 做反射实例化，类与构造参数未充分约束；在安装可选 `trulens` 与 `trulens-providers-litellm` 时，攻击者可将 `api_base`/`api_key` 导向任意主机，造成 SSRF。已在 3.17.0 修复。属已确认条件性 SSRF，利用依赖未认证跟踪服务与特定可选依赖组合。

🔗 来源：[GHSA-2wqp-q3c6-ccj5](https://github.com/mlflow/mlflow/security/advisories/GHSA-2wqp-q3c6-ccj5) · [NVD CVE-2026-115886](https://nvd.nist.gov/vuln/detail/CVE-2026-115886) · [v3.17.0 发布说明](https://github.com/mlflow/mlflow/releases/tag/v3.17.0)

**[7] AWS托管MCP脚本沙箱校验不全**
📌 类型：AI基础设施CVE

AWS 于 10 月 23 日发布安全公告 2026-149-AWS，公开 CVE-2026-115845（CVSS 3.1 约 6.4 Medium）：托管 AWS MCP Server 的 `run_script` 工具中，Python 代码校验器对禁止输入列表不完整，经认证的远程用户可能通过精心构造的脚本在其自身隔离会话内执行任意代码。影响对象为 AWS 托管服务（非客户自建版本号）；AWS 已在服务侧完成修复，公告写明客户无需操作。属厂商已确认并已闭环的托管面问题。

🔗 来源：[AWS 安全公告 2026-149-AWS](https://aws.amazon.com/security/security-bulletins/2026-149-aws/) · [NVD CVE-2026-115845](https://nvd.nist.gov/vuln/detail/CVE-2026-115845)

### 二、深度速览

#### 【AI 赋能防御】

PHP2Shell 将“AI 辅助漏洞研究”从概念推到了互联网基础软件的应急节奏：多家研究机构在相近窗口独立把多年潜伏的引擎级内存问题收敛为可复现 RCE，迫使 PHP 提前出补丁，同时披露前 honeypot 与泄露细节已压缩防御窗口。对企业的可操作含义不是追逐具体 AI 工具品牌，而是假设高影响力运行时缺陷的发现与利用速度同步加快：缩短外部 PHP/边缘运行时的盘点与补丁 SLA，并把“披露前异常扫描”纳入 SOC 假设。与同日 LiteLLM 供应链事件对照，防御侧 AI 能力提升与攻击侧对 AI 网关/凭据面的兴趣正同时上升。

🔗 来源：[Wiz：PHP2Shell](https://www.wiz.io/blog/php2shell-php-rce) · [LiteLLM 官方事故通告](https://docs.litellm.ai/blog/security-incident-oct-21-2026)

#### 【AI 系统风险】

本期风险主轴是“AI 控制面成为高价值凭据汇聚点”。LiteLLM 投毒表明：一旦发布令牌与网关日志同时失守，恶意 wheel 可在每次 Python 启动时窃取云、浏览器与模型提供商密钥，并进入 LLMjacking 侦察。并行的客户端与本地 Agent 面则继续暴露协议层疏漏：ReqLLM 在 WebSocket 路径关闭 TLS 校验；Uni-CLI 遗留 MCP HTTP 口缺少浏览器 Origin 边界；MLflow 未认证 GenAI 评分端点在可选 LiteLLM 提供方路径上变成 SSRF；HF Datasets 仍可通过废弃 pandas/pickle 构建器执行代码。共性缓解：对 AI 网关与代理固定版本并阻断异常新包、对发布流水线与开发者 OAuth 做日志脱敏与公网暴露审计、升级流式/MCP 客户端至强制证书校验与 Origin 守卫、禁止未认证跟踪服务与不可信 pickle 数据集进入训练/评测流水线。

🔗 来源：[Wiz：LiteLLM](https://www.wiz.io/blog/litellm-compromised-steals-credentials) · [GHSA-6vww-5m28-f26v](https://github.com/agentjido/req_llm/security/advisories/GHSA-6vww-5m28-f26v) · [GHSA-2wqp-q3c6-ccj5](https://github.com/mlflow/mlflow/security/advisories/GHSA-2wqp-q3c6-ccj5)

### 三、今日趋势洞察

AI 网关与发布依赖正在从“便利中间件”变成与云 IAM 同级的凭据爆破面：LiteLLM 二次年内供应链事件与同日多个 MCP/流式客户端边界缺陷共同说明，控制面失守会一次性扩散到多提供商密钥与本地工具调用。与此同时，AI 辅助漏洞发现已实质压缩基础运行时的披露—利用窗，企业若仍按人工研究节奏安排补丁，将系统性落后于攻防双方的机器速度。

### 四、企业行动清单

- 立即在软件库、CI 与镜像仓库检索并隔离 `litellm==1.107.0` 及 10 月 21 日拉取的 `latest`/`main-stable` 等浮动标签，固定至 1.106.2 或经核验的安全版本，并轮换受影响主机上的云、Git、模型提供商与代理主密钥。
- 盘点对公网或半可信网络暴露的 AI 网关与内部 LiteLLM/代理日志，关闭开发者 OAuth/CLI 令牌写入可被读取的响应与日志字段。
- 将 `req_llm` 升至 1.29.0+，将 Uni-CLI 升至 0.225.2+，并复查本机 MCP HTTP 传输是否仍对浏览器开放遗留端口。
- 对自建 MLflow Tracking 升级至 3.17.0+，关闭未认证访问，并确认是否安装了 `trulens`/`trulens-providers-litellm` 可选栈。
- 在数据科学流水线中禁用 `datasets` 的 pandas/pickle 构建加载不可信文件，待官方合并 CVE-2026-57845 修复后再评估升级；同步将对外 PHP 运行时升至含 109618/109619 修复的版本。
