### 一、今日要点

**[1] vLLM 连发四项安全公告**
📌 类型：AI基础设施CVE

GitHub Advisory Database 于 9 月 4 日收录开源推理服务 vLLM 的四项缺陷，修复版本均为 0.26.0。CVE-2026-73557（GHSA-pr7f-p5mw-fc87）指出：针对历史 CVE-2025-62164 的稀疏张量不变量保护依赖进程级全局状态，在启用 `--enable-prompt-embeds` 时，同一 `/v1/chat/completions` 请求中并发的多个 prompt embedding 部件可竞态绕过该守卫，使畸形稀疏载荷进入 `to_dense()`。CVE-2026-73556 为 lm-format-enforcer 结构化输出后端缺少正则编译超时导致的拒绝服务；CVE-2026-73555 为校验错误信息泄露内部路径与运行用户名；CVE-2026-71486 为 derender 端点对调用方提供的 token ID 列表缺少输出规模边界，可放大 CPU/内存消耗。公开材料为已确认产品缺陷与补丁，未标明大规模在野利用。

🔗 来源：[GHSA-pr7f-p5mw-fc87](https://github.com/advisories/GHSA-pr7f-p5mw-fc87) · [GHSA-48jh-3gj7-fg8v](https://github.com/advisories/GHSA-48jh-3gj7-fg8v) · [GHSA-hwrm-c4cx-rf4j](https://github.com/advisories/GHSA-hwrm-c4cx-rf4j) · [GHSA-8737-qx52-hjff](https://github.com/advisories/GHSA-8737-qx52-hjff)

**[2] CodeWhale 交互壳与配置读文件**
📌 类型：AI自身安全

GitHub Advisory 于 9 月 4 日审阅收录编程代理 CodeWhale（及相关 deepseek-tui 包）两项高危问题，维护方确认修复版本为 0.8.64。CVE-2026-75857（GHSA-g29h-pfmp-qp9r）中，`exec_shell` 需审批，但其兄弟工具 `exec_shell_interact` 对已批准的长驻交互进程（如 `python3 -i`、`ssh`、`sudo -i`）写入模型控制的标准输入时不再弹窗；一旦会话内存在已批准交互壳，后续提示注入可驱动该进程特权下的后续命令。CVE-2026-75859（GHSA-62f5-cp2p-vq95）允许仓库内 `.codewhale/config.toml` / `.deepseek/config.toml` 的 `instructions` 指定任意路径（含 `~/.ssh/id_rsa`、`~/.aws/credentials`），内容被读入系统提示且无工作区边界校验。属已确认缺陷与补丁，公开材料未标明在野大规模利用。

🔗 来源：[GHSA-g29h-pfmp-qp9r](https://github.com/advisories/GHSA-g29h-pfmp-qp9r) · [GHSA-62f5-cp2p-vq95](https://github.com/advisories/GHSA-62f5-cp2p-vq95)

**[3] Fortinet 复盘 Bedrock LLMjacking**
📌 类型：AI自身安全

FortiGuard Labs 于 9 月 3 日发布事件分析：攻击者利用泄露的长期有效、具备 AdministratorAccess 的 AWS IAM 访问密钥创建新 IAM 身份，经 AWS Marketplace 订阅基础模型并调用 Amazon Bedrock，将受害账户的付费推理能力用于自用或转售，手法称为 LLMjacking。厂商指出该类滥用在 API 层表现为合法 InvokeModel 调用，CloudTrail 默认难以单凭“首次使用 AI 服务”判定恶意；相关黑产侧研究（如 Operation Bizarre Bazaar）曾统计逾 3.5 万次攻击会话与 30 余家 LLM 提供商转售市场——该部分为既有研究引用。防御建议包括全面开启 CloudTrail、启用默认关闭的 Bedrock 调用日志，以及将长期宽权限 IAM 密钥视为最高优先级风险。属已确认事件响应观察加厂商检测覆盖说明。

🔗 来源：[FortiGuard Labs](https://www.fortinet.com/blog/threat-research/someone-else-is-using-your-ai) · [GBHackers](https://gbhackers.com/llmjacking-attack-abuses-leaked-aws-credentials)

**[4] OpenAI 推 Daybreak 前线防御计划**
📌 类型：AI赋能安全

OpenAI 于 9 月 4 日宣布 “Daybreak for Frontline Defenders”：承诺以约 10 亿美元规模补贴资源受限的前线防御方使用 Daybreak 网络模型与产品、培训与技术支持，目标在约六个月内消耗；优先覆盖美国水务/污水、电网、州与地方政府、社区与地区银行、非营利与开源维护者，并计划数周内向合作国家扩展。官方称已有约两千个获批组织/工作区的数千名防御者使用 Daybreak；同日公布与 MS-ISAC 的公共部门及水务试点，以及 Daybreak Defense Network 中逾 35 项企业产品与合作服务集成。上述规模、覆盖与效果表述均为厂商来源；访问仍限定经核验的授权防御用途。

🔗 来源：[OpenAI 官方公告](https://openai.com/index/daybreak-for-frontline-defenders/) · [Help Net Security](https://www.helpnetsecurity.com/2026/09/04/openai-daybreak-frontline-defenders-access/)

**[5] Mythos 漏洞产出复核能力告急**
📌 类型：AI赋能安全

Help Net Security 于 9 月 4 日报道软件供应链公司 Echo 对 Anthropic Claude Mythos Preview 公开数据的梳理：模型曾对 281 个开源项目产出 23,019 条候选漏洞；外部厂商复核约 1,900 条中约 90.8% 被确认为真实问题，但其余逾 2.1 万条尚未经 Anthropic 以外人员审阅（统计截至 2026-05-22）。在已发布的 27 个 CVE 中，模型自评严重度与独立 CVSS/维护者评分常不一致，14 项存在偏差且多数偏高。Exploit 基准显示 Mythos 可将已知崩溃转为可利用漏洞的成功率远高于上一代模型，但试验条件由 Anthropic 设计且剥离浏览器沙箱等纵深防御，属研究演示数据。文章结论强调：AI 发现能力已超出人工复核与修复吞吐，单纯加扫描并不能缓解积压。

🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/09/04/echo-claude-mythos-vulnerability-findings/)

**[6] OWASP 发布 2026 LLM Top 10 与 ACS**
📌 类型：AI治理合规

OWASP GenAI Security Project 于 9 月 1–2 日正式对外宣布 2026 版 LLM 应用 Top 10，并同步推出捐赠至该项目的 Agent Control Standard（ACS）及行业框架对照资源；官方称资源包在首发约 48 小时内下载逾万次，社区成员超 3 万。据 CSA 9 月 4 日研究札记归纳：新版首次以约 6,639 起真实事件加权（25%）结合专家共识（75%）排序，Excessive Agency 由第 6 升至第 3；原 System Prompt Leakage 扩展为 Hidden Context Exposure。ACS v0.1 侧重运行时可检查、可追踪与可插桩，引入 Agent Bill of Materials 及基于 OpenTelemetry/OCSF 的追踪设想。属标准与治理框架更新，非漏洞通告。

🔗 来源：[OWASP GenAI 公告](https://genai.owasp.org/2026/09/01/owasp-genai-security-project-unveils-2026-top-10-for-llm-applications-new-agent-control-standard-and-sponsors-as-community-tops-30000-members/) · [LLM Top 10 2026 资源页](https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/) · [CSA 研究札记](https://labs.cloudsecurityalliance.org/research/csa-research-note-owasp-genai-top10-2026-agent-control-stand/)

### 二、深度速览

#### 【AI 赋能防御】

OpenAI 将 Daybreak 从“核验防御方可用的门禁服务”推进到以十亿美元量级补贴关键基础设施与地方政府安全团队，并与 MS-ISAC 及 35+ 产品集成并行，反映防御侧前沿网络能力正试图缩短“模型能力上升”与“资源薄弱运营方落地”之间的差距。厂商叙事强调在攻击者普及同类能力前抢占“防御者窗口”；对企业而言，关键路径是验证访问是否限定授权防御、输出是否进入人工确认与变更流程，而非把补贴额度等同于已完成加固。🔗 来源：[OpenAI](https://openai.com/index/daybreak-for-frontline-defenders/)

Echo 对 Mythos 数据的复盘则给出另一面：高吞吐漏洞发现若缺少匹配的人工复核、严重度校准与修复队列，会把“更多发现”转化为积压与错误优先级。模型自评 Critical 在 Temporal、MinIO 等案例中被维护者大幅下调，说明 AI 辅助挖洞结果应作为分诊输入，而不能直接驱动补丁排序。🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/09/04/echo-claude-mythos-vulnerability-findings/)

#### 【AI 系统风险】

vLLM 四项公告共同指向“默认开放或可选特性打开后的推理 API 攻击面”：并发嵌入加载的全局状态竞态、结构化输出后端补丁遗漏、错误回显指纹化、以及 derender 对调用方数据缺少与生成路径对等的边界。对自托管推理集群，升级至 0.26.0、关闭不必要的 prompt embeds / 高风险后端，并在反代层净化错误体，比只盯模型权重更紧迫。CodeWhale 则把风险前移到开发者工作站：一次壳审批与仓库配置合并即可变成持续命令通道或密钥外泄入口，与 GitSpawn 类“审批层之下执行”问题同构。Fortinet 的 LLMjacking 案例进一步说明：即便模型与网关本身无新 CVE，云身份失陷也能把 AI 账单与模型访问权直接货币化。🔗 来源：[vLLM Advisories](https://github.com/advisories/GHSA-pr7f-p5mw-fc87) · [CodeWhale GHSA](https://github.com/advisories/GHSA-g29h-pfmp-qp9r) · [Fortinet](https://www.fortinet.com/blog/threat-research/someone-else-is-using-your-ai)

#### 【全球治理与标准】

OWASP GenAI 在 9 月初将 2026 LLM Top 10 与 ACS 一并推入公众视野：风险排序开始显式纳入大规模事件证据，并把“过度自主权”提到与提示注入、敏感信息泄露同一决策层级；ACS 则试图把治理从清单推进到 AgBOM 与运行时策略强制点。CSA 同日札记提示企业应据此重订智能体风险登记册，并评估 ACS 作为采购/审计语言的演进节奏。该类别本期有可核验的标准发布与权威二次解读，故予收录。

### 三、今日趋势洞察

推理服务与编程代理的补丁节奏正在与“云身份货币化 AI 用量”同步加压：一侧是 vLLM、CodeWhale 等组件以官方 Advisory 明确可利用条件与修复版本，另一侧是 Bedrock 级合法 API 被盗用即可产生高额账单。与此同时，防御叙事同时出现“大规模补贴前沿防御模型”与“AI 挖洞产出超过人工复核”两股力量，说明组织若只采购发现能力、不治理 MCP/壳工具审批、IAM 与漏洞分诊队列，将在攻防两端同时失速。

### 四、企业行动清单

- 清点生产与实验环境中的 vLLM 实例，升级至 0.26.0 及以上；关闭非必要的 `--enable-prompt-embeds` 与 lm-format-enforcer 后端，并检查反代是否向外泄露校验错误中的路径与用户名。
- 将 CodeWhale / deepseek-tui 升至 0.8.64+；复查开发者是否在不可信仓库中启用项目级 `instructions`，并禁止对交互壳工具授予“一次批准、长期免审”的默认策略。
- 在 AWS 账户中排查长期 AdministratorAccess IAM 密钥与异常 Marketplace/Bedrock 订阅及 InvokeModel 峰值，开启 Bedrock 调用日志，将首次基础模型调用与新建身份、陌生 IP 等信号关联告警。
- 若申请或接入 Daybreak 类防御模型，限定至授权安全/IR 账号，并规定漏洞与补丁建议进入生产前的人工复核与测试门禁。
- 按 OWASP 2026 LLM Top 10 将 Excessive Agency 与 Hidden Context Exposure 写入智能体风险登记与采购问卷，评估是否试点 AgBOM/运行时追踪类控制。
