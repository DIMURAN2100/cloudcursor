### 一、今日要点

**[1] MaxKB 提示注入可致命令执行**
📌 类型：AI自身安全

NVD 于 9 月 21 日收录 CVE-2026-77521（CVSS 3.1 评分 10.0）：开源企业 AI 助手 MaxKB 在挂载工具、MCP、Skill 或子应用时，会经 `SandboxShellBackend` 向智能体暴露未排除、且未纳入人工确认的 `execute` shell 能力。未受信聊天或经 RAG/上传文档注入的间接提示，可驱动模型在源码部署（默认沙箱关闭）上以应用用户直接执行命令；官方容器虽启用沙箱，但基于 `shell=True` 的 gosu 包装仍可被 shell 元字符绕过至更高权限。修复版本为 v2.10.5-lts。该条为已协调披露的研究确认事实，公开材料未声称已出现在野大规模利用。

🔗 来源：[NVD CVE-2026-77521](https://nvd.nist.gov/vuln/detail/CVE-2026-77521) · [MaxKB GHSA-f36j-f34j-h3rx](https://github.com/1Panel-dev/MaxKB/security/advisories/GHSA-f36j-f34j-h3rx) · [Lasso Security 研究](https://www.lasso.security/blog/cve-2026-77521-maxkbypass---from-prompt-injection-to-bypassing-maxkb-agents-sandbox)

**[2] Talos 披露 LLM 投票式自主 C2 木马**
📌 类型：AI赋能安全

Cisco Talos 于 9 月 22 日发布开源狩猎框架 CAIRN，并同步披露 Windows 植入 CLOSEDQUORUM：样本将下一步战术动作委托给 DeepSeek、Qwen、Mistral、Gemini 等商业大模型投票表决，意图窃取凭证与加密钱包，从而弱化对传统攻击者自建 C2 基础设施的依赖。Talos 明确写明**尚未确认在野部署**；公开分析样本含占位 API 密钥与假 webhook，未观察到完整端到端实战执行。该发现属于研究级威胁样例，同时为防御方提供“认知工件”（提示模板、供应商端点等）元数据狩猎路径。

🔗 来源：[Talos CLOSEDQUORUM](https://blog.talosintelligence.com/the-closed-quorum-inside-the-first-reported-autonomous-ai-c2-implant/) · [Talos CAIRN 介绍](https://blog.talosintelligence.com/introducing-cairn-frontier-tracking-for-ai-integrated-malware/) · [Help Net Security 报道](https://www.helpnetsecurity.com/2026/09/22/cairn-open-source-framework-ai-malware-closedquorum/)

**[3] Atlassian MCP 未认证可代操作员调用**
📌 类型：AI基础设施CVE

NVD 于 9 月 22 日收录 CVE-2026-77244（CVSS 10.0）：`mcp-atlassian`（Jira/Confluence 的 MCP 服务）在 0.22.0 之前，HTTP 传输未校验真实用户身份，且下游会回退到运营者环境变量中的全局凭据；网络可达 MCP 端点的客户端即可按操作员权限读写 Atlassian 资源。同日还披露 DNS 重绑定类 SSRF（CVE-2026-77242）与 OAuth 明文回退文件等问题。官方修复版本为 v0.22.0。属已确认代码缺陷，公开材料未给出在野利用证据。

🔗 来源：[NVD CVE-2026-77244](https://nvd.nist.gov/vuln/detail/CVE-2026-77244) · [GitHub 安全公告 GHSA-wrhw-j3f9-8vc6](https://github.com/sooperset/mcp-atlassian/security/advisories/GHSA-wrhw-j3f9-8vc6) · [v0.22.0 发布说明](https://github.com/sooperset/mcp-atlassian/releases/tag/v0.22.0)

**[4] LightRAG 摄入内容可致 WebUI XSS**
📌 类型：AI基础设施CVE

GitHub Advisory 于 9 月 22 日发布 CVE-2026-86062：`lightrag-hku` WebUI 对助手/回答内容以未消毒的原始 HTML（`rehypeRaw`、无 `rehype-sanitize`）渲染，攻击者只要能写入一份被检索的文档，即可在后续查看者（常为管理员）浏览器执行脚本，并可能窃取 `localStorage` 中的认证令牌。同日还披露经 IPv6 过渡地址绕过的图片下载 SSRF（CVE-2026-85740，高危）。受影响版本至 1.5.4，补丁版本为 1.5.5。默认配置下部分场景可不需认证即可触发，属研究确认的应用层缺陷。

🔗 来源：[GHSA-xpjq-3w4w-w5wr（XSS）](https://github.com/advisories/GHSA-xpjq-3w4w-w5wr) · [GHSA-vv3m-f8x4-7377（SSRF）](https://github.com/advisories/GHSA-vv3m-f8x4-7377)

**[5] OpenClaw iOS 深链日志泄露密钥**
📌 类型：AI自身安全

NVD 于 9 月 22 日收录 CVE-2026-95815：OpenClaw iOS 在 2026.8.11 之前会将包含持久 bearer 密钥的完整智能体深链 URL 写入统一诊断日志；获取诊断归档的攻击者可恢复未轮换密钥，并伪造深链提交智能体请求、绕过本地确认提示。NVD 给出 CVSS 3.1 约 6.3（需本地/诊断数据接触与用户交互条件）。修复需升级至含提交修复的版本；属于客户端密钥生命周期与日志分级问题。

🔗 来源：[NVD CVE-2026-95815](https://nvd.nist.gov/vuln/detail/CVE-2026-95815) · [GitHub Advisory GHSA-wjj6-g7c3-q75f](https://github.com/advisories/GHSA-wjj6-g7c3-q75f)

**[6] NotebookLM MCP 批导出路径穿越**
📌 类型：AI基础设施CVE

NVD 于 9 月 21 日收录 CVE-2026-61647：NotebookLM MCP（及对应 HTTP 服务）在 1.6.0–2.0.2 中，`POST /batch-to-vault` 与自 1.7.0 起暴露的 `batch_to_vault` MCP 工具，因攻击者可控的 `vault_dir`/`slug_prefix`，可将 Markdown/JSON 写出到预期 vault 目录之外的任意可写位置。影响智能体导出管线与本地知识库落盘边界。应以项目安全公告与补丁版本为准完成升级。

🔗 来源：[NVD CVE-2026-61647](https://nvd.nist.gov/vuln/detail/CVE-2026-61647) · [GHSA-jjhp-8crj-mppq](https://github.com/roomi-fields/notebooklm-mcp/security/advisories/GHSA-jjhp-8crj-mppq)

### 二、深度速览

#### 【AI 赋能防御】

Cisco Talos 开源的 CAIRN 以“认知工件”元数据（嵌入提示、供应商 API 端点、编排逻辑、面向 AI 沙箱的规避文本等）对样本做分层分类与关联，而无需下载或运行恶意代码。该方法将 AI 集成木马的狩猎从传统 IOC 扩展到提示/供应商指纹图谱，并已用于回溯至 2025 年 CERT-UA 披露的 LAMEHUG 等早期样例。HELP NET SECURITY 同步指出，AI 规避技巧在红队教学材料与无关恶意样本之间出现跨年扩散，说明防御方需要把供应商调用痕迹与提示字符串纳入威胁情报流水线。该工具定位为研究与狩猎辅助，效果数据以 Talos 公开叙述为准。

🔗 来源：[Talos CAIRN](https://blog.talosintelligence.com/introducing-cairn-frontier-tracking-for-ai-integrated-malware/) · [Help Net Security](https://www.helpnetsecurity.com/2026/09/22/cairn-open-source-framework-ai-malware-closedquorum/)

#### 【AI 系统风险】

本期多条缺陷共同指向同一机制：**不可信自然语言/文档内容 → 高权限工具调用**。MaxKB 将提示注入映射到默认暴露的 shell；LightRAG 将摄入文档中的 HTML 直接渲染到管理端会话；mcp-atlassian 则在身份校验失败时用操作员全局令牌“代劳”。缓解上应默认关闭或严格闸控代码执行类工具、对 RAG 输出做 HTML 消毒、对 MCP HTTP 传输强制真实身份与最小权限凭据，并把诊断日志中的 bearer/深链视为密钥材料。CLOSEDQUORUM 则提醒：即便尚无确认在野部署，攻方已在实验把战术决策外包给多模型表决，传统仅封锁固定 C2 域名的策略将逐步失效。

🔗 来源：[MaxKB GHSA](https://github.com/1Panel-dev/MaxKB/security/advisories/GHSA-f36j-f34j-h3rx) · [mcp-atlassian GHSA](https://github.com/sooperset/mcp-atlassian/security/advisories/GHSA-wrhw-j3f9-8vc6) · [LightRAG XSS GHSA](https://github.com/advisories/GHSA-xpjq-3w4w-w5wr) · [Talos CLOSEDQUORUM](https://blog.talosintelligence.com/the-closed-quorum-inside-the-first-reported-autonomous-ai-c2-implant/)

### 三、今日趋势洞察

智能体与 MCP/RAG 编排层正集中暴露“身份形同虚设 + 危险能力默认开启”的组合缺陷，补丁窗口已从模型本身迁移到工具网关与文档摄入面。与此同时，攻防两侧都在把大模型嵌入决策环：防御侧用元数据狩猎 AI 集成木马，攻击侧样例则尝试用多模型投票替代人工 C2，预示检测指标需同时覆盖提示/供应商调用与传统网络 IOC。

### 四、企业行动清单

- 盘点并升级所有 MaxKB 实例至 v2.10.5-lts 及以上，关闭未业务必需的 shell/代码执行能力，并复核 `MAXKB_SANDBOX` 与容器用户是否以非 root 运行。
- 清查对外暴露的 `mcp-atlassian` 与同类 MCP HTTP 端点，升级至 0.22.0+，禁用环境变量全局令牌回退，改为按调用者签发短时凭证。
- 对 LightRAG、NotebookLM MCP 等 RAG/导出组件执行版本对齐（LightRAG ≥1.5.5），并对摄入文档与导出路径实施消毒与路径白名单。
- 将诊断日志、崩溃归档与 MDM 备份纳入密钥泄露面评估；对 OpenClaw 等移动智能体客户端轮换 bearer，并禁止明文深链入日志。
- 在威胁狩猎中增加对 LLM 供应商 API 端点、嵌入提示模板与多模型编排痕迹的检测用例，可参考 CAIRN 的认知工件分类思路做内部试点。
