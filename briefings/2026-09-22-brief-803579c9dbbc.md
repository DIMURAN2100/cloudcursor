### 一、今日要点

**[1] Codex双路径沙箱逃逸**
📌 类型：AI自身安全

Accomplish AI 研究员 Oren Yomtov 于 9 月 15 日公开、多家媒体于 9 月 21 日跟进：OpenAI Codex 存在两处沙箱逃逸——Heapjack 与 Overpatch。Heapjack 利用 Codex Desktop 默认安装的 `node_repl`：可信与不可信 JavaScript 共用同一 V8 堆，未受信任代码可经 `v8.getHeapSnapshot()` 提取授权令牌，向沙箱外原生父进程伪造请求，在最严格的 `read-only` 模式下即可无提示执行主机命令；Overpatch 则滥用 CLI 的 `apply_patch` 依补丁路径父目录扩权，可经符号链接改写家目录 `.zshrc` 等文件。问题于 8 月 12 日报告、约八日内修复：Desktop 需 ≥26.818.21641，CLI 需 ≥0.149.0。属已确认研究披露与厂商补丁事实，未见公开在野大规模利用声明。

🔗 来源：[Accomplish 原始披露](https://www.accomplish.ai/blog/escaping-the-openai-codex-sandbox-twice/) · [iThome](https://www.ithome.com.tw/news/179082) · [SecurityOnline](https://securityonline.info/openai-codex-sandbox-escape)

**[2] LMDeploy反序列化满分RCE**
📌 类型：AI基础设施CVE

GitHub/NVD 于 9 月 18 日披露 CVE-2025-66455（GHSA-2vh9-42vm-xmv2，CVSS 3.1 基础分 9.8 Critical）：LMDeploy 在 ≥0.9.2 且 &lt;0.16.0 启用 PyTorch DistServe/PD 解耦控制面时，`handle_zmq_recv()` 经 ZeroMQ 使用 `recv_pyobj()`（底层 pickle）反序列化对端消息；攻击者若能访问未强制 API Key 的 `POST /distserve/p2p_connect`，可指定恶意 ZMQ 地址并投递特制对象，以服务进程权限远程代码执行。普通未启用 DistServe 路径的部署不直接暴露该数据流。官方已在 0.16.0 将协议改为 JSON 并做 schema 校验。属已确认漏洞与补丁公告；GHSA 记录显示 9 月 21 日仍有更新。

🔗 来源：[GitHub Advisory GHSA-2vh9-42vm-xmv2](https://github.com/advisories/GHSA-2vh9-42vm-xmv2) · [NVD CVE-2025-66455](https://nvd.nist.gov/vuln/detail/CVE-2025-66455)

**[3] 恶意模型配置注入eval**
📌 类型：AI基础设施CVE

同日披露 CVE-2026-33625（GHSA-3hmm-rh5q-gwwr，CVSS 3.1 基础分 8.8 High）：LMDeploy 0.12.1–0.12.2 在加载 Hugging Face 模型配置时，将 `quantization_config.quant_dtype` 未经校验传入 `eval(f'torch.{quant_dtype}')`。攻击者可发布带恶意 `quant_dtype` 的 AWQ 类模型，使加载/服务该模型的主机执行任意 Python 代码。修复版本为 0.12.3。与上条不同，本缺陷属模型工件供应链投毒路径，用户交互主要体现为“加载不可信模型”。属已确认研究级供应链漏洞，未见公开在野利用报告。

🔗 来源：[GitHub Advisory GHSA-3hmm-rh5q-gwwr](https://github.com/advisories/GHSA-3hmm-rh5q-gwwr) · [NVD CVE-2026-33625](https://nvd.nist.gov/vuln/detail/CVE-2026-33625)

**[4] 智能体漏洞治理蓝皮书发布**
📌 类型：AI治理合规

9 月 21 日，公安部第三研究所网络安全法律研究中心联合 360 集团等单位编制的《2026智能体安全漏洞治理蓝皮书》公开发布（经济参考网、证券市场周刊等转载）。蓝皮书指出智能体风险已从内容输出延伸至系统操作与现实业务，并提出继承性、耦合性、放大性、复用性、扩散性等特征，主张在“大安全”格局下构建“法律制度为底座、运行控制为主线、全生命周期治理为抓手、产业协同为支撑”的框架。文中将 360“图龙锋”列为产业实践案例，并援引其累计挖洞与权威核验数据（厂商来源）。属已确认的国内治理文本发布与参编单位披露，不是监管处罚或强制标准生效通告。

🔗 来源：[经济参考网（东方财富转载）](https://finance.eastmoney.com/a/202609213880224041.html) · [证券市场周刊](https://static.weeklyonstock.com/26/0921/zbf201330.html)

**[5] 编码代理护栏须外置**
📌 类型：AI赋能安全

DevOps.com 等 9 月 21 日基于 Codex 披露复盘指出：当强制执行逻辑位于被约束的代理内部（自行扩权的 `apply_patch`、可被同堆读取的信任令牌），“只读沙箱”无法构成真实边界。业界此前在 Cursor、Gemini CLI、Antigravity 等编码代理上也观察到“沙箱内写配置、沙箱外可信工具再执行”的同类结构。对防守与采购方，这意味着隔离与凭证应放在代理不可改写的控制面（如独立虚拟机/容器 + 出站代理），版本巡检需同时覆盖 Desktop 与 CLI 两套版本号。属对已确认研究的工程解读，不是新的在野攻击通报。

🔗 来源：[DevOps.com 分析](https://devops.com/codex-sandbox-escapes-show-why-agent-guardrails-cant-live-inside-the-agent) · [Accomplish 原始披露](https://www.accomplish.ai/blog/escaping-the-openai-codex-sandbox-twice/)

### 二、深度速览

#### 【AI 赋能防御】

蓝皮书将智能体同时定位为“漏洞载体”与“治理赋能工具”，并引用 360 图龙锋（厂商来源）的工程化路径：以安全领域大模型解析代码与业务逻辑，再由多组专业智能体分工完成攻击面梳理、研判与复现，并协同调用传统安全工具。文中披露该系统累计挖掘漏洞超 10000 个、其中 260 个获国家信息安全漏洞库等权威机构核验，覆盖 Codex、Claude Code 等产品中的高危问题。上述数据属参编厂商自我披露，应用作能力方向参考，不宜直接等同监管结论或行业基准。对企业而言，可对标其强调的“受控前提下把智能体纳入漏洞发现—验证—处置闭环”，而不是无边界放开自动利用。

🔗 来源：[经济参考网转载](https://finance.eastmoney.com/a/202609213880224041.html)

#### 【AI 系统风险】

Codex 与 LMDeploy 本周共同说明：AI 运行时安全失败往往不在“模型说了什么”，而在工具链信任落点。Heapjack 证明只读模式仍可因同进程共享秘密而失守；LMDeploy DistServe 证明控制面 pickle + 可选无认证 API 可把推理集群变成 RCE 入口；恶意 `quant_dtype` 则把 Hugging Face 模型配置变成代码执行载体。缓解应组合：立即升级到已修复版本；对编码代理默认视第三方仓库为不可信输入；对推理服务禁用或网络隔离 DistServe 控制面并强制 API Key；禁止生产环境加载未核验来源模型，并对配置字段做白名单而非 `eval`。

🔗 来源：[Accomplish](https://www.accomplish.ai/blog/escaping-the-openai-codex-sandbox-twice/) · [GHSA-2vh9-42vm-xmv2](https://github.com/advisories/GHSA-2vh9-42vm-xmv2) · [GHSA-3hmm-rh5q-gwwr](https://github.com/advisories/GHSA-3hmm-rh5q-gwwr)

#### 【全球治理与标准】

《2026智能体安全漏洞治理蓝皮书》为国内首部聚焦智能体漏洞治理的公开蓝皮书文本（据参编方与媒体表述），提出将智能体漏洞纳入网络空间整体治理并强调全生命周期与产业协同。本日未见同步生效的强制性国家标准或跨境监管处罚可核实更新；企业可将该框架作为内部治理对标材料，与现有漏洞管理、AI 资产台账和运行控制策略对齐。

🔗 来源：[证券市场周刊](https://static.weeklyonstock.com/26/0921/zbf201330.html)

### 三、今日趋势洞察

编码代理与推理框架的高影响问题同时落在“执行边界是否外置”和“模型/配置是否可当代码执行”两条轴上：只读、工作区写入与量化配置一旦被实现细节击穿，提示注入或供应链投毒即可直接升格为主机/集群接管。与此同时，治理侧开始把智能体漏洞特征与“以智能体治漏洞”并列表述，说明攻防与政策叙事正共同从内容安全转向任务执行安全。

### 四、企业行动清单

- 清点全部 Codex Desktop 与 Codex CLI 安装点（含 CI runner），分别核验是否已至 Desktop ≥26.818.21641、CLI ≥0.149.0，未达标一律停用对不可信仓库的自动分析。
- 将开发者默认策略改为：第三方克隆仓库按不可信输入处理，禁止仅依赖 `read-only` 作为主机隔离保证。
- 盘点生产与实验环境中的 LMDeploy：启用 DistServe/PD 解耦的升级至 ≥0.16.0，其余加载路径至少升至覆盖 CVE-2026-33625 的 0.12.3+，并关闭公网可达的 `/distserve/*`。
- 禁止在无签名/无来源核验流程下拉取 Hugging Face 量化配置；对 `quant_dtype` 等配置字段实施白名单解析，禁用动态 `eval`。
- 对照蓝皮书提出的全生命周期框架，更新智能体与 MCP/推理网关资产台账，明确运行控制责任人与漏洞响应接口人。
