### 一、今日要点

**[1] LiteLLM密钥复用可提权RCE**
📌 类型：AI基础设施CVE

NVD 于 10 月 22 日公开 CVE-2026-114612（CVSS 3.1 约 9.9 Critical）；对应 GitHub Advisory GHSA-7hp6-4w63-5g45 同日更新。LiteLLM 代理自 1.87.0 起将“静态密钥加密”与“会话令牌签发”共用同一密码学上下文：具备 `internal_user` 权限的认证用户可在申请 API Key 时把伪造的管理员凭据写入 metadata，再把返回的密文当作 Bearer 令牌回放，使代理解密后信任伪造的 `proxy_admin` 身份，进而经 MCP stdio 端点执行任意命令。1.91.0 之后默认配置即可利用；1.87.0–1.90.x 需显式开启 `EXPERIMENTAL_UI_LOGIN`。已确认修复线为 1.100.4 / 1.101.3 / 1.102.2 / 1.103.1 / 1.104.0-rc.2。属已确认提权至主机命令执行；未见在野利用通报。

🔗 来源：[GitHub Advisory GHSA-7hp6-4w63-5g45](https://github.com/BerriAI/litellm/security/advisories/GHSA-7hp6-4w63-5g45) · [NVD CVE-2026-114612](https://nvd.nist.gov/vuln/detail/CVE-2026-114612)

**[2] Strands A2A会话可跨租户串扰**
📌 类型：AI自身安全

AWS 于 10 月 22 日发布安全公告 2026-146-AWS，同步公开 CVE-2026-115419（CVSS 3.1 约 8.1 / CVSS 4.0 约 8.6 High）：Amazon Strands Agents SDK（Python `strands-agents` 含 `multiagent.a2a` 的版本至 1.43.0 之前，TypeScript `@strands-agents/sdk` 至 1.5.0 之前）的 A2A 服务端未正确按调用方隔离会话状态。多租户部署下，认证远程用户可通过不同 `context_id` 访问其他调用方的对话历史，并写入持久指令以影响后续调用者的模型行为。正式修复为 Python 1.43.0 与 TypeScript 1.5.0；公告明确在升级前不存在完整变通，只能做到“单用户/单租户独占一个 A2A 实例”。属厂商已确认的会话隔离缺陷。

🔗 来源：[AWS 安全公告 2026-146-AWS](https://aws.amazon.com/security/security-bulletins/2026-146-aws/) · [NVD CVE-2026-115419](https://nvd.nist.gov/vuln/detail/CVE-2026-115419) · [GHSA-4v6f-7vjh-6x4m](https://github.com/strands-agents/harness-sdk/security/advisories/GHSA-4v6f-7vjh-6x4m)

**[3] Storm-0940用ARTEX加速供应链滥用**
📌 类型：AI赋能安全

微软威胁情报于 10 月 21 日发文（厂商来源）：评估与中国相关的 Storm-0940 自约 2026 年 9 月起将渗透测试智能体框架 ARTEX 嵌入既有进攻工作流，在多起案例中实现从锁定目标到云特权访问不足 3 小时，并认定其与近期 ConnectWise 云备份相关多租户应用供应链事件相关。披露称攻击者在获取被滥用应用身份后，以机器速度对超过 2,250 个租户发起登录尝试（峰值约每分钟 2,900 次），并在部分环境通过 Microsoft Graph 开展侦察、应用凭据变更与权限扩张；微软明确本次 ARTEX 相关活动并非源于微软产品自身漏洞。属厂商威胁情报归因与观测，应与司法裁定区分；相对 10 月上旬公开的韩金融业 ARTEX 报道，本期新增供应链应用身份与 Entra/Graph 后续面细节。

🔗 来源：[Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2026/10/21/storm-0940-uses-artex-agentic-ai-connectwise-supply-chain-compromise)

**[4] vLLM多模态参数可触发RCE**
📌 类型：AI基础设施CVE

NVD / GitHub Advisory 于 10 月 21 日集中公开 vLLM 0.31.0 之前一组多模态处理面问题。其中 CVE-2026-114053（CVSS 3.1 约 8.1 / CVSS 4.0 约 9.2 Critical）：在启用 `trust_remote_code` 且处理器使用动态 `auto_map` 时，未认证客户端可通过请求中的 `mm_processor_kwargs.code_revision` 指定 Hugging Face 处理器代码修订，使 `AutoProcessor.from_pretrained` 导入攻击者控制的 Python，于 API 进程内任意代码执行。同批还包括伪造多模态 UUID 导致引擎崩溃（CVE-2026-114050）、未校验 `mm_processor_kwargs` 资源耗尽（CVE-2026-114055）以及缓存键别名等。公开材料指向升级至 vLLM 0.31.0+；属已确认研究披露，利用条件含 `trust_remote_code` 与可拉取/缓存的处理器修订。

🔗 来源：[GHSA-h3rc-6mm3-gc2m](https://github.com/vllm-project/vllm/security/advisories/GHSA-h3rc-6mm3-gc2m) · [NVD CVE-2026-114053](https://nvd.nist.gov/vuln/detail/CVE-2026-114053) · [NVD CVE-2026-114050](https://nvd.nist.gov/vuln/detail/CVE-2026-114050)

**[5] GraphRAG摄入文档可注入Cypher**
📌 类型：AI自身安全

NVD 于 10 月 22 日公开 CVE-2026-114510（CVSS 3.1 约 7.1 High）：Flexible GraphRAG 0.6.0 至 0.8.2 之前，FalkorDB 适配器中 `_escape()` 先转义引号再转义反斜杠，导致攻击者控制的实体/关系字符串可提前闭合并注入 Cypher。当配置 `GRAPH_BACKEND=langchain` 且 `GRAPH_DB=falkordb` 时，被摄入文档中的间接提示注入可驱动抽取模型产出恶意图元素，进而修改/删除图数据，并在查询结果回传用户或 LLM 时外泄图内容；动态节点/关系类型亦被不安全拼入反引号位置。LlamaIndex FalkorDB 存储路径不受影响。已在 0.8.2 修复。属已确认图查询注入，攻击链依赖文档摄入与特定后端组合。

🔗 来源：[GHSA-vqrg-773h-4wxc](https://github.com/stevereiner/flexible-graphrag/security/advisories/GHSA-vqrg-773h-4wxc) · [NVD CVE-2026-114510](https://nvd.nist.gov/vuln/detail/CVE-2026-114510) · [v0.8.2 发布说明](https://github.com/stevereiner/flexible-graphrag/releases/tag/v0.8.2)

**[6] Royal MCP预览令牌可接管站点**
📌 类型：AI基础设施CVE

NVD / WPScan 于约 10 月 20～22 日公开 CVE-2026-111958（CVSS 3.1 约 7.5 High）：WordPress 插件 Royal MCP 在 1.5.7 之前未将预览链接令牌限定到单次预览用途；持有有效令牌的一方会被认证为令牌所属用户（默认配置常为管理员），并可在无 nonce 的情况下调用整个 REST API，导致站点完全接管。官方修复版本为 1.5.7。属已确认认证绕过；影响面为安装该 MCP 插件且预览令牌可外泄或被截获的 WordPress 站点。

🔗 来源：[WPScan 公告](https://wpscan.com/vulnerability/014f061c-54f3-491e-b4a0-85cfa6fb178b/) · [NVD CVE-2026-111958](https://nvd.nist.gov/vuln/detail/CVE-2026-111958)

**[7] vLLM请求面可被打成可用性故障**
📌 类型：AI基础设施CVE

除 RCE 主线外，同日披露的 CVE-2026-114050 / 114055 表明：在共享推理服务上，未认证或低门槛请求即可通过伪造多模态缓存身份制造致命 token 占位符不匹配，或用超大 `mm_processor_kwargs`（图像尺寸、patch/crop/frame 计数等）耗尽内存并终止整实例，而健康检查路径可能仍返回正常。这使“公网开放的 OpenAI 兼容推理口”即便未开启 `trust_remote_code`，仍面临以机器速度实施的服务可用性打击。修复基线同为 vLLM 0.31.0+；缓解还包括关闭未鉴权入口、限制多模态参数与隔离租户级实例。

🔗 来源：[GHSA-p92p-rxj5-7p2x](https://github.com/vllm-project/vllm/security/advisories/GHSA-p92p-rxj5-7p2x) · [GHSA-gx7p-2j49-hfq4](https://github.com/vllm-project/vllm/security/advisories/GHSA-gx7p-2j49-hfq4) · [NVD CVE-2026-114055](https://nvd.nist.gov/vuln/detail/CVE-2026-114055)

### 二、深度速览

#### 【AI 赋能防御】

微软对 Storm-0940 / ARTEX 的追踪（厂商来源）把“智能体渗透框架”从韩金融业个案扩展到全球多行业供应链滥用：关键信号不再只是单点漏洞利用成功，而是服务主体登录洪峰、同一网段在密码喷洒与第三方应用凭据滥用之间的连续性，以及 Graph 上的应用凭据改写与角色变更。对企业 SOC 可对照的落地点是：按应用 ID（而非显示名）盘点 ConnectWise 等相关企业应用与服务主体；分开审查成功/失败的服务主体登录；将异常 Graph 写操作与授权变更纳入与 AI 自动化流量相关的狩猎假设，并在厂商给出恢复指引前保持受影响连接禁用、保留取证而非先删企业应用。（厂商威胁情报，非独立司法裁定。）

🔗 来源：[Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2026/10/21/storm-0940-uses-artex-agentic-ai-connectwise-supply-chain-compromise)

#### 【AI 系统风险】

本期控制面失败高度集中在“密码学/会话语义被复用或未隔离”。LiteLLM 把密封密钥与会话令牌放进同一加密上下文，使内部用户可把密文当令牌完成管理员冒充并打到 MCP 命令通道；Strands A2A 则在 HTTP 多智能体接口上丢失按 `context_id` 的会话隔离，使对话历史与持久指令可跨租户串扰。另一条线是“不可信内容进入结构化执行面”：Flexible GraphRAG 的错误转义顺序让摄入文档经抽取模型进入 Cypher；vLLM 在 `trust_remote_code` 下把请求侧 `code_revision` 送进处理器导入路径。共性缓解：密钥域与会话域分离、多租户 Agent/A2A 强制会话隔离或单租户实例、对 RAG/图写入使用参数化查询与转义顺序审计，以及对推理服务默认关闭远程代码信任并校验多模态缓存身份。

🔗 来源：[GHSA-7hp6-4w63-5g45](https://github.com/BerriAI/litellm/security/advisories/GHSA-7hp6-4w63-5g45) · [AWS 2026-146-AWS](https://aws.amazon.com/security/security-bulletins/2026-146-aws/) · [CVE-2026-114053](https://nvd.nist.gov/vuln/detail/CVE-2026-114053)

### 三、今日趋势洞察

AI 网关与 Agent 协议栈的高危面正从“缺认证接口”转向“加密上下文混用、会话隔离失败、预览令牌语义过宽”等控制面设计错误，使一次内部身份或令牌泄露即可升级为管理员与主机命令通道；与此同时，攻击侧已把 ARTEX 类智能体用于供应链应用身份的机器速度滥用，而防御侧对推理/RAG 栈仍需同时应对请求侧代码修订劫持与文档驱动的图查询注入，说明“模型输入污染”和“基础设施默认值”正在同一运营窗口内叠加。

### 四、企业行动清单

- 立即将 LiteLLM 升至对应修复线（1.100.4 / 1.101.3 / 1.102.2 / 1.103.1 或更新），盘点 `internal_user` 账号与 MCP stdio 暴露面，并轮换可能被伪造回放的会话/管理员相关密钥。
- 将 Strands Agents 升至 Python 1.43.0+ 或 TypeScript 1.5.0+；升级前停止向多用户/多租户暴露同一 A2A 实例，改为每租户独立进程。
- 盘点公网或共享集群上的 vLLM：升级至 0.31.0+，关闭非必要的 `trust_remote_code`，对 `/inference` 等多模态入口启用鉴权并限制 `mm_processor_kwargs`。
- 检查 Flexible GraphRAG 是否使用 LangChain+FalkorDB 组合：升级至 0.8.2+，审查摄入文档来源与图写入路径的参数化/转义。
- 按微软公告应用 ID 审查 Entra 中相关第三方应用与服务主体登录/Graph 写操作；将 Royal MCP WordPress 插件升至 1.5.7+，作废并轮换已外发的预览令牌。
