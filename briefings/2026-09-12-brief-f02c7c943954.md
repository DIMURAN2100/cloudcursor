本期资讯主要覆盖东八区 2026-09-10 至 2026-09-12 约 48～72 小时内可核实公开信息；其中 IBM ContextForge 安全公告初始发布于 9 月 9 日、NVD 于 9 月 10–11 日完成收录，按重大 AI 基础设施风险放宽时效一并收录。

### 一、今日要点

**[1] MySQL MCP无鉴权可执行SQL**
📌 类型：AI基础设施CVE

GitHub Advisory 于 2026-09-11 披露 `mysql-mcp-server` 的 Critical 漏洞 CVE-2026-59971（GHSA-rqfv-2mw9-78g2）：当 `MCP_TRANSPORT=sse` 时，服务构造 `SseServerTransport` 未传入 `security_settings`，导致 MCP Python SDK 的 Origin/Host DNS 重绑定防护处于关闭，且默认绑定 `0.0.0.0`、路由无认证。网络攻击者可直接调用 `execute_sql` 执行任意 SQL；本地绑定场景下还可通过浏览器 DNS 重绑定代理触发。默认 stdio 模式不受影响。修复版本为 0.4.2。属已确认代码漏洞公告，未见公开在野利用证据。

🔗 来源：[GitHub Advisory GHSA-rqfv-2mw9-78g2](https://github.com/advisories/GHSA-rqfv-2mw9-78g2)

**[2] FrontMCP OpenAPI引用SSRF绕过**
📌 类型：AI基础设施CVE

同日披露的 High 级漏洞 CVE-2026-59973（GHSA-65h7-9wrw-629c）显示，此前针对 OpenAPI 外部 `$ref` 的主机名黑名单修复（CVE-2026-39885）可被绕过：`mcp-from-openapi` 2.3.0 仍会通过解析、重定向或 IPv4 映射的 IPv6 等路径向 loopback/内网发起后端请求。FrontMCP / `@frontmcp/adapters` 在加载不可信 OpenAPI 规格生成工具时会调用该依赖，多租户或托管部署风险更高。公告给出的修复版本为 `mcp-from-openapi` 2.5.0 与 `frontmcp`/`@frontmcp/adapters` 1.5.0。属补丁绕过类研究确认漏洞，非在野利用通报。

🔗 来源：[GitHub Advisory GHSA-65h7-9wrw-629c](https://github.com/advisories/GHSA-65h7-9wrw-629c)

**[3] ContextForge默认口令可夺管**
📌 类型：AI基础设施CVE

IBM 安全公告（初始发布 2026-09-09，NVD 收录 09-10）披露 IBM ContextForge MCP Gateway CVE-2026-78573：`platform_admin_password`、`default_user_password`、`basic_auth_password` 等配置字段出厂值为公开默认口令 `changeme`；在启用 `api_allow_basic_auth` 或管理 UI（`mcpgateway_ui_enabled`）且未改密时，远程攻击者可获管理权限（IBM CVSS 9.8）。受影响版本 v1.0.0–v1.0.7（公告修复路径升级至 v1.0.10）。默认安装上述特性均为关闭，未开启则无即时暴露。属厂商确认的默认凭据缺陷。

🔗 来源：[IBM 安全公告](https://www.ibm.com/support/pages/node/7286834) · [NVD CVE-2026-78573](https://nvd.nist.gov/vuln/detail/CVE-2026-78573)

**[4] MaxKB提示注入可逃逸沙箱**
📌 类型：AI自身安全

Lasso Security 于 2026-09-10 公开 MaxKB（FIT2CLOUD/1Panel-dev）研究披露 CVE-2026-77521（GHSA-f36j-f34j-h3rx，Critical 10.0）：挂载工具/MCP/Skill 的助手会走 `deepagents` + 主机 Shell 后端，自动暴露未纳入人机确认的 `execute` 能力；不可信聊天或经 RAG/文档的间接提示注入可驱动模型执行命令。源码部署默认沙箱关闭可直接主机执行；官方镜像开启沙箱后仍可被绕过，且容器常以 root 运行。厂商已于 8 月 6 日发布 v2.10.5-lts 修复。属协调披露的研究确认漏洞，非在野攻击通报。

🔗 来源：[Lasso 研究报告](https://www.lasso.security/blog/cve-2026-77521-maxkbypass---from-prompt-injection-to-bypassing-maxkb-agents-sandbox) · [MaxKB 安全公告 GHSA-f36j-f34j-h3rx](https://github.com/1Panel-dev/MaxKB/security/advisories/GHSA-f36j-f34j-h3rx)

**[5] PaperCut发布正式维护补丁**
📌 类型：AI赋能安全

PaperCut 于 2026-09-11（厂商来源/权威媒体）发布 NG/MF 正式维护版本 26.0.5、25.0.13、24.1.10，替换此前针对 CVE-2026-81578/CVE-2026-82078 的全部紧急补丁，并纳入额外硬化。该两洞正被 GreyNoise 等跟踪的 AI Agent 编排战役在野利用，已影响约 440 台实例、395 个组织。THN、Help Net Security 等同步报道补丁替换与战役规模；厂商强调正式 MR 经过完整 QA。属已确认在野利用事件的修复进展更新。

🔗 来源：[The Hacker News](https://thehackernews.com/2026/09/papercut-replaces-emergency-patches.html) · [Help Net Security](https://www.helpnetsecurity.com/2026/09/11/ai-agents-papercut-ng-mf-attack-campaign/) · [PaperCut 紧急安全通告页](https://www.papercut.com/kb/Main/security-bulletin-27-aug-2026-urgent-security-advisory/)

**[6] Sysdig观察八秒手工凭证链**
📌 类型：AI赋能安全

Sysdig TRT 于 2026-09-11 发布研究：在已入 CISA KEV 的 marimo 预认证 RCE CVE-2026-39987 蜜罐中，观察到一名攻击者未使用 LLM Agent，却在约八秒内完成从开放 WebSocket 到堡垒机 SSH 的凭证窃取与横向链；其工具为四小时内手工编写调试，并对植入的提示注入诱饵无反应。研究强调“机器速度”并不等同于“必须有 AI”，同时继续看到带 LLM 指纹的自动化利用并行存在。属厂商威胁研究观测，非新 AI 产品漏洞首发。

🔗 来源：[Sysdig TRT 原文](https://www.sysdig.com/blog/machine-speed-hold-the-ai-hand-rolled-marimo-cve-2026-39987-exploit)

### 二、深度速览

#### 【AI 赋能防御】

PaperCut 战役的防御侧启示在 9 月 11 日进一步清晰：除紧急补丁外，厂商已用正式维护版本收敛回归与加固项，媒体报道强调教育等重度依赖打印管理的行业仍应假设暴露窗口内可能已被踩点。Dark Reading 同日分析将该案放入“AI 进入完整杀伤链”语境，并引用 Google GTIG 关于对手从聊天排错走向多步 Agent 工作流的观察。企业处置不应止于打补丁，还需按厂商指引对疑似失陷的 Application Server 做干净重建与 AD/凭证取证。

🔗 来源：[Dark Reading](https://www.darkreading.com/cyberattacks-data-breaches/papercut-ai-swarm-attack-cyber-kill-chain) · [The Hacker News](https://thehackernews.com/2026/09/papercut-replaces-emergency-patches.html)

Sysdig 对 marimo 利用的对照表明，面向数据科学/笔记本平台的检测基线需要同时覆盖“LLM 痕迹”与“纯手工预置工具包”两类操作者：前者可能触发提示注入诱饵与脚本指纹，后者则以极短的凭证到堡垒链路压缩 SOC 反应时间。建议限制 `/terminal/ws` 暴露、升级至已修复版本，并收紧笔记本主机所持云凭据的作用域。

🔗 来源：[Sysdig TRT 原文](https://www.sysdig.com/blog/machine-speed-hold-the-ai-hand-rolled-marimo-cve-2026-39987-exploit)

#### 【AI 系统风险】

MCP 相关组件在 48 小时内连续出现“传输层未启用安全默认”“规格加载 SSRF 修复被语义绕过”“网关默认口令”三类控制面缺陷，说明 Agent 工具链的危险面已从模型提示层下沉到协议实现与运维配置。MySQL MCP 在 SSE 模式下把任意 SQL 暴露给网络；FrontMCP 则在“看似已修”的 `$ref` 黑名单上留下解析/重定向缝隙；ContextForge 以启动警告代替失败关闭，使默认凭据可在开启管理面后直接夺权。缓解共性包括：禁用公网暴露的 MCP/SSE、强制非默认密钥、对 OpenAPI/工具生成入口做信任分级，并核验修复版本是否真正覆盖绕过路径。

🔗 来源：[GHSA-rqfv-2mw9-78g2](https://github.com/advisories/GHSA-rqfv-2mw9-78g2) · [GHSA-65h7-9wrw-629c](https://github.com/advisories/GHSA-65h7-9wrw-629c) · [IBM 公告](https://www.ibm.com/support/pages/node/7286834)

MaxKB 案例把 OWASP LLM01 提示注入与危险工具能力直连：只要助手挂载工具，Agent 框架即可自动注入 `execute`，沙箱成为唯一（且可绕过的）屏障。对自建 RAG/公开嵌入机器人，应假设检索内容不可信，优先升级至 2.10.5-lts+，关闭或严格审批 Shell 类工具，并以非 root、最小权限运行容器。

🔗 来源：[Lasso 研究报告](https://www.lasso.security/blog/cve-2026-77521-maxkbypass---from-prompt-injection-to-bypassing-maxkb-agents-sandbox) · [MaxKB GHSA](https://github.com/1Panel-dev/MaxKB/security/advisories/GHSA-f36j-f34j-h3rx)

### 三、今日趋势洞察

Agent 攻击面正从“模型是否听话”转向“MCP/网关/工具加载器是否默认安全”，同一窗口内的无鉴权传输、SSRF 修复绕过与默认口令说明协议生态仍按应用原型而非生产边界交付。与此同时，防御方必须同时应对 AI 编排的规模化利用与同等机器速度的手工自动化，补丁与暴露面收敛仍是最短路径。

### 四、企业行动清单

- 清点生产与实验环境中的 `mysql-mcp-server`，确认未以 SSE/`0.0.0.0` 暴露；若使用则升级至 0.4.2+ 并关闭公网访问。
- 审计 FrontMCP / `mcp-from-openapi` 及一切从不可信 URL 加载 OpenAPI 生成 MCP 工具的流水线，升级至公告修复版本并禁止指向内网的 `$ref`。
- 检查 IBM ContextForge MCP Gateway 是否启用 basic auth 或管理 UI；立即改为强口令并升级至 v1.0.10+。
- 排查自建 MaxKB/同类 RAG Agent 是否挂载 Shell/MCP 工具，升级至 v2.10.5-lts+，禁用公开嵌入助手的危险工具。
- 将 PaperCut NG/MF 升至 26.0.5 / 25.0.13 / 24.1.10 正式维护版，对曾暴露的服务器按厂商指引重建并核查 AD 异常权限。
