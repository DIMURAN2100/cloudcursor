# 全球网络安全简报（AI 专题）— 2026-10-09（GMT+8）

本期主要覆盖东八区过去约 72 小时内可核验的公开披露（含 10 月 6–8 日发布的重大漏洞与研究），时效均已对照原始公告或权威报道发布时间核对。

---

### 一、今日要点

**[1] Ollama 模型拉取路径穿越**
📌 类型：AI基础设施CVE

波兰 CERT Polska 于 10 月 8 日协调披露 CVE-2026-103663：Ollama `/api/pull` 对层 digest 校验不足，未认证远程攻击者可借路径穿越将恶意二进制写入模型存储目录之外。在进程对 `/usr/lib/ollama` 具备写权限的常见 Docker 部署中，恶意文件可在下次重启后以 root 加载执行。受影响版本为 0.34.2 起至修复前；官方已在 0.35.0 修复。该问题由 striga.ai 的 Bartłomiej Dmitruk 报告，属已确认漏洞而非在野利用通报。

🔗 来源：[CERT Polska](https://cert.pl/en/posts/2026/10/CVE-2026-103663/) · [NVD CVE-2026-103663](https://nvd.nist.gov/vuln/detail/CVE-2026-103663)

**[2] Banks 提示库角色注入**
📌 类型：AI自身安全

GitHub Advisory / NVD 于 10 月 8 日收录 CVE-2026-107717：Python 提示模板库 Banks（≤2.4.5）的 `Prompt.chat_messages()` 会把渲染结果逐行当作 `ChatMessage` JSON 解析。攻击者可控模板变量若输出形如 `{"role":"system",...}` 的内容，可越界成为 system/assistant/tool 消息，绕过提示边界。同日另披露 DirectoryPromptRegistry 符号链接穿越 CVE-2026-107716（≤2.5.0，修于 2.5.1）。角色注入已在 2.5.0 修复；属库级缺陷，实际影响取决于应用是否把返回消息直接送入 LLM。

🔗 来源：[GitHub Advisory GHSA-hmq2-7hp6-7crh](https://github.com/masci/banks/security/advisories/GHSA-hmq2-7hp6-7crh) · [NVD CVE-2026-107717](https://nvd.nist.gov/vuln/detail/CVE-2026-107717)

**[3] BeamMCP 嵌套模式未强制校验**
📌 类型：AI基础设施CVE

Erlang Ecosystem Foundation CNA 于 10 月 8 日发布 CVE-2026-88257：ScriptKittyOS `beam_mcp`（≥0.1.0、<0.10.1）在 `tools/list` 中广告嵌套对象与数组约束，但 `tools/call` / `prompts/get` 仅校验顶层字段，可让宿主在声明禁止的取值下仍进入 dispatch。同批 CVE-2026-104634（CVSS 2.3）指出布尔参数被规范化为字符串后改变 Elixir 真值分支。影响取决于宿主是否信任已声明 schema；0.10.1 起对文档子集做全深度强制校验。

🔗 来源：[EEF CNA CVE-2026-88257](https://cna.erlef.org/cves/CVE-2026-88257.html) · [NVD CVE-2026-88257](https://nvd.nist.gov/vuln/detail/CVE-2026-88257)

**[4] PraisonAI 部署代码注入**
📌 类型：AI基础设施CVE

NVD 于 10 月 7 日收录 CVE-2026-62176（GHSA 更早公开）：PraisonAI `deploy/api.py` 将 `agents_file` 直接拼入 f-string 生成并执行服务端代码，攻击者若控制该参数（CLI、配置或上游 API）可注入任意 Python；CVSS 9.1，需高权限前提。官方称 ≥4.6.78 已修复。此为部署链路代码注入，与此前已通报的注入防护默认失效问题不同，属独立补丁面。

🔗 来源：[GitHub Advisory GHSA-g6j7-pffp-8whg](https://github.com/MervinPraison/PraisonAI/security/advisories/GHSA-g6j7-pffp-8whg) · [NVD CVE-2026-62176](https://nvd.nist.gov/vuln/detail/CVE-2026-62176)

**[5] Copilot CLI 密码学上下文注入**
📌 类型：AI自身安全

Adversa AI 于 10 月 6 日公开对 GitHub Copilot CLI 的 Cryptographic Context Injection（CCI）研究演示：在 autopilot 模式下让代理抓取恶意页面，以密文载荷诱导其在本地运行时解密，再把解密结果当作可信指令读取 `.env` 等文件并外传；示范中约 28 秒完成外泄。同一明文注入会被拦截；`mai-code-1.1-flash` 约半数试验成功，两款 GPT-5.6 拒绝。GitHub 已确认行为但拒绝按漏洞定级（研究方披露）；属研究演示，未见在野大规模利用报告。The Register、CyberPress 作交叉报道。

🔗 来源：[Adversa AI](https://adversa.ai/blog/cryptographic-context-injection-github-copilot) · [The Register](https://www.theregister.com/ai-and-ml/2026/10/06/zombie-instructions-on-carefully-constructed-web-pages-could-trick-github-copilot-cli-into-sharing-secrets/5301206)

**[6] ARTEX 智能体打击韩金融业**
📌 类型：AI赋能安全

CrowdStrike（厂商来源）于 10 月 7 日发文、iTnews 等 10 月 8 日跟进：未知威胁行为体在 9 月末至 10 月初针对韩国金融机构的活动中，使用开源渗透测试智能体 ARTEX，并观察到与 Claude Code 等编码代理会话相关的痕迹。厂商以中等置信度评估攻击者可能为中文使用者、偏财务动机，并称通过分析 AI 编码工具会话与基础设施线索还原嫌疑人特征。所述归因与工具链细节来自 CrowdStrike 单方情报，应区别于已司法确认的事实。

🔗 来源：[CrowdStrike 博客](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/) · [iTnews](https://www.itnews.com.au/news/crowdstrike-says-china-based-suspect-used-ai-tools-in-south-korean-bank-hacks-629513)

### 二、深度速览

#### 【AI 赋能防御】

CrowdStrike 对韩国金融业攻击的追踪表明，防御方已开始把“AI 编码/渗透智能体会话产物”本身当作威胁情报与取证对象：会话记录、提示语言特征与工具链指纹可用于还原攻击者工作流。与此同时，攻击侧也在用 ARTEX 一类代理加速侦察与利用编排，SOC 需要把异常的代理 CLI 调用、非常规渗透脚本生成与横向移动关联起来。厂商归因仍属中等置信度，企业侧更宜落地可观测指标（代理进程、模型 API 调用、异常工具链），而非仅依赖公开画像。（厂商来源）

🔗 来源：[CrowdStrike](https://www.crowdstrike.com/en-us/blog/unknown-threat-actor-uses-artex-to-target-south-korean-finance/) · [iTnews](https://www.itnews.com.au/news/crowdstrike-says-china-based-suspect-used-ai-tools-in-south-korean-bank-hacks-629513)

#### 【AI 系统风险】

Ollama 拉取链路证明：模型工件分发接口若对 digest/路径校验不严，可从“拉模型”跃迁为写任意文件甚至重启后 root 执行，暴露面覆盖大量本地与 Docker 推理节点。Banks 与 BeamMCP 则分别展示提示结构边界与 MCP schema 契约失效：前者把用户文本抬升为 system 角色，后者让宿主在“自认为已校验”的前提下接收违例参数。Copilot CLI 的 CCI 进一步说明，静态文本护栏无法覆盖代理运行时解密出的指令；缓解应转向行为链监控、禁用高危 autopilot、限制出站与密钥可达路径，而非仅加强提示分类器。

🔗 来源：[CERT Polska](https://cert.pl/en/posts/2026/10/CVE-2026-103663/) · [Banks GHSA](https://github.com/masci/banks/security/advisories/GHSA-hmq2-7hp6-7crh) · [Adversa AI](https://adversa.ai/blog/cryptographic-context-injection-github-copilot)

### 三、今日趋势洞察

本地/边缘推理与 MCP/提示中间件的校验缺口仍在同步暴露：拉取与 schema 层“声明≠强制”会把供应链与工具调用直接连到主机权限。编码与渗透智能体则双向加速——既被红队/犯罪团伙用于实战编排，也被研究者用来演示护栏绕过；企业若只监控传统恶意软件签名而忽略代理会话与出站行为链，将系统性漏检。

---

### 四、企业行动清单

1. 盘点所有对外或内网可达的 Ollama 实例，确认版本 ≥0.35.0，并限制 `/api/pull` 暴露面与容器对 `/usr/lib/ollama` 的写权限。
2. 审计 Python 依赖中的 `banks`：升级至 ≥2.5.1，检查是否将 `chat_messages()` 结果未经角色白名单直接送入 LLM。
3. 对自建 MCP（含 Elixir/beam_mcp）在宿主侧重做嵌套参数校验，升级 beam_mcp 至 ≥0.10.1，勿仅信任 `tools/list` 广告的 schema。
4. 将 PraisonAI 部署链路升至 ≥4.6.78，禁止未消毒的 `agents_file`/CI 配置进入代码生成路径。
5. 对 Copilot CLI 等编码代理：关闭非必要 autopilot、禁止对未信任 URL 的自动抓取、将密钥移出代理可读目录，并监控解密后立即外连的异常行为链。
