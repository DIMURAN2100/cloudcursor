### 一、今日要点

**[1] 官方智能体包被投毒**
📌 类型：AI自身安全

Wiz 于 2026-11-17T17:03:37-05:00 发布分析，并在 2026-11-18 14:00 UTC 更新了原因判断和外传样本统计。分析写明，PyPI 上的微软包 `agent-framework` 于 2026-11-17 20:35 UTC 出现恶意版本 1.26.1，21:08 UTC 出现 1.26.2，约 21:30 UTC 起这两个版本不再提供；Wiz 写明当时的安全版本是 1.26.0，并给出月下载量接近 20 万、周下载量约 4.1 万。两个版本都会在 `site-packages` 放入 `.pth` 文件，Python 每次启动都会执行其中的窃取逻辑，即使业务代码没有导入该包；1.26.1 的文件名为 `agent_framework_meta.pth`，1.26.2 改为 `af_runtime_diag.pth`，并增加对 GitHub Actions OIDC 令牌的收集。Wiz 的更新写明，攻击者似乎掌握了微软发布流水线 ESRP 的客户端证书和私钥：来自 AWS 的第一次发布被 IP 过滤拒绝，来自微软地址空间的第二次发布成功；证书来源尚未得知，工具自报为开源渗透框架 Cairn。同一更新对攻击者所用免费层 webhook 上保存的 50 条请求做了分类：4 条来自攻击者自己的机器，29 条像沙箱、厂商扫描或测试，其余 17 条只对应 3 个不同的成功外传。以上原因判断和样本分类是 Wiz 的厂商分析。本简报采集时，PyPI JSON 的当前版本为 1.26.0，wheel 上传时间为 2026-11-12T18:25:37Z，发布列表中已没有 1.26.1 和 1.26.2。

🔗 来源：[Wiz](https://www.wiz.io/blog/malicious-version-of-microsofts-agent-framework-published-to-pypi) · [The Hacker News](https://thehackernews.com/2026/11/attackers-compromise-microsofts-agent.html) · [PyPI](https://pypi.org/project/agent-framework/)

**[3] 假爬虫探测密钥文件**
📌 类型：AI自身安全

Tin Computer 研究员 Ege Demir 于 2026 年 11 月 18 日发表观察，时间跨度写明为 2026 年 9 月下旬至 11 月 18 日，对象是该公司自己运行的 10 个网站。报告把名为 Octopus 的扫描写成：每次请求轮换 32 个人工智能爬虫名称，并为每个站点新租一台 Google Cloud 主机，样本中有 15 个区域的 97 台机器，多数存活不到一小时；访问以路径 `/z9x8c7v6b5-debug-trigger-` 加主机名开始，随后请求大量密钥文件。名为 Gecko 的扫描使用截断后的浏览器标识，请求 Claude Code、Codex、Cursor 和 Gemini CLI 存放密钥的路径，页面点名 `/.claude/settings.json` 和 `/.cursor/mcp.json`；人工智能工具路径在五周内从 4 条增至 26 条，11 月 12 日曾换过一天的新清单，之后只保留令牌文件。报告写明操作者尚未证实，并把 GreyNoise、Fastly 和 Cequence 更早的假爬虫报告列为已有观察。这是研究者对其自有站点的测量，不是全网受害统计。

### 二、深度速览

#### 【AI 赋能防御】

Wiz 在 11 月 18 日 14:00 UTC 的更新里给出的是一条外传地址上的样本账，不是全球受害人数。该地址位于 webhook.site 免费层。Wiz 写明免费层最多保存 100 条请求、7 天后过期，并确认攻击者所用地址属于免费层、最多留下 50 条。这 50 条中，4 条来自攻击者自己的机器和攻击过程，29 条被归到沙箱、厂商扫描和测试，剩下 17 条只对应 3 个不同的成功外传。超过保存上限或返回 410、429 的请求不在这 50 条里，因此 3 不能写成全部安装者的受害数。Tin Computer 给出的是日志里的稳定特征：Octopus 每次都以 `/z9x8c7v6b5-debug-trigger-` 加主机名开头，随后在同一连接、数秒内换用 32 个爬虫名称。报告写明，没有真实爬虫会这样做。

🔗 来源：[Wiz](https://www.wiz.io/blog/malicious-version-of-microsofts-agent-framework-published-to-pypi) · [Tin Computer](https://tin.computer/blog/fake-ai-crawler-secrets-scanners)

#### 【AI 系统风险】

1.26.1 和 1.26.2 的差异在触发文件，不在窃取目标的大类。两个版本都收集名称中带令牌、密钥、密码或云厂商字样的环境变量，以及 Azure CLI、包管理器、Git、Docker、Hugging Face 和 `.env` 一类文件；1.26.2 把 GitHub Actions 中可写出 `id-token` 的工作流也纳入，并请求可交换 Azure 访问权限的 OIDC 令牌。Wiz 写明，只按 1.26.1 的文件名搜索会漏掉 1.26.2。原因判断停留在厂商分析：ESRP 的客户端证书和私钥似乎已被使用，第一次发布因来源 IP 失败，第二次从微软地址空间成功，工具自报为 Cairn。证书如何离开微软，页面写明尚未得知。The Hacker News 于 11 月 18 日的报道仍把发布权限的取得方式写成不清楚，与 Wiz 同日较晚的更新不是同一句话。

Stormshield 把新的部分放在后台和关联，而不是另一条独立的漏洞编号。招聘邮件、会议注册和包裹通知都把人引向仿冒站点；供应链一侧，报告引用的是 SafeDep 已于 11 月 3 日写下的 `antd-img-crop` 伪造提交，npm 包本身未被写成受影响。约 50 个品牌这个数字，是报告对仿冒规模的量化。与朝鲜相关入侵集合的对应，报告写成技术重叠和相似性。

### 四、企业行动清单

- 盘点 lockfile、CI 日志、虚拟环境和容器镜像中的 `agent-framework`。出现 1.26.1 或 1.26.2 的，卸掉这两个版本并固定到 1.26.0。同时在 `site-packages` 查找 `agent_framework_meta.pth`、`agent_framework_meta/_telemetry.py`、`af_runtime_diag.pth` 和 `af_runtime_diag.py`。Wiz 写明，这些文件所在环境里此后每一次 Python 启动都会执行窃取逻辑。从一台干净系统轮换该主机和运行器当时能读到的 Azure、GitHub、Hugging Face 和 OpenAI 令牌，并复查 Azure 登录与活动日志。Wiz 写明，被取走的托管身份令牌和经 OIDC 交换的令牌最长 24 小时有效。
- 在代理和 DNS 日志中检索 Wiz 公布的外传地址 `webhook[.]site/d381fd80-ec62-42ad-8f5c-d1b15103c9bb`。该分析写明，返回 200 表示该主机的数据被接受，410 或 429 表示当时未被这个免费层地址保存。免费层账本里的 3 个成功外传，只覆盖已保存的 50 条请求。
- 审计安装过 1.26.2、并且工作流具有 `id-token: write` 的 GitHub Actions。Wiz 写明该版本会为 `api://AzureADTokenExchange` 和 Azure 资源管理请求 OIDC 令牌。核对信任这些仓库和工作流的 Entra ID 联合凭据，以及对应应用注册的登录记录。轮换暴露给这些作业的仓库和组织机密。
- 在 Web 访问日志中查找 Tin Computer 写明的路径前缀 `/z9x8c7v6b5-debug-trigger-`。同一连接内连续换用 GPTBot、ClaudeBot 或其他人工智能爬虫名称的，按该报告的描述归到 Octopus，不要把 User-Agent 本身当作放行依据。同时检查站点是否对 `/.claude/settings.json` 和 `/.cursor/mcp.json` 返回过内容。
- 核对以人工智能或区块链公司名义发来、并要求克隆仓库或在本机执行安装的招聘邮件、会议注册和包裹通知。Stormshield 写明这三类场景与带毒仓库汇合到同一套基础设施；`antd-img-crop` 的伪造提交已由 SafeDep 于 2026 年 11 月 3 日记录，报告写明 npm 包本身未受影响。执行前与品牌的官方域名核对发件人和仓库所有者。
