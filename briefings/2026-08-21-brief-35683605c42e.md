### 一、今日要点

**[1] Splunk MCP 反序列化 RCE**
📌 类型：AI基础设施CVE

Splunk 于 2026-08-19 发布安全加固公告 SVD-2026-0808，披露 Splunk MCP Server app 1.2.1 之前版本存在 CVE-2026-76404：持有 admin 角色的用户可因凭据管理组件对存储数据缺少类型校验、反序列化不可信对象，在底层操作系统执行任意命令。官方给出 CVSSv3.1 9.1（Critical），临时缓解为关闭或移除该 MCP Server app，并升级至 1.2.1。属厂商已确认漏洞与补丁事实，本期未见独立在野利用通报。

🔗 来源：[Splunk Advisory SVD-2026-0808](https://advisory.splunk.com/advisories/SVD-2026-0808) · [NVD CVE-2026-76404](https://nvd.nist.gov/vuln/detail/CVE-2026-76404)

**[2] Google 公开 AVDH 多智能体挖洞**
📌 类型：AI赋能安全

Google Threat Intelligence Group / Mandiant 于 2026-08-18 首次公开内部运行约 10 个月的 Agentic Vulnerability Discovery Harness（AVDH）架构蓝图：以 Google ADK 编排 Explorer、威胁建模、入口发现与富化等顺序智能体，并在关键节点插入人工顾问校验。官方称在涉及被盗企业代码仓的应急响应中，约 48 小时内确认逾 100 个真正阳性的严重漏洞；累计覆盖数千万行代码、数千次流水线，已产出含 CVE-2026-13242、CVE-2026-55803 在内的 12 个已分配 CVE，另有约十数个处于协调披露。定位为点时高强度审查与红队加速器，并与持续扫描类能力（如 CodeMender）互补；效果数据为 Google 官方披露。

🔗 来源：[Google Cloud Threat Intelligence](https://cloud.google.com/blog/topics/threat-intelligence/staying-ahead-of-adversarial-ai-through-agentic-source-code-review) · [GBHackers 报道](https://gbhackers.com/google-mandiant-ai-agents-find-over-100-critical-vulnerabilities)

**[3] n8n MCP 路径穿越致 RCE**
📌 类型：AI基础设施CVE

NVD 于 2026-08-20 收录 CVE-2026-77068：n8n 在 2.33.4 之前及 2.34.x 的 2.34.1 之前，用于 MCP 节点 schema 加载的 `@n8n/workflow-sdk` 将攻击者可控的节点类型字符串直接映射为 schema 模块路径且未过滤路径穿越，具备 global:member 的认证用户可引用恶意文件并在 n8n 主进程执行代码。同日并列收录 CVE-2026-77073（MCP `create_workflow_from_code` 在认证类型为表达式时可绕过校验、持久化跨项目凭据引用）。项目安全公告早于 08-05 已发布，本期新进展为 CVE/NVD 入库与公开可引用编号；修复版本为 2.33.4 / 2.34.1 及以上。

🔗 来源：[NVD CVE-2026-77068](https://nvd.nist.gov/vuln/detail/CVE-2026-77068) · [GitHub Advisory GHSA-6h4x-896x-fw5m](https://github.com/n8n-io/n8n/security/advisories/GHSA-6h4x-896x-fw5m) · [NVD CVE-2026-77073](https://nvd.nist.gov/vuln/detail/CVE-2026-77073)

**[4] MCP 明文密钥与权限膨胀风险**
📌 类型：AI自身安全

The Hacker News 于 2026-08-17 前后刊发针对 MCP 服务器运营风险的分析（非单一 CVE）：MCP 使智能体通过非人类身份（API 密钥/令牌）触达内部文档与云资源，但大量部署将长期有效凭据以明文写入本地配置、权限过宽，并叠加提示注入后扩大数据外泄与工具滥用面。文章强调需将 MCP 纳入与对外可达控制面同等的清单、密钥轮换与最小权限治理。属权威媒体基于行业实践的风险综述，非宣称特定在野大规模入侵事件。

🔗 来源：[The Hacker News](https://thehackernews.com/2026/08/how-mcp-servers-can-expose-enterprise.html)

**[5] Neo.mjs 文件系统 MCP 命令注入**
📌 类型：AI基础设施CVE

NVD 于 2026-08-20 公布 CVE-2026-18482：neo.mjs 的 `ai/mcp/server/file-system` 中，`checkSyntax()` 与 `runPlaywrightTest()` 将调用方可控的 `absolutePath` 不安全拼入 shell 命令，可在诱导智能体调用工具时造成任意 OS 命令执行。独立研究披露称影响约至 13.1.0 及以下本地 stdio 部署，CVSS 约 7.8；修复提交 `88c77fc` / `5acc564e` 见于 2026-07 代码修复，撰文时指出 npm 发布滞后风险。属 NVD 新收录与研究确认机制，原始补丁早于 72 小时窗口，写入时按“新公开 CVE 记录”处理而非全新零日爆发。

🔗 来源：[NVD CVE-2026-18482](https://nvd.nist.gov/vuln/detail/CVE-2026-18482) · [novice-22 分析](https://novice-22.com/posts/neo-mjs/)

**[6] 工作流自动化 MCP 凭据越权**
📌 类型：AI基础设施CVE

与 n8n 同日 NVD 条目 CVE-2026-77073 显示：在 MCP Bearer API 密钥有效且知晓目标凭据 ID 的前提下，攻击者可利用表达式型认证配置，将未授权的跨项目凭据引用写入工作流，扩大自动化平台上的凭据横向移动面。该问题与路径穿越 RCE（77068）同属 MCP 工具链信任边界失效，应一并升级并审计 MCP 暴露的工作流创建/schema 加载接口。

🔗 来源：[NVD CVE-2026-77073](https://nvd.nist.gov/vuln/detail/CVE-2026-77073) · [GitHub Advisory GHSA-vfrj-582q-mvcp](https://github.com/n8n-io/n8n/security/advisories/GHSA-vfrj-582q-mvcp)

### 二、深度速览

#### 【AI 赋能防御】

AVDH 的核心不是“换一个更强的模型”，而是把威胁建模、入口筛选、上下文富化与人工门禁写成确定性编排：轻量模型做广覆盖入口扫描，重量级推理与顾问审核集中在高价值路径，从而在代码被盗后的黄金响应窗口内压缩可利用面。Google 同时给出可复用的架构图与“人类专家注入管线”原则，对已具备代码仓访问权限的 SOC/PSIRT 团队，提供了可对照自建的多智能体漏洞发现样板；其 100+ 真阳性与 12 个 CVE 为厂商自报成效，外部复现成本与基准集仍可能难以对齐。

🔗 来源：[Google AVDH 蓝图](https://cloud.google.com/blog/topics/threat-intelligence/staying-ahead-of-adversarial-ai-through-agentic-source-code-review)

Splunk 将 MCP Server 作为可安装 app 纳入传统企业安全栈后，反序列化 RCE 提醒：AI 工具面一旦获得高权限角色，其缺陷严重度会按“安全平台自身”而非“实验性插件”计价。应急顺序上，应优先清点生产 Splunk 是否启用 MCP app，再决定升级或卸载，而不是仅依赖通用 LLM 护栏。

🔗 来源：[Splunk SVD-2026-0808](https://advisory.splunk.com/advisories/SVD-2026-0808)

#### 【AI 系统风险】

n8n 与 Neo.mjs 两条线共同说明：MCP 工具参数若直接进入文件系统路径或 shell，传统路径穿越/命令注入会以“智能体工具调用”形式复活；认证成员或本地开发者身份往往已足够触发。缓解需在协议层做参数白名单与沙箱，而不是依赖模型拒绝恶意自然语言。n8n 需升级到 2.33.4/2.34.1+，并限制 MCP Bearer 与成员角色可触达的 schema/工作流 API；Neo.mjs 应确认是否已拉取含修复提交的构建，避免继续运行仅“路径沙箱、命令未转义”的旧 MCP 文件服务器。

🔗 来源：[NVD CVE-2026-77068](https://nvd.nist.gov/vuln/detail/CVE-2026-77068) · [NVD CVE-2026-18482](https://nvd.nist.gov/vuln/detail/CVE-2026-18482)

MCP 明文密钥与过宽工具权限使“配置即攻击面”：即便没有新 CVE，未清单化的 MCP 进程也会把云密钥与内部 API 暴露给可被提示注入驱动的代理。运营上应把 MCP 服务器视作持有机器身份的服务端点，强制密钥托管、短生命周期令牌、审计日志与禁止默认全权限工具集。

🔗 来源：[The Hacker News](https://thehackernews.com/2026/08/how-mcp-servers-can-expose-enterprise.html)

### 三、今日趋势洞察

企业安全与自动化平台正把 MCP 从“实验连接器”推进到高权限生产组件，因此反序列化、路径穿越与跨项目凭据等经典缺陷一旦落在 MCP 工具实现上，会直接换算成平台级 RCE 或凭据平面失陷。与此同时，防御方开始公开可复制的多智能体漏洞发现编排，攻防两侧都在把“代理管线 + 人工门禁”作为加速杠杆，使代码暴露后的 48 小时窗口成为新的关键竞赛区间。

### 四、企业行动清单

- 立即盘点生产 Splunk 是否安装 MCP Server app，受影响实例升级至 1.2.1 或按公告临时卸载。
- 将 n8n 升至 2.33.4 / 2.34.1 及以上，并复核 MCP Bearer、成员角色对 `create_workflow_from_code` 与节点 schema 加载的可达范围。
- 建立 MCP 服务器与机器身份清单：清理明文配置中的长期密钥，轮换已暴露令牌，关闭未使用的 STDIO/远程 MCP 端点。
- 对本地开发用文件系统类 MCP（含 neo.mjs 等）核对补丁构建，禁止将未转义路径参数传入 shell 的工具默认对智能体开放。
- 若承担代码泄露应急或红队职责，对照 AVDH 公开蓝图评估是否可为关键仓建立“威胁建模门禁 + 并行入口扫描”的点时审查流水线。
