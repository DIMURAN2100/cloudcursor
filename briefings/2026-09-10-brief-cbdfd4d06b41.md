### 一、今日要点

**[1] 美警告工业级知识蒸馏**
📌 类型：AI治理合规

CISA、NSA 与 FBI 于 9 月 8 日发布联合网络安全公告（AA26-251A），指控多家中国 AI 企业自 2024 年末以来，对 Claude、GPT、Gemini、Grok 等美国前沿模型实施“工业级”知识蒸馏，系统性抽取推理、编码与智能体等受限能力，并称蒸馏已成为其模型研发的核心路径而非补充。公告点名 DeepSeek、Moonshot AI、阿里巴巴、MiniMax、StepFun、Z.AI，并描述经“中转站”代理、共享高级订阅与跨通路自动故障切换等规避地域限制与检测的手法；同时建议提供商加强异常用量检测、对可疑蒸馏请求实施响应扰动，并跨厂商共享情报。此为美方政府威胁通报与归因判断，不等同于经第三方独立审计的逐条技术取证。

🔗 来源：[CISA 联合公告 AA26-251A](https://www.cisa.gov/news-events/cybersecurity-advisories/aa26-251a) · [CISA 新闻稿](https://www.cisa.gov/news-events/news/cisa-nsa-and-fbi-warn-china-based-ai-companies-targeting-us-ai-models-industrial-scale-knowledge) · [Help Net Security](https://www.helpnetsecurity.com/2026/09/09/china-malicious-ai-knowledge-distillation-against-us-companies/)

**[2] DeepSeek沙箱可自解除**
📌 类型：AI自身安全

OX Research 披露并经 VulnCheck 于 9 月 8 日登记 CVE-2026-82533（CVSS 9.4）：DeepSeek 开源编码智能体运行时 DeepSeek Harness 的本地控制面 API 仅依据客户端可伪造的 Host 头判定信任，沙箱限制文件写但未隔离回环网络。在默认安装下，经提示注入诱导的智能体可用单条命令将会话升至 `danger-full-access`，关闭沙箱与审批提示；若端口经隧道暴露，未认证调用者还可导出全部会话日志。受影响版本为 0.1.1-rc.2 及更早；修复于 0.1.2-alpha.1（GitHub），npm 上首个含修复包为 0.1.2-alpha.2，当前建议升级至 0.1.2-rc.1 或更新。属已确认漏洞与研究演示链路，公开报道未证实大规模在野利用。

🔗 来源：[OX Research](https://www.ox.security/blog/cve-2026-82533-deepseek-harness-ai-agent-sandbox-escape/) · [VulnCheck 公告](https://www.vulncheck.com/advisories/deepseek-harness-alpha-1-authentication-bypass-via-host-header-spoofing) · [The Hacker News](https://thehackernews.com/2026/09/deepseek-harness-flaw-let-ai-agents.html)

**[3] 窃密日志可重放AI令牌**
📌 类型：AI自身安全

Okta 威胁情报于 9 月 8 日发布研究报告（The Hacker News 9 月 9 日报道）：分析 2026 年 8 月 2 日 Telegram 释放的约 7GB 信息窃取木马日志（涉及 5,871 台主机、162 个国家），发现大量可重放的 AI/身份会话令牌与 API 密钥，可绕过基于口令与 MFA 的登录流程直接接入 Google、Microsoft、Anthropic、Cursor 等服务及部分 LLM API。研究统计显示样本中含数千枚未过期会话相关令牌，以及仍有效的 Gemini、OpenAI、Groq、OpenRouter 等 API 密钥；并指出地下市场已出现专门解析 AI 会话的工具与“反检测”浏览器复用链路。此为厂商对公开窃密样本的分析，非某一具体企业被入侵的确认通报。

🔗 来源：[Okta Threat Intelligence](https://www.okta.com/blog/threat-intelligence/signing_in_without_actually_signing_in) · [The Hacker News](https://thehackernews.com/2026/09/infostealer-logs-expose-replayable-ai.html)

**[4] MCP版本参数触发RCE**
📌 类型：AI基础设施CVE

GitHub Advisory（2026-09-09）披露高危问题：`functype-mcp-server` 的 `set_functype_version` 工具将不受约束的 `version` 字符串直接拼入 `pnpm add functype@<version>`，随后动态导入新安装包，攻击者可通过 MCP `tools/call` 利用 `file:`/`npm:` 等别名语法安装任意包并在 MCP 进程内执行代码（顾问评级 High，CVSS 7.8）。stdio 模式下默认无认证。受影响版本 ≤ 1.4.3，已在 1.4.4 修复。属已确认组件漏洞，公开信息未见在野利用证据。

🔗 来源：[GitHub Advisory GHSA-wcjj-9m6g-2fr2](https://github.com/advisories/GHSA-wcjj-9m6g-2fr2)

**[5] Nuxt模块泄露Ollama密钥**
📌 类型：AI基础设施CVE

同日 GitHub Advisory 披露：`nuxt-ollama` 1.2.26 起将含 `api_key` 在内的模块选项无条件写入 Nuxt **public** runtime config，导致密钥随 SSR HTML 中的 `window.__NUXT__` 明文暴露；未认证访客一次 GET 即可盗取 Ollama 云端 API 密钥并冒用额度。受影响范围为 ≥1.2.26 且 <1.3.1，修复版本 1.3.1。适用于将密钥写入前端可序列化配置的部署场景，属配置/设计缺陷类已确认漏洞。

🔗 来源：[GitHub Advisory GHSA-fxg7-897c-57mp](https://github.com/advisories/GHSA-fxg7-897c-57mp)

**[6] 台湾启动AI风险盘点**
📌 类型：AI治理合规

据 iThome 9 月 9 日报道，台湾数位发展部次長侯宜秀宣布：在《人工智能基本法》施行及 7 月公布 AI 风险分类框架后，数发部已联合卫福、法务、经济、教育、金管会、交通、NCC、劳动等八大部会启动 AI 应用风险盘点，目标年底完成八部会四步骤盘点，并争取 2027 年 6 月底前完成各部会第一轮法规调适。框架采“分类但不分级”，强调由主管机关依场景设计措施，并对高风险应用依基本法落实救济、补偿或保险等最低要求；风险检核系统已登录 144 个应用情境，个案暂不公开。此为施政推进报道，正式文本与部会细则仍以官方后续发布为准。

🔗 来源：[iThome](https://www.ithome.com.tw/news/178826)

### 二、深度速览

#### 【AI 赋能防御】

Okta 报告把防御重点从“防撞库”前移到“令牌生命周期”：对 AI 控制台与 API 实施会话重放检测、短时 OAuth 访问令牌、密钥用量上限与 IP 允许列表，并避免明文 API Key 写入智能体配置文件。结合其样本统计，企业可将 AI 订阅账号、浏览器会话与开发机密钥一并纳入信息窃取木马泄露监测范围，发现命中后触发吊销与强制重认证。上述为厂商威胁情报与产品化控制建议，落地效果取决于身份平台与端点防护的实际覆盖。

🔗 来源：[Okta Threat Intelligence](https://www.okta.com/blog/threat-intelligence/signing_in_without_actually_signing_in)

CISA 联合公告同时给出面向模型提供商的检测与反制清单：监控全天候无人类波动的用量、异常订阅—API 吞吐比、新账号瞬时打满配额，以及对可疑蒸馏流量实施响应扰动、差分隐私与跨平台指标共享。对使用第三方聚合 API 或“中转”接入的企业客户，亦应审计密钥是否被用于异常高并发、跨地域抽样子请求。

🔗 来源：[CISA AA26-251A](https://www.cisa.gov/news-events/cybersecurity-advisories/aa26-251a)

#### 【AI 系统风险】

DeepSeek Harness 案例表明：仅限制文件写、却保留回环网络与无认证本地控制面，会使“沙箱”在提示注入后变成可自我改写的权限开关；修复引入启动令牌与签名 Cookie 后，文档仍提示读与网络未完全约束，企业不应把单一沙箱当作不可信代码的唯一边界。

🔗 来源：[OX Research](https://www.ox.security/blog/cve-2026-82533-deepseek-harness-ai-agent-sandbox-escape/)

同日 MCP 与 Ollama 前端模块两条 Advisory，分别对应“工具参数直达包管理器安装+动态导入”与“密钥误入 public 运行时配置”两类经典失败模式：前者把 MCP 工具面升级为 RCE 入口，后者把云推理密钥暴露给任意访客。对内网 stdio MCP 与面向公网的 Nuxt/Ollama 集成，均应立即核版本并限制工具面可达性。

🔗 来源：[GHSA-wcjj-9m6g-2fr2](https://github.com/advisories/GHSA-wcjj-9m6g-2fr2) · [GHSA-fxg7-897c-57mp](https://github.com/advisories/GHSA-fxg7-897c-57mp)

#### 【全球治理与标准】

美方三国联合公告将恶意蒸馏升格为国家级网络安全通报，并把 MITRE ATLAS 映射与供应商协同检测写入正式建议，显示模型能力窃取已进入政府—产业联防议程。台湾侧则推进基本法落地后的跨部会风险盘点与法规调适时间表，采取不同于欧盟 AI Act 固定分級的“分类但不分級”路径。两地动作层级不同，但都把“可审计的治理流程”从原则文件推进到执行日历。

🔗 来源：[CISA AA26-251A](https://www.cisa.gov/news-events/cybersecurity-advisories/aa26-251a) · [iThome](https://www.ithome.com.tw/news/178826)

### 三、今日趋势洞察

模型访问权本身正在成为并行于漏洞利用的高价值资产：一端是政府通报的工业级蒸馏与跨通路规避，另一端是窃密日志中可重放的会话令牌与明文 API 密钥，二者都把“合法通道滥用”推到防御核心。与此同时，编码智能体运行时与 MCP/前端集成组件连续暴露信任边界缺陷——沙箱可自关、工具参数可 Renote 装包、密钥可进 public 配置——说明 Agent 工具链的本地控制面安全，已与模型对齐、提示过滤同等紧迫。

### 四、企业行动清单

1. 核对 DeepSeek Harness / 第三方桌面封装版本，升级至含认证修复的 0.1.2-alpha.2（或更新的 0.1.2-rc.1+），并关闭不必要的端口转发与隧道。
2. 盘点 `functype-mcp-server`、`nuxt-ollama` 等依赖：分别升至 ≥1.4.4 与 ≥1.3.1，审查 MCP 工具是否接受未校验版本/包名参数，检查前端 HTML 是否泄露推理密钥。
3. 对 AI 控制台与 API：启用会话异常/重放监测，为密钥设置用量上限与来源限制，将浏览器与开发机配置中的明文 API Key 迁入密钥库或短时 OAuth 流程。
4. 面向模型平台与 API 聚合层：建立蒸馏类滥用检测规则（全天候高吞吐、新账号打满配额、跨地域中转特征），并准备可疑流量的响应扰动与跨团队通报通道。
5. 在运营于台湾或对接台机关采购的业务中，对照数发部风险分类框架与检核系统要求，梳理高风险 AI 应用的责任归属与救济/保险安排时间表。
