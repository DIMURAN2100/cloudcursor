# 全球网络安全简报（AI 专题）— 2026-09-16（GMT+8）

本期主要覆盖过去约 48 小时内可核验动态；中国国家安全部部长署名文章原发于 9 月 13 日，因属高规格治理表态，按重大事件放宽至约 72 小时收录。

### 一、今日要点

**[1] PraisonAI MCP 未授权执行**
📌 类型：AI基础设施CVE

开源多智能体框架 PraisonAI 被披露默认 UI 在 `0.0.0.0` 暴露 `POST /api/mcp/connect`，未强制认证即可接受调用方控制的 `command`/`args`，并由 Stdio MCP 客户端以 UI 服务账户启动本地进程（CVE-2026-57124，CVSS 9.8）。同批还披露 LLM 可控路径的 `multiedit` 任意文件读写（CVE-2026-57145）等缺陷。官方分别在 4.6.59、4.6.62 修复；暴露面面向可达网络的未加固 UI 部署。

🔗 来源：[CVE-2026-57124](https://www.cve.org/CVERecord?id=CVE-2026-57124) · [GitHub Advisory GHSA-p75f-6fp4-p57w](https://github.com/MervinPraison/PraisonAI/security/advisories/GHSA-p75f-6fp4-p57w)

**[2] mcp-gitlab 多缺陷连发**
📌 类型：AI基础设施CVE

npm 包 `@zereight/mcp-gitlab` 于 9 月 15 日连续发布安全公告：动态 `X-GitLab-API-URL` 可导致 SSRF 并外带 Private-Token（CVE-2026-61559）；Streamable HTTP 传输缺少有效 Host/Origin 校验，遭 DNS 重绑定可达本地 MCP（CVE-2026-61568）；另有 GraphQL 读写只读/项目白名单绕过、未认证传输与会话耗尽等问题（GHSA-5648-rgj9-v224）。影响将 GitLab 能力暴露给 LLM 代理的开发与自动化环境。补丁版本分别指向 2.1.27 / 2.1.30。

🔗 来源：[GHSA-2h44-8472-frjj](https://github.com/advisories/GHSA-2h44-8472-frjj) · [GHSA-vmp7-252j-cwp7](https://github.com/advisories/GHSA-vmp7-252j-cwp7)

**[3] Casdoor MCP 跨组织越权**
📌 类型：AI基础设施CVE

身份与访问管理平台 Casdoor（至 4.4.0）在 `/api/mcp` 用户管理工具路径上存在授权绕过（CVE-2026-91998）：任意应用的 `clientId`/`clientSecret` 被解析为 `app/<name>` 主体后，授权检查对 `app` 所有者无条件放行，跳过组织范围。攻击者可跨组织枚举用户（含密码盐）、创建管理员、修改或删除账户。属研究披露的已确认缺陷，公告时未见统一 patched 版本表述，需跟进官方发行。

🔗 来源：[CVE-2026-91998](https://www.cve.org/CVERecord?id=CVE-2026-91998) · [研究者技术说明](https://github.com/geo-chen/oss/blob/main/casdoor.md)

**[4] 黑产售卖无审查 Luciferus**
📌 类型：AI自身安全

Sophos CTU（厂商来源）报告，Exploit 黑客论坛自 8 月 24 日起出现名为 Luciferus 的订阅制“无道德限制” AI 服务广告，定位为替代对 ChatGPT/Claude 的越狱；卖方宣称 1200 亿参数专有模型，Sophos 以低置信度评估可能基于阿里开源 Qwen 系微调。研究人员向 Junior 档位请求简单 Python 远控木马示例后，服务返回俄语说明与源代码（未实际运行验证）。9 月 14–15 日研究与安全媒体公开报道，表明地下市场正将“先天无护栏”模型作为稳定商品化能力。

🔗 来源：[Sophos 研究博客](https://www.sophos.com/en-us/blog/uncensored-luciferus-ai-service-advertised-underground) · [Help Net Security](https://www.helpnetsecurity.com/2026/09/15/luciferus-uncensored-ai-service-hacking-forum/)

**[5] 微软发布人本 AI 准则草案**
📌 类型：AI治理合规

Microsoft AI 发布面向 MAI 模型的《Humanist AI Code of Conduct》首版草案，开放约六周公众咨询（至约 10 月 25 日），拟于年内修订并用于指导 2027 年起的模型开发；当前模型尚未按该准则训练。准则强调人类控制、指令层级（准则优先于运营方与用户指令）及不可覆盖的绝对约束，覆盖大规模杀伤性武器援助、进攻性网络行动、有害深度伪造与大规模操纵等；同时允许经授权的防御性安全研究。iThome 与 Help Net Security 同步报道。

🔗 来源：[Microsoft AI 官方说明](https://microsoft.ai/news/mai-code-of-conduct/) · [准则草案文本](https://microsoft.ai/code-of-conduct/)

**[7] Cloudflare 分离训练爬取**
📌 类型：AI治理合规

Cloudflare 于 9 月 15 日推出 “Disallow AI Training” 设置，使站点可在保留搜索索引的同时拒绝同一混合用途爬虫用于模型训练，并将 Apple、Google、Microsoft 等符合透明度与选择权要求的运营方标为 “Accountable”。官方称约 17% 站点启用某种训练阻断机制，而阻断搜索不足 1%。此为平台侧数据与爬虫治理能力更新，非漏洞披露。

🔗 来源：[Cloudflare 官方博客](https://blog.cloudflare.com/accountable-mixed-use-ai-crawlers/)

### 二、深度速览

#### 【AI 赋能防御】

Cloudflare 将爬虫用途拆为 Search / Training / Agent，并以网络侧识别与 Bot Preference Sync 落实 robots 偏好，使“拒绝训练但不牺牲搜索可见性”成为可执行控制；同时要求 Accountable 运营方提供训练退出、摘要退出路径与 URL 级可见性。对企业安全与法务团队而言，这把 AI 训练数据合规从单靠 robots.txt 声明，推进到可阻断、可审计的配置项，适合对照内容变现模式调整默认策略。

🔗 来源：[Cloudflare 官方博客](https://blog.cloudflare.com/accountable-mixed-use-ai-crawlers/)

Sophos 对 Luciferus 的地下广告监测显示，威胁情报工作流正把“无审查 LLM 即服务”纳入常规黑市观察对象：关注论坛帖、定价档位差异、是否直接应答恶意软件请求，以及底座模型归因置信度。此类情报有助于 SOC 更新对攻击者能力获取路径的假设，但当前公开材料仍以广告与探针响应为主，不宜外推为已大规模实战战役。

🔗 来源：[Sophos](https://www.sophos.com/en-us/blog/uncensored-luciferus-ai-service-advertised-underground)

#### 【AI 系统风险】

PraisonAI 与 mcp-gitlab 本周公告共同指向同一机制：把 MCP 当作“本地工具总线”时，默认监听、缺认证、调用方可控命令/URL/路径，会把代理权限直接映射为宿主机或令牌窃取能力。CVE-2026-57124 说明即使后续 MCP 握手失败，进程也可能已启动；mcp-gitlab 的动态 API URL 与 DNS 重绑定则说明浏览器可达的本地传输同样危险。缓解重点是：MCP/UI 禁止默认公网绑定、强制认证与 Origin/Host 校验、命令与路径白名单、禁用未审查的动态上游 URL。

🔗 来源：[PraisonAI GHSA-p75f-6fp4-p57w](https://github.com/MervinPraison/PraisonAI/security/advisories/GHSA-p75f-6fp4-p57w) · [GHSA-vmp7-252j-cwp7](https://github.com/advisories/GHSA-vmp7-252j-cwp7)

Casdoor 的 `/api/mcp` 案例进一步说明：为智能体新增的管理工具若复用“应用凭据 = 全局信任”的捷径，会把 MCP 变成跨租户 IAM 后门。影响对象是多组织部署的 Casdoor 及任何将 MCP 用户 CRUD 暴露给自动化代理的集成。在官方补丁明确前，应限制应用密钥分发、关闭或隔离 MCP 管理端点，并审计是否已有异常跨组织用户变更。

🔗 来源：[CVE-2026-91998](https://www.cve.org/CVERecord?id=CVE-2026-91998)

#### 【全球治理与标准】

微软以公开咨询推进厂商级行为准则，将“人类可中断/可关闭、最小权限、禁止进攻性网络与大规模操纵”写成可配置但仍不可被运营方覆盖的约束；同期中国国安系统高官发文把 AI 纳入国家安全风险框架并点名深度伪造、自动化攻防与出境模型泄密。两者层级与价值取向不同，但都表明大模型与智能体治理正从原则倡议进入可引用文本与监管平台建设阶段。

🔗 来源：[Microsoft AI](https://microsoft.ai/news/mai-code-of-conduct/) · [中央社](https://www.cna.com.tw/news/acn/202609140072.aspx)

### 三、今日趋势洞察

智能体工具链（MCP 连接器、多智能体 UI、IAM 的 MCP 管理面）连续以“缺认证 + 过宽信任边界”形式进入 CVE，说明连接协议普及快于默认安全基线。与此同时，地下市场以无护栏模型订阅降低恶意代码生成门槛，而头部厂商与国家机构同步加码行为准则与安全监管叙事——攻防两侧都在把“代理可行动”当作既成事实来治理。

### 四、企业行动清单

- 盘点并升级所有 PraisonAI UI / Claw 部署至 ≥4.6.62，关闭公网 `0.0.0.0` 绑定，对 `/api/mcp/*` 强制认证与网络隔离。
- 将 `@zereight/mcp-gitlab` 升至 ≥2.1.30，禁用 `ENABLE_DYNAMIC_API_URL`，并为本地 Streamable HTTP MCP 配置 Host/Origin 允许列表。
- 检查 Casdoor 是否启用 `/api/mcp` 用户工具；轮换应用 `clientSecret`，审计跨组织用户创建/删除记录，跟进官方修复版。
- 在 SBOM/依赖扫描中把 MCP 服务器与智能体 UI 列为高优先级组件，禁止未认证 stdio/HTTP 工具接入生产密钥。
- 对照微软准则与本地数据出境政策，更新模型使用红线；对内容站点复核 Cloudflare/搜索平台的 Training 与 Search 分项策略。
