### 一、今日要点（7 条）

**[1] Darktrace AI 安全调研**
📌 类型：AI 赋能安全

**[2] 红队实测提示注入高危**
📌 类型：AI 赋能安全

Evolve Security 在其面向安全团队的指南中指出，大量 LLM 集成应用在对抗性测试中暴露出提示注入相关薄弱点，并强调「仅靠传统输入校验难以区分恶意指令与正常自然语言」，从而推动以 AI 渗透测试、对抗样本与流程化测试程序补强评估体系。该表述属于安全服务机构的方法论文档，具体百分比与样本口径应以原文为准；其价值在于把「模型即解析器」带来的检测盲区翻译为可执行的测试清单。

🔗 来源：[Evolve Security](https://www.evolvesecurity.com/blog-posts/how-to-test-for-prompt-injection-a-security-teams-guide)

**[3] OWASP 锁定 LLM01 提示注入**
📌 类型：AI 自身安全

OWASP Gen AI 安全项目持续将「提示注入」置于 LLM 应用风险清单的核心位置，阐明其机制涵盖直接操纵用户输入与通过外部内容实施的间接注入，并指出即便引入 RAG 或微调等技术路线，也无法凭单一手段消除该类结构性风险。对于正在上线 Copilot/Agent 类能力的团队，该页面适合作为与研发对齐语义的「公共基准」，便于把对话式交互的特殊性纳入威胁建模。

🔗 来源：[OWASP Gen AI Security Project](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)

**[4] IBM 详解提示词注入机理**
📌 类型：AI 自身安全

IBM 中文知识库文章从工程视角解释提示词注入如何借助「系统提示与用户输入同为自然语言字符串」这一事实覆盖开发者意图，并说明其与「越狱」在手法与目标上的差异与关联。该材料偏基础科普，但对需要向业务方快速说明「为何 regex 不够」的安全负责人仍然实用，可用于内部培训与供应商问卷中的能力对齐。

🔗 来源：[IBM](https://www.ibm.com/cn-zh/think/topics/prompt-injection)

**[5] arXiv 提出智能体分层攻击模型**
📌 类型：AI 自身安全

arXiv 预印本《A Systematic Survey of Security Threats and Defenses in LLM-Based AI Agents》提出 Layered Attack Surface Model（LASM）与跨会话时间维度，将工具执行、记忆、生态（含 MCP）与多智能体协作等层级的威胁拆解开，并给出防御覆盖与评测真空的结构化结论；论文声称对 2021–2026 年间大量文献进行系统编码，属于「研究社群对 agentic 安全的阶段性盘点」。引用预印本结论时应标注其尚未经同行评议的事实。

🔗 来源：[arXiv](https://arxiv.org/html/2604.23338v2)

**[6] Semantic Kernel 双 CVE 可达主机 RCE**
📌 类型：AI 基础设施 CVE

微软安全博客披露 Microsoft Defender 安全研究团队在对 AI agent 框架的系列研究中，发现 Semantic Kernel 两条已修复的高危路径：CVE-2026-26030（Python 端 In-Memory Vector Store 默认过滤逻辑结合不安全拼接与 `eval()` _sink，可在具备提示注入面且启用默认搜索插件配置时导致远程代码执行）与 CVE-2026-25592（.NET 端 `SessionsPythonPlugin` 相关文件传输接口被错误暴露给模型，可能导致沙箱边界被跨越并向主机写入危险路径）。官方给出版本阈值（如 Python `semantic-kernel` 需 **≥1.39.4**、.NET SDK 需 **≥1.71.0**）以及终端狩猎查询思路，并预告同类执行风险可能存在于其他第三方 agent 框架。以下为微软文章配图的公开 URL，可与正文对照阅读。

🔗 来源：[Microsoft Security Blog（厂商来源）](https://www.microsoft.com/en-us/security/blog/2026/05/07/prompts-become-shells-rce-vulnerabilities-ai-agent-frameworks/)

**[7] NVD 收录 LLM 网关 New API 漏洞**
📌 类型：AI 基础设施 CVE

美国国家漏洞数据库（NVD）条目 CVE-2026-25802 将 **New API** 描述为 LLM 网关与 AI 资产管理相关软件，并链接至上游 GitHub 安全公告与修复提交；若组织自建统一模型路由或资产台账系统，应据此核对组件版本与补丁窗口。该条目的技术细节与 CVSS 向量以 NVD 与厂商 advisory 为准。

🔗 来源：[NVD](https://nvd.nist.gov/vuln/detail/CVE-2026-25802)

### 二、深度速览

#### 【AI 升级安全】AI 赋能防御与检测

微软针对 Semantic Kernel 漏洞给出的处置思路超越「修复依赖版本」本身：文章强调 **LLM 不是安全边界**，需要把模型输出映射工具参数的路径视为攻击者可控输入，并在主机层保留 EDR/进程遥测以捕获 agent 宿主进程的异常子进程链路与持久化落盘行为；同时提供示例狩猎查询用于回溯潜在入侵窗口。上述论点与查询模板均以微软官方披露为准，落地时应结合自有 SIEM 语法改写。

🔗 来源：[Microsoft Security Blog（厂商来源）](https://www.microsoft.com/en-us/security/blog/2026/05/07/prompts-become-shells-rce-vulnerabilities-ai-agent-frameworks/)

Darktrace 的公开材料将「AI 驱动的检测与运营效率」组织成对外可读的资源页，并嵌入其对威胁可视、自动化分诊等能力的陈述；安全管理层可用其作为趋势扫描入口，但应避免把单一厂商调研直接等同于行业统计结论，而是抽取其对「告警质量、集成深度、数据主权」等评估维度的提问清单。

🔗 来源：[Darktrace](https://www.darktrace.com/resource/the-state-of-ai-cybersecurity-2026)

#### 【AI 安全风险与治理】AI 自身威胁与监管动态

OWASP 与 IBM 材料从不同受众层级强化同一条工程常识：在 LLM 应用中，**指令与数据的边界无法仅靠类型系统保障**，因此需要输出验证、工具最小权限、对人机协同审批等组合控制；OWASP 条目同时引用 MITRE ATLAS 的相关技术项，便于与传统安全团队对齐「这不是单纯内容合规问题」。

🔗 来源：[OWASP Gen AI Security Project](https://genai.owasp.org/llmrisk/llm01-prompt-injection/) · [IBM](https://www.ibm.com/cn-zh/think/topics/prompt-injection)

欧盟委员会「AI Act」官方政策页概述该法案作为首部横向 AI 立法框架的定位，强调基于风险的分级义务，并介绍 AI Pact、服务台等过渡安排；它不替代具体条款的专业法律解读，但对跨国企业梳理「监管对话的共同锚点」仍有帮助。

🔗 来源：[European Commission](https://digital-strategy.ec.europa.eu/en/policies/regulatory-framework-ai)

### 三、今日趋势洞察

智能体将模型输出直接映射为文件、代码与网络侧效应后，**提示注入正在系统性地从内容滥用迁移为执行原语**；与此同时，公开文献与框架披露共同指向「分层防御与跨会话审计」缺口——评测集仍高度偏向单会话瞬时攻击，而治理规则对 MCP 工具生态与多步轨迹归因的覆盖仍在追赶架构演进。

💡 关键洞察（3～5 行）

- 代理框架把「自然语言 → 工具参数」变成了关键信任边界，漏洞披露开始常规化出现 **RCE 级别**影响（厂商博客/NVD）。  
- 社区标准（OWASP）与大众科普（IBM）共同强调：**提示注入不是传统注入的子类**，需要新的纵深防御组合。  
- 学术界综述指出 **跨会话与生态层威胁**评测基础设施不足，与企业正在快速上线的 Agent/MCP 能力形成张力（预印本）。  

---

⚠️ 核心风险（列 3 条）

1) **工具权限过热**：模型一旦被注入，危害取决于工具与宿主权限；建议默认最小权限、强隔离与高影响操作二次确认（参考微软处置建议与 OWASP 条目）。  
2) **组件版本滞后**：LLM 网关、agent 框架补丁窗口正在缩短；建议把相关依赖纳入紧急补丁通道并与供应链清单联动（参考 NVD 与 GitHub advisory）。  
3) **评测与运营脱节**：若仅有单轮红队而缺少跨会话内存/日志审计，难以发现慢速升级链路与编排层故障（参考 arXiv 综述的方法论结论）。

---

📌 建议行动（3～5 条）

- 立即核对 Semantic Kernel Python/`semantic-kernel` 是否 **≥1.39.4**、.NET SDK 是否 **≥1.71.0**，并在升级窗口内跑微软给出的狩猎查询模板。  
- 对自建 LLM 网关（含 New API 类组件）执行 CVE-2026-25802 影响评估与版本对齐。  
- 将提示注入场景纳入常规渗透测试范围，并要求供应商提供工具调用与敏感操作的审计日志字段定义。  
- 对欧盟市场相关系统启动 AI Act 义务映射（从高风险清单、记录保存到人工监督触发点），以官方政策页为索引展开法务研判。
