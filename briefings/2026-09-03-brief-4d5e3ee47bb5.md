### 一、今日要点

**[1] 恶意 Git 配置劫持编程代理**
📌 类型：AI自身安全

Manifold Security 于 9 月 1 日公开 GitSpawn 研究，披露七款命令行 AI 编程代理中至少八处同类缺陷：代理在启动或采集仓库上下文时调用 `git status` / `git diff` 等命令，却未剥离仓库本地 `.git/config`；攻击者可借 `core.fsmonitor` 等配置项指定任意命令，以用户权限在沙箱外、无审批提示下执行。投递条件为完整保留 `.git` 目录的压缩包、共享盘或 U 盘等目录拷贝，普通 `git clone` 不会带入该配置。截至公开时，goose、Claude Code（主路径）与 Cursor 等已有修复，Hermes Agent、Qwen Code、Grok Build 及 Claude Code 另一路径在 9 月 1 日复测仍可触发；OpenAI 同日为 Codex 发布 CVE-2026-19592 等同类修复。公开材料未确认在野利用，属已验证研究披露。

🔗 来源：[Manifold Security](https://www.manifold.security/blog/ai-coding-agents-git-hijack) · [The Hacker News](https://thehackernews.com/2026/09/malicious-git-configs-can-make-claude.html) · [NVD CVE-2026-19592](https://nvd.nist.gov/vuln/detail/CVE-2026-19592)

**[2] OpenAI Astra 达 Critical 网安阈值**
📌 类型：AI自身安全

OpenAI 于 9 月 1 日宣布即将发布的 Astra 模型已达到其《准备框架》（Preparedness Framework）下“重大”（Critical）网络安全能力阈值，为首个获此定级的公司模型。官方称在具备合适工具与访问时，Astra 可在无逐步人工指导下发现并利用多类加固系统中的未知缺陷；评测包括 ExploitBench 满分、含 2026 年中新披露 V8 漏洞的内部基准，以及专家主导下完成浏览器沙箱逃逸与本地提权链；评测中还发现并利用两个零日，正负责任披露。公司表示已延期部分开发与发布以强化防滥用与未授权行动防护，高级网安能力初期仅向有限测试者与 Daybreak Blue 防御用途开放。上述为厂商自评与安全承诺，系统卡细节将于正式发布时公开。

🔗 来源：[OpenAI](https://openai.com/index/path-to-astra/) · [SecurityWeek](https://www.securityweek.com/openais-astra-becomes-first-model-to-cross-critical-cybersecurity-threshold) · [WIRED](https://www.wired.com/story/openai-astra-first-ai-model-with-critical-cyber-abilities/)

**[3] Omnigent 智能体编排曝多枚高危 CVE**
📌 类型：AI基础设施CVE

GitHub Advisory Database 于 9 月 2 日收录 Databricks 系 `omnigent`（pip）一批经审阅公告，受影响版本均小于 0.3.0，官方修复版本为 0.3.0。其中 CVE-2026-62674（Critical，CVSS 9.0）允许具备会话编辑权限的用户通过上传完整 Agent Bundle 覆盖共享/模板智能体并注入恶意 stdio MCP，使后续 runner 执行攻击者命令；CVE-2026-62675（High，8.8）允许认证用户在上传的 bundle 中声明危险 Python `callable` 工具，在 runner 上导入执行任意本地代码；CVE-2026-62676（High，7.1）为护栏 shell 解析器“失败即放行”，未识别的包装命令可绕过仓库/分支与工作目录约束。NVD 记录显示 CVE 首发约 8 月 21 日，本次为 Advisory 数据库集中可见性更新。属已确认产品漏洞与补丁发布，公开材料未标注大规模在野利用。

🔗 来源：[GHSA-jrrm-9hc7-2v3h](https://github.com/advisories/GHSA-jrrm-9hc7-2v3h) · [GHSA-756x-9hf6-q4h4](https://github.com/advisories/GHSA-756x-9hf6-q4h4) · [GHSA-7mqg-cx4g-x2rf](https://github.com/advisories/GHSA-7mqg-cx4g-x2rf)

**[4] Claude 辅助移植 PLC 预认证 RCE**
📌 类型：AI赋能安全

Forescout Research（Vedere Labs）于 9 月 1 日发文、The Hacker News 于 9 月 2 日跟进：研究人员在人工持续引导下，使用 Claude Code（由 Sonnet 4.6 切换至 Opus 4.6）将针对 WAGO 750-852 的 CVE-2021-31886（Nucleus FTP USER 栈溢出，CVSS 9.8）预认证 RCE 利用移植到 WAGO 750-831，并在真实硬件上执行攻击者提供的 ARM shellcode。末段 RCE 开发消耗约 535.74 美元 API 费用、历时约 8.5 小时；后续尝试扩展为 C2 植入因写入闪存映射区导致 PLC 变砖。研究方强调当前仍需专家介入，成本与门槛使该类 OT 攻击相对“更容易的暴露面利用”吸引力有限，但轨迹显示嵌入式利用门槛可能随模型能力下降。此为受控研究演示，非在野 OT 战役通报。

🔗 来源：[Forescout](https://www.forescout.com/blog/can-ai-create-plc-attacks-yes-but-it%E2%80%99s-not-that-easy-yet/) · [The Hacker News](https://thehackernews.com/2026/09/researchers-use-claude-to-port-pre-auth.html)

**[5] 台 AIEC 公布主权 AI 月度评测**
📌 类型：AI治理合规

台湾数位发展部 AI 产品与系统评测中心（AIEC）于 9 月 2 日发布 2026 年 8 月语言模型基准评测结果，并宣布将按月更新。评测覆盖国内外约 188 个通用模型，三项基本指标分别为繁体中文语言理解、台湾社会文化理解与台湾价值观理解（分别采用近五年学测国文、社会科及具跨党派共识的价值观题组）。数发部长林宜敬同时界定主权 AI 需兼具“台湾观点”与“算力部署受台湾法律管辖”。iThome 报道称本地模型在价值观维度整体优于部分国外模型，而繁中理解上国际大模型亦已可达较高准确率。属政府侧评测与治理口径发布，非强制禁售或下架决定。

🔗 来源：[AIEC 2026年8月评测结果](https://www.aiec.org.tw/web/guest/news/-/asset_publisher/ixn9o9yiT8S9/content/2026%E5%B9%B48%E6%9C%88%E8%A9%95%E6%B8%AC%E7%B5%90%E6%9E%9C) · [iThome](https://www.ithome.com.tw/news/178626)

**[6] 模型监督工具时或推翻正确结果**
📌 类型：AI赋能安全

Help Net Security 于 9 月 2 日介绍伯尔尼应用科学大学研究（arXiv:2608.28794）：对无 JavaScript 的旋转类 CAPTCHA，传统几何算法可在约 0.006 秒内稳定求解，而多款大模型单独解题表现显著较差；当允许模型调用已正确的求解脚本时，GPT-4o 与 Grok 可照搬满分，但 Gemini 会因“看起来略偏”否决脚本给出的合法离散答案并失分。研究还观察到模型能描述目标位置却无法输出精确点击坐标等现象。结论指向：在“LLM 监督确定性工具”架构中，过度信任模型覆判可能引入新错误，而非必然纠错。属学术评测与设计启示，非安全产品漏洞通告。

🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/09/02/ai-captcha-solver-research/) · [arXiv:2608.28794](https://arxiv.org/pdf/2608.28794)

### 二、深度速览

#### 【AI 赋能防御】

Forescout 的 PLC 移植实验把“AI 辅助漏洞利用”从通用软件推进到闭源嵌入式 OT：模型可在 Ghidra、终端与真机回路中改写 USER/CWD 序列以绕过缓冲区清零，并在取得代码执行后快速生成 ICMP/UDP 示证载荷。与此同时，高 API 成本、变砖风险与对人类转向的依赖，说明当前商用模型更像“加速专家工作流”而非无人 OT 蠕虫。防御方可优先关闭/隔离互联网可达 FTP、落实 PLC 网段划分，并把“AI 辅助利用成本下降”纳入威胁建模时间表，而非等待完全自主利用成熟。🔗 来源：[Forescout](https://www.forescout.com/blog/can-ai-create-plc-attacks-yes-but-it%E2%80%99s-not-that-easy-yet/)

伯尔尼研究则提醒另一类“赋能”陷阱：当确定性工具已给出正确答案时，让概率模型拥有最终否决权可能降低系统可靠性。安全编排与自动响应链路应默认“工具结果可审计、模型覆判需二次确认”，避免把 LLM 放在无回退的关键路径上。🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/09/02/ai-captcha-solver-research/)

#### 【AI 系统风险】

GitSpawn 表明，编程代理最大的启动面往往不在提示词，而在“为了知道自己在哪”而调用的本地 Git 子进程。仓库自带配置成为指令面后，沙箱、信任对话框与鉴权时序都可能被绕过；修复必须覆盖启动路径、review/ultrareview 等二次 Git 调用，并对未打补丁代理实施“禁止打开未信任目录包”的临时控制。OpenAI Astra 的 Critical 定级则把能力风险推到企业采购与供应商尽职调查层面：高级网安能力将被限流与监控，但组织仍需假设未来同类模型会更易获得，并同步评估内部红队与滥用检测能力。Omnigent 一批 CVE 进一步说明：多智能体托管平台的共享 Agent、MCP 与护栏解析必须按“租户不可信”设计，失败默认放行等于没有护栏。🔗 来源：[Manifold](https://www.manifold.security/blog/ai-coding-agents-git-hijack) · [OpenAI](https://openai.com/index/path-to-astra/) · [GitHub Advisories](https://github.com/advisories/GHSA-jrrm-9hc7-2v3h)

#### 【全球治理与标准】

AIEC 将主权 AI 评测从原则表述落实为可复现的月度公开榜单，并把“境内算力管辖”与价值观对齐并列为定义要件，为企业在台采购、本地化部署与合规叙事提供第三方参照。OpenAI 以内部准备框架公开 Critical 阈值与发布限制，属于厂商自我监管透明度实践，可与政府评测、DSA 等外部义务并行观察，但二者效力与审计标准并不等同。🔗 来源：[AIEC](https://www.aiec.org.tw/web/guest/news/-/asset_publisher/ixn9o9yiT8S9/content/2026%E5%B9%B48%E6%9C%88%E8%A9%95%E6%B8%AC%E7%B5%90%E6%9E%9C) · [OpenAI](https://openai.com/index/path-to-astra/)

### 三、今日趋势洞察

编程代理的关键失败点正从“模型是否听话”前移到“会话启动时信任了哪些本地工具与仓库元数据”，Git 配置与共享 Agent Bundle 同属未经验证的指令面。与此并行，前沿模型网安能力被厂商正式标到 Critical，OT 侧 AI 辅助利用已能在真机完成 RCE 移植但仍受成本与专家门槛约束——能力跃升与工程护栏缺口正在同一时间窗口叠加。

### 四、企业行动清单

- 立即盘点开发者终端上的 Claude Code、Codex、Cursor、goose、Qwen Code、Hermes、Grok Build 等版本，升级至厂商已声明修复的版本；未修复前禁止用代理打开来自压缩包/共享盘且含 `.git` 的未信任工程目录。
- 在终端防护与 DLPE 策略中拦截“保留完整 `.git/config` 且改写 `core.fsmonitor` 等可执行配置”的可疑仓库投递，并对代理进程的 Git 子进程调用做异常命令审计。
- 若使用 Omnigent 或同类多智能体托管，确认升级到 0.3.0+，审查共享/模板 Agent 上传权限，禁用租户自定义 `callable` 与未批准 MCP stdio。
- 对暴露 FTP/管理面的 WAGO 等 PLC，按 CERT@VDE 建议关闭或隔离 21 端口并加强网段隔离，将 AI 辅助利用列入 OT 红队情景但不夸大为当前主流在野手段。
- 采购或部署面向台湾市场的通用模型时，对照 AIEC 月度主权评测中的语言、社会文化与价值观指标，并核验算力与数据是否落在可管辖环境。
