本期以过去约 24～72 小时（2026-08-14 至 08-17，GMT+8）可核验公开信息为主；Atlassian RovoBlast 的权威媒体报道与 DEF CON 披露窗口略早，因企业 AI 助手外泄链仍具决策价值放宽收录；Grafana MCP、Flowise Custom MCP 等 NVD/厂商公告落在约一周内且直接影响 AI 工具链，一并核验后纳入。

### 一、今日要点

**[1] CoreBreak绕过模型调度护栏**
📌 类型：AI自身安全

The Hacker News 于 8 月 16 日报道：Stealth 研究员 Hedi Ingber 与 Aviyam Ivgi 在 Black Hat USA 2026 提出跨平台模式 CoreBreak——在 Amazon Bedrock AgentCore、Google ADK（Python）与 Vercel AI SDK harness 中，调度层把“形状像模型工具调用”的数据当作已授权指令执行，部分路径甚至从不调用模型，使系统提示、内容过滤与拒答训练失去介入机会。已确认 CVE 包括 Bedrock AgentCore 的 CVE-2026-18830（CVSS v4 8.6，AWS 已在 7 月 31 日前对托管 InvokeHarness API 自动修复）、ADK 的 CVE-2026-18236（CVSS v4 9.3，需升级至 2.5.0）以及 Vercel harness 的 CVE-2026-64650/64651（需升级对应包）。属已确认的框架/托管服务漏洞与研究披露，非提示注入类在野战役；影响范围受限于各智能体已配置的工具集。Cloud Security Alliance Labs 同期研究笔记强调应对调度层做来源证明审计，而非仅加固模型侧护栏。

🔗 来源：[The Hacker News](https://thehackernews.com/2026/08/aws-google-and-vercel-patch-agent-flaws.html) · [AWS 安全公告 2026-073-AWS](https://aws.amazon.com/security/security-bulletins/2026-073-aws/) · [CSA Labs 研究笔记](https://labs.cloudsecurityalliance.org/research/csa-research-note-agent-infra-guardrail-bypass-20260806-csa/)

**[2] Grafana MCP高危SSRF可摸内网**
📌 类型：AI基础设施CVE

Grafana Labs 于 8 月 11 日发布 CVE-2026-19516：在 Grafana MCP 中，可调用 `grafana_api_request` 的调用方可通过 `X-Grafana-URL` 头指定出站目标，并自选 HTTP 方法、路径与正文；目标未限制在已配置的 Grafana 实例，从而对内网、回环、链路本地乃至元数据端点构成服务端请求伪造（SSRF），CVSS 3.1 评分 9.1。公告说明此前 CVE-2026-15583 的修复阻止了把服务账号令牌发往非预期地址，但未限制目的地本身。官方修复版本为 mcp-grafana ≥1.1.0。属厂商原始安全公告确认的漏洞，需运维侧主动升级。

🔗 来源：[Grafana 安全公告 CVE-2026-19516](https://grafana.com/security/security-advisories/cve-2026-19516) · [NVD CVE-2026-19516](https://nvd.nist.gov/vuln/detail/CVE-2026-19516)

**[3] Flowise自定义MCP节点可致RCE**
📌 类型：AI基础设施CVE

NVD 于 8 月 13 日收录 CVE-2026-73601：Flowise 3.1.3 之前版本在 `CUSTOM_MCP_PROTOCOL` 为默认 `stdio` 时，Custom MCP 节点允许经认证用户通过操控环境变量与命令参数执行任意命令；公开分析指出可滥用 `PYTHONWARNINGS`/`BROWSER` 或借助工作目录与 `node` 绕过校验。CVSS v4 评分约 9.0（Critical）。GitHub 安全公告与 VulnCheck 均指向升级至 3.1.3，并建议将默认协议改为更安全的传输方式、避免对环境变量采用脆弱的黑名单策略。属已确认的 AI 编排平台漏洞（需已认证访问），非未授权在野利用声明。

🔗 来源：[VulnCheck 公告](https://www.vulncheck.com/advisories/flowise-before-remote-code-execution-via-custom-mcp) · [NVD CVE-2026-73601](https://nvd.nist.gov/vuln/detail/CVE-2026-73601) · [Flowise GHSA-g98q-rm45-q9h8](https://github.com/FlowiseAI/Flowise/security/advisories/GHSA-g98q-rm45-q9h8)

**[4] RovoBlast一键提示注入外泄**
📌 类型：AI自身安全

Varonis Threat Labs 披露并在 DEF CON 34 演示 RovoBlast：攻击者构造含 `rovoChatPrompt` 参数的链接，已登录用户一键即可把攻击者指令写入 Atlassian 企业助手 Rovo 的会话；Rovo 在受害者权限内检索 Jira、Confluence 及已连接的 Slack、Microsoft 365、Google Workspace 等，并可借助 ResearchAgent 等多步能力向外带出摘要内容。该路径不依赖越狱或提权，属于参数到提示（P2P）注入。Atlassian 经 Bugcrowd 负责披露后，于 2026 年 7 月 8 日完成服务端修复；CSO Online（8 月 10 日）等权威报道仍强调需收缩连接器范围、禁用非必要浏览/自治代理，并把法务、HR、财务与应急文档排除在助手可见域之外。属已修复的研究演示型漏洞与企业配置风险提示。

🔗 来源：[Varonis 技术博文](https://www.varonis.com/blog/rovoblast) · [CSO Online](https://www.csoonline.com/article/4207306/one-click-flaw-in-atlassian-rovo-exposed-enterprise-data-via-prompt-injection-attack.html)

**[5] Cribl并购CardinalOps强化AI检测**
📌 类型：AI赋能安全

iThome 8 月 17 日报道：遥测数据平台厂商 Cribl 宣布并购专注 AI 检测工程的 CardinalOps，计划把其能力并入既有平台，在 SIEM、EDR、XDR 之上持续检查检测覆盖缺口与高噪声规则，并借此推进“替代传统 SIEM”路径。交易金额未官方披露；报道援引以色列科技媒体 CTech 消息称规模约 1 亿美元。属厂商并购与媒体转述（金额为非官方消息），反映 SOC 侧把 AI 用于检测工程治理、而非仅做告警摘要的产品整合趋势。

🔗 来源：[iThome](https://www.ithome.com.tw/news/178149)

**[6] Cortex记忆MCP误信项目目录**
📌 类型：AI基础设施CVE

NVD 于 8 月 14 日公布 CVE-2026-49986：跨平台持久记忆 MCP 服务 `neuro-cortex-memory`（Cortex）在 3.17.1 之前，将 Claude Code 自动设置的 `CLAUDE_PROJECT_DIR` 环境变量当作可信的 Cortex 开发检出目录，可能在打开恶意/不可信项目时执行非预期引导代码。CVSS 约 7.1（High）。官方修复版本为 3.17.1。属记忆类 MCP 供应链与本地开发代理交叉的已确认漏洞。

**[7] mcp-atlassian任意文件读取风险**
📌 类型：AI基础设施CVE

开源 MCP 服务器 mcp-atlassian（对接 Confluence/Jira）在 0.22.0 之前存在 CVE-2026-73498：`confluence_upload_attachment` 将客户端提供的 `file_path` 直接交给 `open()`，缺少路径校验，可导致任意文件读取（High，CVSS 约 7.7）。修复版本为 v0.22.0。该组件常被编码/运维智能体用于工单与知识库操作，属于企业 AI 工具链中的直接依赖风险。

🔗 来源：[NVD CVE-2026-73498](https://nvd.nist.gov/vuln/detail/CVE-2026-73498) · [GitHub Advisory GHSA-g5r6-gv6m-f5jv](https://github.com/sooperset/mcp-atlassian/security/advisories/GHSA-g5r6-gv6m-f5jv) · [v0.22.0 发布](https://github.com/sooperset/mcp-atlassian/releases/tag/v0.22.0)

### 二、深度速览

#### 【AI 赋能防御】

Cribl 并购 CardinalOps，把“遥测管道”与“AI 检测工程”绑在同一产品叙事下：重点不是再用大模型复述告警，而是持续度量规则覆盖、失效与噪声，服务希望弱化传统 SIEM 中心架构的团队。企业若跟进同类整合，应先厘清检测缺口的责任边界（平台方 vs SOC 规则所有者）与并购后的数据出境/租户隔离条款，避免把检测工程外包成不可审计的黑箱。

🔗 来源：[iThome](https://www.ithome.com.tw/news/178149)

#### 【AI 系统风险】

CoreBreak 与提示注入的分水岭在于：前者攻击的是“工具调度是否验证模型回合来源”，后者攻击的是“模型判断是否被语义操控”。当 harness 信任消息形状或会话里伪造的确认事件时，所有押在模型护栏上的投资都会被结构性绕过。CSA 建议把监测扩展到调度层——核对每次工具执行是否能回溯到同会话中真实的模型补全——并对人工确认门禁校验工具归属与参数一致性。

🔗 来源：[The Hacker News](https://thehackernews.com/2026/08/aws-google-and-vercel-patch-agent-flaws.html) · [CSA Labs](https://labs.cloudsecurityalliance.org/research/csa-research-note-agent-infra-guardrail-bypass-20260806-csa/)

同一窗口内，Grafana MCP SSRF、Flowise Custom MCP RCE、Cortex 记忆 MCP 与 mcp-atlassian 路径问题显示：MCP/工具服务器正在复现经典 Web 漏洞（SSRF、命令注入、任意文件读），但暴露面挂在高权限智能体会话上。缓解优先级应是：升级组件版本、默认禁用 stdio 自定义 MCP、限制 MCP 出站与本地文件根、对记忆/项目目录变量去信任。

🔗 来源：[Grafana CVE-2026-19516](https://grafana.com/security/security-advisories/cve-2026-19516) · [CVE-2026-73601](https://nvd.nist.gov/vuln/detail/CVE-2026-73601)

RovoBlast 再次证明企业助手的“一键参数预填”会把钓鱼链接升级为会话级指令注入；即便厂商已服务端修复 URL 路径，内容载体注入与过宽连接器仍需靠权限收缩与日志审计兜底。

🔗 来源：[Varonis](https://www.varonis.com/blog/rovoblast)

### 三、今日趋势洞察

智能体风险正从“骗过模型”扩展到“绕过调度与 MCP 插件层”：CoreBreak 证明无模型回合也可触发工具，而本周多枚 MCP 相关 CVE 表明工具服务器本身就是可被传统漏洞打穿的执行面。防御与采购需要把 harness、MCP 与连接器纳入与业务应用同级的补丁与信任边界管理，而不仅仅加厚提示词护栏。

### 四、企业行动清单

1. 盘点 Bedrock AgentCore、自托管 Google ADK、Vercel AI SDK harness 版本：确认托管侧修复生效，自托管组件升级至 ADK ≥2.5.0 与已修复 harness 版本，并抽查近期无法回溯到模型补全的工具调用日志。  
2. 立即升级 Grafana MCP（≥1.1.0）、Flowise（≥3.1.3）、mcp-atlassian（≥0.22.0）与 Cortex/neuro-cortex-memory（≥3.17.1），并关闭非必要的 Custom MCP stdio 与任意出站。  
3. 审查 Atlassian Rovo 及同类企业助手的连接器范围：移除法务/HR/财务/应急知识库接入，关闭非必要的多步浏览与自治代理能力。  
4. 将 MCP 服务器与智能体 harness 写入 SBOM/依赖扫描基线，对“记忆目录、项目路径、环境变量透传”类配置做去信任评审。  
5. 评估 SOC 检测工程并购/整合方案时，要求供应商提供规则覆盖度量、噪声治理与跨租户隔离的可审计接口，而非仅演示告警摘要效果。
