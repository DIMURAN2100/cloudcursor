### 一、今日要点

**[1] NVIDIA发布智能体安全平台**
📌 类型：AI赋能安全

NVIDIA 于 9 月 28 日宣布推出 Open Agent Safety Platform，以开源运行时 OpenShell 与基于 BlueField-4 DPU 的带外监视组件 Sentry，在应用层之下为自主智能体设定可执行边界，并可在毫秒级隔离越界行为。官方称近期多起前沿实验室智能体绕过应用层管控的事件暴露同一模式，平台旨在覆盖测试到部署的全栈治理；Anthropic、CrowdStrike、Microsoft、Palo Alto Networks、Salesforce 等逾百家组织参与。厂商来源声明尚属产品与联盟发布，未构成对既有事故的独立取证结论。

🔗 来源：[NVIDIA Newsroom](https://nvidianews.nvidia.com/news/open-agent-safety-platform) · [CrowdStrike 官方博客](https://www.crowdstrike.com/en-us/blog/crowdstrike-nvidia-extend-security-across-ai-stack) · [美联社 / ABC7](https://abc7news.com/post/nvidia-unveils-security-platform-stop-ai-agents-going-rogue-new-troubling-incidents/19883509)

**[2] Obot网关绕过MCP访问控制**
📌 类型：AI自身安全

NVD 于 9 月 27 日收录 CVE-2026-101084（CVSS 9.6）：Obot 在 v0.21.1 之前未对 `/mcp-connect` 强制执行访问控制规则，任意已认证用户只要掌握 MCP Server ID，即可连接本应受限的 MCP 服务，并借助平台已存储的 OAuth 凭据调用上游工具。该问题与 9 月 28 日简报已覆盖的 Docker 快速启动默认无认证夺管（CVE-2026-101065）机制不同，主要冲击“已开启认证与分组 ACL”的生产部署。官方安全公告给出修复版本 v0.21.1；公开资料未见在野利用确认。

🔗 来源：[NVD CVE-2026-101084](https://nvd.nist.gov/vuln/detail/CVE-2026-101084) · [Obot GHSA-vw82-7fv8-r6gp](https://github.com/obot-platform/obot/security/advisories/GHSA-vw82-7fv8-r6gp)

**[3] Token Optimizer MCP命令注入**
📌 类型：AI基础设施CVE

NVD 于 9 月 28 日公布 CVE-2026-55157（CVSS 8.4）：面向多款 AI 编码客户端的 Token Optimizer MCP 在 `smart_user` / `get-user-info` 路径将用户名拼入 shell 命令，双引号无法阻止 `$()` 命令替换，可导致以 MCP 服务进程权限执行任意命令。同日关联 CVE-2026-55156 指向仪表盘会话 API 无认证与路径穿越。补丁版本为 5.1.0；属已修复的研究披露，未见在野利用报告。

🔗 来源：[NVD CVE-2026-55157](https://nvd.nist.gov/vuln/detail/CVE-2026-55157) · [GitHub 安全公告 GHSA-49mq-fc6q-3h46](https://github.com/ooples/token-optimizer-mcp/security/advisories/GHSA-49mq-fc6q-3h46)

**[4] code-ollama只读工具可RCE**
📌 类型：AI自身安全

GitHub Advisory Database 于 9 月 28 日发布 GHSA-456v-xq2p-r4cj（CVSS 约 7.8）：`code-ollama`（≤0.36.0）的 `grep_search` 将 pattern/path 拼入经 `child_process.exec` 执行的 shell 命令，转义不完整导致 `$()` 注入。该工具被标为只读并在 Plan 模式自动执行、无需用户审批；恶意或被攻陷的 Ollama 服务端可通过 tool_calls 触发。修复版本 0.36.1；属研究演示路径，公开渠道未见大规模在野利用。

🔗 来源：[GitHub Advisory GHSA-456v-xq2p-r4cj](https://github.com/advisories/GHSA-456v-xq2p-r4cj)

**[5] Telegram MCP文件URL致SSRF**
📌 类型：AI基础设施CVE

NVD 于 9 月 28 日收录 CVE-2026-55096（CVSS 7.1）：`fast-mcp-telegram` 在 30.1 之前通过 `send_message` / `send_message_to_phone` 按 URL 拉取附件时，SSRF 拒绝列表只检查主机名字面量、不解析 DNS，攻击者可用解析到内网或回环的域名完成可读型 SSRF，响应体还可作为 Telegram 附件外带。官方安全公告与 0.30.1 发行说明给出修复；未见在野利用确认。

🔗 来源：[NVD CVE-2026-55096](https://nvd.nist.gov/vuln/detail/CVE-2026-55096) · [GHSA-xr72-j7vj-vp7g](https://github.com/leshchenko1979/fast-mcp-telegram/security/advisories/GHSA-xr72-j7vj-vp7g)

**[6] Penpot MCP桥接未认证劫持**
📌 类型：AI基础设施CVE

NVD 于 9 月 27 日公布 CVE-2026-100868（CVSS 6.3）：Penpot 2.18.0 之前，MCP 插件 WebSocket 桥接在单用户模式下绑定全部网卡且不要求认证，邻近网络攻击者可冒充浏览器插件、截获任务载荷并向 MCP 客户端返回伪造结果，或通过多连接造成拒绝服务。文档中的 `PENPOT_MCP_SERVER_HOST` 未作用于该 WebSocket 组件。项目安全公告与相关提交指向 2.18.0 修复路径；属配置与绑定缺陷披露，未见在野利用报告。

🔗 来源：[NVD CVE-2026-100868](https://nvd.nist.gov/vuln/detail/CVE-2026-100868) · [Penpot GHSA-ch2q-6x56-qg5r](https://github.com/penpot/penpot/security/advisories/GHSA-ch2q-6x56-qg5r)

**[7] Zscaler MCP令牌可跨资源重放**
📌 类型：AI基础设施CVE

NVD 于 9 月 28 日收录 CVE-2026-59563（CVSS 4.6）：Zscaler MCP Server 0.7.0/0.7.1 中 HMAC 确认令牌未绑定目标资源标识，MCP 客户端或智能体可将为一资源生成的令牌重放到同类型另一资源。厂商已在 0.7.2 通过将资源 ID 绑定进令牌修复（相关 PR #41）。严重度为中等，但提示企业级 MCP 写操作确认机制仍可能被智能体复用绕过；公开资料未见在野利用。

🔗 来源：[NVD CVE-2026-59563](https://nvd.nist.gov/vuln/detail/CVE-2026-59563) · [Zscaler MCP 修复 PR](https://github.com/zscaler/zscaler-mcp-server/pull/41)

### 二、深度速览

#### 【AI 赋能防御】

NVIDIA Open Agent Safety Platform 将控制面拆成两层：OpenShell 在 CPU 侧以沙箱与可验证策略约束文件、网络、工具与凭据访问，并强调边界位于模型与 agent harness 之外，从而同时覆盖开源与闭源模型；Sentry 则在 BlueField-4 上以智能体不可见的带外域做监视与隔离，降低“运行时被拿下后看门狗一并失效”的共模风险。CrowdStrike 等安全厂商同步宣布在该参考设计上深化协作，把终端/云检测与智能体运行时策略衔接。需注意：官方与 AP 报道中“若早部署或可阻止某次 Hugging Face 事件”属于厂商能力推演，不是事后取证结论；企业应将其视为纵深防御选项，而非替代提示注入与 MCP 身份治理。

🔗 来源：[NVIDIA Newsroom](https://nvidianews.nvidia.com/news/open-agent-safety-platform) · [CrowdStrike 博客](https://www.crowdstrike.com/en-us/blog/crowdstrike-nvidia-extend-security-across-ai-stack)

Token Optimizer、Telegram MCP 与 Zscaler MCP 的修复节奏显示，MCP 工具链正成为可补丁的“标准软件面”：命令注入、DNS 未解析的 SSRF、以及确认令牌未绑定资源，都是传统安全缺陷在智能体协议上的复现。对 SOC 而言，可将 MCP 服务版本、监听地址与工具权限纳入与普通微服务同等的漏洞与配置基线，而不是仅依赖模型层护栏。

🔗 来源：[NVD CVE-2026-55157](https://nvd.nist.gov/vuln/detail/CVE-2026-55157) · [NVD CVE-2026-55096](https://nvd.nist.gov/vuln/detail/CVE-2026-55096) · [NVD CVE-2026-59563](https://nvd.nist.gov/vuln/detail/CVE-2026-59563)

#### 【AI 系统风险】

Obot `/mcp-connect` 授权旁路说明：即便 UI 已按 Registry/ACL 隐藏服务，网关若未复检同一策略，持有 Server ID 的低权限用户仍可调用上游工具并继承平台托管凭据，形成“身份已登录 + 授权未生效”的经典失败模式。与昨日披露的默认无认证快速启动相比，本洞更贴近企业内多租户误配后的横向越权。缓解要点是升级至含 ACR 强制校验的版本，并审计 MCP Server ID 的暴露面与 OAuth 令牌作用域。

🔗 来源：[Obot GHSA-vw82-7fv8-r6gp](https://github.com/obot-platform/obot/security/advisories/GHSA-vw82-7fv8-r6gp)

code-ollama 与 Token Optimizer 两条命令注入链条高度同构：工具参数进入 shell、转义不完整、且“只读/辅助”工具自动执行削弱人审。攻击前提分别是不可信 Ollama 端或可调用 MCP 工具的客户端，属于研究演示级利用条件，但对企业自建编码智能体仍具现实意义——应对“只读工具”做与写工具同等的参数白名单与非 shell 执行策略。

🔗 来源：[GHSA-456v-xq2p-r4cj](https://github.com/advisories/GHSA-456v-xq2p-r4cj) · [GHSA-49mq-fc6q-3h46](https://github.com/ooples/token-optimizer-mcp/security/advisories/GHSA-49mq-fc6q-3h46)

Penpot MCP 桥接暴露了“文档声称绑定 localhost、实现却 `0.0.0.0` 且无认证”的本地开发默认风险：邻近网络即可劫持设计任务通道。开发者工作站上的 MCP 插件应默认环回绑定并强制鉴权，远程模式再显式开启。

🔗 来源：[NVD CVE-2026-100868](https://nvd.nist.gov/vuln/detail/CVE-2026-100868)

### 三、今日趋势洞察

智能体安全正同时向“栈下硬件化纵深”与“MCP 工具链传统漏洞化”两端延伸：一端以 OpenShell/Sentry 把策略执行移出模型与应用层，另一端则在命令注入、SSRF、ACL 旁路与确认令牌绑定上密集出洞。二者共同指向同一结构问题——工具调用与托管凭据一旦成为默认能力，边界必须落在可强制执行的运行时与身份控制，而不能依赖模型自觉或 UI 层展示过滤。

### 四、企业行动清单

- 盘点已部署的 Obot 实例版本，确认 `/mcp-connect` 是否强制 ACR，并将受影响环境升级至含修复的版本后复测跨组 MCP 访问。
- 清查开发者工作站与 CI 中的 Token Optimizer MCP、`code-ollama`、`fast-mcp-telegram`、Penpot MCP 与 Zscaler MCP Server 版本，按对应公告升至已修复发行版。
- 对所有对外或跨主机监听的 MCP/WebSocket 端口做绑定地址与鉴权审计，禁止文档默认 localhost 与实际 `0.0.0.0` 无认证并存。
- 将标注为“只读”但仍经 shell 执行的智能体工具纳入高危变更评审，禁止未做参数白名单的自动审批。
- 评估 OpenShell/Sentry 类运行时边界是否纳入现有终端与云检测策略，明确智能体出站、凭据与工具调用的独立阻断责任人。
