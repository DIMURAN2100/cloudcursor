## 一、今日要点（5～8 条）

**[1] Claude漏洞扫描框架**
📌 类型：AI赋能安全

Anthropic 发布开源参考实现 `defending-code-reference-harness`，演示如何用 Claude 完成威胁建模、漏洞发现、验证分级与修补建议。该框架提供 `/threat-model`、`/vuln-scan`、`/triage`、`/patch` 等 Claude Code 技能，并内置基于 Docker + AddressSanitizer 的自主扫描管线，在 gVisor 隔离容器中运行 AI 代理，仅允许对外连接模型 API。厂商同时强调，AI 生成的修补方案必须经过人工审查与测试，不可直接合入生产。

🔗 来源：[iThome](https://www.ithome.com.tw/news/176595)

**[2] Mythos挖掘OT漏洞**
📌 类型：AI赋能安全

工业网络安全公司 Dragos 加入 Anthropic 的 Project Glasswing，将 Claude Mythos Preview 用于扫描自家 OT 安全软件中的新型漏洞。Dragos 指出，多数 AI 辅助漏洞挖掘此前主要针对 IT 系统测试，而电力、水务、制造等 OT 环境的软件漏洞具有更长生命周期与不同风险画像。Anthropic 称该计划已扩展至约 150 家组织，并同步推出 Claude Security 等防御侧工具，旨在让防御方在强能力模型广泛可用前建立修复与披露机制。

🔗 来源：[Industrial Cyber](https://industrialcyber.co/ai/dragos-applies-claude-mythos-preview-to-uncover-vulnerabilities-in-ot-security-software)

**[3] JetBrains插件窃钥**
📌 类型：AI自身安全

Aikido Security 披露 JetBrains Marketplace 上至少 15 款恶意 IDE 插件，伪装成 DeepSeek、CodeGPT 等 AI 编程助手，在用户保存 OpenAI、DeepSeek、SiliconFlow 等 API 密钥时以明文 HTTP 外传至攻击者服务器（39.107.60.51）。这些插件分布在 7 个厂商账号下，累计安装量近 7 万次，最新一批直至 2026 年 6 月 10 日仍在上架。BleepingComputer 独立验证其中 `DeepSeek AI Assist` 插件仍含窃密代码，部分插件截至报道时仍可下载。

🔗 来源：[BleepingComputer](https://www.bleepingcomputer.com/news/security/malicious-jetbrains-marketplace-plugins-steal-ai-api-keys-from-developers/)

**[4] Gemini诈骗诉讼**
📌 类型：AI自身安全

Google 于 6 月 12 日向纽约南区联邦法院起诉代号「Outsider Enterprise」的网络犯罪集团，指控其通过 Telegram 销售钓鱼即服务（Phishing-as-a-Service）套件，并指导客户使用 **Google Gemini** 生成仿冒 Google、YouTube、E-ZPass 等品牌的诈骗网站。诉状称该组织在两周内向 Android 用户发送约 250 万条诈骗短信，部署 9000 个假站与逾 100 万恶意 URL，致数十万受害者损失数百万美元。Google 称这是首次针对滥用自家消费级 AI 模型的大规模诈骗行动采取法律行动，并与 FBI 及运营商协作阻断传播。

🔗 来源：[TechCrunch](https://techcrunch.com/2026/06/12/chinese-cybercrime-operation-that-used-ai-to-scam-hundreds-of-thousands-of-victims-sued-by-google/)

**[5] 影子AI治理缺口**
📌 类型：AI自身安全

资诚在台湾投资人关系协会活动中援引 PwC《2026 全球数字信任洞察报告》指出，尽管多数企业宣称已管理 AI 工具，但超过九成员工实际使用个人订阅的 AI 服务，企业官方授权工具在总使用量中可能不足 10%。报告进一步警示，当 Agentic AI 同时具备高权限数据访问、暴露于不可信外部内容（易受间接提示注入）及对外通信能力时，攻击者一旦挟持代理即可继承高管级信任凭证。建议将自主代理视为高特权实体，并强制在敏感操作节点引入 Human-in-the-loop 与 Kill Switch。

🔗 来源：[iThome](https://www.ithome.com.tw/news/176614)

**[6] 代理AI失效模式**
📌 类型：AI自身安全

微软 AI 红队发布 Agentic AI 失效模式分类法 v2.0，基于 12 个月真实红队 engagements 新增七类风险，包括代理供应链妥协（通过 MCP 服务器/插件描述注入自然语言指令）、目标劫持、代理间信任升级、会话上下文污染及计算机使用代理（CUA）视觉攻击等。红队发现 Human-in-the-loop 绕过是最高频被利用模式，部分攻击链可实现从零点击外部输入到数据外泄的完整链路。微软威胁情报还确认了 Claude Code GitHub Action 中存在可访问工作流密钥的提示注入路径。

🔗 来源：[Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2026/06/04/updating-taxonomy-failure-modes-agentic-ai-systems-year-red-teaming-taught-us/)

**[7] Vertex跨租户RCE**
📌 类型：AI基础设施CVE

Palo Alto Networks Unit 42 披露 Google Cloud Vertex AI Python SDK（`google-cloud-aiplatform` 1.139.0—1.140.0）存在「Pickle in the Middle」漏洞：当用户未指定自定义 staging bucket 时，SDK 以项目 ID + 区域生成可预测桶名，仅检查桶是否存在而不验证归属，攻击者可预先在自己的 GCP 项目中「抢占」同名桶，在约 2.5 秒窗口内将合法模型替换为含恶意 pickle 载荷的文件，进而在受害者 Vertex AI 服务基础设施中实现跨租户远程代码执行。Google 已在 v1.148.0 加入桶归属校验与随机化命名，建议立即升级并显式指定 staging bucket。

🔗 来源：[Unit 42 (Palo Alto Networks)](https://unit42.paloaltonetworks.com/hijacking-vertex-ai-model/)

**[8] 自复制AI蠕虫**
📌 类型：AI自身安全

研究人员构建了一种完全在本地开源权重模型上运行的自复制 AI 蠕虫，无需依赖云端 API 即可跨主机传播并利用实时推理选择攻击路径。Cloud Security Alliance 等机构指出，此类威胁无法通过修补单一 CVE 消除，防御需转向网络分段、行为异常检测与运行时监控，以识别非常规多步攻击链。该研究将 AI 蠕虫概念从理论推演推向可实验验证阶段，对部署本地 LLM 与 Agent 框架的组织构成新的系统性风险。

🔗 来源：[The Hacker News](https://thehackernews.com/2026/06/researchers-build-self-replicating-ai.html)

## 二、深度速览

#### 【AI 升级安全】AI 赋能防御与检测

Anthropic 将 Project Glasswing 的实战经验沉淀为可复用的 `defending-code-reference-harness` 开源框架，覆盖从威胁建模到自主验证的完整流水线。其自主扫描模块默认针对 C/C++ 内存漏洞，通过 ASAN 编译目标程序并在 gVisor 沙箱中让发现代理与验证代理分容器运行，验证代理仅接收 PoC 字节流以避免被发现过程「污染」判断。框架还提供 `/customize` 技能以移植到其他语言与漏洞类型，标志着 AI 漏洞挖掘正从单点工具演示走向可编排、可审计的工程化管线。

🔗 来源：[Anthropic GitHub（厂商来源）](https://github.com/anthropics/defending-code-reference-harness)

Dragos 将 Claude Mythos Preview 引入 OT 漏洞研究，针对保护电网、管道、制造产线的安全软件进行 AI 辅助审计。与 IT 环境不同，OT 软件漏洞的影响周期更长、修复窗口更窄，且常涉及专有协议与物理过程安全。Anthropic 通过 Project Glasswing 联合 AWS、Google、Microsoft、CrowdStrike 等约 150 家组织共享发现与修复实践，试图在强网络能力模型未来 6—12 个月内可能广泛扩散前，建立防御方优先获取工具与协同披露的新规范。

🔗 来源：[Industrial Cyber](https://industrialcyber.co/ai/dragos-applies-claude-mythos-preview-to-uncover-vulnerabilities-in-ot-security-software)

CISA 联合澳大利亚网络安全中心及五眼伙伴发布《Careful Adoption of Agentic AI Services》指南，要求关键基础设施运营方将 Agentic AI 安全纳入现有网络安全框架而非另起炉灶。文件明确列出权限膨胀、行为偏离、多代理级联失败与问责缺口等风险，建议从低风险场景渐进部署，并对工具调用、权限变更与目标漂移实施持续监控，高影响操作必须保留人工审批且审批触发条件由系统设计方而非代理自行决定。

🔗 来源：[Industrial Cyber](https://industrialcyber.co/ai/cisa-and-partners-release-agentic-ai-security-guidance-to-protect-critical-infrastructure-outline-mitigation-action)

#### 【AI 安全风险与治理】AI 自身威胁与监管动态

JetBrains Marketplace 恶意插件 campaign 揭示了 AI 开发工具链的新型供应链攻击面：攻击者不再窃取传统 npm 依赖，而是直接针对开发者配置的 LLM API 密钥——这些密钥往往绑定计费账户与大量云端资源权限。15 款插件共享同一窃密代码库、累计近 7 万次安装，说明 IDE 插件市场的审核机制对 AI 助手类扩展仍存在盲区。安全团队应将 IDE 插件纳入与 CI/CD 密钥同等级别的白名单与定期审计范围。

🔗 来源：[Aikido Security](https://www.aikido.dev/blog/multiple-jetbrains-ide-plugins-caught-stealing-ai-keys)

中国工业互联网研究院在安全内参发表研究，指出智能体「技能」生态存在系统性风险：Snyk 对 ClawHub 的评测显示 36.82% 技能存在安全缺陷，2026 年 2 月该平台 7 天内遭批量上传 1184 个恶意技能。问题涵盖提示词注入、过度权限申请（30% 申请管理员级权限、45% 具备任意命令执行）及「一次授权、持续生效」导致版本更新后恶意代码仍可运行。研究建议建立技能安全测评机制、国家级恶意技能情报库，并在权限变更节点强制重新触发用户授权。

🔗 来源：[安全内参](https://www.secrss.com/articles/91215)

微软 v2.0 失效模式分类法将 OpenClaw 等开源 Agent 框架的实战数据纳入证据基础：OpenClaw 发布后 48 小时内衍生超 2100 个 Agent，安全审计发现 512 项漏洞（含 CVE-2026-25253 一键 RCE），技能市场检出 336 个恶意插件。2025 年 MCP 相关软件已公布 99 个 CVE，工具描述投毒从理论风险变为可观测攻击面。报告建议为每个已部署 Agent 生成包含 MCP 服务器、插件与提示模板的 SBOM，并对代理间消息实施密码学身份认证而非位置信任。

🔗 来源：[Microsoft Security Blog](https://www.microsoft.com/en-us/security/blog/2026/06/04/updating-taxonomy-failure-modes-agentic-ai-systems-year-red-teaming-taught-us/)

## 三、今日趋势洞察（1～3 句）

AI 安全议题正从「模型越狱」单点讨论，转向 **开发工具链、云 AI SDK 与 Agent 插件市场** 的供应链治理——JetBrains 窃密插件与 Vertex AI 桶抢占漏洞表明，攻击面已延伸至开发者密钥与模型上传管线等基础设施环节。与此同时，**防御方正加速将前沿模型能力产品化**：Anthropic、Dragos 与 CISA 分别从开源框架、OT 实战与监管指南三个层面推动「AI 赋能防御」走向可复用工程实践，但厂商也同步警示 AI 生成修补与自主代理决策仍需人工把关。生成式 AI 被攻击者用于规模化钓鱼建站（Google 诉 Outsider Enterprise 案）与本地自复制蠕虫研究并存，说明 **AI 既是攻击加速器，也正成为攻击目标与新型攻击载体**。

💡 关键洞察（3～5 行）
- AI 供应链风险从 npm/PyPI 延伸至 IDE 插件市场与 Vertex AI 模型上传管线，开发者密钥与模型工件成为新攻击面（BleepingComputer / Unit 42）。

⚠️ 核心风险（列 3 条）
1) 运行时权限滥用 — Agent/插件继承过高权限即可静默外传密钥或执行命令；建议最小权限、密钥短期凭证与 IDE 插件白名单。  
2) 模型供应链投毒 — 可预测 staging bucket、恶意插件与技能包可在部署前替换模型或注入指令；建议升级 SDK、显式指定存储桶并审计 Agent 依赖。  
3) 间接提示注入 — 外部文档/邮件中的隐藏指令可劫持 Agent 决策链；建议输入隔离、行为沙箱与敏感操作强制人工审批。
