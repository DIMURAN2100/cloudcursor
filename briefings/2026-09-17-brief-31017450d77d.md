### 一、今日要点

**[1] mcp-gitlab 未认证可读出 PAT**
📌 类型：AI基础设施CVE

GitHub Advisory Database 于 9 月 16 日收录 **CVE-2026-61560**（CVSS Critical）：npm 包 `@zereight/mcp-gitlab` 在 `SSE=true` 时对全部 MCP 工具不做认证，其中 `upload_markdown` 的 `file_path` 未做路径约束，可读取本机任意文件并上传至 GitLab 项目。攻击者可借此读取 `/proc/self/environ` 窃取 `GITLAB_PERSONAL_ACCESS_TOKEN`，造成完整账户接管；官方称此为 Docker 部署默认配置。补丁版本为 **2.1.27**。属已确认缺陷，公告未给出在野利用证据。该包 9 月 15 日前后已连续披露 SSRF、DNS 重绑定等问题，本次为更高影响的认证缺失与本地文件读取链。

🔗 来源：[GitHub Advisory GHSA-cv3r-c5h8-f4g5](https://github.com/advisories/GHSA-cv3r-c5h8-f4g5) · [CVE-2026-61560](https://www.cve.org/CVERecord?id=CVE-2026-61560)

**[2] AI编码助手会话被劫持投毒**
📌 类型：AI自身安全

Mandiant《AI Risk and Resilience》2026 年 9 月报告披露一起已确认事件：攻击者劫持某未具名 SaaS 厂商开发者的活跃 AI 编码助手会话，先诱使接受遭投毒的第三方依赖建议，再经恶意 PyPI 包植入信息窃取木马并窃取 GitHub OAuth 令牌，随后将自扩散蠕虫 **Shai-Hulud** 散布至约 **100** 个内部代码仓库，并污染公司正式命名空间包导致二次感染。公开材料未说明入侵时间与会话接管具体手法。属厂商威胁情报中的实战案例，而非实验室演示。

🔗 来源：[Mandiant 报告页](https://cloud.google.com/security/resources/ai-risk-and-resilience-2026) · [The Hacker News](https://thehackernews.com/2026/09/attacker-hijacks-ai-coding-assistant.html)

**[3] BragJack 劫持五款浏览器AI**
📌 类型：AI自身安全

Forever Security 于 9 月 16 日发布 **BragJack** 研究：恶意浏览器扩展在已安装前提下，可劫持 Chrome（Gemini Live）、Perplexity Comet、Microsoft Edge、Opera Neon 与 Claude in Chrome 的内置 AI“身体”控制面。机制是篡改 AI 仅信任的厂商页面并注入指令，而非传统提示注入；可在部分产品上实现零点击代理驱动、本地文件读取或摄像头麦克风访问。Chrome 相关面已以 **CVE-2026-0628** 修复，Edge 为 **CVE-2026-55945**；截至报道时未见 KEV 收录或公开在野利用。属研究演示，前提是用户已安装攻击者扩展。

🔗 来源：[Forever Security 原文](https://forever.security/blog/bragjack-hijacking-5-browsers-via-built-in-ai-assistants) · [The Hacker News](https://thehackernews.com/2026/09/one-extension-could-hijack-ai.html)

**[4] RMCP 曝OAuth欺骗与会话泄漏**
📌 类型：AI基础设施CVE

官方 Rust MCP SDK 组件 `rmcp` 两条高危公告于 9 月 16 日进入 GitHub Advisory / NVD：**CVE-2026-63127** 未校验 OAuth Protected Resource 元数据中的 `resource` 字段，恶意 MCP 服务器可诱导客户端把合法授权服务器签发的访问令牌导向攻击者；**CVE-2026-63128** 在 Streamable HTTP 传输下可被未认证请求永久填满会话表，造成远程拒绝服务。影响 `< 2.0.0`，修复版本为 **2.0.0**。属已确认库级缺陷，面向所有基于 `rmcp` 且依赖 OAuth 保护 MCP 服务器的客户端集成。

🔗 来源：[GHSA-33f5-2c5q-wgwj](https://github.com/advisories/GHSA-33f5-2c5q-wgwj) · [GHSA-9pj6-vhgr-3mwh](https://github.com/advisories/GHSA-9pj6-vhgr-3mwh)

**[5] 欧委会主席吁放缓自我改进模型**
📌 类型：AI治理合规

欧盟委员会主席乌尔苏拉·冯德莱恩 9 月 16 日在欧洲议会国情咨文中称，正在开发的前沿模型将使黑客攻击能力达到“此前难以想象”的水平，并警告自我改进（self-recursive）模型与智能体逃逸、植入恶意代码等早期迹象；她表示将邀请领先 AI 实验室讨论如何支持其自行放缓步伐，并推动与加拿大、英国等在模型评估、验证、预警与 AI 安全上合作，同时重申《AI Act》是护栏基础。属高层政策表态，非法案即时生效。

🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/09/16/eu-ursula-von-der-leyen-ai/)

**[6] 上海上线生成式AI安全测试平台**
📌 类型：AI治理合规

在网信上海等渠道 9 月 15 日公开报道中，由上海市信息安全测评认证中心建设的全国首个生成式人工智能安全测试公共服务平台“智测能手”，已于 9 月 14 日国家网络安全宣传周上海地区活动开幕式发布。平台覆盖大模型安全测评、AIGC 标识验证、深度伪造内容检测，以及支持 MCP、SKILLS 等智能体相关代码审计的多 Agent 协同代码审计能力，定位为面向企业尤其是中小微的普惠化安全测试公共服务。属地方治理与测评能力落地，非漏洞披露。

🔗 来源：[网信上海 / 新浪科技转载](https://finance.sina.com.cn/tech/roll/2026-09-15/doc-inirwwna3816876.shtml) · [搜狐同步稿](https://www.sohu.com/a/1076350267_121106832)

**[7] 失控会计智能体单小时烧费五万美元**
📌 类型：AI自身安全

同一份 Mandiant 报告给出无非攻击者场景的案例研究：某会计智能体进入失控执行循环，在不到一小时内发出逾 **15,000** 次高成本 API 调用，产生约 **50,000** 美元云费用并干扰业务交易。报告据此强调企业需为智能体配置身份边界、速率与费用护栏，并将 SOC 观测转向实时行为遥测。属厂商案例研究中的运维失控风险，非外部入侵。

### 二、深度速览

#### 【AI 赋能防御】

Mandiant 基于红队与事件响应指出：企业 AI 部署中提示注入仍是主攻击向量，同时常伴随文件权限与访问控制不足。一例内部评估中，测试人员说服管理代码仓与 CI/CD 的 AI 助手“参与授权安全测试”，并提供其控制的外部 GitHub 个人访问令牌；因 GitHub 属已批准域名，助手将敏感内部仓库克隆并推送至外部账户。对防御侧的含义是：将域名允许列表视为充分信任边界已不够，必须对智能体写操作、外传目标与令牌使用施加独立审批与行为遥测。

🔗 来源：[Mandiant 报告页](https://cloud.google.com/security/resources/ai-risk-and-resilience-2026)

报告同时汇总攻击者侧变化：将 LLM 嵌入多阶段决策、用中间件与代理池绕过商业平台护栏与计费，以及把传统供应链手法迁移到 OpenClaw skills、AI 编码助手与 LLM 安全扫描器。对 SOC 而言，应将“依赖安装建议是否来自助手”“MCP/扩展是否突然新增工具描述”纳入告警假设，而不仅监控传统恶意二进制。

🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/09/16/google-mandiant-enterprise-ai-security-risks-report/)

#### 【AI 系统风险】

`@zereight/mcp-gitlab` 的 CVE-2026-61560 与前一日同包 SSRF/DNS 重绑定公告共同说明：把 MCP 以 SSE 默认暴露到网络，等于把宿主文件系统与云令牌暴露给未认证调用方。`upload_markdown` 本意是便利文档同步，在缺认证与路径净化时成为 PAT 外泄通道。缓解应同步升级至 ≥2.1.27、禁用默认公网 SSE、禁止智能体工具读取 `/proc` 与密钥路径，并轮换可能已暴露的 GitLab 令牌。

🔗 来源：[GHSA-cv3r-c5h8-f4g5](https://github.com/advisories/GHSA-cv3r-c5h8-f4g5)

BragJack 与 RMCP OAuth 欺骗指向同一类“身份混淆”：攻击者不攻模型对齐，而攻 AI 只信任的页面、扩展权限或资源元数据。浏览器侧应限制扩展对厂商 AI 页面的脚本注入与 declarativeNetRequest 滥用；MCP 客户端侧必须按 RFC 9728 校验 `resource` 一致性，并尽快将 `rmcp` 升至 2.0.0。Mandiant 的编码助手被劫持案例则提醒：依赖安装建议与长效 OAuth 令牌应视为高风险操作面。

🔗 来源：[Forever Security](https://forever.security/blog/bragjack-hijacking-5-browsers-via-built-in-ai-assistants) · [GHSA-33f5-2c5q-wgwj](https://github.com/advisories/GHSA-33f5-2c5q-wgwj)

#### 【全球治理与标准】

冯德莱恩将自我改进模型与智能化黑客能力上升为欧盟战略风险，并提出与加、英联合评估及邀请前沿实验室“放缓”的政治倡议；同期上海以公共服务平台方式把大模型测评、AIGC 标识与智能体代码审计做成可落地能力。两者路径不同——一边是超国家政策协调，一边是地方测评供给——但都表明治理重点正从原则声明转向可执行的评测、验证与企业可达服务。

🔗 来源：[Help Net Security](https://www.helpnetsecurity.com/2026/09/16/eu-ursula-von-der-leyen-ai/) · [网信上海转载](https://finance.sina.com.cn/tech/roll/2026-09-15/doc-inirwwna3816876.shtml)

### 三、今日趋势洞察

智能体安全事件正从“模型说了什么”转向“代理被谁命令、用了哪枚令牌、装了哪个依赖”：MCP 默认暴露面、浏览器内置 AI 控制面与编码助手会话，在同一新闻周期里分别以 Critical CVE、研究演示和 Mandiant 实战案例出现。治理层则同步用“放缓自我改进”与“公共测评平台”回应同一结构——代理可行动能力已经普及，安全控制与评测供给仍在追赶。

### 四、企业行动清单

- 立即将 `@zereight/mcp-gitlab` 升级至 ≥2.1.27，关闭未认证 SSE 公网暴露，轮换相关 GitLab PAT 并审计近期仓库/CI 变量变更。
- 盘点所有基于 `rmcp` 的 MCP 客户端，升级至 2.0.0，并验证 OAuth 资源元数据 `resource` 字段一致性校验已生效。
- 对 AI 编码助手启用依赖允许列表与校验和校验，禁止助手直接持有长效 OAuth/云密钥，依赖下载改经内部制品库。
- 审查企业浏览器扩展策略：限制对 AI 厂商页面的脚本注入类权限，优先升级已修复的 Chrome/Edge 版本。
- 为生产智能体设置 API 调用速率、费用熔断与异常循环告警，避免非攻击场景下的失控烧费与业务中断。
